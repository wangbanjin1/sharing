# 混合数据融合样本构造流水线设计（`hybrid_memory_data`）

本文面向 `D:\coding\hybrid_memory_data` 代码仓，以 300 个由真实网元单据抽象得到的基础用户画像为起点，结合 `storyline_and_intent_unified_table.xlsx` 中的核心素材，围绕 **4 模块 13 项最小必测评测体系**（`M1~M3`、`F1~F3`、`I1~I3`、`E1~E4`），给出“网元单据 + 多轮对话”混合数据集的工程评估与模块化流水线设计，输出直接对接 [评测系统模块化设计](评测系统模块化设计.md) 的标准 `eval_cases.jsonl`。

## 一、流水线工程评估总表

数据构造与全量评测按环境解耦：**数据流水线的口语润色与语义质检在外部环境调用大模型 API 完成**；生成并通过质检的 `eval_cases.jsonl` **带回内部调试环境（黄区）**，使用内部已有大模型与向量模型跑全量测试与多轮调试，测试阶段不依赖外部付费接口。综合评估如下：

| 评估维度 | 工程设计口径 | 量化指标与实现机制 |
| :--- | :--- | :--- |
| **1. 数据集规模与分集策略** | 基于 300 个基础用户画像实施分层聚类抽样，按画像级物理隔离划分为三集并保留扩展池；单样本规模严格受表 1（基础时间跨度 `G1.1`、事件节点规模 `G1.2`、单据与会话配比 `G4.1`）控制，通过多用户样本组合共同覆盖 4 大类共 13 项最小评测维度 | 启用 130 个画像，预留 170 个作后续扩展与盲测轮换：<br>• `Dev`（调优集）：30 人（短/中档为主，覆盖基础验证与快速回归）；<br>• `Eval`（回归集）：60 人（短/中/长三档均衡，确保 13 项每项覆盖 30~50 个正负评测点）；<br>• `Held-out`（盲测集，含记忆积累后的留出新任务增益 `E4`）：40 人（中/长档为主，画像零重叠）；<br>• 全局配比：需用记忆与无需记忆按 **1 : 1**，单维度正向与负向边界样本按 **6 : 4**，非偏好噪声类型与干扰占比（`U8.5`）覆盖低噪 `<20%` / 中噪 `20%~50%` / 高噪 `>50%` |
| **2. 单用户双源融合与主支线配比（对齐表 1 因子）** | 严格遵循表 1 故事线维度控制单用户事件规模、主支线拓扑与双源比例，避免脱离约束设值，不强求单用户塞满全部 13 项评测维度 | 严格按表 1 因子与联动约束采样：<br>• **基础时间跨度（`G1.1`）**：`{2 周 / 1 个月 / 3 个月 / 6 个月}`；<br>• **事件节点规模（`G1.2`）**：少 `[10, 15]` / 中 `[16, 22]` / 多 `[30, 60]`（约束：2 周档不配 `≥30` 节点；6 个月档不配 `[10, 15]` 节点）；<br>• **主支线结构与穿插关系（`G2.2`）**：`{单主线 / 主线+1条支线 / 主线+2~3条支线}`，配合支线触发事件（`G2.3`）与支线归宿状态（`G2.4`：回原主线 / 转新主线 / 周期性复现）；<br>• **单据与会话配比（`G4.1`）**：`{100:0（纯静默单据） / 90:10 / 80:20 / 70:30}`（始终保持单据多于会话）；<br>• **历史证据至测试点间隔（`G4.3`）**：`{近距 <5 步 / 中距 5~15 步 / 远距 15~35 步}`（`[10, 15]` 规模不配 `15~35` 步） |
| **3. 求解复杂度分级（`solver_tier`）** | 针对半结构化与非结构化混合输入，对每条评测会话显式标注三级求解难度，支撑分能力层级归因与线上分级路由评估 | • **规则可解（`rule`）**：半结构化指令、结构化单据入库、完整三要素模板解析、白名单/套餐/时间算术确定性校验；<br>• **小模型可解（`small_model`）**：常规口语改写、单意图补参、单轮常规偏好填充、明确域外/闲聊收口与常规资源路由；<br>• **大模型可解（`large_model`）**：间接语用理解、多业务并发与否定排除、偏好冲突修订、中途改口清旧约束、跨阶段推理与程序避错迁移 |
| **4. 构建与评测资源成本** | 数据构造与全量评测环境解耦：外部环境按单用户样本核算 API 润色与质检成本（预留 1.5~2 倍重试与抽检余量），导出标准用例集后回迁内部调试环境（黄区）执行全量评测 | • **构建侧（按单用户样本估算，参考外部 API 常规单价并留足余量）**：<br>&nbsp;&nbsp;- 网元单据与状态机真值由确定性程序生成（零模型开销）；<br>&nbsp;&nbsp;- 单用户样本对话润色 + 语义质检 + 失败重采样（含 1.5~2 倍余量）：约 **1.5 万 ~ 3.0 万 tokens / 用户样本**，单样本成本约 **¥0.10 ~ ¥0.25 / 人**；<br>&nbsp;&nbsp;- 按 130 人折算单次全量构建约 **¥15 ~ ¥35**（含多轮迭代调优总预算可控在 **¥150 以内**）；<br>• **评测侧**：`eval_cases.jsonl` 迁入黄区，依托内部自有推理模型与向量模型完成全量基线测试与 `k` 次独立采样，零外部 API 费用 |
| **5. 多样性与防泄露保障** | 通过画像源头、故事线因子、意图表达维度、语言风格与向量去重五层约束控制样本多样性，并执行确定性防答案泄露校验 | ① **画像源头多样**：300 画像按业务类型、套餐档位、空值比例聚类抽样；<br>② **故事线因子多样**：从表 1 组合采样跨度、主支线、演化趋势、双源配合与噪声占比；<br>③ **意图表达多样**：从表 2（意图表达维度与因子表）组合采样要素组合与表达层级（清晰直述、口语省略、间接语用吐槽、多业务并发、否定排除、模糊指代、参数冲突/越界等）；<br>④ **说话人风格与禁词控制**：润色阶段注入随机说话人风格配置与高频模板词黑名单；<br>⑤ **向量去重与防泄露**：同类样本首轮提问余弦相似度 `> 0.88` 自动重采样；规则卡口严禁首轮提问字面泄露待补全或待检索槽位值 |
| **6. 人工介入节点与工作量** | 仅在规则定标、小样本校验与盲测终审三个关键节点引入人工，发现问题统一回改生成器与提示词，禁止手工修补数据产物 | 总人工投入约 **1.5 ~ 2 人天**（预留复核余量）：<br>① 规范定标（0.5 人天）：确认业务硬规则边界及 13 项每项 2~3 条示范样本（Golden Seed）；<br>② 小样本验收（0.5 人天）：抽检 5~10 名全覆盖用户样本并回修生成器；<br>③ 盲测终审（0.5~1 人天）：对 Held-out 核心评测会话执行无歧义与真值一致性复核 |
| **7. 流水线构建与迭代耗时** | 确定性骨架生成与高并发异步润色分离，引入骨架内容哈希缓存支持增量重跑（耗时预留重试与并发抖动余量） | • 确定性模块（抽样、状态机真值、单据生成、规则质检）：`< 10 秒`；<br>• 外部 API 异步并发润色（15~25 并发，含重试余量）：130 人全量首次构建约 **5 ~ 10 分钟**，5~10 人小样本验证 `< 1 分钟`；<br>• 增量迭代：基于骨架与模板哈希缓存，局部修改仅重跑受影响片段（秒级完成） |

## 二、流水线总体模块化架构

流水线坚持 **“确定性程序生成骨架与真值 + 外部大模型 API 仅做口语润色 + 自动规则与向量卡口质检”** 的四阶段解耦设计，彻底杜绝大模型算错时间或编造真值的问题；最终导出的 `eval_cases.jsonl` 可直接带回黄区，使用内部本地模型完成全量评测与调试。

![[hybrid_data_pipeline_overall.drawio.svg]]

| 阶段模块 | 对应代码模块（`hybrid_memory_data`） | 核心职责 | 输入 | 输出 |
| :--- | :--- | :--- | :--- | :--- |
| **① 画像分层抽样** | `profile_sampler` | 对 300 个基础画像做特征聚类与清洗，切分画像零重叠的 Dev / Eval / Held-out / 预留池 | `user_profiles.json`（300 人） | 分集画像索引与原生空值标记（`unobserved_dims`） |
| **② 骨架编排与真值计算** | `storyline_planner` + `memory_state_machine` | 按 13 项最小矩阵编排时间轴单据与对话骨架，纯代码状态机推演每处埋点的期望记忆与期望意图，标注 `solver_tier` | 分集画像、业务规则库、13 项素材词表 | 带确定性真值与检查点标记的故事线骨架 |
| **③ 双轨渲染** | `dual_renderer` | 单据轨纯规则生成（保留真实 `null` 与可控噪声）；对话轨调用外部 LLM API 按风格卡并发润色并按骨架哈希缓存 | 故事线骨架、风格卡与套话黑名单 | 完整双源事件流与自然口语对话 |
| **④ 自动质检与导出** | `qc_and_exporter` | 规则全检（时间算术、白名单/套餐、防答案泄露、原生 `null` 保留）+ 向量相似度去重 + 抽样语义复核 | 渲染完成的候选样本 | 标准 `eval_cases.jsonl`（供黄区全量评测）+ 覆盖率报告 |

## 三、300 画像切分、三类求解分级与 `E4` 阶段留出设计

为了防止调优过拟合、精准区分不同能力层级并支撑阶段积累增益实验，数据组织围绕三个结构约束展开。

![[hybrid_data_e4_and_tier_split.drawio.svg]]

### 3.1 300 基础画像的聚类与物理隔离
- **特征聚类**：先按主力应用类型（高频游戏、办公会议、户外直播、多业务并发）、套餐档位、活跃频次与原生空值（`null`）比例将 300 名用户聚类分群。
- **物理隔离**：在各簇内按比例分层抽样切分出 **Dev（30 人）**、**Eval（60 人）**、**Held-out（40 人）**，三者画像零重叠；剩余 **170 人**留在预留池，供后续业务扩展或定期轮换盲测集。

### 3.2 三类求解分级标签（`solver_tier`）
由于实际业务输入包含半结构化记录与不同复杂度的口语表达，每条评测会话显式标注求解分级，便于评测报告按层级拆解效果与开销：

| 求解分级 | 典型输入与任务特征 | 对应主要评测项 |
| :--- | :--- | :--- |
| **规则可解（`rule`）** | 半结构化指令或标准网元单据入库、完整明确的三要素输入、白名单/套餐 MOS/时长上限硬校验、精确字段算术校验 | `M1`（单据提取）、`I1`（基础清晰模板）、`I3`（确定性规则驳回） |
| **小模型可解（`small_model`）** | 常见口语改写、单意图缺失参数补全、单轮常规偏好填充、明确域外与闲聊 1~2 轮快速收口、常规资源路由 | `M1/M3`（常规对话提取与检索）、`F1/F2`（单点指代与偏好）、`I2/I3`（常规澄清与收口） |
| **大模型可解（`large_model`）** | 间接语用吐槽暗示、多业务并发与否定排除、偏好冲突修订与临时回退、多轮中途改口清旧约束、跨阶段信息组合与程序避错经验迁移 | `M2`（复杂演进）、`F2/F3`（跨场景隔离与避错迁移）、`I1/I2/I3`（高难语用与长会话）、`E4` |

### 3.3 `E4` 阶段记忆积累留出题构造
在 Held-out 的 40 名用户中，按时间轴显式划分两段历史与一组未参与学习的留出新任务：
- **阶段 1 历史流（检查点 `C1`）**：形成基础长期习惯与早期事件。
- **阶段 2 新增历史流（检查点 `C2`）**：引入局部规则修订、新场景个性化偏好与踩坑避错经验（如大型场馆提前 30 分钟预热）。
- **同一批留出新任务**：测试发生于全部历史之后，分别设置 4 类正向分组（跨阶段信息组合、个性化规则形成、局部规则修订、程序经验迁移）与 2 类反例（未改规则保持、常规居家不适用场馆预热经验）。评测时仅切换 `C1` 与 `C2` 检查点，其余变量严格一致，计算留出净增益 \(\Delta \text{EM}\)。

### 3.4 单用户样本的双源融合与主支线配比（对齐表 1 故事线因子）
**核心原则：单样本事件规模、时间跨度、主支线拓扑、双源配比与回溯间隔严格由表 1（`1_故事线维度与因子表`）控制**，不另行设值；通过多个用户样本组合采样，共同覆盖 4 大类共 13 项最小评测维度。

| 用户样本档位 | 基础时间跨度与事件节点规模（`G1.1 / G1.2`） | 主支线拓扑、双源配比、间隔与噪声约束（`G2.2 / G4.1 / G4.3 / U8.5`） | 适用集与侧重点 |
| :--- | :---: | :--- | :--- |
| **少节点短程档** | 2 周 · `[10, 15]` 节点 | 主支线结构（`G2.2`）：单主线 或 主线+1条支线；单据与会话配比（`G4.1`）∈ `{100:0 / 80:20 / 70:30}`；回溯间隔（`G4.3`）仅配近/中距（`<15` 步）；干扰占比（`U8.5`）低/中噪 | 主力用于 **Dev 调优集**与纯静默单据基线（`100:0` 末尾接测试会话），快速验证形成、检索与单轮直通 |
| **中节点标准档** | 1 个月 · `[16, 22]` 节点 | 主支线结构（`G2.2`）：单主线 或 主线+1条支线（含回原主线/转新主线）；单据与会话配比（`G4.1`）∈ `{100:0 / 90:10 / 80:20 / 70:30}`；回溯间隔（`G4.3`）覆盖近/中距；干扰占比（`U8.5`）覆盖低/中/高噪（`>50%`） | 主力用于 **Eval 回归集**：覆盖习惯形成、偏好修订、跨场景隔离、多轮消歧与冲突更新 |
| **多节点长程 / 留出增益档** | 3~6 个月 · `[30, 60]` 节点 | 主支线结构（`G2.2`）：主线+1条支线 或 主线+2~3条支线；单据与会话配比（`G4.1`）∈ `{90:10 / 80:20 / 70:30}`（6 个月档不配 `[10, 15]` 节点）；回溯间隔（`G4.3`）重点覆盖远距 `15~35` 步；支持记忆积累留出新任务增益（`E4`）阶段 1/2 检查点 | 主力用于 **Eval 长程与 Held-out 盲测集**：覆盖跨月回溯、程序避错迁移与阶段积累净增益 |

其中，每名用户的对话会话按如下结构自然穿插在单据流中：
- **单据分布**：有效单据聚焦 2~3 个主力应用与 1~2 个场景，保证稳定偏好自然达到重复阈值 \(N_{\min}\)；噪声单据按比例混入短时取消单据、卡顿降质单据与同期无关并行单据（测 `M1` 过滤与 `F1` 防误关联）。
- **会话组合**：每名用户一般配 2~3 个前序铺垫/演化会话（建立自定义表述、显式修订或踩坑经验，同时混入 1 个假设咨询/闲聊陷阱），加 4~6 个核心埋点评测会话（如 1~2 个记忆利用 + 1 个多轮消歧/改口 + 1~2 个无需记忆直通/驳回/闲聊对照）。

### 3.5 全局覆盖完备性保障机制
由于单用户样本不强求覆盖全部评测维度，系统通过 **“配额定义 → 约束分配 → 覆盖校验与缺口补采”** 三步闭环，确定性保障 4 大类 13 项最小评测维度及表 1、表 2 核心因子的全量覆盖：
1. **全局覆盖配额矩阵（Coverage Quota Matrix）**：在规划阶段预先配置 `Dev / Eval / Held-out` 各分集的目标配额，明确 13 项最小评测维度及二级子场景的样本下限（如 Eval 集每项至少 30~50 个评测点），同时约定需用与无需记忆 `1:1`、正向与负向 `6:4`、三类求解分级（`solver_tier`）及表 1 关键档位（如 `100:0` 纯静默单据、高噪与远距回溯）的最低占比。
2. **基于约束的评测点分配（Quota-Constrained Allocation）**：不采用无约束随机采样，而是由调度器将配额矩阵中的待测评测点按画像特征与表 1 联动约束定向分配至兼容用户（例如含未观测空值的画像优先承接无记录防盲猜评测点，多应用高频画像优先承接长程与多支线评测点），并校验单用户内部评测点无语义冲突、满足时间跨度与节点规模联动约束。
3. **导出前覆盖率校验与缺口补采（Coverage Verification & Backfill）**：在导出 `eval_cases.jsonl` 前，自动汇总全量通过质检样本的实际分布并与配额矩阵核对；若某项维度因质检过滤出现样本缺口，仅针对缺口维度定向补采与增量渲染，直至全部维度达标后输出正式数据集。

## 四、确定性骨架与外部 API 双轨渲染

### 4.1 状态机确定性算真值（真值不交由模型生成）
- 故事线编排器按 `storyline_and_intent_unified_table.xlsx` 抽取的成对因子组合，生成带精确时间戳的事件序列（历史单据、前序对话、噪音单据、埋点评测会话）。
- 内置的确定性记忆状态机同步走一遍该时间轴，直接产出每处埋点的**期望记忆条目**（有效偏好、已置旧版本、禁止入库的闲聊/咨询条目）与**期望意图模板**（严格满足 `end - start == duration` 与套餐边界），从根源消除真值算术错误。

### 4.2 双轨渲染与外部 LLM 并发润色
- **网元单据轨（纯规则）**：直接依据用户画像与真实分布生成结构化单据，原生空值（`null`）按真实比例保留，可控注入短时取消单据、卡顿异常单据与并行无关单据（服务于 `M1 / F1` 负向测试）。
- **对话轨（外部大模型 API 润色）**：
  - 仅负责将结构化意图骨架改写为自然口语，绝不改动底层槽位与真值（80% 常规对话用轻量模型，20% 间接语用/反语/多业务并发等难例用强模型）；
  - 每次请求注入随机采样的**说话人风格卡**（极简急躁型、先吐槽后提诉求型、口语倒装省略型、带自定义简称型等）与**禁用套话黑名单**；
  - 强制注入**防泄露约束**（如测 `F2` 偏好或 `I2` 慢路径消歧时，首轮提问严禁出现被遮蔽的参数值）；
  - 按“骨架内容 + 风格卡 + Prompt 版本”计算哈希做本地缓存，支持异步并发与断点续跑，微调单个场景仅重跑受影响片段。

## 五、自动质检卡口与人工最小参与节点

### 5.1 两级自动质检卡口（`qc_and_exporter`）
1. **确定性规则全检（100% 覆盖）**：
   - 时间算术校验（`end - start == duration`、起止时间合法）；
   - 业务规则一致性校验（白名单、套餐 MOS 档位、单次时长上限）；
   - 防答案泄露校验（需靠记忆或澄清补齐的槽位值，严禁以字面形式出现在首轮提问中）；
   - 空值边界校验（画像标注为未观测的维度，历史单据中严禁擅自回填）。
2. **向量相似度去重与抽样语义复核**：
   - 调用向量模型计算同评测项下首轮提问的余弦相似度，相似度 `> 0.88` 自动打回换风格卡重润色；
   - 随机抽样 20% 会话交由大模型核查“题意是否清晰可解、是否存在二义性”。

### 5.2 人工参与的 3 个高杠杆节点
- **节点 1（前置定标，0.5 天）**：对齐业务规则表与 13 项各 2~3 条示范样本（Golden Seed），固化为润色 Prompt 的参考示例。
- **节点 2（5~10 人小样本验收，2~3 小时）**：先跑通覆盖全部 13 项的小样本并生成 HTML 审阅页人工核查；发现问题一律回改生成器代码与模板，绝不手工修改生成结果。
- **节点 3（Held-out 核心题终审，0.5 天）**：对最终用于里程碑验收的 Held-out 核心会话做一轮人工快速过目，保证盲测尺子无歧义。

## 六、单条样本构造数据流与输出对齐

以 `USER_001` 为例，展示从原始基础画像经骨架状态机、双轨本地渲染、质检卡口到输出 `eval_cases.jsonl` 的完整数据流：

![[hybrid_data_sample_generation_flow.drawio.svg]]

### 6.1 输出文件 `eval_cases.jsonl` 核心字段（直接对接 Eval Run Harness）
每行对应 1 名用户的完整连续时间轴用例，核心字段如下：
- **基础标识与分层**：`case_id`、`split`（`dev / eval / held_out`）、`user_profile_id`、`unobserved_dims`；
- **连续双源事件流（`timeline_events`）**：按时间戳严格排序的网元单据、前序对话与埋点评测会话，每条记录标注 `event_type`、`timestamp`、`stage`（用于 `E4` 区分阶段 1 / 阶段 2 / 留出新任务）；
- **埋点评测标注（`eval_points`）**：每个埋点会话挂载 `eval_tags`（如 `["M1", "F2", "I2"]`）、`solver_tier`（`rule / small_model / large_model`）、`need_memory`（`true / false`）、`sim_user_goal`（模拟用户隐含需求与应答规则）、`gt_intent`（期望意图模板或拒识/咨询标签）与 `gt_memory`（期望记忆条目与禁止入库/禁止召回清单）。

### 6.2 `D:\coding\hybrid_memory_data` 迭代落地顺序
1. **第一阶段（小样本闭环）**：基于现有 `src/v2/` 接入 300 画像聚类抽样与外部 LLM 润色/向量去重流水线，先抽取 5~10 名用户跑通覆盖全部 13 项的小样本，人工验收并修正模板。
2. **第二阶段（Dev + Eval 构建与黄区首轮基线）**：一键生成 Dev（30 人）与 Eval（60 人）的 `eval_cases.jsonl`，校验 13 项覆盖率、1:1 需用/无需记忆配比与三类 `solver_tier` 分布，带回黄区用内部模型跑首轮评测基线。
3. **第三阶段（Held-out 与 `E4` 锁定）**：生成 40 人 Held-out 盲测集（含 `E4` 阶段积累留出题），人工终审后物理冻结，带回黄区仅用于版本里程碑验收。
