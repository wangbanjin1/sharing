# 电信网络意图提取 Agent · Eval Run 评测系统模块化设计

本文面向电信网络保障场景下的意图提取 Agent（结合历史网元单据流与多轮口语对话），给出 Eval Run 评测系统的模块化架构设计。系统按“**用例构建 → 执行与环境 → 证据沉淀 → 判定与归因 → 持续治理**”五个解耦层次组织，既支持记忆生命周期过程评测，也支持端到端意图提取闭环评测与误差归因。

---

## 一、总体模块化架构

Eval Run 评测系统划分为五个核心模块，各模块之间通过标准化数据结构（用例定义、快照引用、证据记录、评测报告）解耦，避免评测脚本与被测 Agent 强绑定。

![[eval_run_overall_modules.drawio.svg]]

| 模块 | 核心职责 | 上游输入 | 下游输出 |
| :--- | :--- | :--- | :--- |
| **1. EvalCase（用例构建）** | 定义双源故事线、意图表达变体、交互规则与标准答案，管理数据集划分 | 真实网元单据、业务规则库、线上失败案例 | 标准化用例集（Dev / Eval / Held-out）与标准记忆状态快照 |
| **2. Harness & Environment（执行与环境）** | 编排三组对照实验，按 Stage A 建库锁定快照、Stage B 单 Trial 隔离执行多轮交互 | 用例集、被测 Agent 与记忆系统、外部只读知识源 | 锁定记忆快照、全量交互轨迹、最终输出与运行度量 |
| **3. Evidence（证据沉淀）** | 旁路采集并结构化落盘记忆状态、检索候选、交互轨迹、结果产物与版本元信息 | Stage A / Stage B 运行时回调与快照接口 | 可回溯、可复盘的标准化 Evidence 记录 |
| **4. Evaluator（判定与归因）** | 执行记忆过程评测与端到端闭环评测，汇总核心指标并完成失败模块归因 | Evidence 记录、用例真值、标准记忆状态快照 | 分场景评测报告、核心指标看板与失败归因清单 |
| **5. Governance（持续治理）** | 依据归因结果驱动算法优化与基准维护两条独立闭环，防止过拟合与评测漂移 | 归因清单、人工抽检样本、线上新增 Badcase | 更新后的基准集/评估器、迭代后的记忆与意图版本 |

## 二、模块一：EvalCase 用例构建

EvalCase 负责明确“用什么测、标准答案是什么、如何保证评测题目有效且无泄露”，内部拆分为三个子模块：

### 2.1 双源故事线建模
- **异构双源联动**：同步构造持续流式的历史网元单据（高频、隐式、保留真实空值 `null` 分布）与稀疏多轮口语对话（显式意愿、改口原因、个性化表述映射）。
- **记忆演化因子覆盖**：覆盖冷启动与热启动、长期习惯形成、偏好冲突更新、临时切换与到期恢复、可控噪声（短时取消单据、卡顿异常记录、同期无关并行单据）以及位置粒度隔离。
- **场景显式区分**：将测试用例明确划分为**无需记忆场景**（检验记忆系统不引入误干扰）与**需用记忆场景**（检验记忆系统带来的准确率与交互效率增益）。

### 2.2 意图与交互覆盖
- **三类核心意图**：网络保障诉求（输出业务对象、保障时间、体验参数三要素模板）、业务/资费/白名单规则咨询、9 类域外请求拒识。
- **语言与参数复杂度**：覆盖信息缺失或指代模糊（`Underspecified`）、多意图混合、复杂句法、口语省略以及参数越界/冲突错误。
- **多轮交互边界**：定义单轮直通、两轮澄清、三轮动态收敛与执行恢复等交互模式，明确最大澄清轮次上限 \(X\)、权限协商与撤销终止条件。

### 2.3 用例治理与数据集划分
- **真值确定性校验**：结合确定性业务规则校验时间算术一致性（如 `end - start == duration`）与槽位合法性，生成标准答案与标准记忆状态快照（Ground-Truth Memory Snapshot）。
- **防泄露审核**：审核题目描述清晰可解，剔除在用户提问话术中直接暴露标准答案线索的样本。
- **三集严格隔离**：划分为 **Dev 调优集**（日常开发与提示词迭代）、**Eval 回归集**（版本合入与横向对比）与 **Held-out 盲测集**（只用于里程碑验收，严禁参与调优）。

## 三、模块二：Harness 与 Environment（双阶段执行与记忆交互）

Harness 与 Environment 负责把评测稳定、可复现、无干扰地跑起来，核心机制是**三组对照实验编排**与 **Stage A / Stage B 双阶段快照隔离**。

![[eval_harness_stage_a_b.drawio.svg]]

### 3.1 Evaluation Harness 编排控制器
- **统一接入适配层**：屏蔽不同底层大模型、提示词框架与记忆后端的差异，通过统一的初始化、历史写入、单轮对话与状态导出接口接入被测对象。
- **三组标准对照**：在同一套用例集上平行运行三组配置，用于后续剥离上游与下游误差：
  1. **无记忆基线（`No-Mem`）**：关闭长期记忆，衡量纯意图提取下界与无需记忆场景基线；
  2. **真实记忆（`Full-Mem`）**：完整接入被测记忆系统，衡量记忆写入、演进、检索与意图理解联调的真实线上表现；
  3. **标准记忆上界（`Oracle-Mem`）**：直接注入标准记忆状态快照，剥离上游记忆误差，测算下游意图理解与决策模块的能力上界。
- **预算与重复采样控制**：对每个任务统一限定最大澄清轮次 \(X\)、工具调用步数与超时熔断，支持独立重复运行 \(k\) 次 Trial 以评估稳定性（`pass@k` 与 `pass^k`）。

### 3.2 Stage A：历史流式输入建库与快照锁定
- **按时间轴逐条灌入**：按真实时间戳顺序逐条输入历史网元单据、前序对话与噪声记录，驱动记忆系统执行写入与生命周期演进（情景记忆只追加 `ADD-Only`、语义记忆按唯一键查表更新与冲突置旧 `superseded`、候选态激活、时间衰减与受控遗忘）。
- **锁定不可变快照**：建库完成后，将情景记忆、语义记忆与经验（程序）记忆的状态持久化为只读快照。该快照同时用于两件事：一是在 Stage A 结束时直接与标准记忆状态快照比对评分；二是在 Stage B 中供多个测试题与多次 Trial 复用，避免重复建库开销及跨用例状态互相干扰。

### 3.3 Stage B：在线多轮交互测试（单 Trial 快照恢复）
- **单 Trial 状态恢复**：每个 Trial 启动前从 Stage A 锁定的快照恢复长期记忆，并清空工作记忆与会话上下文，确保每次采样严格独立。
- **外部只读信息源**：为 Agent 提供确定性的只读外部知识库 RAG（业务规则、资费政策、白名单）与用户套餐档位查询接口（最低 MOS 与 VIP 优先级）。
- **User Simulator（用户模拟器）**：持有该用例的隐含真实需求与画像约束，依据预设交互规则与被测 Agent 开展 1 至 \(X\) 轮动态对话，模拟补充缺失参数、确认偏好冲突、中途改口或撤销需求等真实行为，同时禁止向 Agent 泄露评测真值。

## 四、模块三与模块四：Evidence 证据沉淀与 Evaluator 双线判分

为了避免仅看最终答案掩盖中间过程缺陷（例如记忆检索漏召回却靠模型猜对，或冗余追问导致用户体验下降），系统在执行侧旁路沉淀三类证据，并在判定侧拆分为**记忆生命周期评测**与**记忆内容及意图闭环评测**两条主线。

![[eval_evidence_and_evaluator.drawio.svg]]

### 4.1 Evidence 证据沉淀层
所有证据均为旁路只读采集，不侵入被测 Agent 推理过程，统一按 `run_id / task_id / trial_id` 关联落盘：
1. **记忆演进与检索证据**：Stage A 每次写入前后的状态快照与版本变更记录；Stage B 分库路由结果与检索返回的 Top-K 候选列表及排序分数。
2. **交互轨迹与结果产物**：每轮的直通或澄清路由决策、只读外部查询（RAG / 套餐）调用记录、多轮追问与改口对话全文、最终输出的意图模板或咨询/拒识判定结果。
3. **运行度量与版本绑定**：单次任务闭环对话轮数、累计输入/输出 Token 消耗、端到端响应时延，以及完整绑定的模型版本、Prompt 版本、记忆系统配置与用例集版本号。

### 4.2 Evaluator 双线判分引擎
- **主线一：记忆生命周期评测（过程质量，M1 ~ M3）**
  - **M1 记忆形成**：核验从单据与对话中抽取的关键要素是否准确，是否有效过滤闲聊与中途取消的无效单据。
  - **M2 记忆演进**：核验多次重复后习惯归纳、偏好冲突时旧版本置旧（`superseded`）以及过期/显式删除时的受控遗忘是否准确。
  - **M3 记忆检索**：核验分库路由是否正确、目标记忆是否排在 Top-K 前列（查准率、查全率、MRR），以及是否过滤已失效历史版本。
- **主线二：记忆内容与意图闭环评测（端到端，1.1 ~ 7.3）**
  - **记忆内容利用**：检验情景回溯、语义偏好填充与经验（程序）避错策略是否真实生效。
  - **意图闭环质量**：检验复杂句法解析、9 类域外拒识边界以及多轮主动消歧能力（同时约束冗余追问 `Over-Clarification` 与未澄清直接执行 `Premature Execution`）。
  - **两类场景分开统计**：**无需记忆场景**重点监控是否因误召回导致指标下降；**需用记忆场景**重点衡量相对无记忆基线的净增益。

### 4.3 混合判定器与指标聚合
- **确定性规则断言为主**：三要素意图模板采用全字段精确匹配（`EM`）加时间算术校验，防止局部字段凑分；槽位 `F1` 作为细粒度辅助观测指标。
- **轨迹级 Judge 为辅**：针对多轮主动消歧的提问质量、拒识说明合理性、改口响应贴合度等非结构化维度，结合规则约束与 LLM Judge 判分，并定期通过人工抽检校准评估器一致性。
- **效果与效率双维聚合**：
  - 效果维度：全量匹配率（`EM`）、槽位 `F1`、记忆检索查准/查全/`MRR`、主动消歧与拒识准确率、多采样 `pass@k` 与一致性 `pass^k`。
  - 效率维度：相对无记忆基线的**多轮澄清减少率**、**累计 Token 节省率**以及端到端响应时延 `P50 / P95`。

## 五、模块五：Governance 持续治理与闭环迭代

评测运行结束后，核心价值在于把分数转化为明确的工程改进方向。系统依托三组对照分数拆解误差来源，将失败样本分流至**算法优化**与**基准维护**两条独立闭环。

![[eval_governance_attribution_loop.drawio.svg]]

### 5.1 基于对照差值的误差归因
- **上游记忆损耗（`Oracle-Mem − Full-Mem`）**：当标准记忆上界能做对、真实记忆做错时，直接结合 Evidence 中的 M1 ~ M3 证据，定位到写入漏提、冲突未置旧或检索漏召回。
- **下游意图与决策损耗（`100% − Oracle-Mem`）**：当注入标准记忆后依然失败时，定位到下游复杂句法理解、槽位时间算术、域外拒识边界或澄清策略不足。
- **评测自身异常分流**：若复核轨迹发现用例本身存在二义性、模拟用户偏离画像约束或 Judge 误判，则归入基准异常，不计入算法退化。

### 5.2 双闭环落地机制
- **闭环 A（算法优化闭环）**：将上游记忆损耗定向反馈至记忆写入、状态更新与混合检索引擎；将下游意图损耗反馈至意图提取 Prompt、澄清策略与经验记忆沉淀（高频确定性规则下沉为硬固化校验，复杂交互策略沉淀为软固化经验条目），改完后在 Eval 回归集重测验证净收益。
- **闭环 B（基准维护闭环）**：持续清理用例歧义、修正模拟用户提示词、校准评估器一致性，并把线上真实 Badcase 脱敏转化为新增回归用例；全程保持 Held-out 盲测集物理隔离，确保长期评测结论客观可信。

### 6.2 单条样本输入输出数据流示例

以 `USER_001` 的一次游戏网络保障请求为例，展示各环节具体输入输出载荷。

![[eval_run_e2e_dataflow.drawio.svg]]

| 步骤               | 执行主体                 | 输入数据示例                                 | 输出数据示例                                                                              |
| :--------------- | :------------------- | :------------------------------------- | :---------------------------------------------------------------------------------- |
| **① Stage A 建库** | 记忆写入与演进引擎            | 4 条历史单据（王者荣耀 20:00–22:00 / ≤30ms）与前序对话 | 锁定快照 `Snapshot v1`（1 条有效语义偏好 + 4 条情景流水）                                             |
| **② Turn 1 发消息** | 模拟用户（`USER_001`）     | 用例隐含需求（今晚 20:00–23:00 保王者，≤30ms）       | 口语消息：`"老样子，今晚8点帮我保一下王者，不过今天想多玩会儿"`                                                  |
| **③④ 双路检索**      | Agent → 记忆快照 + 只读库   | `query="今晚8点保王者"`、`user_id="USER_001"` | 记忆 Top-1：`王者荣耀 / 20:00-22:00 / ≤30ms`；套餐：`VIP金卡 / 白名单 / 上限240min`                   |
| **⑤ 慢路径消歧**      | 被测意图提取 Agent         | Turn 1 消息 + 召回偏好 + 套餐规则                | 精准反问：`"已确认王者荣耀 20:00 开始、时延≤30ms，请问保到几点？"`                                           |
| **⑥ Turn 2 回复**  | 模拟用户（`USER_001`）     | Agent 的澄清反问                            | 补充参数：`"就保到11点吧，还是30ms"`                                                             |
| **⑦ 终态输出**       | 被测意图提取 Agent         | 两轮对话上下文 + 召回偏好 + 算术校验                  | `{"app":"王者荣耀","start":"20:00","end":"23:00","duration":"180min","latency":"30ms"}` |
| **⑧⑨ 采集与判分**     | Evidence → Evaluator | 检索 Top-K 日志、2 轮交互轨迹、终态 JSON 与真值        | `M3 Recall@1=1`、`EM=PASS`、主动消歧 `PASS`、较 `No-Mem` 减少 1 轮追问                           |
