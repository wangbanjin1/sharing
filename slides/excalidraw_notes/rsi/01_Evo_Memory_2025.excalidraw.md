1. 解决什么问题 ^txt_0030

1. 现有记忆评测（如 LoCoMo、LongMemEval）主要测静态对话事实回忆，Agent 记住了「说过什么」却没学会「怎么解同类新题」；
2. 缺少统一的流式测试时进化评测框架，导致检索型、工作流型、分层记忆等 10 余类方法无法在同一任务流协议下公平对比。 ^txt_0031

2. 数据集与任务流构造（10 类任务） ^txt_0033

• 单轮推理与问答（5 类）：MMLU-Pro（经济/工程/哲学）、GPQA-Diamond、AIME-24、AIME-25、ToolBench（API 工具调用）；
• 多轮目标交互（4 类环境）：ALFWorld、BabyAI、ScienceWorld、PDDL 规划任务；
• 流式化改造：将静态题库排成连续序列，前序任务的解题策略与成败反馈直接服务后续任务。 ^txt_0034

3. 统一评测范式与 ReMem 决策空间 ^txt_0036

4. 评测协议、参照基线与压力维度 ^txt_0039

• 统一评测 10+ 记忆模块（ReAct、A-MEM、SelfRAG、MemOS、Mem0、LangMem、DC、AWM 等），覆盖 Gemini-2.5 与 Claude-3.5/3.7 基座；
• 提出两类标杆：ExpRAG（极简任务级 Top-k 经验检索拼接）与 ReMem（Think-Act-Refine 在线推理与记忆修剪融合）；
• 核心指标：精确匹配 EM / 成功率 S / 进度分 P / 平均完成步数，并额外评测 Easy→Hard 与 Hard→Easy 顺序切换及成败混合反馈抗噪能力。 ^txt_0040

原论文核心实证结论（单轮 + 多轮 + 序列难度 + 失败反馈） ^txt_0094

• 持续提分与大幅提效：Gemini-2.5 Flash 下 ReMem 在单轮任务均分达 0.65（ToolBench API 0.85/0.71）；多轮 BabyAI 达 0.92/0.96、ScienceWorld 达 0.95/0.62，且
  ALFWorld 平均步数从 22.6 步大幅降至 11.5 步；
• 简单基线很能打：极简 ExpRAG 在多项任务上击败 Mem0、LangMem、AWM 等复杂系统；
• 顺序与失败噪声敏感：Hard→Easy 迁移收益高于 Easy→Hard（难题经验更具迁移性，ReMem 达 0.94/0.97）；当失败轨迹不经筛选直接入库时，传统基线普遍掉分，仅带
  Refine 修剪的 ReMem 保持稳健（Claude 3.7 Sonnet 下均值 0.81 对比 Mem0 0.43）。 ^txt_0095

对联接 Agent 与后续 RSI 研发的启发 ^txt_0097

1. 评测集流式化改造模板：可直接把现有静态单据/意图题库按业务相关性编排为连续任务流，把「平均交互轮次/步数下降」纳入 RSI 效率指标；
2. 难题先行与失败去噪：经验沉淀不能只记成功单据，更要带在线 Refine 剪枝机制过滤失败噪音，否则记忆库会迅速退化；
3. 基线标杆选择：后续做 RSI 算法迭代时，务必把极简 ExpRAG 作为第一对照基线，确保复杂进化机制确实带来超额净收益。 ^txt_0098

极简 ExpRAG 与 ReMem（Think-Act-Refine）核心区别 ^txt_0101

• 极简 ExpRAG（只存不删 + 开头检索一次）：任务结束后将「输入 + 轨迹 + 成败」按模板直接追加进向量库；新任务到来时
  检索 Top-k 拼入 Prompt 作答。成功经验占主导时表现稳健，适合作为第一对照基线；但混入失败或冲突经验时无法清理，易引入误导。
• ReMem（将记忆整理纳入动作空间）：将智能体动作从 {Think, Act} 扩展为 {Think, Refine Memory, Act}。推理中途若发现
  召回记忆存在噪声或冲突，可主动执行 Refine（重检索 retrieve / 剪枝删错 prune / 重组 organize），与 Think 交替理顺经验后再由 Act 输出。
• 联接 Agent 场景示例：经验库同时存有「弱覆盖降画质有效经验」与两条「盲目给高码率致卡顿失败经验」——ExpRAG 原样全量
  拼入提示词；ReMem 先 Think 识别冲突，再调用 Refine 剪除失败噪声，最终由 Act 输出稳妥配置。 ^txt_0102

工程时延权衡 · ReMem 调用开销与联接 Agent 落地折中 ^txt_0104

• 在线时延代价：ReMem 将 Refine 置于在线决策循环中，每多一轮 Think ↔ Refine 便增加一次串行大模型调用，单步响应延迟与
  Token 开销显著高于 ExpRAG（任务开头检索一次 + 单次推理生成）。
• 长程任务与短程对话的差异：论文长程环境（如 ALFWorld 20+ 步）靠在线剪枝将平均步数压减一半（22.6 → 11.5 步），摊薄后总耗时
  不增反降；联接 Agent 仅 1~3 轮实时交互，在线多次串行调用会直接拉高首轮响应时延，工程性价比偏低。
• 联接 Agent 工程折中方案：
  1. 在线与离线解耦：将 Refine（失败剪枝、冲突去重、重组提炼）移至会话结束后的异步后台执行，在线主路径保持轻量检索与单次生成；
  2. 在线按需轻量化门控：无冲突请求零额外时延；仅当召回记忆存在明显冲突时，在单次推理内一并完成去噪筛选。 ^txt_0105
