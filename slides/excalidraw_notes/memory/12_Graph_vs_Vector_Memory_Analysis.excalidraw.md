1. 建出来的图到底长什么样（对比普通向量） ^txt_0030

• 普通向量（Mem0）：按 user_id 存「1 份全局摘要 S + 一批 15~60 字扁平短句」，每条带时间戳和 1024 维向量；没有节点/边，也没有原文溯源，更新时直接原地覆盖或删旧；
• 建图（Zep / Graphiti）：三层结构——底层无损存原文 Episode；中层是实体节点与有向边 (src)-[rel]->(dst)，每条边挂事实文本、1024 维向量、[t_valid, t_invalid) 有效期与
  episodes[] 频次；顶层存实体聚合摘要；
• 实测单用户图长相：并非复杂蜘蛛网，平均仅 11~18 节点，72%~76.5% 的边直连中心 User 节点（浅星型），最多从应用再伸 1 跳到别名；只有多用户共享基站（Cell）与应用（App）
  时才连成真正多跳网。 ^txt_0031

2. 建图怎么搜索（对比普通向量单路检索） ^txt_0033

• 普通向量（Mem0）：单路检索——问题 q 编码为向量，在当前用户库内算余弦相似度，直接取 Top-8 短句；没有关键词精确匹配，也没有跨条目邻接扩展或时间窗硬过滤；
• 建图（Zep / Graphiti）：先按 user_id（严格模式再按当前时间过滤有效边）筛候选，再走三路并行排序：① 边向量余弦排序；② 对「实体+关系+事实文本」做 BM25 关键词排序（
  精准命中私有简称「腾会」或基站号）；③ 从向量 Top-3 边的端点做 1~2 跳 BFS 邻接扩展，按 episodes[] 频次排序；最后用 RRF 融合取 Top-8 边。 ^txt_0034

对联接 Agent 的落地架构建议（吸收建图优点，避开纯 LLM 写入瓶颈） ^txt_0097

1. 网元单据走「确定性结构化双时态槽位表」：零 LLM 直写精确时间戳、画质/时延参数与运行结果（根治 U001_P02 与 U002_P01）；直接复用 Zep 最有用的两个结构字段——
   [t_valid, t_invalid) 有效期与 source_episodes[] 频次计数，查询默认硬过滤失效项，写入零 Token、毫秒落盘；
2. 对话表达走「轻量向量 + BM25 混合检索」：保留自然语言高保真优势（私有简称、改口撤销原话、假设咨询语境），用低成本 BM25 补齐普通向量对专名简称的召回短板，单
   题上下文稳定控制在 ~1K Token；
3. 群体排障再挂共享枢纽图：单用户场景不强维护重型全量知识图谱；等进入基站小区（Cell）与标准应用（App）跨用户关联排障时，仅针对共享枢纽节点建轻量邻接索引。 ^txt_0098
