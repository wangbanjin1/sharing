• 解决问题：① 无损保存原始对话消息与参考发生时间，避免摘要压缩丢失非实体化细节；② 为上层语义抽取提供跨轮指代消解上下文，并支撑事实被提及频次的回溯统计。
• 输入：单条交互对话消息；工程接口同时支持纯文本、业务结构化 JSON 单据与确定性事实三元组。 ^txt_0026

2. 情景记忆：标准输出与存储形式 ^txt_0028

• 时间：双时间戳字段——事件参考发生时间与系统入库时间；
• 起因 / 经过 / 结果：情景层不拆分要素也不做摘要改写，统一无损保存于 {唯一编号, 发言人角色, 原始未改写全文, 输入数据类型}，并通过双向提及关联边连接上层实体；
• 存储形式：图数据库（时序知识图谱）。 ^txt_0029

3. 语义记忆（Semantic Entity & Community Layer）：问题与输入 ^txt_0031

• 解决问题：① 将分散在多轮对话中的碎片信息聚合为统一实体摘要与结构化关系事实；② 解决用户状态或偏好随时间变更时，直接覆盖丢历史、同时保留又冲突的两难问题。
• 输入：① 当前新写入情节节点 + 最近 n = 4 条历史情节节点（指代上下文与参考时间基准）；② 图谱中已有候选实体节点与关系事实边。 ^txt_0032

  提升 6.56%）；

对比联接 Agent 记忆体系的设计补强（对应总表与补充说明） ^txt_0132

1. 避免失效旧边污染在线推理：借鉴 Zep 双时态截断思想保留历史，但在线默认仅注入当前有效记录，防止小模型被已失效旧状态干扰；
2. 补齐场景与时段作用域：Graphiti 二元边仅靠会话分区与时间区间限定，联接 Agent 需显式增加业务场景与周期时段作用域；
3. 补齐结构化情景要素与程序记忆：情景层除原始对话外直接绑定结构化意图模板与闭环状态，并补齐 Graphiti 缺失的程序记忆（澄清与保障策略）。 ^txt_0133
