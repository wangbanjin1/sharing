2. 图谱版抽取：先调实体抽取器识别节点与类型标签，再调关系生成器

3. 全局摘要 S 由独立后台模块异步周期刷新。 ^txt_0052

阈值设定 ^txt_0054

• 近期消息滑窗固定 m = 10 条；
• 单条事实长度 15~80 词（上限 100 词）；
• 无出现频次阈值（单次提及即抽取）。 ^txt_0055

触发时机 ^txt_0057

每次新一轮问答消息对到达后立即触发（阶段一）。 ^txt_0058

2. 更新（裁决 · 阶段二） ^txt_0060

去重扩充、冲突消解与图对齐 ^txt_0061

算法流程 ^txt_0063

1. 基础版四操作：向量召回前 10 条相似旧记忆，经 Tool Call 交第 2 次大模型按固定
   优先级裁决：
  ① 无相似项 → 新增（ADD）；
  ② 矛盾冲突 → 物理删除旧记录（DELETE）；
  ③ 补充增量 → 保留原 id 覆盖更新（UPDATE）；
  ④ 无增量 → 跳过（NOOP）。
  （开源代码为降延迟改为只追加 ADD-Only，靠读时取最新时间戳）
2. 图谱版对齐与软失效：复用余弦相似度 > t 的已有实体节点；矛盾旧边由大模型标
   为 invalid 而不物理删除。 ^txt_0064

阈值设定 ^txt_0066

• 更新比对召回条数固定 s = 10；
• 图谱版实体对齐设余弦相似度阈值 t。 ^txt_0067

触发时机 ^txt_0069

紧接阶段一抽出候选事实后同步执行（阶段二）。 ^txt_0070

基础版向量召回与图谱版双路并行 ^txt_0073

向量检索算法 ^txt_0075

• 采用 text-embedding-small-3 编码稠密向量；
• 基础版：向量数据库 HNSW 近似最近邻索引 + 余弦相似度；
• 图谱版：Neo4j 原生 HNSW 向量索引 + 余弦相似度。 ^txt_0076

检索与重排流程 ^txt_0078

1. 基础版：问题编码向量，召回余弦相似度最高的 Top-k 条事实拼入提示词（
   冲突时按提示词规则优先采信最新时间戳记录）；
2. 图谱版双路并行：
  ① 实体中心检索：提取问题核心实体，向量定位锚点节点并遍历一跳入边与
出边；
  ② 语义三元组检索：整句查询向量与全图三元组文本向量算余弦相似度，过
滤高于相关性阈值的边降序融合。 ^txt_0079

检索时机 ^txt_0081

每次调用大模型生成回复之前。 ^txt_0082

4. 遗忘（状态衰减） ^txt_0084

无时间衰减 · 仅图谱软失效 ^txt_0085

自动衰减机制 ^txt_0087

无基于时间跨度或访问频次的自动衰减淘
汰公式（不随时间自然降权或遗忘）。 ^txt_0088

冲突软失效（仅 Mem0g） ^txt_0090

图谱版检测到新旧事实冲突时，将旧边标
记为 invalid 移出当前有效集，保留历史
节点与边支撑时间推理。 ^txt_0091

5. 删除（物理擦除） ^txt_0093

仅基础版冲突时物理删除 ^txt_0094

物理删除机制（仅基础版） ^txt_0096

基础版在阶段二判定新旧事实直接矛盾时，
调用 DELETE 工具从向量数据库中物理
删除旧记录。 ^txt_0097

工程代价与局限 ^txt_0099

物理擦除导致历史状态永久丢失，无法回
答“以前住在哪里”等历时性回溯问题。 ^txt_0100

原论文样本示例与 LoCoMo 实证结论（对应表格备注行） ^txt_0106

• 事实句示例（基础版 Mem0）：“User 养了一只名叫 Poppy 的狗，每天早晨带它散步”；
• 三元组示例（图谱版 Mem0g）：(Alice:Person) -[lives_in]-> (San_Francisco:City)；
• 实证结论（LoCoMo 基准 · GPT-4o-mini）：基础版冲突时执行物理覆盖/删除，无法回答历时性旧状态问题；图谱版 Mem0g 改为标记 invalid 软失效保留历史边，在 LoCoMo
  时间推理题上 LLM-as-a-Judge 得分从 55.51% 提升至 58.13%（Open-Domain 72.93% → 75.71%）。 ^txt_0107

对比联接 Agent 记忆体系的设计补强（对应总表与补充说明） ^txt_0109

1. 补齐作用域隔离：Mem0 仅按 user_id 隔离；联接 Agent 需细化到「特定用户 + 业务场景 / 周期时段条件」，防止同一用户跨场景同名偏好混淆；
2. 补齐长期习惯准入与溯源：Mem0 单次提及即抽取入库；联接 Agent 需结合来源情景事件编号列表与观测频次规则，区分单次偶发提及与长期稳定习惯；
3. 补齐全状态生命周期与多记忆协同：引入「候选 / 生效 / 强化 / 已失效」状态与生效/失效时间戳，并补齐情景记忆（历史单据回溯）与程序记忆（澄清与保障策略）。 ^txt_0110
