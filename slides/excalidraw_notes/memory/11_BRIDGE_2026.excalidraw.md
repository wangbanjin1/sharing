1. 现有记忆 Benchmark 测不出架构好坏（省 17–154 倍 Token 打平 SOTA） ^txt_0030

• 现状问题：近年记忆框架不断堆叠原子事实抽取、冲突覆盖（Supersession）、定期反思（Reflection）与知识图谱合成等重型模块；
• 极简 BRIDGE：写入仅单次 LLM 调用（带前 W=10 条笔记滑动上下文生成观察笔记并保留原文）；检索仅 BM25 + 余弦相似度 RRF 混合排序；
  渲染仅对 Top-3 高相关块保留原文、其余 7 块放笔记并按时间线升序交由 Reader 作答（每次查询仅 5–7K Tokens，比全上下文省 17–154 倍）；
• 核心结论：在 LongMemEval-S、BEAM、EverMemBench 直接打平 SOTA，说明现有基准只测了「能否捞出旧事实（Recall）」，测不出复杂架构是否值得其成本。 ^txt_0031

2. BRIDGE 极简数据结构与零调参超参（零图谱 · 零覆写 · 双存原文） ^txt_0033

3. 把评测从“问过去”拉向“做当下”（Always-on, Applied Memory 常驻应用型记忆） ^txt_0036

• 核心概念：实用的 Agent 不是等用户问“我上周说过什么规范”才答得出，而是当前只提普通新需求（完全不提历史）时，能自觉把过往规矩和习惯用上；
• 5 类对抗测试（每类 20 个场景，检验模型在不被提醒时的自觉执行率）：
  ① RA+ / RA-（规则遵守与禁忌规避）：历史随口提过“所有公开接口必须限流”或“事故后禁用 eval()”，后续让写重置密码接口或求值，检验是否自觉遵守或规避；
  ② PI-S / PI-P（风格与流程模式归纳）：历史未明文规定规则，仅在代码或 4 次事故排查中反复示范特定格式或固定 5 步流程，检验新任务能否延续该模式；
  ③ DM（动态多轮一致性）：检验一条规则能否在多轮追问对话中持续生效，避免首轮记得、第三轮遗忘；
• 两大流派能力反转（以 GPT-4.1-mini 为统一 Reader）：规则遵守（RA+）上 LangMem 拿到 80%、BRIDGE 仅 35%；流程归纳（PI-P）上 BRIDGE 拿到 88%、LangMem 跌至 55%；
• 根本原因：记忆的表示形式（Representation）决定能力边界——LangMem 拆为独立原子事实利于提取显式规则，但拆碎后丢掉了代码风格与操作步骤的原始形态；
  而 BRIDGE 保留原文与块级上下文，天然擅长学习隐式模式，却在显式规则上因长块上下文稀释而吃亏。 ^txt_0037

4. “召回失败”其实是“呈现失败（Presentation Failure）”与常驻指令置顶 ^txt_0039

• 日志归因：为什么 BRIDGE 在 RA+ 上仅 35%？排查日志发现 BRIDGE 已经把那条规则检索回来了，只是下游 Reader 未执行——因为按时间序渲染时，
  随口一提的规则混在大量普通历史对话中间，注意力权重过低；
• 什么是「常驻指令（Standing Directives）」：指用户在历史交互中声明过、期望后续所有相关任务默认持续生效的显式规则与红线约束（如“必须做X / 严禁做Y”）；
• §4.3 Top-of-Context 呈现诊断实验（不动底层存储，也不改检索算法，仅改变 Prompt 组装层的摆放方式）：
  - 默认时间序渲染（Canonical BRIDGE）：通过约束数为 10 / 19（52.6%）；
  - 普通通用摘要置顶（Generic Summary）：笼统概括冲淡了具体约束，反而跌至 8 / 20（40.0%）；
  - 常驻指令单独拎出置顶（Top-of-Context Standing Directives）：将常驻指令拎到上下文最顶部后，通过数直接从 10 / 19 提升至 18 / 19（94.7%）！

• 标准基准打平/反超：单次查询仅 5–7K Tokens（比全上下文省 17–154 倍），在 LongMemEval-S、BEAM 打平 SOTA，EverMemBench 反超 5.7~6.3 分；

对联接 Agent 记忆架构、Prompt 组装与评测体系的 4 条直接落地启发 ^txt_0091

1. 存储层「双轨表示」：表示形式决定能力边界——显式偏好与禁用红线抽为独立原子槽位（保 RA+/RA- 80%），历史单据与排障过程保留块级原文（保 PI-P 88%）；
2. 呈现层「Top-of-Context 分通道注入」：复刻 §4.3 结论，在 Prompt 组装层把「常驻指令/禁忌约束」单独拎到上下文最顶部，与按时间升序的「历史单据/经历」分通道注入；
3. 评测层转向「Always-on Applied Memory」：评测集不仅测“问过去”，更要在新请求不提历史时测 Agent 能否自觉遵守带宽红线、场馆预热流程与多轮一致性(DM)；
4. 产品层「可见、可编辑、可删除」：防范常驻记忆主动套用过期或错误规则的副作用，为用户提供可见可删改的记忆管理面板。 ^txt_0092

5. 常驻记忆的副作用与产品可控入口 + 跨厂商生成期约束裁判 ^txt_0099

• 常驻记忆的副作用（Broader Impact 反思）：当 Agent 学会“不被提醒就主动应用旧规则”时，它同样会主动应用过时或错误的旧规则；
• 产品层设计准则：任何向「常驻应用型记忆（Always-on Applied Memory）」演进的系统，在产品层都必须为用户提供【可见、可编辑、可删除】的记忆管理入口，
  否则“记性太好”反而会变成顽固的线上 Bug；
• 生成期约束裁判机制（消除同模型家族自偏好）：
  - 对抗测试不比对静态参考答案文本，而是针对每条历史约束逐项判定为 applied（已执行）/ violated（违背）/ n/a（不适用）；
  - 裁判模型强制选用与数据生成器、被测 Reader 不同厂商的模型，消除同家族自偏好偏差。 ^txt_0100
