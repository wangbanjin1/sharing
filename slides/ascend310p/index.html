基于 CANN 最新开放的框架，支持在 Ascend 310P 上开发融合 Ascend C 算子。

Section 02.1 · Operator Compilation & Packaging

2.1 算子编译、ascend950 报错排障与出包安装

松鼠分享会
算子编译命令（--ops 锚定存放算子的文件夹路径）
bash build.sh --pkg --soc=ascend310p --ops=prompt_flash_attention \
  --cann_3rd_lib_path=/dataset/personal/w00939968/Ascend/ops-transformer/third_party
报错现象与根因分析
  • 现象：Invalid socVersion ascend950 of op AddExample, please check whether AddConfig are correctly configured in Opdef.
  • 调用链：build.sh → cmake/scripts/prepare.sh → opbuild_gen_default
  • 根因：传入 --soc=ascend310p 时，opbuild 遍历 prompt_flash_attention_def.cpp 中所有已配置的 soc 版本（含 ascend950），但 310p 环境中 ascend950 配置不完整导致生成代码失败。删除红框代码即可：
this->AICore().AddConfig("ascend910b", aicoreConfig);    // 存在
this->AICore().AddConfig("ascend910_93", aicoreConfig);  // 存在
this->AICore().AddConfig("ascend950", aicoreConfig);     // 310p环境不支持，删除
安装算子包与配置环境变量
./build_out/cann-ops-transformer-custom_linux-aarch64.run
export LD_LIBRARY_PATH=/usr/local/Ascend/cann-9.0.0/opp/vendors/custom_transformer/op_api/lib/:${LD_LIBRARY_PATH}

Section 03 & 03.1 · Graph Lowering & ONNX Plugin

3. 算子入图网络结构 & 3.1 onnx_plugin 编译导入

松鼠分享会
3. 算子入图背景与示例网络结构
  • 生产环境使用两种模型格式：om 模型（依托 CANN 构建）和 mindir 模型（基于 MindSpore 构建）。原始 ONNX 模型导出上述两种模型并引入自定义算子时需采用不同做法。
  • 示例网络整体结构：
    Query → Linear → ReLU → Linear → NPUPromptFlashAttention → +残差 → Output
3.1 onnx_plugin 编译与拷贝部署
  • 先生成算子对应的 onnx_plugin，完成后在 build 路径下得到 libop_transformer_onnx_plugin.so：
bash build.sh --onnxplugin --soc=ascend310p --ops=prompt_flash_attention \
  --cann_3rd_lib_path=/dataset/personal/w00939968/Ascend/ops-transformer/third_party
  • 将该 .so 拷贝到对应算子路径下，使转换模型时让 ge 识别到：
cp build/libop_transformer_onnx_plugin.so \
   /usr/local/Ascend/cann-9.0.0/opp/vendors/custom_transformer/built-in/framework/onnx/

Section 03.2 · Export OM Model with Custom Op

3.2 导出 OM 模型时引入自定义算子

松鼠分享会
1. 对齐算子 type 与 onnx_plugin 注册定义
  • NPUPromptFlashAttention 是 ONNX 算子需使用的名称，前缀 ai.onnx::xx 由 opset.version = 12 控制：
REGISTER_CUSTOM_OP("PartitionedCall").FrameworkType(ONNX)
  .OriginOpType({ge::AscendString("npu::1::NPUPromptFlashAttention"),
                 ge::AscendString("ai.onnx::12::NPUPromptFlashAttention"), ...})
  .ParseParamsFn(ParseParamsPromptFlashAttention)
  .ParseOpToGraphFn(ParseOpToGraphNpuPromptFlashAttention)
  .ImplyType(ImplyType::TVM);
2. ONNX 创建算子代码与 ATC 转换命令
node_attention = make_node(
    "NPUPromptFlashAttention",
    inputs=["query_enhanced", "key_id", "value_id"],
    outputs=["attention_raw"], name="PromptFlashAttention", domain=""
)
# 挂载 type="PromptFlashAttention", input_names, output_names, num_heads=8 等属性

# 使用 ATC 完成模型转换：
atc --model=prompt_flash_attention2.onnx --framework=5 \
    --output=./test_om2 --soc_version=Ascend310P3

Section 03.3 · Export MindIR Model with Custom Op

3.3 导出 MindIR 模型时引入自定义算子与 Dump 图验证

松鼠分享会
1. MindSpore 封装下的 ONNX 算子定义（Node type 写 Custom）
  • MindSpore 在 CANN 基础上做了额外封装：定义 ONNX 算子时需把节点的 type 统一写成 Custom，domain="npu"，而把 attributes 里的 type 写成被定义的算子：
node_attention = make_node(
    "Custom",
    inputs=["query_enhanced", "key_id", "value_id"],
    outputs=["attention_raw"], name="PromptFlashAttention", domain="npu"
)
attrs = [ make_attribute("type", "PromptFlashAttention"), ... ]
2. Converter Lite 转换与 DUMP_GE_GRAPH=2 验证
/home/mindspore-lite-2.8.0-linux-aarch64/tools/converter/converter/converter_lite \
  --fmk=ONNX --modelFile=/path/youronnx --outputFile=model \
  --saveType=MINDIR --optimize=ascend_oriented

# MindIR 无法直接用 Netron 可视化，开启 Dump 图再转化一次，选取最后阶段 Dump 图：
export DUMP_GE_GRAPH=2
