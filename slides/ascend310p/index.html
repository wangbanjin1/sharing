Step 02.1 · Operator Build & Packaging

算子编译、Ascend 950 报错根因排障与安装

松鼠分享会
算子编译命令（以 prompt_flash_attention 为例）
  • --ops 锚定的是存放算子的文件夹名称，而非算子 Class 名：
bash build.sh --pkg --soc=ascend310p --ops=prompt_flash_attention \
  --cann_3rd_lib_path=/dataset/.../ops-transformer/third_party
典型编译报错与根因分析
  • 报错现象：Invalid socVersion ascend950 of op ..., check whether AddConfig are correctly configured in Opdef.
  • 调用链：build.sh → cmake/scripts/prepare.sh → opbuild_gen_default
  • 根因与修复：opbuild 会遍历 *_def.cpp 中所有已注册的 SoC，而 310P 环境缺少 ascend950 完整配置，删除该行即可：
this->AICore().AddConfig("ascend910b", aicoreConfig);
this->AICore().AddConfig("ascend910_93", aicoreConfig);
this->AICore().AddConfig("ascend950", aicoreConfig); // 310p环境不支持，删除
安装算子包与配置环境变量
./build_out/cann-ops-transformer-custom_linux-aarch64.run
export LD_LIBRARY_PATH=/usr/local/Ascend/cann-9.0.0/opp/vendors/custom_transformer/op_api/lib/:${LD_LIBRARY_PATH}

Step 03.1 & 03.2 · Graph Lowering (ONNX → OM)

算子入图（一）：ONNX Plugin 编译与 OM 模型导出

松鼠分享会
1. 编译并部署 ONNX Plugin（让 GE 识别自定义算子）
bash build.sh --onnxplugin --soc=ascend310p --ops=prompt_flash_attention --cann_3rd_lib_path=...
cp build/libop_transformer_onnx_plugin.so \
   /usr/local/Ascend/cann-9.0.0/opp/vendors/custom_transformer/built-in/framework/onnx/
2. 对齐 OriginOpType 构造 ONNX 节点并执行 ATC 转换
  • Plugin 中注册了 ai.onnx::12::NPUPromptFlashAttention，构建 ONNX 时需将节点 op_type 设为 "NPUPromptFlashAttention"，opset=12：
node_attention = make_node(
    "NPUPromptFlashAttention",
    inputs=["query_enhanced", "key_id", "value_id"],
    outputs=["attention_raw"],
    name="PromptFlashAttention", domain=""
)
# 挂载 type="PromptFlashAttention", num_heads=8, input_layout="BSH" 等属性...
# ATC 导出 OM 模型：
# atc --model=prompt_flash_attention2.onnx --framework=5 --output=./test_om2 --soc_version=Ascend310P3

Step 04.1 · Case Study: Fused Operator Development

需求实战：借助 Chrys 开发 MatMul+Add+Softmax+ReLU 融合算子

松鼠分享会
需求定义：FP16 四算子融合
  • 目标算子结构：MatMul → Add → Softmax → ReLU（数据类型：float16）。
  • 融合收益：减少中间激活值多次读写 HBM/GM 的带宽开销，在 AI Core 内部流水线完成矩阵乘、偏置加、归一化与非线性激活。
AI 辅助实现过程（Chrys Bypass 模式 + 人工定向引导）
  • 自动化闭环：开启 Chrys bypass 模式，自动驱动算子 Kernel/Host 代码编写、编译检查、单测生成与报错迭代修改。
  • 人机协同排障：遇到昇腾特定 API 或硬件约束报错时，从 CANN 官方文档检索解决方向喂给 Agent，快速突破卡点。
