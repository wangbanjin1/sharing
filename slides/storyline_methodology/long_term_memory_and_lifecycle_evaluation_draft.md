# 长期记忆功能与生命周期评测体系（修订定稿）

---

## 一、双源数据边界与评测总体架构

### 1.1 双源输入与外部规则边界

评测设计与测试集构造严格基于核心网实际采集的网元单据字段与用户交互对话，不虚构未采集字段：

- **网元单据提供的客观信息**：单据流水号（`record_id`）、用户标识（`gpsi`）、设备指纹（`device_fingerprint`）、实际发生时间（`start_time_utc` / `timestamp_local`）、子应用有效持续时长（`SubAppEffDuration` 及聚合活跃时段 `active_hours`、工作日与周末分布 `workday_vs_weekend`）、业务大类与具体子业务（`app_id` / `sub_app_id`）、物理接入区域与基站小区编码（`tai` / `cell_id`）、接入制式与切片（`rat_type` / `snssai`）、实测链路与体验指标（无线侧与核心网侧时延 `DelayAn` / `DelayDn`、业务时延 `ServiceDelay`、上下行带宽与码率、上下行流量及比值 `ul_dl_ratio`、丢包率、卡顿时长与次数 `StallingDuration` / `StallingNumber`、体验评分 `AvgQoe`）。同时，原始网元单据中部分字段（如分辨率 `resolution_mode`、体验评分中位数 `qoe_median`、部分记录的卡顿或小区字段）天然存在未采集空值（`null`）。
- **用户对话提供的主观与交互信息**：对话提及时间、自然语言场所描述（如会议室、场馆、通勤场景）、用户个性化的习惯代称（`expression`）、用户显式提出的目标保障参数、参数更新与意图更新指令、临时生效范围声明，以及会话闭环终态。
- **外部静态业务规则库**：保障应用与子业务白名单映射、各项业务参数物理合法上下界、用户套餐档位与专项权益权限边界。

### 1.2 网元单据底流与对话的四种关系及处理规则

只要用户在核心网内联网活动，后台**网元单据底流即持续存在**（仅存在“有单据无对话”的日常静默期，不存在“有对话而完全无单据”的状态）。在持续单据底流之上，单据与对话存在以下 4 种关系：

1. **日常静默承载（有单据、无对话）**：占大多数日常时段，由网元单据客观记录用户实际使用的 `sub_app_id`、活跃时段、常驻 `cell_id` 与常态网络体验。
2. **前单据触发后对话（异常/在途单据引发保障诉求）**：先产生正在运行或发生卡顿劣化的网元单据，紧接触发用户发起对话请求保障（单据提供当前承载应用与劣化现场，对话提供主观诉求与目标参数）。
3. **前对话获后单据印证（单据验证并增强对话真实性）**：对话闭环确定保障方案后，对应时段实际产生了匹配的顺畅网元单据，证实诉求真实履约且配置有效，用于增强对应记忆与策略的置信度。
4. **有单据但与对话无对应关系（背景并行无关单据）**：对话发生期间后台同步产生 `weixin_im` 或短视频等无关日常单据（或对话预约未来时段尚未产生目标单据）。处理规则：关联绑定必须同时满足**时间窗吻合 + 业务类型（`app_id / sub_app_id`）兼容**双条件，无关并行单据不与当前对话强行绑定，仅在单据通道独立归档。

### 1.3 评测体系分层与端到端组合关系

- **对记忆的评测拆分为正交的两层**：
  1. **白盒中间点评测（记忆生命周期评测）**：在注入历史网元单据与对话流后，直接核验记忆库内部状态快照与检索返回列表，独立评估**记忆形成、记忆演进、记忆检索**三个环节的模块能力。
  2. **黑盒端到端评测（记忆功能与业务闭环评测）**：不再重复描述底层存储更新与淘汰细节，从**情景记忆、语义记忆、程序记忆**三类长期记忆的内容来设计。
- **对意图的评测沿用原表结构并补全基础免构造类别**：保留原评测表的三大意图理解维度，将表 2 中模型本身能理解的**免构造基础类别（`L1.1` 简单语法变体、`L2.1` 表层词汇/句法/情绪变体、`L3.1` 轻度模糊公共简称）**一并纳入评测表作为基础回归集，同时在“驳回与拒识”维度界定清楚三大圈层驳回域范围。
- **端到端测试集按「记忆非必要场景」与「记忆必要场景」分桶统计**：
  - **记忆非必要场景子集**：当前会话输入结合静态规则已足以闭环（无需长期记忆），重点评测**基础意图理解准确率**及挂载记忆后的**无退化保持率（防止记忆负向干扰正常指令）**；
  - **记忆必要场景子集**：缺少历史情景、个人语义偏好或经验策略则无法单轮唯一解出（或需多轮追问），重点评测长期记忆带来的**准确率净提升（$\Delta \text{Acc}$）、澄清轮数减少率与 Token 节省率**。

## 二、白盒中间点评测：记忆生命周期评测

聚焦 **记忆形成、记忆演进、记忆检索** 3 个环节：

| 生命周期环节 | 白盒核验对象 | 关键评测点 | 核心指标 | 参考来源 |
| :--- | :--- | :--- | :--- | :--- |
| **1. 记忆形成** | 单次写入后的新增记忆条目 | 先检索后写入，未命中则存入**未激活候选态**；事件要素、偏好三元组与经验条目抽取是否准确；闲聊噪声是否滤除；单据原生 `null` 字段是否保持为空 | • 结构化抽取 F1<br>• 噪声过滤率与空值保留率 | `Mem0`、`MIRIX-2.0`、`REM` |
| **2. 记忆演进** | 多轮注入后的记忆库状态快照 | 候选记录达频次门限后**激活生效**与跨通道对齐（整合）；新数据写入、冲突旧数据按**生效/失效时间冷冻**（更新）；按有效期、**热度系数或时间衰减曲线**淘汰无用记录（遗忘） | • 记忆状态快照一致率<br>• 冷冻更新与衰减淘汰准确率 | `Zep/Graphiti`、`Memp`、`MemoryAgentBench` |
| **3. 记忆检索** | 给定查询返回的候选列表 | 分库路由与查询改写是否准确；目标激活态记忆是否排前；已冷冻失效记录与未实际执行记录是否滤除 | • `Recall@K`、`NDCG@K`<br>• 冷冻/未执行记录误召回率 ↓ | `LongMemEval`、`REM`、`PersonaMem-v3` |

## 三、黑盒端到端评测（一）：三类长期记忆功能评测

从情景记忆、语义记忆、程序记忆三类长期记忆的内容与业务作用出发设计端到端测试题型，不再重复底层存储与淘汰细节。

### 3.1 情景记忆评测（Episodic Memory）

- **功能与双源配合**：围绕跨会话历史事件指代消解与参数回溯/重算设计（注：长程距离间隔与高比例干扰噪声属于表 1 的难度分档 `G4.2 / G4.3`，在评测统计时按距离与噪声分档切片分析，不单列冗余题型）。网元单据提供客观发生时间、`record_id`、子应用、有效时长、小区编码与实测卡顿/时延指标；对话提供提及时间、自然语言场所与会话闭环终态。
1. **`1.1` 时序推理与跨会话指代消解（`Temporal Reasoning & Coreference`）** —— 参考 `LongMemEval (TR)`、`Zep/Graphiti`、`MIRIX-2.0`
   - `1.1.1` **时间指代（4 类子题型）**：
     - ① 相对日历窗口换算（相对当前会话日期换算绝对日期区间）；
       - *示例*：当前为 7 月 10 日（周五），用户输入“按上周五晚上那场腾讯会议再来一次” → 换算为 7 月 3 日晚间窗口，命中 `timestamp_local = 2026/7/3 20:44` 的 `tencentmeeting` 记录并还原参数。
     - ② 序数先后指代（最近一次 / 上上次，自动跳过闲聊与“仅假设咨询 / 中途撤销”未实际执行的节点）；
       - *示例*：前天实际生效 1080P 虎牙直播，昨天仅问过“开 4K 扣多少流量？先不开”，今早闲聊天气；输入“按我上次开的虎牙直播再来一次” → 跳过闲聊与未执行咨询，定位到前天 1080P 记录。
     - ③ 双时态错位消解（`Bi-Temporal Resolution`：区分事件实际发生时间 `event_time` 与后续对话提及时间 `mention_time`）；
       - *示例*：周四晚实际跑了一场 `douyin_live`（发生时间=周四），周六找 Agent 复盘并商定新低时延参数（提及时间=周六）；下周一输入“时长按周四实际播那场来，参数按周六跟你商定好的配” → 分别按发生时间取周四单据时长、按提及时间取周六对话参数。
     - ④ 基于历史时刻的时间推算（以历史开始时刻或 `SubAppEffDuration` 为基准执行起点平移、时长增减或在途续期重算，满足 `end - start == duration`）；
       - *示例*：昨晚 `20:00~22:00`（`SubAppEffDuration = 7200s`）跑过一场 `douyin_live`，今天输入“按昨晚开播那个点往后推半小时，时长再加 1 小时” → 推算今晚 `20:30~23:30`（共 3 小时）。
   - `1.1.2` **业务与子应用指代**：按 `app_id / sub_app_id` 回溯最近同类子业务事件（区分同一软件下不同活动，如 `douyin_live` 对比 `douyin_watch`）。
     - *示例*：昨天下午刷过抖音短视频（`douyin_watch`），前天晚上做过抖音直播（`douyin_live`）；今天输入“今晚 8 点按上次抖音开播的规格保两小时” → 按 `sub_app_id = douyin_live` 回溯前天直播，不与更近的 `douyin_watch` 混淆。
   - `1.1.3` **历史场所指代**：按前序对话中明确提及的单次事件场所回溯目标历史事件（保持与语义记忆正交；常驻场所代称与 `cell_id` 跨通道映射归入语义记忆及后续跨层难例）。
     - *示例*：前序对话中用户办理过一场“在体育馆彩排的虎牙 4K 直播保障”；今天输入“今晚 7 点到 9 点按上次在体育馆那场直播的配置保一下” → 直接按历史对话事件中的场所字段定位并还原配置。
   - `1.1.4` **运行质量与闭环状态指代**：结合单据 `StallingDuration / AvgQoe` 区分正常顺畅单据与卡顿异常记录，或按闭环终态定位。
     - *示例*：本周两场 `kuaishou_live` 单据中周三无卡顿（`StallingDuration = 0s`）、周五严重卡顿（`StallingDuration = 120s`），输入“按本周直播没卡顿那场来” → 筛出周三记录；或输入“把我昨天中途撤掉的那个会议保障重新开上” → 定位“已撤销”终态事件并恢复参数。
   - `1.1.5` **同名重复事件区分与多条件消歧**：同一用户在相近周期内存在多条同 `sub_app_id` 或同时间窗记录时，联合时间、场所或运行质量定位单次事件、防止跨场次时长与参数拼串；单一条件命中多条参数不同记录时转入多轮消歧。
     - *示例*：昨天上午 10 点（公司、1 小时、1080P）与晚上 8 点（家里、2 小时、720P）各有一场 `tencentmeeting`；输入“按昨天上午在公司那场来” → 锁定上午场不拼串；若仅说“按昨天那场腾讯会议来” → 命中两条不同参数实例，发起 2 轮消歧。

### 3.2 语义记忆评测（Semantic Memory）

- **功能与双源配合**：绑定**单用户（`gpsi`）**维度，围绕个人模糊表达对应关系还原、常驻偏好补全、版本冲突更新与未观测空值拒猜设计。网元单据聚合画像提供应用权重 `frequent_apps`、活跃时段 `active_hours`、常驻小区 `recurrent_cells` 及原生未采集空值（`null`）；对话提供个人模糊表达对应关系（`expression`）、用户显式目标保障参数、更新指令与临时生效范围声明。
1. **`2.1` 个人模糊表达的对应关系还原（`Personalized Expression Mapping`）** —— 参考 `Mem0`、`MIRIX-2.0`、`PersonaMem-v3`
   - `2.1.1` **单一固定对应直接还原（1 对 1 原词复现）**：不区分具体落在哪个槽位，凡该用户此前已明确对应关系的个人模糊说法（对应应用-业务、固定时间窗或打包参数），再次出现时直接单轮还原。
     - *示例*：历史交互已明确该用户口中的“传素材”对应 `百度网盘 + 文件传输`（或“老时间”对应 `20:00~22:00`）；当前输入“下午 2 点到 4 点要传素材，时延控制在 80ms 内” → 直接还原对应槽位闭环。
   - `2.1.2` **近义变体表达泛化还原（语义匹配防字面硬编码）**：用户未逐字重复历史原词，而是使用语义等价的近义说法时，通过语义匹配准确还原对应关系，避免依赖死板的字符串字面匹配。
     - *示例*：历史记录中用户表述为“用百度网盘同步拍摄素材”；当前输入“下午 2 点到 4 点导一下拍好的视频原片，时延 80ms 内” → 语义匹配命中同一映射，还原为 `百度网盘 + 文件传输`。
   - `2.1.3` **一词多境的条件区分与消歧（1 对多语境映射）**：同一模糊词（如“老样子”“开例会”）在该用户的不同业务或不同场景下对应多套不同取值；当前输入含上下文线索时按语境精准选值，缺乏线索无法唯一确定时转入多轮消歧。
     - *示例*：该用户腾讯会议下的“老样子”为 `1080P + 时延 <30ms`，抖音直播下的“老样子”为 `4K + 保上行带宽`；输入“今晚 8 点到 10 点抖音开播按老样子保” → 按直播语境还原为 `4K + 保上行带宽`（若仅说“今晚 8 点到 10 点按老规矩保”无法唯一区分，则发起 2 轮消歧）。
2. **`2.2` 长期稳定偏好归纳与场景隔离（`Preference Induction & Scope Isolation`）** —— 参考 `LongMemEval (MR)`、`PersonaMem-v3 (preference_alignment / avoid_overpersonalization)`、`CoALA`、`Zep/Graphiti`
   - `2.2.1` **偶发记录与长期习惯区分**：观测频次低于 $N_{\min}$ 的偶发记录不作默认补全；达到频次门限的稳定规律（含纯高频顺畅网元单据静默归纳，剔除弱覆盖被动劣化记录）在输入缺参时自动补全。
     - *示例*：历史仅偶发用过 1 次 `bilibili_vod`（$< N_{\min}$）时，说“今晚 8 点到 10 点看视频，1080P”不独断补成 B 站；而稳定出现 $\ge N_{\min}$ 次 `tencentmeeting` 时，说“明早 9 点到 11 点开会，1080P”直接补全业务对象 `tencentmeeting`。
   - `2.2.2` **多维线索联合定位场景与偏好隔离**：利用当前已知的部分偏好或状态组合（如“时段=上午 + 业务=会议”，或“业务-应用 + 分辨率 + 当前卡顿信息”）作为联合检索条件判断用户所处场景，独立匹配该场景下的其余默认槽位，防止同业务跨场景误填。
     - *示例*：该用户工作日上午晨会固定用 `dingtalk_meeting`，晚上外部评审固定用 `tencentmeeting`；输入“明早 9 点到 10 点开会帮我保 1080P”（已知上午+会议+1080P，缺具体软件） → 联合场景条件补齐 `dingtalk_meeting`，不误填晚上的 `tencentmeeting`（同理：公司开腾讯会议默认 `1080P`，通勤弱覆盖有卡顿时开腾讯会议默认 `720P + <30ms`，按已知场景线索分别补全）。
   - `2.2.3` **多习惯占比接近时的消歧追问**：网元单据显示多款同类应用使用占比接近、无绝对主导习惯时，拒绝独断补全并转入慢路径追问选择。
     - *示例*：`user_profiles.json` 显示该用户 `tencentmeeting` 占 `0.58`、`dingtalk_meeting` 占 `0.42`；输入“下午 3 点到 5 点开部门会，1080P”（缺具体软件） → 拒绝独断猜某一款，发起 2 轮追问请用户确认。
3. **`2.3` 偏好更新、双源冲突与临时回退（`Knowledge Update & Conflict Resolution`）** —— 参考 `LongMemEval (KU)`、`MemoryAgentBench (SF)`、`Zep/Graphiti`、`Mem0g`、`PersonaMem-v3 (stale_preference_use)`
   - `2.3.1` **显式更新后采信最新配置**：用户显式更新默认配置后，后续缺参会话准确填入最新生效版本。
     - *示例*：原默认会议画质为 720P，上周显式更正“以后开会全按 1080P 保”；今天输入“下午 2 点到 4 点腾讯会议帮我保一下”（缺参数） → 自动填入最新 1080P，不误填旧 720P。
   - `2.3.2` **历史对话声明与近期高频单据冲突核实**：用户当前输入**未点名具体槽位**，而早期对话留存的旧偏好与近期高频网元单据实测分布发生矛盾时，主动出示依据请用户确认（注：若用户当前已明确点名软件，则直接尊重点名指令，不强行拦截）。
     - *示例*：早期对话中用户曾说“开会一般用钉钉”，但近半月后台连续十余条网元单据 100% 均为 `tencentmeeting`；今天用户输入“明早 9 点到 11 点开会帮我保 1080P”（未点名软件） → 检出旧对话记录与近期单据实测矛盾，提示用户确认明早按腾讯会议还是钉钉保障。
   - `2.3.3` **临时配置隔离与到期回退**：声明“仅本次临时生效”或短期有效配置超期后，后续缺参请求自动回退至长期常驻偏好。
     - *示例*：昨天声明“今天出差仅临时按 720P 保腾讯会议，别改平时 1080P 默认”；今天回到日常输入“下午 2 点到 4 点保一下腾讯会议”（缺参数） → 自动填回 1080P 常驻偏好。
4. **`2.4` 未观测空值拒猜与已知项免重问（`Abstention & Selective Clarification`）** —— 参考 `LongMemEval (ABS)`
   - `2.4.1` **冷启动新用户全空拒猜**：无任何历史单据与对话记录的新用户发起模糊或缺参请求时，拒绝编造默认值并转入追问。
     - *示例*：新入网无历史记录的 `gpsi` 用户说“今晚 8 点到 10 点开个直播保障” → 拒绝瞎猜软件与参数，直接追问。
   - `2.4.2` **单据原生空值拒猜与半已知精准追问**：针对历史已知部分槽位（如单据已知常用 `tencentmeeting`）、但另一槽位在 `EXP` 单据与对话中均为未观测空值（如 `resolution_mode = null`）的情况，**静默预填已知槽位不再重复盘问，仅精准追问未观测空值槽位**，严禁凭空编造 `1080P` 等默认值。
     - *示例*：单据显示该用户开会固定用 `tencentmeeting`，但 `resolution_mode` 原生为 `null` 且对话从未提过参数；输入“下午 2 点到 4 点开会帮我保一下” → 自动预填腾讯会议（不重问用什么软件），仅追问目标体验参数。
   - `2.4.3` **新业务类型无历史记录拒猜**：既有用户首次发起无历史记录的全新业务大类（新 `app_id`）请求时，不跨业务硬套旧参数，保持空值边界并追问。
     - *示例*：该用户长期仅使用 `meeting` 与 `vod_streaming`，从未跑过 `mobile_game`；首次输入“今晚 9 点到 11 点打游戏帮我保一下” → 追问具体游戏与时延目标。

### 3.3 程序记忆评测（Procedural / Experiential Memory）

- **功能与双源配合**：区别于绑定单用户的语义习惯，程序记忆沉淀**跨用户可迁移的外部资源调用规则、多轮澄清闭环过程与纠错规避经验**。历史交互轨迹记录外部资源调用情况、多轮澄清收敛过程与用户显式纠错动作；网元单据实测指标（无线侧 `DelayAn` 对比核心网侧 `DelayDn`、丢包率、事后 `StallingDuration` 变化）提供客观成败反馈信号。
1. **`3.1` 外部资源调用路由规则复用（`External Resource Routing Shortcut`）** —— 参考 `ReasoningBank`
   - `3.1.1` **基于原始文本向量的外部资源快速匹配**：存储历史任务中“原始请求文本向量 → 实际调用的外部资源组合（情景库 / 语义库 / 外部静态业务规则库）”，在大模型深度介入规划之前，直接通过原始文本嵌入匹配确定需调用的资源集合，减少慢速路由思考与无关库检索。
     - *示例*：历史经验记录“含超高清/专属低时延字样的请求需同步调用语义画像库与静态套餐权限库，无需检索历史情景库”；新输入“今晚 8 点到 10 点虎牙开启 4K 与 10ms 保障” → 向量直接命中该资源调用规则，跳过无关检索并一步完成权限校验。
2. **`3.2` 多轮澄清闭环轨迹学习与复用（`Test-Time Learning for Clarification`）** —— 参考 `MemoryAgentBench (TTL)`、`ReasoningBank`、`Memp`
   - `3.2.1` **易混淆子业务的闭合式精准追问**：从前序“在用户配合下经多轮澄清才闭环”的历史轨迹中学习高收敛提问方式，面对开放式提问易答偏的模糊诉求，直接复用闭合候选项一步锁定子业务。
     - *示例*：历史案例中用户只说“保抖音”，开放式提问耗时 3 轮才闭环；学习后复用闭合策略直接问“请问您是用抖音**开直播推流**，还是**观看短视频/直播**？（并请告知目标画质或时延）”，2 轮直接闭环。
   - `3.2.2` **规则/权限受限时的“拦截 + 可行平替”一步协商**：当请求超出套餐权限或规则边界时，不等用户反问“那我能开什么”，在指出受限的同时直接给出当前权限内最优可行替代方案，将 3 轮拉锯压缩为 2 轮确认闭环。
     - *示例*：标准档用户申请超权限的 4K 保障时，直接复用协商策略回复“当前标准档暂不支持 4K，为您匹配档内最高可用的 `1080P + 低时延 <30ms` 方案，是否按此开启？”，用户确认即闭环。
3. **`3.3` 显式纠错规避规则与单据劣化避错（`Error Avoidance & Mistake Prevention`）** —— 参考 `ReasoningBank`、`PersonaMem-v3 (mistake_prevention_recall)`、`REM`、`Memp`
   - `3.3.1` **用户显式纠错触发的防再犯规避规则**：前序交互中一旦发生明确的用户纠正动作（如模型盲猜子业务被用户当场纠正），提炼显式规避规则，后续遇到同类五五开模糊分布时禁止盲猜。
     - *示例*：针对“抖音看直播”与“开直播”占比五五开的场景，前序案例因模型盲猜“看直播”被用户纠正为“我是开直播！”；沉淀规避规则后，再次遇到看播/开播五五开且当前句未指明时，严格执行先询问确认、禁止直接猜单边输出。
   - `3.3.2` **结合网元单据劣化记录的参数推荐与避错**：当用户自身无该业务偏好且参数表述模糊时，结合近期单据无线特征（如弱覆盖 `signal_edge`、高丢包），复用实测无卡顿参数并规避曾致严重卡顿（`StallingDuration > 130s`）的高风险配置。
     - *示例*：经验库已从高丢包单据提炼防错准则“丢包率 `>15%` 时配 4K 极易断流”；新会话用户处于同类高丢包小区并模糊要求“画质尽量高、别卡”时，主动避开 4K，推荐稳妥的 1080P/720P 防卡顿方案。
   - `3.3.3` **禁用边界自检与防误套用**：当新任务表面相似但触发经验条目的显式禁用边界（或用户已明确指定合法参数）时，主动跳过旧经验，防止生搬硬套误改用户意图。
     - *示例*：上述弱覆盖降画质经验标明“5G 稳定覆盖下禁用”；当 5G 稳定覆盖用户说“今晚抖音开播，画质尽量高”时，自检触发禁用边界主动跳过该经验，正常按高画质配置。

### 附：`6.1` 域外意图驳回（`OOD Rejection`）的三大圈层域范围定义

以**本域（移动蜂窝网络 4G/5G 核心网下，目标应用/子业务的实时网络联接质量保障意图提取）**为边界，域外驳回测试集按语义距离由近及远覆盖三大圈层（重点采样前两圈高混淆域）：

1. **第一圈：电信与网络强相关邻近域（`Near-OOD`，字面高频出现网络、流量、套餐等词，最易误放行）**
   - **家庭固网宽带与局域网域**：家宽光纤开户/移机/报障、家庭 Wi-Fi 路由器组网与死角排障、光猫配置。
     - *示例*：“我家里千兆宽带在书房 Wi-Fi 信号只有一格，帮我安排装维师傅上门调一下光猫和路由器。”
   - **运营商计费账单与号卡营业域**：话费账单查询、通用流量包订购/退订、停复机、SIM 卡补换卡、携号转网。
     - *示例*：“查一下我上个月话费为什么多扣了 30 块，顺便把之前的夜间流量包退订了。”
   - **无线基站工程与建维投诉域**：基站断电故障申报、地下室/电梯加装室分信号投诉（属工程运维工单域，非单用户会话保障）。
     - *示例*：“我们小区地库常年没 5G 信号，麻烦建个工程单派人来加装信号放大器。”
   - **政企物理专线与云网基础设施域**：企业物理专线施工开通、云服务器公网带宽扩容。
     - *示例*：“公司新租了三楼办公区，需要拉一条 1G 上下对等政企专线，什么时候能进场施工？”
2. **第二圈：终端设备与第三方应用自身故障域（`Medium-OOD`，字面同为“卡顿/打不开/画质受限”，但根因不在网络联接层）**
   - **终端硬件与操作系统故障域**：手机发热降频掉帧、存储满闪退、蓝牙/投屏硬件配对失败、系统设置异常。
     - *示例*：“我手机一打游戏就发烫掉帧，而且存储空间满了总闪退，怎么解决？”
   - **第三方应用（OTT）账号与会员限制域**：应用内未开会员无法选 4K 画质、网盘非会员服务端限速、游戏停服维护、账号封禁登录失败。
     - *示例*：“我在腾讯视频里点不了 4K 蓝光选项，老提示要开超级影视 VIP，帮我解锁一下。”
   - **通信安全拦截与短消息通道域**：骚扰电话屏蔽、涉诈停机申诉、应用短信验证码未下发。
     - *示例*：“我手机号刚才被系统误判涉诈停机了，麻烦帮我核实解封一下。”
3. **第三圈：通用跨域生活助手与开放闲聊域（`Far-OOD`，与通信网络完全无关的基础负样本）**
   - **常见垂直生活服务域**：天气日程闹钟、地图导航与出行订票、电商外卖物流、金融医疗政务问答。
     - *示例*：“帮我查一下明天上海的天气，顺便订一张早上去杭州的高铁票。”
   - **开放闲聊与通用内容生成域**：日常寒暄、百科问答、写文案/写代码、无意义符号或纯情绪感叹词。
     - *示例*：“今天天气真不错，顺便帮我写一段项目周报总结。”

## 五、端到端分桶成功率与效率收益指标（准确率分层 · 澄清轮数 · Token 压降）

在“长期记忆评测 + 意图理解评测”构成的端到端测试集上，设定三组对照条件：**`With-Memory`（挂载长期记忆）**、**`No-Memory`（无跨会话记忆基线）**与 **`Full-Context`（历史原始单据与对话全文拼接基线）**，考核以下三组全局指标：

### 5.1 记忆非必要场景与必要场景分桶成功率

避免全集混合求均值掩盖真实效果，按样本对长期记忆的依赖性拆分为两个独立统计桶：

1. **记忆非必要场景成功率（评测意图理解能力与防负向干扰）**：覆盖单轮完整表达、免构造基础变体（`L1.1 / L2.1 / L3.1`）、复杂句法及纯静态规则驳回样本。对比 `No-Memory` 与 `With-Memory` 的意图模板准确率，一方面衡量基础意图理解底盘，另一方面确保挂载长期记忆后**零退化（不因历史偏好喧宾夺主而篡改当前明确指令）**。
2. **记忆必要场景成功率与净增益（评测长期记忆的实际帮助）**：覆盖跨会话指代、个人模糊表达映射、缺参习惯补全等必须借助记忆才能单轮解出或减少追问的样本，重点统计记忆带来的准确率提升幅度：
   $$\Delta \text{Acc}_{\text{req}} = \text{Acc}_{\text{mem, req}} - \text{Acc}_{\text{no-mem, req}}$$
   符号解释如下：
   - $\text{Acc}_{\text{mem, req}}$：挂载长期记忆系统在记忆必要场景子集上的最终意图准确率；
   - $\text{Acc}_{\text{no-mem, req}}$：无记忆基线在同一子集上的最终意图准确率。

### 5.2 澄清轮数减少指标（`Clarification Turn Reduction`） —— 参考 `ReasoningBank`、`Memp`

1. **平均闭环轮数（`Avg Turns to Resolution`）** 与 **澄清轮数减少率（`Turn Reduction Rate`）**：
   $$\Delta \text{Turns} = \frac{\text{Turns}_{\text{no-mem}} - \text{Turns}_{\text{mem}}}{\text{Turns}_{\text{no-mem}}}$$
   符号解释如下：
   - $\text{Turns}_{\text{no-mem}}$：无记忆基线达成正确意图闭环的平均交互轮数（范围 `1~3` 轮）；
   - $\text{Turns}_{\text{mem}}$：挂载长期记忆系统后达成正确意图闭环的平均交互轮数。
2. **单轮快路径直通率（`1-Turn Fast-Path Resolution Rate`）**：模糊、缺参或指代样本借助长期记忆在 `1` 轮内直接输出正确最终模板的比例；同步监控**未澄清直接执行率 ↓（`Premature Execution Rate`）**，防止在空值或多候选不可唯一推断时靠盲目猜测压降轮数。

### 5.3 上下文与端到端 Token 减少指标（`Token Efficiency`） —— 参考 `REM`、`Mem0`

1. **上下文输入压缩率（`Prompt Token Compression Ratio`，对比 `Full-Context`）**：
   $$\text{Compression}_{\text{prompt}} = 1 - \frac{\text{PromptTokens}_{\text{mem}}}{\text{PromptTokens}_{\text{full-ctx}}}$$
   符号解释如下：
   - $\text{PromptTokens}_{\text{mem}}$：挂载记忆系统时单轮注入精炼记忆的平均输入 Token 数；
   - $\text{PromptTokens}_{\text{full-ctx}}$：拼接原始网元单据与历史对话全文的平均输入 Token 数。
2. **单任务端到端总 Token 节省率（`End-to-End Token Reduction Rate`，分别对比 `No-Memory` 与 `Full-Context`）**：
   $$\Delta \text{Tokens} = \frac{\text{TotalTokens}_{\text{baseline}} - \text{TotalTokens}_{\text{mem}}}{\text{TotalTokens}_{\text{baseline}}}$$
   符号解释如下：
   - $\text{TotalTokens}_{\text{mem}}$：挂载记忆系统完成单次任务闭环（`1~3` 轮累计）消耗的输入与输出总 Token 数；
   - $\text{TotalTokens}_{\text{baseline}}$：对应基线完成同一任务消耗的累计总 Token 数。
