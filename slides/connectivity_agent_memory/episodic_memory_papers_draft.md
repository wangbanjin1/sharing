## 0. 总表基准：`总表-我们的设计汇总`（情景记忆行）

| 列 | 列名 | 当前总表定稿内容 |
| :--- | :--- | :--- |
| 1 | 记忆类型 | 情景记忆 |
| 2 | 是否涉及 | 是 |
| 3 | 解决什么问题 | 解决跨会话指代与历史情景回溯问题（如“上周/上个月的什么意图再来一次”），通过时间戳定位该时间段发生的情景记忆并注入工作记忆，辅助当前意图理解与参数补全。 |
| 4 | 触发时机与输入 | **【触发时机】**每次会话之后<br/>**【数据内容】**<br/>1. 用户和 Agent 交互对话<br/>2. 结构化意图模板<br/>3. 意图状态的变化<br/>4. 调用的外部资源（RAG、记忆、业务规则） |
| 5 | 标准输出 | **【概述】**标准化的事件表达（表述事件发生的时间、地点、人物、起因、经过、结果）<br/>**【核心要素】**<br/>• 时间：交互开始时间或者交互最终闭环的时间<br/>• 起因：用户的诉求（含修改参数、撤销意图等动作），业务+应用+KPI参数+保障时间的组合<br/>• 经过：意图理解任务的轨迹、调用的外部资源<br/>• 结果：意图模板、意图闭环的状态 |
| 6 | 存储形式 | 结构化文本 |
| 7 | 生成-算法 | 结合意图状态变更记录与任务执行轨迹，抽提“时间—起因—经过—结果”标准化事件摘要并写入 |
| 8 | 生成-时机 | 每次会话结束/意图闭环之后 |
| 9 | 更新-算法 | 同一事件后续补充或状态翻转时，按时间线追加更新状态与结果 |
| 10 | 更新-时机 | 跨轮次或跨会话延续同一事件时 |
| 11 | 检索-算法 | 时间窗过滤（解析“上周/上个月”等时间表达）+ 语义向量相似度检索 |
| 12 | 检索-时机 | 识别到跨会话指代或历史任务回溯诉求时，在意图理解前注入工作记忆 |
| 13 | 遗忘-算法 | 按时间衰减与访问频次降权归档 |
| 14 | 遗忘-时机 | 超过保留窗口或冷门低频事件定期归档 |
| 15 | 删除-算法 | 支持按事件 ID 或时间范围显式删除并同步清理索引 |
| 16 | 删除-时机 | 用户显式要求删除或合规清理时 |

## 1. `CoALA`（认知底座）— 待您最终确认

> 笔记来源：`papers/notes/papers/00_memory_coala.md`

| 列 | 列名 | 严格对照总表骨架（有才写，没有的不写） |
| :--- | :--- | :--- |
| 1 | 记忆类型 | 情景记忆 |
| 2 | 是否涉及 | 是（三类长期记忆之一） |
| 3 | 解决什么问题 | 1. 跨会话保留用户的历史对话与行为记录（如零售场景下的历史购买与对话记录），避免新会话从零开始；<br/>2. 在规划阶段提供过往交互轨迹或输入—输出示例作为上下文先验；<br/>3. 作为后续反思提炼语义记忆事实的原始经历来源。 |
| 4 | 触发时机与输入 | **【触发时机】**`Learning` 阶段（`Sec 6` 建议 `Deferring Learning` 推迟至每次会话/交互结束之后）<br/>**【数据内容】**<br/>1. 用户和 Agent 交互对话（历史对话记录）<br/>2. 动作执行与外部环境/工具调用反馈轨迹（Trajectories） |
| 5 | 标准输出 | **【概述】**历史事件流（Event Flows）、过往完整交互轨迹或输入—输出示例对<br/>**【核心要素】**<br/>• 时间：早先决策周期的发生顺序（具体如引用的 `Generative Agents` 事件列表带时间戳）<br/>• 经过：历史交互对话流、外部动作与环境反馈轨迹 |
| 6 | 存储形式 | 外部文本 / 事件列表（序列化的交互轨迹文本） |
| 7 | 生成-算法 | 通过内部 `Learning` 动作将工作记忆中的本轮交互经历摘要或直接整理后写入。 |
| 8 | 生成-时机 | 建议 `Deferring Learning`：每次会话/交互结束之后统一生成。 |
| 9 | 更新-算法 | 仅追加写入新经历（`Adding`）；原文 `Sec 4.5` 明确指出修改既有记忆（`Modifying`）未解决。 |
| 10 | 更新-时机 | 每次会话结束追加新记录。 |
| 11 | 检索-算法 | 通过内部 `Retrieval` 动作检索读入工作记忆（原文 `Sec 4.3` 以 `Generative Agents` 为例：按**近度 + 重要度 + 相关度**加权召回）。 |
| 12 | 检索-时机 | 规划（`Planning`）阶段需要历史先验参考时。 |
| 13 | 遗忘-算法 | 无（原文未给出遗忘衰减或淘汰公式）。 |
| 14 | 遗忘-时机 | 无。 |
| 15 | 删除-算法 | 无（原文 `Sec 4.5` 明确未解决 `Deleting`）。 |
| 16 | 删除-时机 | 无。 |

## 2. 待逐篇确认候选池（按跨会话指代/时间回溯相关性排序）

1. **`Zep / Graphiti`**（`03_memory_zep_graphiti.md`）：`EpisodicNode` 原始会话保留 + `valid_at` / `created_at` 双时间戳 + `:MENTIONS` 溯源 + 近 4~10 条历史情节作指代消解上下文
2. **`MIRIX-2.0`**（`09_memory_mirix.md`）：独立 `Episodic` 分库 + 不可变证据平面 $P_u$ + 时间区间过滤查询算子
3. **`MemoryOS`**（`02_memory_memoryos.md`）：STM 对话页（含时间戳）→ MTM 主题段池（语义+关键词聚类）
4. **`A-MEM`**（`07_memory_amem.md`）：带 `timestamp` / `context` / `links` 的原子笔记 `MemoryNote` 与邻居链接回溯
5. **`MemOS`**（`08_memory_memos.md`）：`MemCube` 带时间戳与 `MERGED_TO` 血缘边的统一容器
6. **`Epistemics`**（`11_memory_epistemics_agent_memory.md`）：`BoundaryLearner` 情景边界切分与保留/摘要/遗忘门控
7. **`LongMemEval`**（`18_benchmark_longmemeval.md`）：跨会话 `Temporal Reasoning` 时间窗剪枝检索优化框架
8. **`LoCoMo`**（`16_benchmark_locomo.md`）：时序因果事件图与跨会话指代评测基准
9. **`Mem0`**（`01_memory_mem0.md`）：`Mem0g` 图记忆时序关系与历史会话增量更新
10. **`MemGPT`** / 其他库内补充（按您筛选决定是否纳入）
