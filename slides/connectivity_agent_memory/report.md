分层设计 · 双渠道门控萃取 · 混合存储检索 · 经验记忆闭环 · 受控遗忘 · GT-First 基准

## 1. 四层记忆分工与协作

面向网络保障的**意图理解 Agent** 同时接收两路异构信号：高频隐式的**网元单据流**与稀疏显式的**多轮口语对话**，核心目标是在信息缺失或模糊（Underspecified）时识别用户真实诉求，实现“成熟习惯快路径直通、未知或冲突场景慢路径澄清”。

我们将记忆拆分为四个正交层级：**工作记忆**（当前会话意图与待决槽位）、**情景与事实记忆**（双渠道事件流、偏好槽位与未观测空值边界）、**语义与表达映射层**（职业画像、口语别名字典与基站-场所隔离表）、以及**经验记忆**（跨场景意图消歧与避坑规则）。

| :--- | :--- | :--- | :--- |
| **1. 分层架构** | `CoALA`（四分库底座） | `Epistemics` 实测跨层迁移率为 `0`，缺血缘与基站隔离 | `MemOS` `MemCube` 血缘账本（达 $N_{\min}$ 显式晋升）+ `cell_id ↔ venue` 隔离 |
| **2. 情景萃取** | `Mem0`（抽取 + 四操作消解） | 短时废单污染库、预算泄压误删、单据含 `null` 缺失 | `Experience-Following` 写入门控 + `Epistemics` 防自泄露 + `MediQ` 空值拒答边界 |
| **3. 存储检索** | `Zep`（双时间戳多路检索） | `MERIT` 纯向量方差 `0.45`；`A-MEM` 陈旧嵌入；口语脱节 | `MIRIX-2.0` 证据与索引分离 + `BehaviorMem` 双池解耦 + 同行结构化槽位提取 |

| **5. 管理遗忘** | `Zep`（双时间戳软失效） | `BEMULA` 遗忘成功率 $\le 1.5\%$；`MemSecBench` 重编误伤 `30.2 pp` | 常态走 `SUPERSEDE` 软失效；显式删除沿 `source_episodes` 血缘局部剥离 |
| **6. 基准评测** | `LoCoMo / PersonaMem-v3` | 先对话后标注致真值漂移；模拟器剧透虚高 `24.4%` | `GT-First` 先建标准快照 + `Disclosure-Gated` 防剧透 + `τ²-Bench` 双端交互与 $\text{pass}^k$ |

## 2. 双渠道萃取、噪音门控与冲突消解

以 **Mem0** 的两阶段抽取与冲突消解为主基座；针对**情景记忆噪音污染、否定误抽与空值幻觉**问题，叠加 `Experience-Following` 写入门控与 `MediQ` 未观测边界保留机制：

- **单据侧噪音判据**：有效时长小于阈值 $T_{\min}$ 的误触打开或中途取消单据，以及在统计窗 $W_{\text{span}}$ 内仅偶发 1 次、无跨日复现的孤立访问，均触发 `IGNORE_NOISE`。
- **对话侧噪音判据**：无保障槽位的纯闲聊寒暄、域外诉求（如宽带报修）、已自愈无需干预的反馈，以及否定子句中被排除的靶点（如“不要 4K”），禁止写入正偏好。
- **空值边界与冲突消解**：原始单据中为 `null` 的指标（如 `qoe_median`）显式保留在 `unobserved_dims` 禁止回填；有效事件按现存槽位比对路由至 `ADD / UPDATE / SUPERSEDE`。

<!-- [EMBED: 静态图 2 · 双渠道记忆萃取、否定分离与冲突消解全景流程] -->

| 典型场景 | 输入特征示例 | 门控与预处理动作 | 记忆状态结果 |
| :--- | :--- | :--- | :--- |
| **1. 噪音拦截** | 2 分钟优酷取消单 + “客服几点下班”闲聊 | `dur < T_min` 与无保障槽位判定，直接拦截 | 发射 `IGNORE_NOISE`，标准记忆快照零变动 |
| **2. 否定与空值保护** | “不要 4K，720p 就行” + 单据 `qoe_median=null` | 剥离否定靶点“4K”，显式登记 `qoe_median` 未观测 | 仅写入 `720p` 正偏好，严禁猜测回填 QoE |
| **3. 一致强化晋升** | 工作日早高峰连续使用腾讯会议达 $N_{\min}$ 次 | 命中现存 `main_app` 槽位，执行一致累加 | `UPDATE` 支持度，状态由 `weak` 晋升为 `strong` |
| **4. 改口与支线退场** | 出差结束回归通勤，或将目标改为 `<=30ms` | 识别冲突变更，定位旧支线或旧目标槽位 | `SUPERSEDE` 标 `invalid_at`，新状态生效且可追溯 |

## 3. 混合存储与多路检索机制

存储与检索以 **Zep / Graphiti** 为主基座，叠加 **MIRIX-2.0** 与 **BehaviorMem** 的存储解耦思路，落地结构化与向量混合检索管线。三项核心技术的引入动机与解决的问题如下：

- **为什么用 `Zep` 双时间戳时序图谱（解决“过期规则误召回”）**：意图与偏好随时间动态演进（如上周出差临时规则、本周回归常态）。每条关系边绑定生效时间 `valid_at` 与失效时间 `invalid_at`，检索期直接过滤已失效历史边；同时“向量 + 关键词 + 图遍历”兼顾模糊语义与实体跳转。
- **为什么用 `MIRIX-2.0` 原始证据与索引分离（解决“陈旧嵌入与参数拆散”）**：`A-MEM` 修改文本后未重算向量引发陈旧嵌入，且长文切块易拆散同一单据中的“应用-时段-时延”绑定。证据与索引分离后，向量仅用于定位候选记录，随后直接读取**同行结构化槽位列**（Row-Level Column Projection），保证数值参数 100% 精确且更新无需重算摘要。
- **为什么用 `BehaviorMem` 记忆/推断双池解耦（解决“推测污染事实真值”）**：原始单据与用户明说归入客观事实池（Remember），画像归因与习惯倾向归入推断池（Infer）。双池物理隔离后，客观事实直接支撑精准参数查询，概率推断需受支持度阈值校验才可辅助决策，防止错误推断反向污染事实库。

| 检索阶段 | 具体处理机制 | 解决的痛点与论文局限 |
| :--- | :--- | :--- |
| **1. 口语归一化** | 通过个性化表述映射层（`expression`）将别名（“腾会”）与体感词（“460 / 别卡”）转为标准槽位，场所映射为基站候选 | 消除口语与网元字段的词表鸿沟，且全程隔离内部基站编号 |
| **2. 混合召回与同行投影** | 向量定位候选记录 + 结构化 `SELECT` + 双时间戳图谱遍历；随后读取同行结构化槽位列并经 `service_to_app` 二阶段补全 | 解决纯向量召回丢失数值约束（`<=50ms`）及 `MERIT` 高方差（`0.45`）问题 |
| **3. 时效与空值校验** | 过滤 `superseded` 历史边；若查询指向 `unobserved_dims`（如缺失 `qoe_median`），直接返回拒答信号 | 消除过期规则误触发，杜绝未观测指标幻觉回填 |

## 4. 经验记忆构造、受挫门控与动态淘汰

经验记忆以 **AWM** 与 **ReasoningBank** 的成败双源蒸馏为主基座；针对 `Experience-Following` 揭露的错误自举、`WASP-Mem` 指出的自由文本冗余以及 `REM` 实证的常驻注入干扰，设计构造与运行态闭环：

> **构造期（离线/准实时）**
> - **成败双源对比 + 原话核验（`MIRIX-2.0`）**：对比顺畅单据与卡顿异常记录提炼规律（如展馆开播提前预热），每条经验必须绑定源单据 ID 或用户原话切片，未命中引用直接丢弃。
> - **结构化编辑去重（`WASP-Mem`）**：统一收敛为 `Schema Form-ED`（`trigger_condition` · `failure_pattern` · `action_policy`），消除自由文本重复膨胀。

> **运行态（在线闭环）**
> - **受挫门控按需召回（`REM`）**：成熟习惯走快路径直通时禁止默认注入经验；仅当出现弱网边缘、多单冲突或用户反复反馈卡顿时才召回 Top-k 经验，并通过 `Confirm_Slot` 协商确认。
> - **单次曝光驱逐与胜率淘汰**：追踪保障后网络实际运行结果，若曝光经验未带来体验改善立即触发单次驱逐或低胜率淘汰。

## 5. 演化管理与双约束受控遗忘

针对 `Epistemics` 揭露的跨层迁移失效以及 `BEMULA / MemSecBench` 揭露的遗忘难题（显式遗忘成功率 $\text{RPR} \le 1.5\%$，暴力重编摘要误伤良性记忆高达 $30.2\text{ pp}$），管理层按三类动作分流治理：

- **跨层晋升**：同一偏好在时间窗 $W_{\text{span}}$ 内累计达支持次数 $N_{\min}$，由候选（`weak`）晋升为稳定偏好（`strong`）并写入血缘账本，支撑快路径。
- **常态软失效（`SUPERSEDE`）**：临时支线（出差/恶劣天气）到期或用户改口时，标记 `status="superseded"` 并写 `invalid_at`，保留历史审计链。
- **双约束定向遗忘**：用户显式要求忘掉某敏感地点或旧习惯时，沿 `source_episodes` 血缘图精确剥离原始记录并局部重算关联槽位，守住“目标残余 = 0”且“良性零误伤”。

## 6. GT-First 基准构造与双端交互评测

以 `LoCoMo / PersonaMem-v3` 为起点，针对先写对话后标注的真值漂移与 `UserProxyBench` 揭露的模拟器剧透虚高（`24.4%`），依托已有**两层 40 维故事线因子表**，采用 **GT-First 先建状态机真值 + 物理隔离双渠道渲染 + `τ²-Bench` 双端交互评测**。

<!-- [EMBED: 静态图 3 · GT-First 基准构造与双端评测闭环全景] -->

> **评测一票否决红线与核心软指标**
> - **四条一票否决红线**：① 对未观测维度（如缺失 `qoe_median`）臆造数值；② 对话侧泄露内部基站编号；③ 短时无效单据污染长期偏好；④ 高风险变更未经 `Confirm_Slot` 确认直接下发。
> - **三项核心软指标**：节点级标准记忆状态快照槽位一致率、多次采样稳定性 $\text{pass}^k$、以及快路径直通与慢路径消歧的分流准确率。
