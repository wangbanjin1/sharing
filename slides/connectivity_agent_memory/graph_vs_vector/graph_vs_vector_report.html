读这张表要注意两件事。 ① Q1 的差距不可信：向量侧用的是字符 bigram TF-IDF 替代 embedding，"最常用"这种语义排序它本来就弱， 真实 embedding 在单跳上应该接近满分，所以 Q1 应视为平手。 ② Q2/Q3/Q4 的差距与编码器质量无关：向量库里根本没有"谁和谁同小区""这条边什么时候失效"这种结构， 再好的 embedding 也变不出来。这三行才是建图的真实收益。

结论

  • 建图的优势不是"记得更准"，是"能回答需要走关系和时间的问题"。 单跳偏好、单条事实的召回，向量完全够用，而且写入便宜一个量级。
  • 真正的分水岭是三个能力：多跳（用户→小区→邻居→偏好）、时间点查询（11 月 15 日那天是什么状态）、 变更取证（旧边失效但不删除，能回答"变过吗"）。这三件事在向量库里没有对应结构，只能靠模型现场推理。
  • 代价也很具体：这张图 20 个用户就 260 条边，真实数据是百万级单据； 每条边都要跑实体抽取 + 消解 + 时间归一，写入成本比"一次 embedding"高一个量级； 实体消解一错（同名合并、别名拆开），上面三个能力的收益会直接归零。
  • 对我们这个场景的判断：意图理解 Agent 的高频查询是"这个用户/这个业务默认怎么配"—— 单跳，向量够； 真正需要图的是"跨会话指代"和"变更核实"（用户说"还是老样子"，但老样子已经变过两次）。 所以不是二选一，而是向量做默认，图只覆盖需要溯源的那一小撮查询。
