1 故事线的正交因子方法论（排布层与内容层解耦设计）

1.1 故事线两层解耦设计思路

面向移动网络体验保障（联接 Agent）的长期记忆与多轮意图评测，需要构造跨度数周至数月、包含自然语言对话与网元结构化单据的长周期测试数据，覆盖记忆萃取（偏好抽取、合并更新、分场景组织、画像生成、噪声抑制）与记忆检索（直接、排序、条件、排除、组合、缺失拒答）的各项测试点。

固定剧本模板或单层平铺变量表存在三方面问题：第一，时间线排布与事件内容耦合，调整干扰密度或主支线穿插方式时会影响单点业务内容；第二，同层因子存在条件依赖或跨层重复，例如将受时间窗口约束的“事件规模”与“时间跨度”并列，将仅在存在支线时生效的“支线归宿”与“事件线结构”并列，或在排布层与内容层重复定义“偏好演进”与“闲聊干扰”；第三，边界与噪声场景覆盖不全，缺少对负向排斥偏好、短期临时偏好过期、未提及属性拒答边界以及闲聊、试探、情绪发泄、单次偶发等非偏好噪声的控制参数。

参考 PersonaMem-v3、LoCoMo、DynamicMem、MemoryAgentBench 与 LongMemEval 的设计，故事线生成拆分为排布层与内容层两层结构（图 1）：

  • 第一层定排布（时间线与主支线结构）：控制整条时间线的总时长、事件规模与密度、主支线结构、跨期变化趋势、跨会话因果关系与测试点安排；其中受父级条件约束的属性（如1. 时间跨度下的1.1 事件规模与1.2 事件密度，3. 事件线结构下的3.1 支线触发事件与3.2 支线归宿）作为对应主因子的子因子采样。
  • 第二层定内容（业务画像属性与信息表达方式）：按“用户级 → 线级 → 节点级”三种取值粒度，无重叠地覆盖用户身份与资产、应用与业务行为、时空轨迹与流量、网络环境与 KQI 偏好、信息来源与噪声干扰、多轮交互与反馈纠正六个方面。

1.3 第二层：故事线内容因子

• 检索：当前所处场景优先排序、带空间/无线覆盖条件召回与跨维组合推荐。

• 检索：口语提问直接命中标准参数、显式优先于隐式排序、严格排除负向排斥项。
4. 用户口头说法与网元单据记录一致或冲突 • 排布层：6.1 单据与对话总体配比（纯单据/纯对话/均衡混合）
• 内容层：11. 来源标注（sessions / CSV logs）与双源关系（一致/并列保留/口头声明与网元实测矛盾冲突）、11.1 证据强度（strong 多次实测 与 weak 随口声明） 		• 萃取：双源一致强化置信度；双源冲突时按证据强度整合（如口称“平时对网速没要求”但网元实测长期高上行直播流量，以 strong 实测为准或双源并列注记来源）；
• 检索：高置信度实测偏好优先于单次低置信度口头记录排序。
5. 使用习惯改变、套餐升级与未提及信息留空 • 排布层：2. 起始状态（冷启动）、4. 跨期变化趋势（单次迁移覆盖/渐进演变/习惯消退弃用）
• 内容层：3~4 & 8. 直播时长/画质习惯跨期升级、主力应用迁移或套餐加速包升档、14. 信息缺失边界（仅提下行未提上行、未提抖动、无切片 ID） 		• 萃取：同义偏好合并去重、新版本偏好（active）覆盖旧版本（superseded），对未提及维度严格留空不编造默认值；
• 检索：最新生效版本排在历史旧版本之前、排除已弃用业务习惯，遇未存储属性主动拒答或追问。
二、【长期记忆 ②】
事实 — 情景记忆（阶段事件与临时偏好）
（Episodic Event Memory）

跨会话存储（带时间窗/TTL）：记异地差旅/赛事事件、短期临时偏好、历史诉求情绪与显式纠正记录		 1. 出差、看比赛或月底流量紧张时的短期临时需求 • 排布层：3.1 支线触发事件（异地出差/大型体育赛事/展会）、3.2 支线归宿（结束后回原主线）
• 内容层：5.1 跨城移动状态、7. 月末流量余量吃紧、13. 短期临时偏好与有效期状态（未过期/临近过期/已过期/混合） 		• 萃取：短期差旅/赛事事件与临时省流或保障偏好绑定时间窗（TTL）独立存储，结束后自动回退不污染常驻语义记忆；
• 检索：未过期临时偏好排在已过期前、阶段条件召回、“月底流量紧+手游卡顿”省流保时延组合推理、全部过期时主动说明。
2. 网络问题投诉、当面纠正系统错误与单次临时调整 • 排布层：4. 跨期变化趋势（多次波动与当面纠正后改回）、6.2 证据间隔
• 内容层：16. 主动诉求（弱覆盖提速/开加速包/解限速；active 与 closed）与情绪轨迹（不满投诉→改观）、18. 当面显式纠正与单次临时豁免声明 		• 萃取：同一诉求重申合并、新诉求关闭旧诉求、显式纠正最高优先级覆写、单场临时豁免（“仅今天改 720p”）隔离不改写常驻档案；
• 检索：未完结诉求（active）与最新纠正记录优先排序，排除已解决诉求与被纠正前的错误旧值。
3. 日常闲聊、套餐咨询试探与偶尔一次的行为干扰 • 排布层：1.2 事件密度、6.3 间隔期干扰占比（低/中/高）
• 内容层：15. 对话侧非偏好噪声（日常寒暄、假设试探“如果升级5G-A专网包…”、纯情绪抱怨、频次=1 的单次偶发看剧/熬夜） 		• 萃取：非偏好噪声抑制（防 FP 误抽：闲聊、未落单的假设试探与单次偶发行为严禁写入长期偏好，纯情绪仅记入反馈信号）；
• 检索：当历史仅有假设试探或单次偶发记录时，查询常驻偏好能如实拒答。

长期情景库原样保存每次历史保障单据与实际运行结果（不合并、不衰减）；短期工作记忆在当轮会话中检索读入历史单据并跟踪改期/消歧槽位		 1. 记录每次保障单据的参数与实际运行结果（过滤误触取消单） • 排布层：1.2 事件密度（忙闲交替）、6.1 单据与对话配比

• 内容层：10. 同场馆先后埋入空场顺畅单 SN_A、正赛基站拥塞卡顿单 SN_B 与中途取消的无效单据、17. 模糊指代（“按上次在奥体那单来”）与不存在单据虚假指代 		• 检索与消歧：条件与排除检索（指定“没卡那次”时自动排除拥塞单 SN_B 与中途取消的无效单据、锁定顺畅单 SN_A）；仅提场馆名且存在多张有效候选单或指代单据不存在时，主动列明候选差异发起反问消歧。
四、【长期记忆 ③】
程序化 / 经验记忆
（Procedural / Experiential Memory）

跨会话持久存储：从短期工作记忆慢路径澄清与长期情景单据正反对比中提炼因果调参规则与消歧流程（Workflows）		 1. 从历史多轮澄清和排障过程中提炼调参经验 • 排布层：5. 跨会话因果关系、6.2 证据间隔、6.3 干扰占比（穿插大量日常快路径与闲聊）
• 内容层：17~18. 缺参追问与显式纠偏（如字面陷阱纠偏、要求高密场馆提前预热锁流）、10~11. 同场馆前单拥塞 bad 改参后顺畅 good 正反对比、15. 未闭环试探噪声 		• 萃取（源头样本定位与因果提取）：评测能否从海量日常会话与单据流中识别已闭环的慢路径澄清/排障样本，提炼“场景条件→无线根因→调参动作→结果”因果规则，且不把未闭环试探误提炼为经验。
2. 换个说法或换个同类场馆时直接复用已有经验 • 排布层：3. 事件线结构（支线 A 沉淀经验 → 切换至同类支线 B）、6.2 长间隔
• 内容层：5. 同属万人高密场馆或高速走廊的不同具体地名（如“奥体中心”→“工体中心”）、8.1/10.1 互斥权重与高峰 PRB 拥塞规律、12.2 口语换词 		• 检索与应用（跨表述泛化召回与慢转快）：评测当新请求更换具体场馆名或口语表述、但底层无线环境条件（高密场馆+上行直播推流）一致时，能否准确找回对应经验规则，自动补齐提前预热/高优切片实现 1 轮快路径闭环。
3. 字面相似但实际网络环境不同时避免套错经验 • 排布层：3. 事件线结构（从高密场馆支线切回常规驻地主线）
• 内容层：5. 空间切换（从“体育场馆看球开播”切回“常规室内驻地看球开播”）、9. 无线覆盖切换（从边缘弱覆盖高密拥塞小区切回常规 5G 宏站稳定覆盖小区） 		• 检索与边界过滤（防经验误套用）：评测当新请求与经验记录字面相似（同含“球赛、直播”）、但底层无线负载与覆盖条件不符时，能否核验适用边界（scope）并主动抑制场馆降画质/预热经验。

（Multi-Memory Coupling）

面向真实复杂请求的多层记忆联合检索、槽位拼接与优先级冲突裁决（预留复杂 Case 扩展空间）		 1. 【语义 + 情景】平时的高画质习惯遇上出差或月底省流时的临时调整 • 排布层：3.1 短期支线事件窗（异地漫游/月末最后3天）、4. 跨期变化

• 内容层：12.2 首轮高省略口语指令 + 13. 赛事短期事件窗 + 10. 历史场馆拥塞单据 + 18. 多条候选经验规则（含适用与不适用规则） 		• 耦合评测：检验单轮复杂请求下的四类记忆协同：将三类长期记忆联合检索读入短期工作记忆：用长期语义记忆召回最新升级版主线参数与口语映射 → 用长期情景记忆对齐赛事日短期窗口并规避历史拥塞单据配置 → 用长期程序化/经验记忆触发“提前 30min 预热锁流”（同时抑制不匹配的微信对词规则），在工作记忆内合成参数实现 1 轮快路径闭环。

1.5 两层组合规则、配置表结构与跨 3 个月完整组合示例

第一层排布因子与第二层内容因子组合为具体故事线时，遵循以下工程规则：

  1. 先定时间线结构，再按三级粒度填内容：先从第一层采样得到时间线结构；再按取值粒度填第二层——“用户”级因子整条故事线取一次，“线”级因子每条事件线取一次，“节点”级因子每个事件节点独立取一次。
  2. 主从层级条件采样（消除父子条件冲突）：先采样主因子，再在其范围内采样对应子因子。例如先定1. 时间跨度，再定与之匹配的1.1 事件规模与1.2 事件密度；仅当3. 事件线结构包含支线时才采样3.1 支线触发事件与3.2 支线归宿；仅当10. 网络异常 ≠ 无异常时才采样10.1 异常发生阶段。
  3. 声明式合法性约束（不写死在代码分支中）：只排除物理或逻辑冲突的组合，并统一声明在配置表的 constraints 列表中（例如排除“时间跨度 2 周与按月周期规律”、“平稳保持型节奏与套餐跨期升降级”、“仅网元单据体现与对话显式直接陈述”）。
  4. “先答案后会话”反向真值绑定与分阶段构建策略：前期与中期采用“先定义答案、再反向生成会话”路线（参照 LongMemEval、DynamicMem、PERMA）：① 先定义评测骨架（测试维度、测试目的与难度分布）→ ② 先写出结构化标准答案（萃取侧写明 gold_profile 的生效值、过期值、来源与置信度，检索侧写明 gold_answer 与 gold_memory_ids）→ ③ 按成对覆盖（Pairwise Coverage）采样两层因子，反向生成能唯一推导出该答案的自然语言对话与网元结构化单据序列 → ④ 通过多 LLM 交叉验证检验对话自然度与答案唯一性；到后期上线阶段再结合“先有真实会话、后抽检标注答案”路线（参照 LoCoMo、MemoryAgentBench）补充长尾边界样本。
  5. 增量扩展：新增测试维度时，直接在对应因子类别下补充主因子或子因子定义，不影响已有因子与数据。
真实组合示例：跨 3 个月“主线居家直播 + 支线异地场馆推流”的两层因子取值示例

4. 语音 ASR 同音错字与吞音粘连 “把那个漫游（慢游）流量包开一下”、“上行（尚行）推流掉帧” 重点覆盖（Speak & Spell 2409.06263、Omnilingua-AudioMC 2611.04390） 现有 ASR 噪声集中于通用英文音素，欠缺垂直行业专有名词/设备型号同音误识与个人口头禅同音字联合恢复。
5. 多层嵌套条件与例外从句 “要是今晚十点前还没修好，除非已经在走赔付流程了，否则帮我转高级专家” 覆盖较弱（BlendX 2403.18277 含简单条件句） 极度欠缺“如果 A 则 B，除非 C 否则 D”多层布尔条件树转结构化执行约束的评测。
6. 中英混杂、缩写与数字单位省写 “5G SA 切 NSA 后 ping 抖动 200ms，帮查下 APN 和切片 QoS” 覆盖极少（多数基准为纯英文或标准书面中文） 欠缺高密度技术缩写 + 口语数字简写（如“晚 8 到 10”、“1080p 升 4K”）混合解析。

17. 试探性条件咨询 与 正式下达执行指令 “如果我把今晚直播保障从 4K 降回 1080p，会不会影响推流画质？”（仅做假设咨询，并未授权立刻修改工单配置） 2026 新兴焦点（CAREFUL-Bench 2611.02978） 多数工具调用基准不区分“What-if 咨询态”与“Commit 执行态”，导致 Agent 在用户仅咨询时擅自调用写接口改坏环境状态。

结合 2024–2026 22 篇核心文献对联接 Agent 评测集构建的方法论总结
  • 在记忆测试点构造上：综合 PersonaMem-v3、BehaviorMem、Why Bother Me Again? 与 LoCoMo-Plus，不仅要埋入跨周期的事实与习惯（含 77% 稳定、13% 消退、8% 新增、1% 偶发四类轨迹及 ≥ 20 分 / ≥ 3 次晋升阈值），还要埋入用户的交互免打扰边界（哪些已知槽位不准重复追问）与零字面重合的隐式认知约束。
  • 在语法 · 语义 · 语用变体构造上：针对现有数据集最欠缺的盲区，重点构造“必须联合三类长期记忆与短期工作记忆才能消解的变体”——包括语法层的电报式残缺短语 + 句内多次口误自我修正（Self-Repair）、语义层的零字面重合个性化表述映射（查 expression 映射） + 复合意图否定排除（A ∧ ¬B 否定子句分离与权重衰减过滤）、以及语用层的高情绪抱怨言外之意（Read the Room ISA） + 跨周历史工单省略指代 + 试探性咨询态与执行态区分（CAREFUL-Bench）。
  • 在多轮用户–Agent 交互模拟上：借鉴 τ²-bench 双控环境、Disclosure-Gated Simulation 5 级分步信息提供规则与 UserProxyBench 契约忠实度审计，严禁模拟用户第一轮吐露全部底牌或无条件配合，而是覆盖 双向交互动作（含反问原由、中途改口 IntentDelta、旁人插话干扰 Multi-User DST 与高危写操作执行前二次确认 CAREFUL-Bench）。

3.2 核心指标的判分逻辑与精简算式表达

阶段 1 的抽取召回率与误抽率、阶段 2 的召回率及阶段 3 的克制率均为直观的比例统计（命中样本数除以总样本数）。全流程中保留两个核心算式：一是阶段 2 衡量“最新生效记录有没有排在旧记录/异常单前面”的时效分级排序分 NDCG@k；二是阶段 3 衡量“红线一票否决与三层记忆顺应”的受控决策得分 Score。

第一，在阶段 2 的排序评估中，当工作记忆存在同地多单冲突（如上周六在鸟巢既有下午顺畅单 SN_A、又有晚上卡顿单 SN_B）或事实记忆新旧交替时，即便两条记录都进入前 5 条，若卡顿单或过期旧记录排在第 1 位，下游模型仍易误用错误参数。因此按分级相关度 $\text{rel}_i$（当前生效事实/目标正常工单/对应经验规则 $\text{rel}=2$，辅助关联记录 $\text{rel}=1$，过期旧记录或体验异常卡顿单 $\text{rel}=0$）计算折损累计增益：

$$\text{DCG}@k = \sum_{i=1}^{k} \frac{2^{\text{rel}_i} - 1}{\log_2(i + 1)}, \qquad \text{NDCG}@k = \frac{\text{DCG}@k}{\text{IDCG}@k}$$
  • $\text{rel}_i$：检索列表第 $i$ 位结果的相关度等级（生效正例最高，过期或异常单据强制归零）；
  • $\text{IDCG}@k$：将所有生效正例排在最顶部时的理想最大 $\text{DCG}@k$；
  • 核对：当周六鸟巢的正常单 SN_A 与重叠消歧经验规则排在第 1、2 位，而卡顿单 SN_B 排在第 3 位时，正例占据最前位置，$\text{NDCG}@5 = 1.00$；反之若卡顿单排第 1 位，第 1 位的分子 $2^0 - 1 = 0$，总分立刻大幅折损。

第二，在阶段 3 的决策评估中，借鉴 PersonaMem-v3 的两步判分逻辑，引入一票否决指示项 $\mathbb{I}(V_{\text{veto}} = 0)$ 与槽位/动作满足度相乘：

$$\text{Score} = \mathbb{I}(V_{\text{veto}} = 0) \cdot \frac{|\hat{S} \cap S^*|}{|S^*|}$$
  • $V_{\text{veto}} \in \{0, 1\}$：一票否决红线标志。凡是套用已过期事实档位、照搬工作记忆中体验异常（卡顿/掉帧）单据的参数、未澄清便盲目抢跑下发冲突单、或违规刺探无关隐私，均令 $V_{\text{veto}} = 1 \implies \text{Score} = 0$；
  • $S^*$ 与 $\hat{S}$：分别为标准答案要求满足的“事实记忆补全槽位 + 工作记忆指代槽位 + 经验记忆调整动作”集合与系统实际输出集合。

4 记忆要记什么：CoALA 四类记忆分工、长短期分层管理与分表存储结构

4.1 单层向量库混存的问题与 CoALA“一短期 + 三长期”记忆分工

在 6G NGC 网络体验保障场景中，系统输入同时包含网元结构化保障单据及网络实际运行结果（记录小区标识 CGI、地点、起止时间、保障规格及事后体验质量 AppQuality=good/bad）与用户多轮自然语言对话。如果把当前对话上下文、用户长期习惯和历史单据直接混存在同一个无分层的文本向量库中，会出现以下四个问题：

  1. 用户的口语叫法与单次外出地点混在一起：用户的口语表达（如“小破站开播”）如果与某次外出场馆的地点、时长存在同一条文本中，回到常驻地点再次使用该叫法时，容易误带出上次外出场馆的参数。
  2. 短期临时改动覆盖平时的固定习惯：用户因异地出差、月末流量紧张或某天暴雨临时将画质降为 720p，如果不与长期常驻习惯分开存储，会直接覆盖平时稳定的 1080p / 4K 默认配置。
  3. 同一地点的正常单据与卡顿单据难以区分：同一场馆如果先后存在运行顺畅的单据（good）与发生卡顿的单据（bad），纯文本向量相似度几乎一致，用户说“照上次没卡那笔办”时很容易选错记录。
  4. 多轮沟通确定的参数调整无法直接用于同类新场景：首次在大型场馆遇到拥塞并经多轮沟通确定提前开启上行切片后，如果只保存当次单据而不提炼通用规则，下次换到其他体育场时仍需重复追问；反过来如果不做适用业务限制，在场馆内看视频点播时又会误触发上行切片。

参考普林斯顿大学提出的 CoALA（Cognitive Architectures for Language Agents, arXiv:2309.02427） 认知架构，系统首先按生命周期将记忆划分为短期记忆（Short-Term Memory）与长期记忆（Long-Term Memory）两级，其中只有工作记忆属于短期记忆，而语义记忆、情景记忆、程序化（经验）记忆三者均属于跨会话持久保存的长期记忆：

  • 短期记忆（Short-Term Memory）—— 1. 工作记忆（Working Memory，解决“当前会话正在处理什么、中间槽位与当轮上下文是什么”）：仅在当前单次会话或当前决策周期内活跃的瞬时上下文草稿板（Scratchpad），也是大模型推理核心唯一直接读取的内存区域。工作记忆负责维护：① 本轮用户输入与当前任务目标；② 多轮澄清交互中的活跃槽位状态（已确认槽位、待澄清冲突项、中途改口修正状态、旁人插话过滤状态）与定长对话页链（FIFO 缓冲）；③ 当轮通过检索（Retrieval）从三类长期记忆中召回并过滤拼装后的活跃记忆上下文。会话结束后，工作记忆中的有效信息通过学习写回（Learning）沉淀至长期记忆，自身随会话终结而释放。
  • 长期记忆 ①（Long-Term）—— 2. 语义记忆（Semantic Memory，事实记忆—语义层，解决“用户平时稳定要什么、口语怎么对应标准字段”）：脱离单次具体事件背景、跨周期长期稳定的客观事实与常驻偏好（What is true）。记录用户的静态身份与套餐权益、长期周期作息习惯（periodic_preference，如工作日午间固定直播时段）、分场景常驻网络偏好与体验三档底线（scene_preference，如常驻基地与高铁移动会议）、服务与应用映射（service_to_app）、个性化表述映射（expression，如“小破站开播”对应 bilibili:openlive）以及基础默认档位（preferred_value）。隐式行为需经中期候选池跨周期累积达标（满足跨度 \(W_{\text{span}}\) 与得分阈值 \(\theta_{\text{long}}\)）后晋升生效；档位升级时采用双时间戳接替（旧记录标为 superseded）；长期未触发按遗忘曲线自然衰减。
  • 长期记忆 ②（Long-Term）—— 3. 情景记忆（Episodic Memory，事实记忆—情景层，解决“过去具体发生过哪些单据与事件、当前处于什么阶段性情境”）：绑定具体时间戳与时空背景的过往具体事件记录、历史单据流水与阶段性状态（What happened & when）。包含两部分内容：① 历史保障单据记录与网元实际运行结果（episodic_order_record）：原样保存过去每次实际执行过的保障单据（单号 SerialNo、执行日期、地点、CGI、起止时间、保障参数）与实际运行结果（AppQuality=good/bad），按单号逐笔原样追加、不跨单合并为平均习惯、不随时间衰减，用于按时间、地点或运行结果好坏精确回溯特定历史单据（如“照上周六在奥体没卡那次来”）或叠加改期平移；② 阶段性事件窗与带有效期 TTL 的临时偏好（episodic_event_preference）：记录异地差旅/赛事事件窗、短期临时降档/省流偏好（带到期时间 TTL）、历史主动诉求（active/closed）与当面显式纠正记录，在有效期内局部覆盖常驻语义记忆，到期后自动标为 expired 失效回退。
  • 长期记忆 ③（Long-Term）—— 4. 程序化记忆 / 经验记忆（Procedural / Experiential Memory，解决“遇到特定无线场景或歧义情况时，系统该怎么调参与处置”）：关于“如何执行动作、流程与调参规则”的显式程序化知识（How to do，对应 CoALA 中的显式程序化记忆 Explicit Procedural Memory）。记录从短期工作记忆的慢路径多轮澄清对话以及长期情景记忆的正反单据（bad 与 good）对比中提炼的网络问题因果调参规则（触发条件 Condition → 问题根因 Cause → 参数调整规则 Action → 预期结果 Outcome）、同地多单消歧处理流程（Workflows）与交互免打扰策略，显式绑定适用与不适用范围（scope.exclude），供后续同类场景直接召回复用。
短期记忆（工作记忆）与三类长期记忆（语义、情景、程序化/经验）的分层管理原则

1. 读写隔离（Retrieval & Learning 双通道）：大模型在单步推理时只直接读取短期工作记忆（Working Memory）；长期语义记忆、长期情景记忆与长期程序化（经验）记忆存储在外部 SQLite + 向量数据库中，必须通过混合检索（Retrieval）按需筛选并拼装加载进短期工作记忆后才能参与当轮推理；会话与单据执行产生的反馈则通过异步学习（Learning）从短期工作记忆写回或经中期候选池晋升至三类长期记忆。

2. 三类长期记忆分表独立更新：长期语义记忆靠跨周期重复累积达标晋升并按双时间戳新旧更替；长期情景记忆中的历史单据按单原样追加、不合并、不衰减，阶段性临时偏好按 TTL 到期失效；长期程序化（经验）记忆靠后续单据的实际运行结果（AppQuality 好坏）持续升降置信度。分表存储、独立更新，才能避免单次临时变动或单笔异常单据污染常驻语义习惯。

5 记忆从短期到长期的演变机制

5.1 北邮 MemoryOS（arXiv:2506.06326）的三级演变机制：STM → MTM → LPM

短期记忆（单次对话、单张实时单据）不能直接等同于长期记忆，否则单次偶发改期或基站故障异常单据会污染用户的长期习惯。北京邮电大学与腾讯 AI Lab 联合提出的《Memory OS of AI Agent》（MemoryOS, arXiv:2506.06326）借鉴操作系统的分层内存管理思想，将 Agent 记忆划分为短期记忆（STM） → 中期记忆（MTM） → 长期个人记忆（LPM）三级架构，其核心流转机制如下：

  1. ① 短期记忆（STM）：对话页 + 对话链 FIFO 缓冲。系统把每一轮问答封装为一个“对话页（page = {Q, R, T, meta_chain}）”，放入定长 FIFO 队列（如容量为 7 页）；若前后页语义连贯，则自动串联成“对话链”并生成链级摘要。当定长队列满时，按先进先出（FIFO）将最老的对话页弹出，移交至中期记忆（MTM）。
  2. ② 中期记忆（MTM）：操作系统“段页式（Segmented Paging）”话题聚合。借鉴 OS 段页式内存设计——“段（Segment）”对应话题摘要，“页（Page）”对应该话题下的具体对话页。当新页从 STM 滑入时，计算向量余弦相似度与关键词 Jaccard 重合度；若超过阈值（如 0.6）则归并入已有话题段累积证据，否则开辟一个新话题段。
  3. ③ 长期个人记忆（LPM）：热度分（Heat）驱动晋升与累积清零。系统为每个中期话题段维护一个综合热度分：Heat = α·被检索次数 + β·段内累积页数 + γ·时间衰减 exp(−Δt/μ)。当段数超限时优先淘汰 Heat 最低的冷段；一旦某个话题段的 Heat > 5（越过晋升阈值），大模型便从该段中提炼出长期事实（写入 User KB）与 90 维偏好特征（写入 User Traits），随后将该段的累积页数清零使热度回落，防止同一批证据被重复提炼。

6.1 经验学习领域的 5 篇代表性论文与核心工作

在 CoALA 的三类长期记忆中，长期语义记忆与长期情景记忆记录“用户平时要什么、过去发生过什么单据”，而长期程序化 / 经验记忆（Procedural / Experiential Memory）记录“遇到特定场景或歧义情况时，系统该如何调参与执行消歧流程”。经验记忆要学习的是具备可迁移性的因果规则：在什么条件下（Condition）、因为什么原因（Cause）、该做什么参数调整动作（Action）、调整后执行结果如何（Outcome）。智能体经验学习方向的 5 篇代表性论文及其核心工作见表 6.1。

7.1 静态剧本回放的局限与在线交互模拟四环节流程

评测多轮记忆与意图 Agent 的难点在于：被测 Agent 每一轮的回复是动态生成的（可能走快路径第 1 轮直接出单，也可能走慢路径追问不同槽位）。静态剧本回放（预设固定多轮台词 U1 → U2 → U3）存在三方面问题：① 次轮台词固定导致答非所问（不管 Agent 上一轮实际问了什么，都机械喂入写死的 U2）；② 测不出漏问与快慢路径分流（若被测 Agent 第 1 轮漏问了“画质”只问了“时长”，写死的 U2 仍会把画质和时长一起报出来，掩盖漏问缺陷；若 Agent 命中经验记忆第 1 轮已闭环，静态回放还会继续强行喂入 U2）；③ 只看终态字面、不查证据来源（无法区分槽位是真从历史记忆中检索出来的，还是模型凭空猜对的）。
