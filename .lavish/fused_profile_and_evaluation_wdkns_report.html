1 故事线的正交因子方法论（排布层 × 内容层 MECE 解耦设计）

1.1 业界长程合成数据的痛点与“两层 MECE 正交解耦”设计思路

评估具备长期记忆与多轮意图理解能力的智能体（例如面向移动网络体验保障的联接 Agent），关键问题在于构造跨度数周至数月、同时包含自然语言对话与网元结构化单据的高拟真长程测试轨迹，并确保合成出的轨迹能够全面覆盖下游记忆萃取（偏好抽取、合并更新、分场景组织、画像生成、噪声抑制）与记忆检索（直接、排序、条件、排除、组合、缺失拒答）的全部考核点。

早期的合成数据管线通常在代码里写死几套固定的剧本模板，或者将所有控制变量平铺在同一张一维表里。这种做法存在三个明显问题：第一，“宏观时间线怎么排布”与“每个事件填什么业务内容”紧耦合，调整干扰密度或主支线穿插方式时往往牵一发而动全身；第二，同层因子之间存在父子条件依赖或跨层语义重复（不够正交）——例如将受限于时间窗口的“事件规模”与“时间跨度”平铺并列，将仅在存在支线时才生效的“支线归宿”与“事件线结构”并列，或在排布层与内容层重复定义“偏好演进”与“闲聊干扰”；第三，评测盲区漏测，缺乏对负向排斥偏好、短期临时偏好过期、未提及属性拒答边界以及闲聊、试探、情绪发泄、单次偶发等非偏好噪声的系统化因子控制。

综合 2024–2026 年 PersonaMem-v3、LoCoMo、DynamicMem、MemoryAgentBench 与 LongMemEval 等基准的合成思想，并遵循 MECE（相互独立、完全穷尽）原则，我们将故事线生成拆分为“排布层 + 内容层”两层结构（图 1）：

  • 第一层定排布（时间线与主支线结构）：控制整条时间线的总时长、事件规模与密度、主支线结构、跨期变化趋势、跨会话因果关系与测试点安排；其中受父级条件约束的属性（如1. 时间跨度下的1.1 事件规模与1.2 事件密度，3. 事件线结构下的3.1 支线触发事件与3.2 支线归宿）作为对应主因子的子因子采样。
  • 第二层定内容（业务画像属性与信息表达方式）：按“用户级 → 线级 → 节点级”三种取值粒度，无重叠地覆盖用户身份与资产、应用与业务行为、时空轨迹与流量、网络环境与 KQI 偏好、信息来源与噪声干扰、多轮交互与反馈纠正六个方面。

• 3. 事件线结构 + 3.2 支线归宿（转新主线/周期复现）：构造居家与办公/出差并行 → 测分场景独立组织存储（不串味）；
• 4. 跨期变化趋势（平稳/迁移覆盖/弃用）：构造同义重复或跨期换机升档 → 测同义合并去重、新值（active）覆盖旧值（superseded）及新旧排序；

二、事实记忆
— 情景记忆
（Episodic Memory）		 解决“用户在特定时间窗发生过什么阶段性事件与反馈”：绑定具体时间窗的外部日程变故（搬家、出差、节假日、大型赛事）、带有效期的短期临时偏好（到期失效不覆盖常驻语义记忆）、以及历史主动诉求（active / closed）、满意度情绪变化与当面显式纠正记录。 • 3.1 支线触发事件（搬家/赛事/出差） + 3.2 结束后回原主线：插入短期事件窗口 → 测临时偏好按时间窗隔离存储、到期自动回退不污染常驻记忆；
• 4. 跨期变化（多次波动与纠正后改回）：编排诉求跟进与多次纠正时序链 → 测诉求闭环更新与最新纠正时序覆写；
• 6.2 证据间隔 + 6.3 干扰占比：穿插不同比例背景会话 → 测抗干扰过滤与长程回忆。 		• 短期临时偏好与阶段状态（因子 13、5.1、7）：填本周/假期/出差临时要求（设未过期、已过期、混合状态）与月底流量吃紧 → 测未过期排已过期前、阶段条件召回、“流量紧+游戏卡”省流保时延组合推理、以及全部过期时主动说明；
• 历史主动诉求、情绪与显式纠正（因子 16、18）：填提速/换套餐诉求（active/closed）、情绪轨迹（不满→改观）与当面纠正（标 source=corrections） → 测诉求重申合并、新诉求关闭旧诉求、最新纠正优先排序、排除已纠正/已撤销项、以及“不满+诉求+偏好”组合安抚方案；
• 对话侧非偏好噪声（因子 15）：穿插日常闲聊、假设试探（“如果换千兆…”）、纯情绪抱怨与单次偶发行为 → 测噪声抑制（防 FP 误记，闲聊/试探/偶发不入正式库，情绪只记入反馈），且仅存试探/偶发时查询常驻偏好如实拒答。
三、工作记忆
（程序化记忆）
（Working / Procedural Memory）		 解决“用户过去具体办过哪些单、实测结果怎样，以及如何复用/改期/消歧”（见表 4.1）：原样保存每张历史保障工单台账（日期、时间段、地点、应用、时长、参数）与网元单据执行回执（实测时延丢包、顺畅或卡顿 AppQuality）及改期记录，按时间追加、不合并；支撑跨会话指代老单据、改期平移与同地多单消歧。 • 1.2 事件密度（忙闲交替/前密后疏）：生成带精确日期与起止时间戳的工单流水 → 测工作记忆台账按时间原样追加、不合并、不衰减；
• 6.1 单据配比 + 6.2 证据间隔（5~35步）：拉远历史工单与当前指代提问的跨会话距离 → 测跨多轮精准找回历史老单据。 		• 单次工单并发与随机时长（因子 4.1、4.2）：填单业务/双并发及 15~240min 连续随机时长 → 测单次工单完整槽位的原样记录与同行槽位提取；
• 网元单据实测回执与废单清洗（因子 10、11、15）：在 CSV 单据回执中标注顺畅正例单（AppQuality=good）与多类业务卡顿单（AppQuality=bad），同地埋入顺畅单 SN_A 与卡顿单 SN_B，并混入 1~8min 废单 → 测入库过滤废单、直接调取工单回执、以及多类卡顿按严重度（游戏>直播>会议>视频）排序召回；
• 跨轮历史单据指代与改期平移（因子 17）：构造按时间/地点/“没卡那次”指代并叠加“推迟半小时”改期，或同地多单模糊指代 → 测条件与排除召回（排除卡顿单 SN_B、命中顺畅单 SN_A）、同行参数提取与改期平移、以及同地多单/虚假单主动反问消歧。
四、经验记忆
（Experiential Memory）		 针对多轮澄清、用户纠正或初次排障失败后改参成功的 Case，提取适用条件 → 歧义/原因 → 澄清结论/调整动作 → 结果因果关系。
注：给定 Case 提取因果关系本身很直接，核心难点在于“如何在长程流中定位这些源头 Case，以及后续换说法时如何找准相关 Case 复用”。		 • 5. 跨会话因果关系 + 6.2 证据间隔 + 6.3 干扰占比：把“初次偏差/卡顿 → 慢路径澄清纠正”埋入大量日常快路径会话与闲聊干扰中 → 测从长程混杂流中定位并串联出慢路径源头 Case 的能力；
• 3. 事件线结构（主支线切换）：前序澄清放在支线 A（如鸟巢演唱会），后序请求放在同类支线 B（工体球赛）或异类主线（居家看球） → 测跨地点找准同类 Case 与异类场景隔离。 		• 构造混杂流中的慢路径源头 Case（因子 17 缺参追问 + 18 显式纠正 + 10/11 正反单据对比 + 15 试探噪声）：埋入“多轮追问才敲定参数”、“初次推荐被纠正”或“前单 bad 改参后 good”的闭环片段，同时混入未达成结论的假设闲聊 → 测源头 Case 识别与因果提取：能否从海量普通会话中精准揪出已闭环的慢路径 Case 提取因果规则，且不把未闭环试探误当经验；
• 构造“换说法/换具体地点、但底层同场景”的正向测试 Case（因子 5 场景层级 + 8.1/10.1 互斥与拥塞 + 12.2 口语换词）：前序在“鸟巢演唱会”澄清沉淀了高密弱覆盖场馆预热切片经验，后序用户改口说“周末去工体看球顺便开播” → 测相关经验 Case 泛化召回：能否跨越字面地名差异，按“人流聚集场馆+上行推流”底层条件找准该条经验，1 轮快路径直接闭环；
• 构造“字面相似、但底层条件不符”的负向干扰 Case（因子 5 场景切换 + 9 覆盖环境）：后序用户在“家里千兆宽带”说“今晚在家看球赛直播”（字面同含看球直播，但无弱覆盖拥塞） → 测经验适用边界过滤：识别底层条件不符、主动排除场馆降画质经验，防止不匹配经验误导。

1.5 两层组合规则、配置表结构与跨 3 个月完整组合示例

第一层排布因子与第二层内容因子组合为具体故事线时，遵循以下工程规则：

  1. 先定时间线结构，再按三级粒度填内容：先从第一层采样得到时间线结构；再按取值粒度填第二层——“用户”级因子整条故事线取一次，“线”级因子每条事件线取一次，“节点”级因子每个事件节点独立取一次。
  2. 主从层级条件采样（消除父子条件冲突）：按照“先采样主因子，再在其范围内采样对应子因子”的顺序执行。例如先定1. 时间跨度，再定与之匹配的1.1 事件规模与1.2 事件密度；仅当3. 事件线结构包含支线时才采样3.1 支线触发事件与3.2 支线归宿；仅当10. 网络异常 ≠ 无异常时才采样10.1 异常发生阶段。
  3. 声明式合法性约束（不写死在代码分支中）：只排除物理或逻辑冲突的组合，并统一声明在配置表的 constraints 列表中（例如排除“时间跨度 2 周 × 按月周期规律”、“平稳保持型节奏 × 套餐跨期升降级”、“仅网元单据体现 × 对话显式直接陈述”）。
  4. “先答案后会话”反向真值绑定与分阶段构建策略：前期与中期采用“先定义答案、再反向生成会话”路线（参照 LongMemEval、DynamicMem、PERMA）：① 先定义评测骨架（测试维度 × 测试目的 × 难度分布）→ ② 先写出结构化标准答案（萃取侧写明 gold_profile 的生效值、过期值、来源与置信度，检索侧写明 gold_answer 与 gold_memory_ids）→ ③ 按成对覆盖（Pairwise Coverage）采样两层因子，反向生成能唯一推导出该答案的自然语言对话与网元结构化单据序列 → ④ 通过多 LLM 交叉验证检验对话自然度与答案唯一性；到后期上线阶段再结合“先有真实会话、后抽检标注答案”路线（参照 LoCoMo、MemoryAgentBench）补充长尾边界样本。
  5. 平滑横向扩展：后续若需新增测试维度，只需在对应因子类别下新增主因子或子因子定义，不影响已有因子与已生成数据。
真实组合示例：跨 3 个月“主线居家直播 + 支线异地场馆推流”的两层因子取值示例

1. 第一层排布因子取值：1. 时间跨度 = 3 个月 → 1.1 事件规模 = 中（18 个节点） & 1.2 事件密度 = 忙闲交替；2. 起始状态 = 冷启动；3. 事件线结构 = 主线 + 1 条支线 → 3.1 支线触发 = 大型赛事展会/出差 & 3.2 支线归宿 = 周期性复现；4. 跨期变化趋势 = 单次迁移覆盖型；5. 跨会话因果关系 = 1 条完整闭环；6. 测试编排 → 6.1 单据与对话配比 = 75 : 25、6.2 间隔 = 中（5~15 步）、6.3 干扰 = 中。

2. 第二层用户级与线级因子取值：

  • 用户级（全局取一次）：1. 职业身份 = 游戏主播，2. 终端组合 = 华为手机（主）+ iPhone（备），3. 套餐档位 = 1000M → 2000M（跨期升级），12.2 措辞映射 = 口语体感词（“极致丝滑”→30ms、“高清”→1080p）；
  • 主线（日常居家）：4. 应用与业务 = 抖音/B站上行直播，5. 活动空间 = 家（固定静止），6. 活跃时段 = 晚高峰 19-23（按日规律，±10min），7. 流量与上下行比例 = 超大流量（>5G）+ 上行主导，8. KQI 要求 = 带宽 ≥100M、丢包 ≤0.1%；
  • 支线（周末异地场馆）：4. 应用与业务 = 户外赛事直播 + 微信语音，5. 活动空间 = 户外/人流聚集场馆，6. 活跃时段 = 周末下午，8. KQI 要求 = 时延 ≤30ms（8.1 允许画质降级保时延），9. 覆盖环境 = 边缘弱覆盖。

3.2 核心指标的判分逻辑与精简算式表达

阶段 1 的抽取召回率与误抽率、阶段 2 的召回率及阶段 3 的克制率均为直观的比例统计（命中样本数除以总样本数）。全流程中保留两个核心算式：一是阶段 2 衡量“最新生效记录有没有排在旧记录/异常单前面”的时效分级排序分 NDCG@k；二是阶段 3 衡量“红线一票否决与三层记忆顺应”的受控决策得分 Score。

第一，在阶段 2 的排序评估中，当工作记忆存在同地多单冲突（如上周六在鸟巢既有下午顺畅单 SN_A、又有晚上卡顿单 SN_B）或事实记忆新旧交替时，即便两条记录都进入前 5 条，若卡顿单或过期旧记录排在第 1 位，下游模型仍易误用错误参数。因此按分级相关度 $\text{rel}_i$（当前生效事实/目标正常工单/对应经验卡 $\text{rel}=2$，辅助关联记录 $\text{rel}=1$，过期旧记录或体验异常卡顿单 $\text{rel}=0$）计算折损累计增益：

$$\text{DCG}@k = \sum_{i=1}^{k} \frac{2^{\text{rel}_i} - 1}{\log_2(i + 1)}, \qquad \text{NDCG}@k = \frac{\text{DCG}@k}{\text{IDCG}@k}$$
  • $\text{rel}_i$：检索列表第 $i$ 位结果的相关度等级（生效正例最高，过期或异常单据强制归零）；
  • $\text{IDCG}@k$：将所有生效正例排在最顶部时的理想最大 $\text{DCG}@k$；
  • 核对：当周六鸟巢的正常单 SN_A 与重叠消歧经验卡排在第 1、2 位，而卡顿单 SN_B 排在第 3 位时，正例占据最前位置，$\text{NDCG}@5 = 1.00$；反之若卡顿单排第 1 位，第 1 位的分子 $2^0 - 1 = 0$，总分立刻大幅折损。

第二，在阶段 3 的决策评估中，借鉴 PersonaMem-v3 的两步判分逻辑，引入一票否决指示项 $\mathbb{I}(V_{\text{veto}} = 0)$ 与槽位/动作满足度相乘：

$$\text{Score} = \mathbb{I}(V_{\text{veto}} = 0) \cdot \frac{|\hat{S} \cap S^*|}{|S^*|}$$
  • $V_{\text{veto}} \in \{0, 1\}$：一票否决红线标志。凡是套用已过期事实档位、照搬工作记忆中体验异常（卡顿/掉帧）单据的参数、未澄清便盲目抢跑下发冲突单、或违规刺探无关隐私，均令 $V_{\text{veto}} = 1 \implies \text{Score} = 0$；
  • $S^*$ 与 $\hat{S}$：分别为标准答案要求满足的“事实记忆补全槽位 + 工作记忆指代槽位 + 经验记忆调整动作”集合与系统实际输出集合。

4 记忆要记什么：三层记忆分工与按决策环节分解（以网络保障为例）

4.1 事实记忆、工作记忆与经验记忆解决什么问题及分库存储原则

以移动网络体验保障（联接 Agent）为例，记忆直接服务于下一次保障决策——减少重复追问、自动补全缺省参数、提前规避网络风险。按性质与更新规律，记忆划分为事实记忆、工作记忆、经验记忆三层：

  • 事实记忆（解决“用户说得少、说得不标准”）：用户平时发起指令时只说“照常开播”、“别卡”，往往省略了时间、地点、带宽与画质档位，且口语用词（如“小破站”）与后台单据标准字段对不上。由于用户的日常偏好稳定且反复出现，可从多次网元结构化单据和对话声明中归纳出周期习惯、默认参数档位、场景偏好、服务与应用映射、个性化表述映射及带有效期的临时偏好，用来自动补全缺省参数并将口语翻译成标准字段。
  • 工作记忆（解决“用户指代过去的某一次具体单据”）：当用户说“按上周六在鸟巢没卡那次来”或“把昨天那单推迟半小时”时，系统需要精确找到那一张历史工单。具体单据是已经发生过的客观事实，一旦被笼统归纳成平均偏好，就会丢掉当天具体时间、实测时长和“哪场顺畅、哪场卡顿”等关键细节。因此工作记忆必须原样保存每张历史工单台账与网元单据执行回执，按时间追加、不合并、不衰减；遇到同地多张不同体验单据时先触发反问。
  • 经验记忆（解决“把首次多轮澄清 / 理解失败变成后续一次快速闭环”）：遇到特殊场馆（如大型体育场赛事日）、多单重叠歧义或复杂诉求时，系统第一次往往理解失败（配错普通档位导致卡顿、或找错单据）或需要经过多轮反问澄清才能对齐。把首次慢路径对齐后的因果调参规则、处理流程与交互策略沉淀为经验记忆，下次再遇同类请求即可直接走快路径一次闭环。
三层记忆分库存储与独立更新的必要性

三类信息的证据门槛与更新方式不同：事实偏好需要多次重复确认（≥ 3 次）、且会随套餐升级而新旧更替；工作记忆中的历史单据是既成事实，任何时候不能合并篡改；经验规则要靠后续工单的执行回执（AppQuality 好坏）持续升降置信度。若将三者混在一个向量库里，容易把一次偶然的卡顿劣化单当成用户的长期偏好，或让一次下雨天的临时降画质覆盖掉常驻 1080p 习惯。分开存储、分开更新，才能各自保持准确。

5 记忆从短期到长期的演变机制（北邮 MemoryOS · 业界对比 · 四步演变逻辑）

5.1 北邮 MemoryOS（arXiv:2506.06326）的三级演变机制：STM → MTM → LPM

短期记忆（单次对话、单张实时单据）不能直接等同于长期记忆，否则单次偶发改期或基站故障异常单据会污染用户的长期习惯。北京邮电大学与腾讯 AI Lab 联合提出的《Memory OS of AI Agent》（MemoryOS, arXiv:2506.06326）借鉴操作系统的分层内存管理思想，将 Agent 记忆划分为短期记忆（STM） → 中期记忆（MTM） → 长期个人记忆（LPM）三级架构，其核心流转机制如下：

  1. ① 短期记忆（STM）：对话页 + 对话链 FIFO 缓冲。系统把每一轮问答封装为一个“对话页（page = {Q, R, T, meta_chain}）”，放入定长 FIFO 队列（如容量为 7 页）；若前后页语义连贯，则自动串联成“对话链”并生成链级摘要。当定长队列满时，按先进先出（FIFO）将最老的对话页弹出，移交至中期记忆（MTM）。
  2. ② 中期记忆（MTM）：操作系统“段页式（Segmented Paging）”话题聚合。借鉴 OS 段页式内存设计——“段（Segment）”对应话题摘要，“页（Page）”对应该话题下的具体对话页。当新页从 STM 滑入时，计算向量余弦相似度与关键词 Jaccard 重合度；若超过阈值（如 0.6）则归并入已有话题段累积证据，否则开辟一个新话题段。
  3. ③ 长期个人记忆（LPM）：热度分（Heat）驱动晋升与累积清零。系统为每个中期话题段维护一个综合热度分：Heat = α·被检索次数 + β·段内累积页数 + γ·时间衰减 exp(−Δt/μ)。当段数超限时优先淘汰 Heat 最低的冷段；一旦某个话题段的 Heat > 5（越过晋升阈值），大模型便从该段中提炼出长期事实（写入 User KB）与 90 维偏好特征（写入 User Traits），随后将该段的累积页数清零使热度回落，防止同一批证据被重复提炼。

① 核心内存（Core Memory / RAM）：常驻提示词的可编辑文本块（persona 块 + human 块）；

4. MemOS（上海 AI Lab）
（arXiv:2507.03724）		 按计算介质分三层：
① 激活记忆（Activation）：运行期 KV Cache 与短期状态；
② 明文记忆（Plaintext）：外部文本、图谱与规则块；
③ 参数记忆（Parametric）：LoRA / 模型权重。		 用统一容器 MemCube（带来源、版本号、访问频次与权限）封装记忆：短期上下文中的高频明文知识先提升为可复用的激活缓存（KV 状态）；经过长期高频调用、验证稳定的用户固定习惯，进一步通过微调蒸馏内化为参数记忆。 由调度器（MemScheduler）监控访问频次与衰减率：低频过期的从激活层降级回明文层或归档淘汰，带版本号控制回滚。
5. MemoryBank / A-MEM
（2305.10250 / 2502.12110）		 • MemoryBank：原始对话日志 + 每日事件摘要 + 全局用户肖像。
• A-MEM：仿卡片盒笔记法（Zettelkasten）的双向链接卡片网。		 • MemoryBank：按艾宾浩斯遗忘曲线 R = exp(−t / S) 演化——初建记忆强度 S=1，每次被重新提及或召回命中则 S + 1 且时间 t 清零，多次强化后升入长期肖像。
• A-MEM：新记录先生成带标签的结构化卡片，再自动与历史卡片建链并反向更新旧卡片的上下文描述。		 MemoryBank 中单次偶发且长期未被召回的条目随 exp(−t/S) 自然跌破阈值被遗忘；A-MEM 通过反向更新旧卡片总结避免旧卡片语义脱节。

6.1 经验学习领域的 5 篇代表性论文与核心工作

事实记忆记录“用户要什么”，经验记忆记录“遇到特定场景或歧义情况时，系统该怎么做”。经验记忆要学习的是具备可迁移性的因果规则：在什么条件下（Condition）、因为什么原因（Cause）、该做什么参数调整动作（Action）、调整后执行结果如何（Outcome）。表 6.1 梳理了学术界在智能体经验学习（Experiential Learning）方向具有代表性的 5 篇经典与核心论文。

7.1 静态剧本回放的局限与在线交互模拟四环节流程

评测多轮记忆与意图 Agent 的难点在于：被测 Agent 每一轮的回复是动态生成的（可能走快路径第 1 轮直接出单，也可能走慢路径追问不同槽位）。传统的“静态剧本回放（写死多轮台词 U1 → U2 → U3）”存在三个缺陷：① 次轮台词固定导致答非所问（不管 Agent 上一轮实际问了什么，都机械喂入写死的 U2）；② 测不出漏问与快慢路径分流（若被测 Agent 第 1 轮漏问了“画质”只问了“时长”，写死的 U2 仍会把画质和时长一起报出来，掩盖漏问缺陷；若 Agent 命中经验记忆第 1 轮已闭环，静态回放还会继续强行喂入 U2）；③ 只看终态字面、不查证据来源（无法区分槽位是真从历史记忆中检索出来的，还是模型凭空猜对的）。

交互式评测采用受控在线交互模拟（Controlled Online Interactive Simulation）：用户模拟器持有完整目标意图，第 1 轮只说模糊诉求；后续轮次严格根据 Agent 实际追问的槽位动态回答（按问给值：问什么才答什么，没问到的隐藏槽位绝不提前吐露）。整个评测闭环由环节 ① 双端物理信息隔离、环节 ② 受控交互循环、环节 ③ 全轨迹中间态采集、环节 ④ 确定性规则为主算分四个环节组成（图 7）。

（对应阶段 3）		 7. 有依据终态准确率
（含一票否决红线）		 单个会话得 1 分必须同时满足 4 个条件：

③ 时间算术自洽（结束时间 − 开始时间 == 保障时长）；
