一、三种长期记忆的核心定位与生命周期闭环（面向意图理解 Agent）

围绕用户提出的“解决什么问题 → 输入/输出/存储 → 生成/更新/检索/遗忘/删除（算法与触发时机）”框架，对情景、语义、程序三类长期记忆进行完整设计。

情景记忆Episodic Memory

  • 解决的问题：解决“过去何时何地发生过什么具体交互与意图演化”的可追溯问题（如临时改口背景、某次保障为何成功或被撤销），同时作为语义晋升与经验蒸馏的原始证据底座。
  • 触发与输入：时机：每次会话结束（或网元单据到达）后异步触发。
    内容：用户与 Agent 交互对话、结构化意图模板、意图状态变化（变更/撤销）、调用的外部资源（RAG、记忆、业务规则）。
  • 标准输出：标准化事件表达（时间、地点/场所、用户、起因[诉求/改参/撤销]、经过[理解轨迹与调用资源]、结果[最终意图模板与闭环状态]）。
  • 存储形式：结构化 JSON/表节点（含时间戳与外键）+ 经过语义文本正文。
  • 生成算法：时机：会话结束即生成。
    算法：时间/起因/结果走模板确定性填充；“经过”由单次 LLM 摘要生成；多粒度（日/周）则在无重叠时间窗结束时压缩提炼。
  • 更新算法：单次事件生成后原则上不改写内容；周期摘要在无重叠窗口内有新事件加入时增量刷新；若用户明确纠错则打标纠错版本。
  • 检索算法：时机：回答“上次/某天做了什么”或需要追溯某条偏好依据时触发。
    算法：先按时间范围与主体精确过滤，再结合关键词/向量召回事件或时间线摘要。
  • 遗忘机制：艾宾浩斯保留率 $R(t,n)$ 随时间自然衰减；超期且已被周期摘要覆盖的细粒度流水降权归档，不再进入热检索池。
  • 删除机制：支持用户显式遗忘指令：按时间/主题/外键精准删除目标事件记录，并增量重算受影响的周期摘要（不暴力度重写全量摘要）。

语义记忆Semantic Memory

  • 解决的问题：解决“用户当前稳定的习惯、个性化表达与默认参数是什么”，在用户输入缺失或模糊时直接补全槽位，支撑快速闭环（减少不必要反问）。
  • 触发与输入：时机：① 对话中用户显式长期声明（“以后默认…”）立即触发；② 后台定时扫描近期情景事件。
    内容：结构化意图槽位（应用、业务、时段、场景、QoS 参数、表达别名）及来源事件 ID。
  • 标准输出：强类型正交偏好条目（含唯一主键 `user_id + scope + slot`、当前值、有效状态、生效/失效双时间戳与 `evidence_event_ids`）。
  • 存储形式：六张正交关系表（如 `expression`、`preferred_value`、`periodic_preference` 等）+ 向量/FTS5 派生索引。
  • 生成算法：时机：显式声明即时生成；隐式习惯需在时间窗 $W_{\text{span}}$ 内跨会话复现达 $N_{\min}$ 次才晋升生成。
    算法：先写入 `candidate`，投票达标后晋升 `active / reinforced`。
  • 更新算法：时机：新结论落入同一正交主键格子时。
    算法：确定性查表比对——同值则支持度 `+1`；异值（用户改口）则旧版标 `superseded` 写 `invalid_at`，新建新版指向旧版。
  • 检索算法：时机：每轮意图理解前必查。
    算法：个性化表述展开 → 周期/业务两跳补全 + 同行槽位列读取 → 过滤 `superseded` 与 `null` 空值边界 → 融合重排。
  • 遗忘机制：带复习稳定性的艾宾浩斯衰减 $R(t,n)$：极长期未使用的 `reinforced` 降级回 `active`（不再免确认直通）；超长未用转 `archived`；`expression` 词典衰减率为 0。
  • 删除机制：支持显式删除指定偏好或全部某场景习惯，同时清理派生向量索引并保留审计删除记录。

程序记忆（经验记忆）Procedural Memory

  • 解决的问题：解决“遇到信息缺失、冲突或模糊输入时，Agent 怎么提问和确认才能更快闭环、减少多轮澄清轮次”（区别于底层只读源码，聚焦业务级交互策略）。
  • 触发与输入：时机：多轮澄清会话结束（特别是经历 2 轮以上澄清、用户纠偏或最终快速收敛的交互）。
    内容：初始模糊/缺失槽位、Agent 澄清提问序列、用户反馈、最终收敛轮次与成败状态。
  • 标准输出：`ReasoningBank` 风格三段式澄清策略条目（`Title` + 含适用/禁用边界的 `Description` + 1～3 句可迁移澄清策略 `Content` + 来源切片核验）。
  • 存储形式：结构化策略条目（`strategies/`）+ 反向切片后的精简难例（`raw_cases/`）+ 固定规则硬固化为 Python 校验函数。
  • 生成算法：时机：澄清难例积累或成败对照完成时。
    算法：`SPEM` 终点反向切片去废步 → `ReasoningBank` 成败双源对比蒸馏（仅成功或成败配对可建新策略，失败负保护禁止单独建模板）。
  • 更新算法：时机：新经验入库或积累 $K_{\text{review}}$ 个反馈案例时。
    算法：`WASP-Mem Free Form` 先读后写隐式归并（增补澄清分支或新建）；采用后若仍拉长轮次或被否定则单次曝光降权。
  • 检索算法：时机：受挫门控（常规快速闭环不注入；仅当多轮未收敛、用户连续否定或冲突难判时触发）。
    算法：按当前澄清状态向量匹配并严格限流注入 **Top-1**（先核验适用/禁用边界）。
  • 遗忘机制：基于使用胜率与时间的 EMA 可靠性衰减：长期未触发或被新澄清策略替代的条目自动降权归档。
  • 删除机制：支持按策略 ID 驱逐错误自举策略，或因业务规则变更批量下线废弃澄清策略。
