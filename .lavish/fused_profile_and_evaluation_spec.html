一、故事线的正交因子（两层）

故事线分两层生成：第一层定排布，决定整条时间线的骨架；第二层定内容，给骨架上的每条线、每个节点填入具体属性。每个因子都是配置表中的一列（可取值 + 采样权重），同层因子相互独立，组合后交给大模型 API 批量出素材。

第一层：故事线排布（12 个因子）
分三组：时间轴骨架、事件结构、测试编排。
第二层：故事线内容（30 个因子）
分七组：用户、业务、时空、网络、记忆演化、交互、单据质量。
大模型 API 生成素材
按“骨架 + 节点因子”生成用户档案、CSV 单据序列和对话，再由状态机推演出标准标签。

3. 怎么组合

  • 先排布，再填内容：先从第一层取值得到时间线骨架；再按取值粒度填第二层——“用户”级因子整条故事线取一次，“线”级因子每条线取一次，“节点”级因子每个节点取一次。
  • 同层正交采样：同一层内各因子独立取值，每个取值带采样权重。
  • 少量合法性约束：只排除冲突组合，写在配置表里，不写死在代码分支中。例如“跨度 2 周 × 按月规律”、“迁移型节奏 × 稳定保持”、“4G 旧机 × 切片保障”、“仅单据体现 × 明确要求记住”。
  • 覆盖要求：参照组合测试的成对覆盖做法，保证任意两个因子的取值两两都至少出现一次，不穷举全部组合。
  • 扩展方式：新增因子只需在对应分组下加一列，不影响已有因子与已生成数据。

• 单用户跨度数月至近 1 年（单人 50 万~100 万 tokens）；误导题先在第 τ 天埋入负向限制状态，间隔数天至数周日常会话后再发出冲突请求。 		• 检索阶段（Recall@k，k=5/20/50）：因为每个问题都绑定了生成时的原子证据点 b_τ 和外部文档块 ID，直接统计标准证据块有百分之多少落在 Top-k 中。
• 生成阶段普通题（确定性实体核对）：答案被限制为唯一具体实体（日期、人名、符合条件的次数），核对实体是否一致。
• 误导与幻觉题（两步判分）：第 1 步看有没有识破错误前提或状态冲突（顺着冲突请求执行直接 0 分）；第 2 步看有没有指出真实历史状态并给替代方案。

因果事件图 + 线索-触发字面脱钩六步嵌入		 • LoCoMo：用带因果有向边的时序事件图控制跨月剧情，每次切一个子图生成一轮会话。
• LoCoMo-Plus（六步嵌入管线）：① 生成 2 轮隐式线索短对话 c_0 → ② 人工筛出有持续约束力的 c_1 → ③ 生成字面脱钩的触发提问 q 并绑定时间间隔 t → ④ 算法过滤高相似配对 → ⑤ 二次唤醒校验 → ⑥ 按间隔 t 插入长对话。 		① 记忆定性：Level-1 跨会话事件事实记忆 + Level-2 隐式认知约束记忆

② 线索长度与脱钩过滤阈值：
• 线索长度硬阈值：每条隐式线索固定为 2 轮（2 lines）对话，A 顺带流露记忆锚点，B 自然回应一句立即闭合话题。
• 双重低相似度过滤：触发句 q 严禁复用线索中的核心名词与动词，并用 BM25（词面重叠）+ MPNet（句向量相似度）双重打分过滤，自动淘汰词面或表层语义接近的候选。
③ 时间间隔安排（Temporal Gap t）：
• 长对话跨度数月、最多 35 个会话（约 300 轮、9K~16K tokens）；线索与触发强制间隔 t ≥ 1 周（1 周至数月不等），中间穿插数十至上百轮无关对话稀释。 		• LoCoMo（事实层）：简短事实问答算词级 F1 分数；不可回答题算拒答准确率。
• LoCoMo-Plus（三档隐式约束一致性）：淘汰字面 F1，改由裁判模型按是否遵守早期隐式约束判分——主动顺应约束/避开禁忌得 1.0 分；未踩雷但笼统得 0.5 分；违反历史约束得 0 分。
• 认知缺口（Cognitive Gap）：事实问答得分 − 隐式约束得分（主流模型普遍暴跌约 40 分）。

（2410.10813）
问题倒拆证据句 → 间接自博弈 → 背景池穿插		 • 数据底座：500 道人工精修测试题，配可自由伸缩的无关背景会话池（Haystack）。

② 证据拆解与位置控制阈值：
• 单题证据会话数：单跳/拒答题 1 条，知识更新题 2~3 条（旧状态 → 新状态），多跳统计题 2~6 条；强制间接流露（Indirect Conveyance），禁止用户直接宣布事实。
• 会话内深度均衡：截断修剪使证据句等比例落在单个会话的开头、中间、结尾。
③ 时间间隔与背景稀释规模安排：
• 设两档规模：LongMemEval_S 混入约 11.5 万 tokens（40~50 个会话），LongMemEval_M 混入 500 个会话（约 150 万 tokens）；按递增时间戳 t_1 < ... < t_N < t_q 排列（跨度数周至数月），在旧值与新值会话间塞入大量无关会话拉开间隔。 		• 检索阶段（Recall@k 与 NDCG@k）：按会话级或轮次级统计包含证据句的那条记录有没有进前 k 条、以及排在第几名。
• 阅读阶段（5 类问答准确率 QA Accuracy）：0/1 二值判分——特别是知识更新题必须答出最后一次修改后的最新值（答早期旧值直接 0 分）；未知拒答题面对虚假前提必须明确拒答（瞎编直接 0 分）。

阶段 1：记忆萃取与更新
（存得准不准）		 1. 画像与经验抽取 F1

2. 状态更新准确率

四、记忆要记什么（以网络保障为例）

记忆是为下一次保障决策服务的：记下来的东西要能让联接 Agent 少问一句、少错一个参数、提前避开一个问题。所以按“生成一张保障工单要经过哪些决策环节、每个环节缺什么信息”来倒推要记什么。

总结：三类记忆解决网络保障的什么问题

事实记忆：用户说得少、说得不标准
  • 问题：用户只说“照常开播”“别卡”，缺时间、地点、参数，用词也和单据字段对不上。
  • 怎么解决：记住周期习惯、默认档位和口语映射，自动补全参数、翻译成标准字段。
  • 为什么能解决：偏好是稳定且反复出现的，可以从多次单据和对话中归纳出来；要求重复出现才确认，能避免把偶发行为当成习惯。
工作记忆：用户指代过去的某一次
  • 问题：用户说“按上周六没卡那次来”“把昨天那单推迟半小时”，需要精确找到那张单。
  • 怎么解决：原样保存每张工单和执行回执，按时间、地点、体验好坏检索；同地多单时先反问。
  • 为什么能解决：具体单据是已经发生的事实，一旦归纳成偏好就会丢掉时间、实测时长和好坏这些细节，所以要逐条保存、不合并、不衰减。
经验记忆：把“多轮澄清 / 理解失败”变成“一次快速闭环”
  • 问题：遇到特殊场馆、多单歧义或复杂诉求时，系统第一次往往理解失败（配错档位/找错单）或需要多轮反问澄清。
  • 怎么解决：把首次“多轮澄清 / 理解失败被纠正”后对齐的参数调整规则与消歧流程记为经验，下次遇到同类请求直接走快路径一次闭环。
  • 为什么能解决：用户的纠正与多轮澄清已经把“什么场景该补什么参数、怎么避开理解偏差”讲清楚了，沉淀成规则后无需每次重走慢路径。

为什么分三类而不是放在一起：三类信息的更新方式不同——偏好要重复确认、会过时；单据是既成事实、不能改；规则要靠执行结果验证。混在一起会互相干扰，例如把一次卡顿单当成用户偏好，或者让一次临时改动覆盖长期习惯。分开存储、分开更新，才能各自保持准确。

  • 适用范围：全局、限定场景或地点、限定时段、仅本次。
  • 时效：生效时间、有效期或过期条件。
  • 置信度：随重复次数、回执验证结果升降。

五、记忆是如何从短期变成长期的？（北邮 MemoryOS · 业界对比 · 四步演变逻辑）

短期记忆（单次对话、单张实时单据）不能直接等于长期记忆，否则一次偶发改期或一次卡顿废单就会把用户画像污染。参考北邮与腾讯 AI Lab 的《Memory OS of AI Agent》（arXiv:2506.06326）以及业界主流团队（Claude Code、OpenAI Codex、Mem0、Zep/Graphiti、Letta/MemGPT、上海 AI Lab MemOS），“短期 → 长期”的核心逻辑是“短期定长缓冲 → 中期按主题聚合 → 靠热度/重复次数越过阈值晋升 → 长期冲突接替与冷衰减”。

1. 北邮 MemoryOS（arXiv:2506.06326）的三级演变机制：STM → MTM → LPM

① 短期记忆（STM）：对话页 + 对话链 FIFO
  • 存什么：把每一轮问答存成“对话页（page = {Q, R, T, meta_chain}）”，放进定长队列（如 7 页）；若前后页语义连贯则串成“对话链”并生成链摘要。
  • 怎么流转：队列满时，按先进先出（FIFO）把最老的对话页弹出，移交到中期记忆（MTM）。
② 中期记忆（MTM）：操作系统“段页式”话题聚合
  • 存什么：借鉴 OS 段页式内存——“段（Segment）”是话题摘要，“页（Page）”是该话题下的具体对话页。
  • 怎么归并：新页进入时算向量余弦相似度 + 关键词 Jaccard 重合度；超过阈值（0.6）就并入已有话题段，否则新建一个段。
③ 长期个人记忆（LPM）：热度分（Heat）驱动晋升
  • 晋升公式：每个段算热度 Heat = α·被检索次数 + β·段内累积页数 + γ·时间衰减 exp(-Δt/μ)。
  • 怎么升格与淘汰：段数超限时淘汰 Heat 最低的冷段；当 Heat > 5 时，大模型从中提炼出长期事实（入 User KB）与 90 维偏好特征（入 User Traits），随后将该段累积页数清零使热度回落，防止重复提炼。

（arXiv:2310.08560）		 仿 OS 虚拟内存两层：
① 核心内存（Core Memory / RAM）：常驻提示词的可编辑文本块（persona 块 + human 块）；
② 外部存储（Disk）：回溯对话表（Recall）与向量归档库（Archival）。		 上下文压力中断 + Agent 自主换页：短期对话在窗口内累积，当达到上下文容量告警线（如 70%）时触发系统中断（Memory Pressure Warning），Agent 自己调用 core_memory_append/replace 把关键事实写进常驻块，或调 archival_memory_insert 刷入外存，再把早期对话移出窗口。 核心内存块设固定字符上限，写满时由 Agent 自主重写压缩（core_memory_replace）；历史原始明细全部退入外存按需检索。
MemOS（上海 AI Lab / MemTensor）
（arXiv:2507.03724）		 按计算介质分三层：
① 激活记忆（Activation）：运行期 KV Cache 与短期状态；
② 明文记忆（Plaintext）：外部文本、图谱与规则块；
③ 参数记忆（Parametric）：LoRA / 模型权重。		 用统一容器 MemCube（带来源、版本号、访问频次与权限）封装记忆：短期上下文中的高频明文知识先提升为可复用的激活缓存（KV 状态）；经过长期高频调用、验证稳定的用户固定习惯，进一步通过微调蒸馏内化为参数记忆。 由调度器（MemScheduler）监控访问频次与衰减率：低频过期的从激活层降级回明文层或归档淘汰，带版本号控制回滚。
MemoryBank / A-MEM
（2305.10250 / 2502.12110）		 • MemoryBank：原始对话日志 + 每日事件摘要 + 全局用户肖像。
• A-MEM：仿卡片盒笔记法（Zettelkasten）的双向链接卡片网。		 • MemoryBank：按艾宾浩斯遗忘曲线 R = exp(-t / S) 演化——初建记忆强度 S=1，每次被重新提及或召回命中则 S + 1 且时间 t 清零，多次强化后升入长期肖像。
• A-MEM：新记录先生成带标签的结构化卡片，再自动与历史卡片建链并反向更新旧卡片的上下文描述。		 MemoryBank 中单次偶发且长期未被召回的条目随 exp(-t/S) 自然跌破阈值被遗忘；A-MEM 通过反向更新旧卡片总结避免旧卡片语义脱节。

六、经验记忆要学到什么

事实记忆回答“用户要什么”，经验记忆回答“遇到这类情况，系统该怎么做”。经验记忆学的是因果规则：在什么条件下、因为什么原因、该做什么调整、调整后结果如何，而不是某一次的具体参数。

1. 相关论文与核心工作

论文 核心工作
Reflexion（2303.11366） 把任务执行后的环境反馈信号转成文字反思（verbal reflection），存进滑动情景记忆，下一次尝试前直接读入上下文以修正行为。
ExpeL（2308.10144） 从一批尝试轨迹中自动收集成功案例与成对的成功/失败对比轨迹，用自然语言增删改提炼出通用结论（insights），推理时同时召回结论规则与相似成功轨迹。

经验跟随实证研究（2505.16067） 系统分析了检索到的历史经验如何影响当前输出：发现经验与当前输入越相似，模型越倾向于直接照搬，容易造成错误经验传播与不匹配经验误导；并提出用后续任务的执行结果作为经验质量的免费验证标签，过滤低质经验。

3. 来源、四类融合策略与关键口径

来源说明与融合策略（来源为 对话+CSV 时）
  • 对话：从 Agent 对话上下文抽取（意图/声明/诉求/纠正），无 CSV 真源；
  • CSV：从行为单据列聚合（证据），按 Gpsi 归用户；
  • 对话+CSV：双侧都有，按 4 类策略融合：
    1. A 单源继承：仅一侧有 → 直接取，无 CSV 支撑标 weak。
    2. B 主证据 + 辅校准：声明为主，用 CSV 分位数把档位校准到实测区间。
    3. C 双侧并存：意图与行为并列，声明与实测并列（∥），不覆盖。
    4. D 冲突仲裁：语义矛盾，意图/纯声明字段保留对话，行为/体验字段取 CSV 值，入 conflict_log。
关键口径与 CSV 24 列
  • CSV 是行为证据，不是偏好声明：偏好必须由行为归纳，冲突在融合阶段消除。
  • 无 GIS 时：地理 / 通勤字段降级为弱证据（仅小区 ID 频次，不做定性 OD）。
  • 体验档位推断：无 AvgQoe / MostResolution 列，体验档位由 DelayAn / DelayDn / 丢包 / Bandwidth / AppQuality 组合推断。
  • CSV 实测列（24 列）：SerialNo, TimeStamp, StartTime, Gpsi, Dnn, S_NSSAI, RatType, Qci, ExpOptFlag, ExpOptStartTime, AppId, SubAppId, AppStatus, AppQuality, Tai, CellId, DelayAn, DelayDn, UplinkBandwidth, DownlinkBandwidth, UplinkPkg, DownlinkPkg, LostUplinkPkg, LostDownlinkPkg, SubAppStartTime, InfoIndicate。
