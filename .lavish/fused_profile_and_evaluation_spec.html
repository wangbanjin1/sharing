一、故事线的正交因子（两层）

故事线分两层生成：第一层定排布，决定整条时间线的骨架；第二层定内容，给骨架上的每条线、每个节点填入具体属性。每个因子都是配置表中的一列（可取值 + 采样权重），同层因子相互独立，组合后交给大模型 API 批量出素材。

第一层：故事线排布（12 个因子）
分三组：时间轴骨架、事件结构、测试编排。
第二层：故事线内容（30 个因子）
分七组：用户、业务、时空、网络、记忆演化、交互、单据质量。
大模型 API 生成素材
按“骨架 + 节点因子”生成用户档案、CSV 单据序列和对话，再由状态机推演出标准标签。

3. 怎么组合

  • 先排布，再填内容：先从第一层取值得到时间线骨架；再按取值粒度填第二层——“用户”级因子整条故事线取一次，“线”级因子每条线取一次，“节点”级因子每个节点取一次。
  • 同层正交采样：同一层内各因子独立取值，每个取值带采样权重。
  • 少量合法性约束：只排除冲突组合，写在配置表里，不写死在代码分支中。例如“跨度 2 周 × 按月规律”、“迁移型节奏 × 稳定保持”、“4G 旧机 × 切片保障”、“仅单据体现 × 明确要求记住”。
  • 覆盖要求：参照组合测试的成对覆盖做法，保证任意两个因子的取值两两都至少出现一次，不穷举全部组合。
  • 扩展方式：新增因子只需在对应分组下加一列，不影响已有因子与已生成数据。

一、语法层
（Syntax）
句子结构与表层符号噪声		 1. 口语碎片化与主谓宾残缺 “上不去网、红灯、书房那个，快看下” 部分覆盖（常规口语改写集含简单短句） 欠缺极端电报式短语（仅抛 1~2 个名词碎片）且需联合历史工单还原完整动作谓词的样本。
2. 语序倒装与话题前置/追补 “先把那台旧的重启了，我是说二楼卧室连不上的那个分机” 少量覆盖（Omnilingua-AudioMC 2611.04390 测口语追补） 欠缺跨句追补修饰导致前句槽位绑定关系反转的精细标注。

4. 语音 ASR 同音错字与吞音粘连 “把那个光猫（广贸）重启一下”、“千兆（签照）宽带掉线” 重点覆盖（Speak & Spell 2409.06263、Speech-LLM DST 2506.08633） 现有 ASR 噪声集中于通用英文音素，欠缺垂直行业专有名词/设备型号同音误识与个人口头禅同音字联合恢复。
5. 多层嵌套条件与例外从句 “要是今晚十点前还没修好，除非已经在走赔付流程了，否则帮我转高级专家” 覆盖较弱（BlendX 2403.18277 含简单条件句） 极度欠缺“如果 A 则 B，除非 C 否则 D”多层布尔条件树转结构化执行约束的评测。
6. 中英混杂、缩写与数字单位省写 “NAS 走 2.5G 口 ping 不通网关，帮查下 VLAN 10 的 DHCP” 覆盖极少（多数基准为纯英文或标准书面中文） 欠缺高密度技术缩写 + 口语数字简写（如“晚 8 到 10”、“千兆改两千兆”）混合解析。
二、语义层
（Semantics）
概念映射、命题逻辑与边界		 7. 零字面重合的个人自定义别称 用户说“我平时打排位那台机器” → 对应标准槽位 service=游戏加速, app=王者荣耀 几乎空白（仅 PersonaMem-v3 2608.21381 初步涉及跨端画像） 传统同义词改写仍具字面或公共语义重合；唯有查询该用户个人历史记忆（expression 映射表）才能解码的私有别称在现有意图集中完全缺失。
8. 上下位概念泛化与具象指代 用上位词“家里做饭看剧那几个屏”指代具体设备，或用具体现象代指抽象故障类别 部分覆盖（ColaBench 2610.30989 测记忆引导知识泛化） 欠缺用户口语粗粒度泛化词与后台细粒度标准目录（Catalog）一对多映射消歧的系统评测。
9. 复合多意图与显式否定排除（A ∧ ¬B） “帮我把书房网速提上去，但千万别动客厅正在看春晚的电视盒子，顺便查下上月账单” 中等覆盖（BlendX 2403.18277、Generative Multi-Intent 2602.08322） 现有多意图集侧重正向意图切分，对否定子句（¬B）被错误提取为正向执行参数（否定污染）的专门惩罚评测极少。
10. 相对时空与动态周期基准 “跟上周五那次一样，今晚再给我开两个钟头” 部分覆盖（LongMemEval 2410.10813、CARTBench 2611.05862） 欠缺锚定“历史某次具体工单发生时刻”进行相对时长与周期换算（end - start == duration）的联合校验。
11. 模糊量词与相对比较级修饰 “把延迟弄得比昨天再稳一点”、“换个稍微划算些的套餐” 少量覆盖（FinInteract 2609.24002、IN3 2402.09205） 欠缺将模糊比较级（“更稳/稍微快点”）结合历史基线数值转化为可量化参数或触发阈值追问的测试。
12. 跨表同名实体歧义与域外相似混淆 家里有两台同名路由器或两个宽带账号；或诉求酷似业务内实则属跨界 OOD 硬件维修 OOD 覆盖较充分（DROID 2510.14110、Beyond the Known 2402.17256） OOD 识别多为静态单轮分类，欠缺“用户账户下真实存在多个同名/同类实例，必须核对工作记忆状态才能判断该问还是该办”的设计。
三、语用层
（Pragmatics）
言外之意、多轮上下文与社交潜台词		 13. 间接言语行为（Indirect Speech Acts / 言外之意） 用户只陈述现象或抱怨：“这网速连发个微信转圈都得半天，今晚还要不要人开会了？”（表面陈述抱怨，实为紧急报修+优先保障会议） 2026 开始关注（Read the Room ISA 2608.30270、UserBench 2507.22034） 现有基准多测试日常看图说话或简单寒暄，极度欠缺高情绪抱怨背后隐含的“工具调用诉求 + 历史经验防雷约束”双层解码。
14. 跨轮零指代、代词省略与历史工单承接 “老毛病又犯了，按上次那个师傅说的办法直接帮我弄了吧” 重点演进方向（Chain Ambiguity 2608.29543、LoCoMo-Plus 2602.10715） 传统指代消解仅回溯当次会话前 2~3 轮；跨越数周历史会话、指向过往有效工单记录（工作记忆）的远距离跨会话省略指代仍极少。
15. 预设错误（Presupposition Failure）与事实冲突 用户预设了错误前提：“把我那个免费赠送的国际漫游包续上”（实际该包早在一个月前已退订且收费） 少量覆盖（LoCoMo 2402.17753 含无答案欺骗提问、Epistemic Parity 2610.33128） 欠缺“先礼貌指出用户预设与事实记忆/历史工单不符，再给出合规替代方案”的多轮纠偏动作评测。
16. 反讽、气话与情绪化反问 “你们这加速包可太厉害了，开了比不开还卡，干脆给我全停了算了！” 几乎空白（现有任务型基准假设用户字面诚实） LLM 极易将情绪化气话（“干脆全停了”）当成真实退订指令直接执行（CAREFUL-Bench 2611.02978 指出破坏性误调风险），亟需情绪安抚 + 二次意图核实测试。
17. 试探性条件咨询 vs. 正式下达执行指令 “如果我把主路由挪到客厅，穿墙模式切回标准，会不会影响书房？”（仅做假设推演，并未授权立刻修改配置） 2026 新兴焦点（CAREFUL-Bench 2611.02978） 多数工具调用基准不区分“What-if 咨询态”与“Commit 执行态”，导致 Agent 在用户仅咨询时擅自调用写接口改坏环境状态。
18. 多人旁白插话、背景交谈与主导人意图剥离 主叫用户正在报修，旁边家人插话“顺便问问电视会员多少钱”，主叫立刻说“别管电视，先弄我书房电脑的网” 2025–2026 开始探索（Multi-User DST 2506.10504、One Assistant Many Memories 2611.04867） 欠缺主客观发言人权限区分、旁人插话噪声抑制以及主叫用户对旁人提议的即时否决跟踪。

对联接 Agent 评测集构建的核心总结（结合 2024–2026 38 篇文献）：
  • 在记忆测试点构造上：综合 PersonaMem-v3、BehaviorMem、Why Bother Me Again? 与 MemUse，不仅要埋入跨周期的事实与习惯（含稳定、消退、新增、偶发四类轨迹），还要埋入用户的交互免打扰边界（哪些已知槽位不准重复追问），并在评测时像 MemUse 一样在轨迹注入点核查“检出的三层记忆究竟有没有真正转化为工具参数与排障动作”。
  • 在语法 · 语义 · 语用变体构造上：针对现有数据集最欠缺的盲区，重点构造“必须联合个人三层记忆才能消解的变体”——包括语法层的电报式残缺短语 + 句内多次口误自我修正（Self-Repair）、语义层的零字面重合私有别称（查 expression 映射） + 复合意图否定排除（A ∧ ¬B 防否定污染）、以及语用层的高情绪抱怨言外之意（Read the Room ISA） + 跨周历史工单省略指代 + 试探性咨询态与执行态区分（CAREFUL-Bench）。
  • 在多轮用户-Agent 交互模拟上：借鉴 τ²-bench 双控环境、Disclosure-Gated Simulation 信息披露门控与 StressSim 对抗压力模拟，严禁模拟用户第一轮吐露全部底牌或无条件配合，而是覆盖 16 × 16 双向交互动作（含反问原由、中途改口 IntentDelta、旁人插话干扰 Multi-User DST 与高危写操作执行前二次确认 CAREFUL-Bench）。

三、全流程评测指标（萃取 → 召回 → 决策）

四、记忆要记什么（以网络保障为例）

记忆是为下一次保障决策服务的：记下来的东西要能让联接 Agent 少问一句、少错一个参数、提前避开一个问题。所以按“生成一张保障工单要经过哪些决策环节、每个环节缺什么信息”来倒推要记什么。

总结：三类记忆解决网络保障的什么问题

事实记忆：用户说得少、说得不标准
  • 问题：用户只说“照常开播”“别卡”，缺时间、地点、参数，用词也和单据字段对不上。
  • 怎么解决：记住周期习惯、默认档位和口语映射，自动补全参数、翻译成标准字段。
  • 为什么能解决：偏好是稳定且反复出现的，可以从多次单据和对话中归纳出来；要求重复出现才确认，能避免把偶发行为当成习惯。
工作记忆：用户指代过去的某一次
  • 问题：用户说“按上周六没卡那次来”“把昨天那单推迟半小时”，需要精确找到那张单。
  • 怎么解决：原样保存每张工单和执行回执，按时间、地点、体验好坏检索；同地多单时先反问。
  • 为什么能解决：具体单据是已经发生的事实，一旦归纳成偏好就会丢掉时间、实测时长和好坏这些细节，所以要逐条保存、不合并、不衰减。
经验记忆：把“多轮澄清 / 理解失败”变成“一次快速闭环”
  • 问题：遇到特殊场馆、多单歧义或复杂诉求时，系统第一次往往理解失败（配错档位/找错单）或需要多轮反问澄清。
  • 怎么解决：把首次“多轮澄清 / 理解失败被纠正”后对齐的参数调整规则与消歧流程记为经验，下次遇到同类请求直接走快路径一次闭环。
  • 为什么能解决：用户的纠正与多轮澄清已经把“什么场景该补什么参数、怎么避开理解偏差”讲清楚了，沉淀成规则后无需每次重走慢路径。

为什么分三类而不是放在一起：三类信息的更新方式不同——偏好要重复确认、会过时；单据是既成事实、不能改；规则要靠执行结果验证。混在一起会互相干扰，例如把一次卡顿单当成用户偏好，或者让一次临时改动覆盖长期习惯。分开存储、分开更新，才能各自保持准确。

五、记忆是如何从短期变成长期的？（北邮 MemoryOS · 业界对比 · 四步演变逻辑）

短期记忆（单次对话、单张实时单据）不能直接等于长期记忆，否则一次偶发改期或一次体验异常单据就会把用户画像污染。参考北邮与腾讯 AI Lab 的《Memory OS of AI Agent》（arXiv:2506.06326）以及业界主流团队（Claude Code、OpenAI Codex、Mem0、Zep/Graphiti、Letta/MemGPT、上海 AI Lab MemOS），“短期 → 长期”的核心逻辑是“短期定长缓冲 → 中期按主题聚合 → 靠热度/重复次数越过阈值晋升 → 长期冲突接替与冷衰减”。

1. 北邮 MemoryOS（arXiv:2506.06326）的三级演变机制：STM → MTM → LPM

① 短期记忆（STM）：对话页 + 对话链 FIFO
  • 存什么：把每一轮问答存成“对话页（page = {Q, R, T, meta_chain}）”，放进定长队列（如 7 页）；若前后页语义连贯则串成“对话链”并生成链摘要。
  • 怎么流转：队列满时，按先进先出（FIFO）把最老的对话页弹出，移交到中期记忆（MTM）。
② 中期记忆（MTM）：操作系统“段页式”话题聚合
  • 存什么：借鉴 OS 段页式内存——“段（Segment）”是话题摘要，“页（Page）”是该话题下的具体对话页。
  • 怎么归并：新页进入时算向量余弦相似度 + 关键词 Jaccard 重合度；超过阈值（0.6）就并入已有话题段，否则新建一个段。
③ 长期个人记忆（LPM）：热度分（Heat）驱动晋升
  • 晋升公式：每个段算热度 Heat = α·被检索次数 + β·段内累积页数 + γ·时间衰减 exp(-Δt/μ)。
  • 怎么升格与淘汰：段数超限时淘汰 Heat 最低的冷段；当 Heat > 5 时，大模型从中提炼出长期事实（入 User KB）与 90 维偏好特征（入 User Traits），随后将该段累积页数清零使热度回落，防止重复提炼。

Claude Code

OpenAI Codex CLI
（Memory v2）		 本地分层目录（~/.codex/memories_v2）：
① 原始会话记录 raw_memories.md 与单次会话摘要；
② 全局长期摘要 memory_summary.md。		 后台抽取与合并 Agent（Consolidation Agent）：单次会话结束先生成短期会话摘要；后台合并进程异步读取多次会话的原始记录，将反复出现的开发环境配置、代码风格与用户指令蒸馏进全局长期摘要。 严格字节预算（Byte Caps）：单会话文件限制 < 9KB，全局长期摘要限制 < 10KB；超限时由合并模型压缩旧条目、覆盖冲突配置。
Mem0
（arXiv:2504.19413）		 向量库 + 知识图谱（Mem0g）双层：不存原始长对话，只存提炼后的原子事实句与“实体—关系—实体”三元组。 两步抽取 + 四动作判定：每轮新对话进来，先结合当前轮与近期滑动摘要抽出候选事实；再去向量库召回最相似的 Top-S 条已有长期记忆，由大模型通过工具调用判定执行 ADD（新增）、UPDATE（更新）、DELETE（删除矛盾）、NOOP（跳过）。 靠 UPDATE / DELETE 原地消解冲突（如新偏好直接覆盖旧偏好节点），避免同一件事存出多条相互矛盾的向量记录。
Zep / Graphiti
（arXiv:2501.13956）		 三层时序知识图谱：
① 原始事件子图（Episode，短期原样记录）；
② 语义实体子图（Entity & Fact，中期事实边）；
③ 社区聚类子图（Community，长期高层画像）。		 每次会话或业务数据先写入 Episode 节点；异步抽取实体与关系边并入语义子图（通过向量+文本匹配合并同名实体）；再按图连通度将高频共现实体聚合成长期社区摘要。 双时间戳有效期接替（不物理删旧边）：每条关系边带事件生效/失效时间 (t_valid ~ t_invalid) 与系统记录时间。偏好改变时给旧边打上截止时间 t_invalid 并建新边，完整保留演变历史。
Letta / MemGPT
（arXiv:2310.08560）		 仿 OS 虚拟内存两层：
① 核心内存（Core Memory / RAM）：常驻提示词的可编辑文本块（persona 块 + human 块）；
② 外部存储（Disk）：回溯对话表（Recall）与向量归档库（Archival）。		 上下文压力中断 + Agent 自主换页：短期对话在窗口内累积，当达到上下文容量告警线（如 70%）时触发系统中断（Memory Pressure Warning），Agent 自己调用 core_memory_append/replace 把关键事实写进常驻块，或调 archival_memory_insert 刷入外存，再把早期对话移出窗口。 核心内存块设固定字符上限，写满时由 Agent 自主重写压缩（core_memory_replace）；历史原始明细全部退入外存按需检索。
MemOS（上海 AI Lab / MemTensor）
（arXiv:2507.03724）		 按计算介质分三层：
① 激活记忆（Activation）：运行期 KV Cache 与短期状态；
② 明文记忆（Plaintext）：外部文本、图谱与规则块；
③ 参数记忆（Parametric）：LoRA / 模型权重。		 用统一容器 MemCube（带来源、版本号、访问频次与权限）封装记忆：短期上下文中的高频明文知识先提升为可复用的激活缓存（KV 状态）；经过长期高频调用、验证稳定的用户固定习惯，进一步通过微调蒸馏内化为参数记忆。 由调度器（MemScheduler）监控访问频次与衰减率：低频过期的从激活层降级回明文层或归档淘汰，带版本号控制回滚。
MemoryBank / A-MEM
（2305.10250 / 2502.12110）		 • MemoryBank：原始对话日志 + 每日事件摘要 + 全局用户肖像。
• A-MEM：仿卡片盒笔记法（Zettelkasten）的双向链接卡片网。		 • MemoryBank：按艾宾浩斯遗忘曲线 R = exp(-t / S) 演化——初建记忆强度 S=1，每次被重新提及或召回命中则 S + 1 且时间 t 清零，多次强化后升入长期肖像。
• A-MEM：新记录先生成带标签的结构化卡片，再自动与历史卡片建链并反向更新旧卡片的上下文描述。		 MemoryBank 中单次偶发且长期未被召回的条目随 exp(-t/S) 自然跌破阈值被遗忘；A-MEM 通过反向更新旧卡片总结避免旧卡片语义脱节。

第 3 步：越过阈值升格长期
（事实 & 经验记忆 / LPM）		 正式生效（active / reinforced）的 A–F 融合画像字段与经验规则卡。 参考北邮 Heat 热度公式与 PersonaMem-v3 证据门限，设三条晋升通道：
① 隐式重复晋升（→ 事实记忆）：同一中期候选段内，一致单据累计达 ≥ 3 次（且近期未衰减）→ 状态从 candidate 升格为 active 写入长期周期习惯，并清零中期未处理计数；
② 显式指令直通（→ 事实/经验记忆）：用户在对话中明确立规（“以后工作日开会都保 1080p”）或给出口语映射 → 高权重直接写入长期记忆；
③ 慢路径澄清与纠正晋升（→ 经验记忆）：中期事件链出现“首次理解失败/缺参 → 多轮澄清或用户纠正 → 最终确认工单”的完整交互闭环 → 提炼出触发条件 → 曾出理解偏差/缺口 → 正确动作与参数写入长期经验库，供后续直接快路径闭环。		 • 第 3 次周六在奥体中心推流（SN_015）后，累计达 3 次 → 自动升格为长期支线周期习惯；

第 4 步：长期有效期接替与衰减淘汰
（借鉴 Zep + MemoryBank）		 套餐/设备升级、常驻地迁移、长期不再去的旧场馆支线。 • 新旧状态接替（不物理硬删）：当新习惯连续达标或用户换 5G 套餐时，借鉴 Zep 给旧习惯打上失效时间戳并标为 superseded（转入 conflict_log 备查），新习惯标为 active；

六、经验记忆要学到什么

事实记忆回答“用户要什么”，经验记忆回答“遇到这类情况，系统该怎么做”。经验记忆学的是因果规则：在什么条件下、因为什么原因、该做什么调整、调整后结果如何，而不是某一次的具体参数。

1. 相关论文与核心工作

论文 核心工作
Reflexion（2303.11366） 把任务执行后的环境反馈信号转成文字反思（verbal reflection），存进滑动情景记忆，下一次尝试前直接读入上下文以修正行为。
ExpeL（2308.10144） 从一批尝试轨迹中自动收集成功案例与成对的成功/失败对比轨迹，用自然语言增删改提炼出通用结论（insights），推理时同时召回结论规则与相似成功轨迹。
Agent Workflow Memory（2409.07429） 从历史轨迹中归纳经常复用的多步处理流程（workflows），离线或在线更新进记忆库，帮智能体在后续复杂任务中减少重复摸索步骤。
ReasoningBank（2509.25140） 从智能体自评的成功和失败经验中提炼可泛化的高层推理策略，验证了“同时学成功与失败并抽象成策略”显著优于只存原始轨迹或只存成功流程。
CoMem（2610.25790） 从检索到的成功与失败案例中学习生成“失败假设（failure hypotheses）”，即在动手前先预判当前任务最可能在哪一步出错，用风险预判指导当前决策。
经验跟随实证研究（2505.16067） 系统分析了检索到的历史经验如何影响当前输出：发现经验与当前输入越相似，模型越倾向于直接照搬，容易造成错误经验传播与不匹配经验误导；并提出用后续任务的执行结果作为经验质量的免费验证标签，过滤低质经验。

2. 要抓住的五个重点（从“多轮澄清/理解失败”到“快速闭环”）

重点 含义 网络保障中的例子
1. 从多轮澄清与理解失败中提炼规则 首次交互时系统为什么没一次办成（漏了什么参数、误解了哪个指代、经过几轮追问/纠正才对齐），把最终对齐的做法记成规则。 首次用户说“周六去体育馆开播”，系统直接按家里普通参数下发被用户纠正（或经 3 轮澄清才确定要提前 20 分钟开切片预热）→ 沉淀为场馆推流经验规则。
2. 下次同类请求直接快速闭环 经验记忆的核心作用是把慢路径变成快路径：下次再遇到相同场景/诉求时，不再重复追问、不再理解出错，一次生成正确工单。 后续用户再说“周六去场馆播一场”，直接命中经验补齐提前预热与切片参数，1 轮快速闭环。
3. 条件抽象到可迁移的粒度 触发条件用场景类型、业务类型、指代特征描述；具体小区、会话 ID 只作为证据挂在下面。 写“人流聚集场馆 + 上行推流”或“同地存在多张不同体验历史单据时的指代消歧”，去另一个体育馆也能直接快速闭环。
4. 正反对比（失败/慢路径 vs. 成功/快路径） 对比“初次理解失败/未预热的差单”与“纠正后/预热后的好单”，锁定真正起作用的参数动作。 对比未预热的异常单 SN_009 与多轮澄清后预热成功的单据 SN_015，锁定关键动作是提前 20 分钟预热。
5. 写明适用边界与回执验证 标明什么情况下不适用（防止乱套用），并用后续快路径工单的回执结果持续验证。 非赛事日或普通下行点播不套用该预热规则；后续快路径执行后回执 AppQuality=good 则置信度上升。

  • 网络问题因果规则：什么场景、什么业务容易出什么问题，该怎么调参数（预热、切片、主辅业务分流、弱网降级保语音）。

3. 来源、四类融合策略与关键口径

来源说明与融合策略（来源为 对话+CSV 时）
  • 对话：从 Agent 对话上下文抽取（意图/声明/诉求/纠正），无 CSV 真源；
  • CSV：从行为单据列聚合（证据），按 Gpsi 归用户；
  • 对话+CSV：双侧都有，按 4 类策略融合：
    1. A 单源继承：仅一侧有 → 直接取，无 CSV 支撑标 weak。
    2. B 主证据 + 辅校准：声明为主，用 CSV 分位数把档位校准到实测区间。
    3. C 双侧并存：意图与行为并列，声明与实测并列（∥），不覆盖。
    4. D 冲突仲裁：语义矛盾，意图/纯声明字段保留对话，行为/体验字段取 CSV 值，入 conflict_log。
关键口径与 CSV 24 列
  • CSV 是行为证据，不是偏好声明：偏好必须由行为归纳，冲突在融合阶段消除。
  • 无 GIS 时：地理 / 通勤字段降级为弱证据（仅小区 ID 频次，不做定性 OD）。
  • 体验档位推断：无 AvgQoe / MostResolution 列，体验档位由 DelayAn / DelayDn / 丢包 / Bandwidth / AppQuality 组合推断。
  • CSV 实测列（24 列）：SerialNo, TimeStamp, StartTime, Gpsi, Dnn, S_NSSAI, RatType, Qci, ExpOptFlag, ExpOptStartTime, AppId, SubAppId, AppStatus, AppQuality, Tai, CellId, DelayAn, DelayDn, UplinkBandwidth, DownlinkBandwidth, UplinkPkg, DownlinkPkg, LostUplinkPkg, LostDownlinkPkg, SubAppStartTime, InfoIndicate。

八、交互模拟与评测

评测多轮记忆与意图 Agent 的难点在于：被测 Agent 每一轮的回复是动态生成的（可能走快路径直接出单，也可能走慢路径追问不同槽位）。如果只按固定剧本逐行喂入写死的 U1 → U2 → U3，一旦 Agent 追问的方向与剧本预设不一致，后续对话就会答非所问。

静态剧本回放的局限（写死多轮台词）
  • 次轮台词固定：直接把数据集中预先写好的 U1, U2, U3 按轮次喂给被测 Agent，不管 Agent 上一轮实际问了什么。
  • 测不出漏问与快慢路径分流：若被测 Agent 第 1 轮漏问了“画质”只问了“时长”，写死的 U2 仍会把画质和时长一起报出来，掩盖漏问缺陷；若 Agent 命中经验记忆第 1 轮已闭环，静态回放还会继续强行喂入 U2。
  • 只看终态字面，不查证据来源：只比对最终 7 个槽位值是否一致，无法区分槽位是真从历史记忆中检索出来的，还是模型凭空猜对的。
在线交互模拟的思路（受控用户模拟器动态应答）
  • 按问给值（问什么才答什么）：用户模拟器持有完整目标意图，但第 1 轮只说模糊诉求；后续轮次严格根据 Agent 实际追问的槽位动态回答，Agent 没问到的隐藏槽位绝不主动提前吐露。
  • 自然检验快路径与慢路径：Agent 第 1 轮若直接下发完整工单则当场结束并算分；若发起澄清反问，则进入多轮交互循环（直到闭环或达到最大轮数上限）。
  • 全链路分段算分：在交互过程中同步采集并计算记忆检索分、交互过程分（分流准确率 / 反问命中率 / 轮数）、有依据终态分（含一票否决红线）与多轮稳定性。

1. 在线交互模拟与分段算分流程

整个评测过程由双端视图隔离、受控多轮交互循环、全轨迹中间态记录、三层指标结算四个环节组成：

flowchart LR V1["用户私有视图"] --> U1["1. 模拟器发模糊诉求 U1"] V2["三层历史记忆库"] --> RET["2. Agent 检索记忆（算 Recall@k / NDCG@k）"] U1 --> RET RET --> ROUTE{"3. 路径分流"} ROUTE -->|"快路径出单 / 域外拒答"| END_EVAL["5. 交互终止与算分"] ROUTE -->|"慢路径反问 A_t"| SIM["4. 模拟器按问给值 U_t+1"] SIM -->|"下一轮（最多 5 轮）"| RET END_EVAL --> S1["阶段 1：记忆更新准确率"] END_EVAL --> S2["过程分：分流/反问/轮数/槽位保持"] END_EVAL --> S3["阶段 3：红线 + 证据落地 + 7 槽位全等"]
环节 ①：双端物理信息隔离
  • 用户侧私有视图：把完整意图拆成“首轮允许说的槽位”和“次轮待揭晓槽位”，从源头防止用户模拟器在首轮把答案全说漏。
  • Agent 侧可观测视图：只允许看到历史记忆库与用户已经说出口的台词，看不到标准答案与待揭晓参数。
环节 ②：受控交互循环
  • 按问给值规则：用户模拟器先判断 Agent 的反问 A_t 有没有问到点子上——问到了才给对应参数；若 Agent 漏问或问偏，则不给该参数或顺着反驳。
  • 动态终止：Agent 一旦输出最终工单、或明确拒答域外请求、或满 5 轮即结束会话。
环节 ③：全轨迹中间态采集
  • 不只记最后一轮结果，而是把每一轮检索召回的 Top-k 记忆 ID、Agent 选择的路径动作（直接办 / 反问 / 取消 / 拒答）、每轮槽位变化与反问文本全部记入轨迹。
环节 ④：确定性规则为主算分
  • 客观指标代码直算：槽位全等、起止时间与时长算术关系、证据 ID 命中、轮数统计全部用确定性逻辑直接核对。
  • 话术红线轻量判定：仅“是否说出刺探隐私生硬话术、反问是否命中歧义点”辅以轻量裁判规则判定。

2. 证据召回率 Recall@k
（k = 3, 5）		 看每轮检索返回的前 k 条记忆 ID 里，包含了百分之多少当前会话必用的标准历史单据、画像或经验卡 ID。 把检索问题单独剥离：终态做错时，先看是不是检索根本没把那张单据或经验捞出来。
3. 证据排序分 NDCG@k
（k = 5）		 不仅看正例证据进没进前 5 条，还看当前生效的目标记录/最新习惯有没有排在过期旧记录、体验异常记录前面（排第 1 得满分，越靠后按对数位置打折）。 防止“正例虽然捞出来了，但排在过期旧单/卡顿单后面，误导下游选错”。
第二层：模拟交互过程
（快慢路径与追问质量）		 4. 快/慢路径分流准确率
（过度澄清率 & 盲目抢跑率）		 比对被测 Agent 第 1 轮的路径选择与样本预期路径：
• 过度澄清率：信息充足或已有经验本该 1 轮直接办，却多此一举发起反问的比例；
• 盲目抢跑率：缺必填参数或存在多单冲突本该先问，却直接瞎猜参数下发工单的比例。		 管住两头极端：既防止什么都反问打扰用户，也防止缺参时盲目抢跑下错单。

第三层：终态决策与稳定性
（对应阶段 3）		 7. 有依据终态准确率
（含一票否决红线）		 单个会话得 1 分必须同时满足 4 个条件：
① 未踩一票否决红线（未用已过期旧档位、未照搬卡顿失败单、未违规刺探隐私，踩中直接 0 分）；

③ 时间算术自洽（结束时间 - 开始时间 == 保障时长）；
④ 7 个业务槽位与标准答案严格全等。		 杜绝“检索没命中却碰巧猜对参数”的虚假高分，并确保踩中红线的危险输出直接判零。
