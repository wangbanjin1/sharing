一、为什么评测 Agent 能力必须用“在线交互模拟”而非静态剧本回放？

评测多轮记忆与意图 Agent 时，核心矛盾在于：被测 Agent 每一轮的回复是动态生成的（可能走快路径直接出单，也可能走慢路径追问不同槽位）。如果评测代码只按固定剧本逐行塞入写死的 U1 → U2 → U3，一旦 Agent 追问的方向与剧本预设不一致，后续对话就会答非所问。

现状痛点：静态固定剧本回放（Teacher-Forcing，当前 session_eval.py）
  • 次轮台词写死：session_turns(session) 直接读取数据集里预生成的 U1, U2, U3 逐轮喂给被测 Agent。
  • 无法评测快慢路径分流与澄清质量：假设被测 Agent 在第 1 轮漏问了“画质档位”只问了“时长”，写死的 U2 依然把画质和时长全吐出来，掩盖了 Agent 漏问的缺陷；反过来，若 Agent 命中经验记忆本该 1 轮直接闭环，静态回放还会强行喂入 U2。
  • 缺少检索中间态与证据溯源校验：只比对最终 7 个槽位字面是否相等（JGA），没校验该槽位是真从历史记忆捞出来的，还是大模型瞎猜碰巧蒙对的。
目标机制：物理信息隔离的在线双端交互评测（User-in-the-Loop Harness）
  • 受控用户模拟器动态应答：复用 isolated_views.py 的物理隔离视图——UserSimulator 手握完整目标意图，但第 1 轮被限制只能说出模糊诉求（turn1_allowed_slots）；后续轮次严格遵循“Agent 问了哪个槽位，才回答哪个槽位”。
  • 自然检验快路径与慢路径：Agent 第 1 轮若直接输出 # status: resolved 则当场结束交互结算得分；若输出 # status: pending 并发起澄清提问，则进入多轮交互循环（最多 max_turns = 5）。
  • 分段全链路算分：在同一套循环里同步采集并结算记忆检索分（Recall@k / NDCG@k）、交互路由分（Route F1 / 平均轮数）、有依据终态槽位分（Grounded JGA + 一票否决红线）与多轮稳定性（pass^k）。

三、评测代码整体架构与四模块设计（基于现有仓库无缝升级）

结合我们本地已有的 D:\coding\qwen_intent_rag\session_eval.py（被测 Agent 逐轮推理与 JGA 判分）和 D:\coding\cross_memory_data\src\generation\tau_bench_simulator.py（物理信息隔离的用户模拟器），只需将两者组合为以下 4 个解耦模块：

模块 1：受控用户模拟器
ControlledUserSimulator
  • 输入：user_private_view（含 turn1_allowed_slots、turn1_forbidden_values、turn2_reveal_slots）+ Agent 上一轮自然语言回复 a_t。
  • 受控约束：Turn 1 只说模糊诉求；Turn ≥ 2 仅当 a_{t-1} 明确追问了某缺失/歧义槽位时才揭晓对应值；若 Agent 反问偏题则顺着追问反驳。
模块 2：在线交互驱动器
InteractionRunner
  • 双端闭环：替代 session_eval.py 原本遍历静态列表的 for t in turns，改为 while turn <= max_turns 动态循环。
  • 终止条件：当 Agent 输出 # status: resolved（快路径闭环或澄清完成）、或者明确拒答域外诉求（OOD）、或达到 max_turns = 5 时终止。
模块 3：全链路轨迹记录器
TrajectoryLogger
  • 逐轮快照：每轮记录 u_t、记忆检索结果 memory_trace（Top-k 候选 ID 与分数）、Agent 动作路由（resolved / pending / cancel / ood_reject）、槽位状态 preds 与自然语言回复 a_t。
  • 落盘格式：输出结构化 interactive_eval.json 供复盘与归因。
模块 4：三层指标结算器
MetricsCalculator
  • 阶段 1 & 2：核对记忆库更新 Diff 与检索 Recall@k / NDCG@k。
  • 交互过程：算快慢路径 Route F1、反问命中率、平均交互轮数与跨轮槽位保持率。
  • 阶段 3 终态：算 Grounded JGA + validator.py 算术自洽 + 4 项一票否决红线 + pass^k。

核心代码实现骨架（interactive_session_eval.py）

from __future__ import annotations
import logging
from typing import Any
from validator import validate

logger = logging.getLogger(__name__)


class ControlledUserSimulator:
    """物理信息隔离的受控用户模拟器：仅在被测 Agent 问对问题时才揭晓隐藏槽位。"""

    def __init__(self, llm_client: Any, user_private_view: dict[str, Any]) -> None:
        self.llm = llm_client
        self.view = user_private_view

    def first_turn_utterance(self) -> str:
        # Turn 1 仅可根据 turn1_allowed_slots 生成口语诉求，严禁泄露 turn1_forbidden_values
        return self.llm.generate_u1(
            allowed_slots=self.view["turn1_allowed_slots"],
            forbidden_values=self.view["turn1_forbidden_values"],
            persona_style=self.view["persona_style"],
        )

    def reply_to_agent(self, history: list[dict[str, str]], agent_question: str) -> str:
        # Turn >= 2：检查 agent_question 询问了哪些槽位，仅从 turn2_reveal_slots 中释放被问到的槽位
        return self.llm.generate_ut(
            history=history,
            agent_question=agent_question,
            revealable_slots=self.view["turn2_reveal_slots"],
            correction_rule=self.view.get("correction_instruction", ""),
        )


def run_interactive_session(
    agent_pipe: Any,
    user_sim: ControlledUserSimulator,
    session_meta: dict[str, Any],
    max_turns: int = 5,
) -> dict[str, Any]:
    """在线驱动 UserSimulator 与被测 Agent 逐轮交互，并采集全链路轨迹。"""
    ref_time = session_meta.get("reference_time", "")
    prev_states: dict[str, dict[str, Any]] = {}
    prev_statuses: dict[str, str] = {}
    history: list[dict[str, str]] = []
    trajectory: list[dict[str, Any]] = []

    u_t = user_sim.first_turn_utterance()

    for turn_idx in range(1, max_turns + 1):
        # 1. 被测 Agent 执行单轮检索与状态推理（内部调用 memory_bridge 检索三层记忆）
        prev_states, prev_statuses, turn_entry = evaluate_agent_turn(
            pipe=agent_pipe,
            utterance=u_t,
            ref_time=ref_time,
            turn_idx=turn_idx,
            prev_states=prev_states,
            prev_statuses=prev_statuses,
            session_meta=session_meta,
        )
        agent_reply = turn_entry.get("agent_utterance", "")
        turn_status = turn_entry.get("status_pred", {})
        trajectory.append({"turn": turn_idx, "user": u_t, "agent": agent_reply, **turn_entry})
        history.append({"user": u_t, "agent": agent_reply})

        # 2. 检查是否满足闭环终止条件（全部意图 resolved 或明确拒答 OOD）
        all_resolved = bool(turn_status) and all(s == "resolved" for s in turn_status.values())
        if all_resolved or turn_entry.get("is_ood_rejected", False):
            break

        # 3. 若处于慢路径 pending 状态，由受控用户模拟器根据 Agent 的追问生成下一轮回答
        if turn_idx < max_turns:
            u_t = user_sim.reply_to_agent(history=history, agent_question=agent_reply)

    return {
        "session_id": session_meta["session_id"],
        "num_turns": len(trajectory),
        "final_preds": trajectory[-1]["preds"] if trajectory else {},
        "trajectory": trajectory,
    }

五、评测代码自动计算的三层 9 项指标汇总表

指标分层 指标名称 代码里的确定性计算方式 主要诊断什么问题
第一层：记忆萃取与检索指标
（对应主文档阶段 1 & 2）		 1. 画像与经验抽取 F1 & 状态更新准确率 跑完学习会话后，对比记忆库快照与标准记忆快照（Ground-Truth Memory Snapshot）的字段交集算 F1；在偏好变更会话上检查旧值是否被替换、临时变动是否未污染长期表、无关记忆行是否 0 改动。 定位“单据/对话里的习惯和慢路径澄清后的经验有没有存准、旧偏好有没有残留”。
2. 证据召回率 Recall@k
（k = 3, 5）		 从每轮 memory_trace 提取检索返回的 Top-k 记忆 ID 集合 R_k，与该会话绑定的标准证据 ID 集合 E_gt 比对：|R_k ∩ E_gt| / |E_gt|。 单独剥离检索问题：终态做错时，先看是不是检索根本没把那张历史单/经验卡捞出来。
3. 证据排序分 NDCG@k
（k = 5）		 正例证据（当前生效习惯、顺畅工单）相关性标为 rel = 2，无关记录标为 0，已过期旧偏好或卡顿废单若混入前 k 条则不给分，计算 DCG@5 / IDCG@5。 防止“正例虽然进了前 5 条，但排在过期旧单/卡顿单后面，误导下游大模型选错”。
第二层：模拟交互与快慢路径指标
（在线交互过程专有）		 4. 快/慢路径分流准确率
（含过度澄清率 & 盲目抢跑率）		 比对 Agent 在第 1 轮的动作（resolved 快路径 vs. pending 慢路径反问）与样本 expected_route：
• 过度澄清率：本该快路径一次闭环却发起反问的比例；
• 盲目抢跑率（Minefield）：缺参或多单冲突本该反问却直接出单的比例。		 管住两头极端：既防止 Agent 畏首畏尾什么都反问，也防止缺参时盲目瞎猜参数直接下发。
5. 慢路径反问命中率 & 平均交互轮数 • 反问命中率：慢路径下第 1 轮反问覆盖的缺失/歧义槽位数 ÷ 实际待澄清槽位数；
• 平均交互轮数（Avg Turns）：统计达成闭环消耗的轮数，对比经验记忆沉淀前后的轮数下降幅度。		 直接量化经验记忆的核心价值：把首次多轮澄清（2~3 轮）变成后续一次快速闭环（1 轮）。
6. 跨轮槽位保持与修正率
（Slot Retention & Revision）		 在多轮补充或用户中途纠正（含 # cancel:）的会话中，分别统计：① 被纠正/补充的目标槽位正确更新的比例（Δ_update）；② 其余已确认槽位在跨轮透传中未丢失的比例（1 - Δ_drop）。 诊断多轮对话中最常见的“改了时长却把上一轮确认好的 4K 画质弄丢了”或“取消子意图失败”。
第三层：终态决策、红线与稳定性指标
（对应主文档阶段 3）		 7. 有依据终态准确率
（Grounded Session JGA + 一票否决红线）		 单个会话得 1 分必须同时通过 4 道关卡：
① 一票否决红线：未引用过期旧偏好、未照搬卡顿失败单、未说出刺探隐私话术（踩中直接 0 分）；
② 证据落地核验：记忆补全槽位的 source_ref 必须存在于当轮 memory_trace Top-k 中；
③ 算术自洽：通过 validator.py（end - start == duration）；
④ 7 槽位严格全等：预测意图集合与 GT 7 个字段完全一致。		 杜绝“检索没命中却靠大模型先验蒙对参数”的虚假高分，并确保踩中红线的危险输出直接清零。
8. 克制率与未知拒答率
（Restraint & OOD Abstention）		 在无关闲聊、通用通信问题、域外诉求（如 T1-2 宽带报修）或无历史记录的陌生场馆样本上，统计 Agent 不强行塞入个人记忆、不伪造保障单（preds == {}）并准确拒止/反问的比例。 防止“过度个性化”——不该用记忆的时候坚决不用，不知道的参数坚决不编。
9. 多轮运行一致性 pass^k
（默认 k = 3）		 对同一测试会话独立运行 n = 3 次在线交互（温度 T = 0.2），只有 3 次全部拿到 Grounded Session JGA = 1.0 才计为该会话 pass^3 = 1。 衡量生产可靠性：单次碰巧跑通不算稳定，连续多次交互均零失误才算真正掌握。
