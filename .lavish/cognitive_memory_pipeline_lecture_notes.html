1 记忆要记什么：CoALA 四类记忆分工、长短期分层管理与分表存储结构

1.1 单层向量库混存的问题与 CoALA“一短期 + 三长期”记忆分工

在 6G NGC 网络体验保障场景中，系统输入同时包含网元结构化保障单据及网络实际运行结果（记录小区标识 CGI、地点、起止时间、保障规格及事后体验质量 AppQuality=good/bad）与用户多轮自然语言对话。如果把当前对话上下文、用户长期习惯和历史单据直接混存在同一个无分层的文本向量库中，会出现以下四个问题：

  1. 用户的口语叫法与单次外出地点混在一起：用户的口语表达（如“小破站开播”）如果与某次外出场馆的地点、时长存在同一条文本中，回到常驻地点再次使用该叫法时，容易误带出上次外出场馆的参数。
  2. 短期临时改动覆盖平时的固定习惯：用户因异地出差、月末流量紧张或某天暴雨临时将画质降为 720p，如果不与长期常驻习惯分开存储，会直接覆盖平时稳定的 1080p / 4K 默认配置。
  3. 同一地点的正常单据与卡顿单据难以区分：同一场馆如果先后存在运行顺畅的单据（good）与发生卡顿的单据（bad），纯文本向量相似度几乎一致，用户说“照上次没卡那笔办”时很容易选错记录。
  4. 多轮沟通确定的参数调整无法直接用于同类新场景：首次在大型场馆遇到拥塞并经多轮沟通确定提前开启上行切片后，如果只保存当次单据而不提炼通用规则，下次换到其他体育场时仍需重复追问；反过来如果不做适用业务限制，在场馆内看视频点播时又会误触发上行切片。

参考普林斯顿大学提出的 CoALA（Cognitive Architectures for Language Agents, arXiv:2309.02427） 认知架构，系统首先按生命周期将记忆划分为短期记忆（Short-Term Memory）与长期记忆（Long-Term Memory）两级，其中只有工作记忆属于短期记忆，而语义记忆、情景记忆、程序化（经验）记忆三者均属于跨会话持久保存的长期记忆：

  • 短期记忆（Short-Term Memory）—— 1. 工作记忆（Working Memory，解决“当前会话正在处理什么、中间槽位与当轮上下文是什么”）：仅在当前单次会话或当前决策周期内活跃的瞬时上下文草稿板（Scratchpad），也是大模型推理核心唯一直接读取的内存区域。工作记忆负责维护：① 本轮用户输入与当前任务目标；② 多轮澄清交互中的活跃槽位状态（已确认槽位、待澄清冲突项、中途改口修正状态、旁人插话过滤状态）与定长对话页链（FIFO 缓冲）；③ 当轮通过检索（Retrieval）从三类长期记忆中召回并过滤拼装后的活跃记忆上下文。会话结束后，工作记忆中的有效信息通过学习写回（Learning）沉淀至长期记忆，自身随会话终结而释放。
  • 长期记忆 ①（Long-Term）—— 2. 语义记忆（Semantic Memory，事实记忆—语义层，解决“用户平时稳定要什么、口语怎么对应标准字段”）：脱离单次具体事件背景、跨周期长期稳定的客观事实与常驻偏好（What is true）。记录用户的静态身份与套餐权益、长期周期作息习惯（periodic_preference，如工作日午间固定直播时段）、分场景常驻网络偏好与体验三档底线（scene_preference，如常驻基地与高铁移动会议）、服务与应用映射（service_to_app）、个性化表述映射（expression，如“小破站开播”对应 bilibili:openlive）以及基础默认档位（preferred_value）。隐式行为需经中期候选池跨周期累积达标（满足跨度 \(W_{\text{span}}\) 与得分阈值 \(\theta_{\text{long}}\)）后晋升生效；档位升级时采用双时间戳接替（旧记录标为 superseded）；长期未触发按遗忘曲线自然衰减。
  • 长期记忆 ②（Long-Term）—— 3. 情景记忆（Episodic Memory，事实记忆—情景层，解决“过去具体发生过哪些单据与事件、当前处于什么阶段性情境”）：绑定具体时间戳与时空背景的过往具体事件记录、历史单据流水与阶段性状态（What happened & when）。包含两部分内容：① 历史保障单据记录与网元实际运行结果（episodic_order_record）：原样保存过去每次实际执行过的保障单据（单号 SerialNo、执行日期、地点、CGI、起止时间、保障参数）与实际运行结果（AppQuality=good/bad），按单号逐笔原样追加、不跨单合并为平均习惯、不随时间衰减，用于按时间、地点或运行结果好坏精确回溯特定历史单据（如“照上周六在奥体没卡那次来”）或叠加改期平移；② 阶段性事件窗与带有效期 TTL 的临时偏好（episodic_event_preference）：记录异地差旅/赛事事件窗、短期临时降档/省流偏好（带到期时间 TTL）、历史主动诉求（active/closed）与当面显式纠正记录，在有效期内局部覆盖常驻语义记忆，到期后自动标为 expired 失效回退。
  • 长期记忆 ③（Long-Term）—— 4. 程序化记忆 / 经验记忆（Procedural / Experiential Memory，解决“遇到特定无线场景或歧义情况时，系统该怎么调参与处置”）：关于“如何执行动作、流程与调参规则”的显式程序化知识（How to do，对应 CoALA 中的显式程序化记忆 Explicit Procedural Memory）。记录从短期工作记忆的慢路径多轮澄清对话以及长期情景记忆的正反单据（bad 与 good）对比中提炼的网络问题因果调参规则（触发条件 Condition → 问题根因 Cause → 参数调整规则 Action → 预期结果 Outcome）、同地多单消歧处理流程（Workflows）与交互免打扰策略，显式绑定适用与不适用范围（scope.exclude），供后续同类场景直接召回复用。
短期记忆（工作记忆）与三类长期记忆（语义、情景、程序化/经验）的分层管理原则

1. 读写隔离（Retrieval & Learning 双通道）：大模型在单步推理时只直接读取短期工作记忆（Working Memory）；长期语义记忆、长期情景记忆与长期程序化（经验）记忆存储在外部 SQLite + 向量数据库中，必须通过混合检索（Retrieval）按需筛选并拼装加载进短期工作记忆后才能参与当轮推理；会话与单据执行产生的反馈则通过异步学习（Learning）从短期工作记忆写回或经中期候选池晋升至三类长期记忆。

2. 三类长期记忆分表独立更新：长期语义记忆靠跨周期重复累积达标晋升并按双时间戳新旧更替；长期情景记忆中的历史单据按单原样追加、不合并、不衰减，阶段性临时偏好按 TTL 到期失效；长期程序化（经验）记忆靠后续单据的实际运行结果（AppQuality 好坏）持续升降置信度。分表存储、独立更新，才能避免单次临时变动或单笔异常单据污染常驻语义习惯。

2 记忆从短期到长期的演变机制与萃取更新规则

2.1 北邮 MemoryOS（arXiv:2506.06326）的三级演变机制：STM → MTM → LPM

短期工作记忆中的单次对话或单张实时单据不能直接等同于长期语义记忆，否则单次偶发改期或基站故障异常单据会污染用户的常驻习惯。北京邮电大学与腾讯 AI Lab 联合提出的《Memory OS of AI Agent》（MemoryOS, arXiv:2506.06326）借鉴操作系统的分层内存管理思想，在短期记忆与长期记忆之间引入中期缓冲层，划分为短期记忆（STM） → 中期记忆（MTM） → 长期个人记忆（LPM）三级架构：

  1. ① 短期记忆（STM，对应 CoALA 工作记忆）：对话页 + 对话链 FIFO 缓冲。系统把当前会话的每一轮问答封装为一个“对话页（page = {Q, R, T, meta_chain}）”，放入定长 FIFO 队列（如容量为 7 页）；若前后页语义连贯，则自动串联成“对话链”并生成链级摘要。当定长队列满或会话结束时，按先进先出（FIFO）将对话页弹出，移交至中期记忆（MTM）。
  2. ② 中期记忆（MTM）：操作系统“段页式（Segmented Paging）”话题聚合。借鉴 OS 段页式内存设计——“段（Segment）”对应话题摘要，“页（Page）”对应该话题下的具体对话页或单据记录。当新页从短期工作记忆滑入时，计算向量余弦相似度与关键词 Jaccard 重合度；若超过阈值（如 0.6）则归并入已有话题段累积证据，否则开辟一个新话题段。
  3. ③ 长期个人记忆（LPM，对应 CoALA 长期语义/程序化记忆）：热度分（Heat）驱动晋升与累积清零。系统为每个中期话题段维护一个综合热度分：\(\text{Heat} = \alpha\cdot\text{被检索次数} + \beta\cdot\text{段内累积页数} + \gamma\cdot\exp(-\Delta t/\mu)\)。当段数超限时优先淘汰 Heat 最低的冷段；一旦某个话题段的热度分越过晋升阈值，便从该段中提炼出长期稳定事实与偏好特征写入长期记忆，随后将该段的累积页数清零使热度回落，防止同一批证据被重复提炼。

① 激活记忆（Activation，短期 KV Cache 与工作状态）；
② 明文记忆（Plaintext，长期外部文本、图谱与规则块）；
③ 参数记忆（Parametric，模型权重）。		 用统一容器 MemCube（带来源、版本号、访问频次与权限）封装记忆：短期工作上下文中的高频知识先提升为可复用的激活缓存；经过长期高频调用、验证稳定的用户固定习惯与规则，进一步固化至长期明文或参数记忆。 由调度器（MemScheduler）监控访问频次与衰减率：低频过期的从激活层降级或归档淘汰，带版本号控制回滚。

2.4 单据预处理、候选池累积参数与记忆保持率衰减计算

原始网元单据流中混有持续时间很短的后台流量记录、基站切换产生的断流拆分记录，以及用户的临时改动或偶发行为。工程实现时，具体业务阈值用可配置参数表示（不在代码里写死固定数值），从短期工作记忆向长期情景记忆、长期语义记忆流转的处理流程与参数定义如图 2.2 与表 2.3 所示：

  1. 过滤时长过短的无效单据，合并因断流拆开的多笔记录 —— 参考 BehaviorMem (arXiv:2610.34790)：系统按最小有效时长参数 \(T_{\min}\) 剔除无对话对应的短时后台记录及中途取消的无效单据；对于同一用户、同一业务因基站切换在短时间间隔 \(\Delta t_{\text{gap}}\) 内断开重连产生的多笔记录，合并为 1 笔完整单据追加写入长期情景记忆（episodic_order_record），避免同一次连续保障被切碎并重复计算次数。
  2. 区分对话明确声明与单据重复行为的权重，将短期变动写入长期情景记忆 —— 参考 PersonaMem-v3 (arXiv:2608.21381)：系统分别为对话显式声明与单据隐式行为配置权重参数 \(w_{\text{exp}}\) 与 \(w_{\text{imp}}\)（满足 \(w_{\text{exp}} > w_{\text{imp}}\)）。对话中说明“今天临时”、“出差这几天”的记录附带有效期 TTL 只写入长期情景记忆（episodic_event_preference），到期自动失效；累计得分低于噪声下限 \(\theta_{\text{noise}}\) 的单次偶发行为不进入长期语义库。
  3. 先放入中期候选池累积，满足跨度与得分阈值后再晋升为长期语义记忆 —— 参考北邮 MemoryOS (arXiv:2506.06326)：常规记录先按“所在区域、应用与业务、时间段”归并到中期候选池（状态标为 candidate）。当同一类记录跨越最小时间范围 \(W_{\text{span}}\) 持续出现，且累计得分达到长期阈值 \(\theta_{\text{long}}\) 时，状态转为正式生效（active）写入长期语义记忆（Semantic Memory），同时清零该候选段的未处理计数。
  4. 偏好变化时保留旧记录并标记失效时间 —— 参考 Zep / Graphiti (arXiv:2501.13956)：当默认档位或常驻时段更新时，给长期语义记忆中的旧记录写入失效时间 \(t_{\text{invalid}}\) 并标为 superseded，同时写入新记录并标为 active（记录生效时间 \(t_{\text{valid}}\)）。

$$R = \exp\!\left(-\frac{\lambda t}{1 + \kappa \ln(1 + n)}\right)$$

符号解释如下：

  1. \(t\)：距离该条记忆最近一次被确认或使用的间隔天数；\(n\)：累计有效出现与被检索命中的次数。
  2. \(\lambda, \kappa\)：分别为基础日衰减率参数与强化系数（作为配置参数按业务周期设定；长期情景记忆中的历史单据记录固定取 \(\lambda = 0\)，不随时间自然衰减，阶段性临时偏好按到期时间戳 TTL 判定失效）。

3 程序化 / 经验记忆要学到什么：从“多轮澄清/理解失败”到“快速闭环”

3.1 经验学习领域的 5 篇代表性论文与核心工作

在 CoALA 的三类长期记忆中，长期语义记忆记录“用户常驻要什么”，长期情景记忆记录“过去具体办过哪些单据且结果如何”，而长期程序化 / 经验记忆（Procedural / Experiential Memory）记录“遇到特定无线场景或歧义情况时，系统该怎么调参与处置（How to do）”。程序化/经验记忆要学习的是具备可迁移性的因果规则与办事流程：在什么条件下（Condition）、因为什么原因（Cause）、该执行什么参数调整规则或消歧流程（Action / Workflow）、执行后实际运行结果如何（Outcome）。表 3.1 列出学术界在智能体程序化与经验学习方向具有代表性的 5 篇核心论文。

1. Reflexion
Shinn et al. (arXiv:2303.11366)		 把任务执行后的环境反馈信号转成文字反思（Verbal Reflection），存进记忆缓冲区，下一次尝试前直接读入短期工作记忆以修正行为。

Wang et al. (arXiv:2409.07429)		 从历史轨迹中归纳经常复用的多步处理流程（Workflows，即显式程序化记忆），离线或在线更新进长期记忆库，帮助智能体在后续同类任务中直接复用成熟流程、减少重复摸索步骤。
4. ReasoningBank
arXiv:2509.25140 (2025)		 从智能体自评的成功和失败经验中提炼可泛化的高层推理策略，实证验证了“同时学成功与失败并抽象成策略”显著优于只存原始轨迹或只存成功流程。
5. 经验跟随实证研究
arXiv:2505.16067 (2025)		 系统分析了检索到的历史经验如何影响当前输出：发现经验与当前输入越相似，模型越倾向于盲目照搬，容易造成错误经验传播与不匹配经验误导；并提出用后续任务的执行结果作为经验质量的验证标签，持续过滤低质经验。

3.3 从长周期记录中定位慢路径源头与正反单据对比提炼

在实际业务流中，慢路径对话与历史单据穿插在大量日常快路径工单与闲聊之间。参考 ExpeL (arXiv:2308.10144) 与 ReasoningBank (arXiv:2509.25140)，系统通过长期情景记忆中的单据号与场景标签串联以下三条记录定位经验源头（见图 3.2）：

  1. 长期情景记忆中的前序同场景异常单据（\(\text{NE}_{\text{bad}}\)）：同一类空间场景下，存在事后实际运行结果为异常（AppQuality = bad，如基站 PRB ≥ 95% 拥塞导致掉帧）的历史单据，或同一地点存在多笔不同规格单据冲突。
  2. 短期工作记忆捕获的多轮澄清或用户纠偏对话（\(S_{\text{slow}}\)）：后续会话中针对该异常或歧义发生多轮追问确认或用户主动纠偏（如“上次开场太卡了，这次提前二十分钟把上行切片开上”，或纠正“对抖音的词其实是微信视频通话”）。
  3. 长期情景记忆中调整参数后的正常单据（\(\text{NE}_{\text{good}}\)）：按沟通后的调整参数执行工单，事后网元实际运行结果恢复为正常（AppQuality = good）。（注：仅做假设性咨询而未实际落单闭环的对话不提炼为程序化/经验规则。）

4.1 滑动窗口切分与否定子句处理

当短期工作记忆接收到包含多个子句的用户长句输入（如“今天不去滨江基地了，今晚七点半在工体中心用小破站开播，别用卡顿那套，照奥体没卡那次办”）时，整句直接转成单个向量会稀释局部口语表达（如“小破站开播”）的权重，而且容易把否定词后面的地点（“滨江基地”）误召回。因此，在向三类长期记忆发起检索（Retrieval）前，先切分子句并处理否定表达（见图 4.1）：

  1. 否定子句分离与权重衰减过滤 —— 参考 BlendX (arXiv:2403.18277)：按标点与连词切分子句，识别带否定词的子句（如“不去”、“别用”、“取消”），提取其中被排斥的地点或状态；如果某条长期记忆候选记录匹配了被排斥项且未被后续正向子句重新指定，将其向量相似度扣减 \(\delta_{\text{neg}}\)。
  2. 按滑动窗口切分短语并匹配向量：对正向子句按窗口长度参数 \(L_{\text{win}}\)、步长参数 \(S_{\text{step}}\) 切分为多个重叠的短窗口，批量编码为向量后与长期记忆库内 phrase_text 的短语向量计算余弦相似度，取所有正向窗口中的最高值作为该记录的向量匹配得分。

4.2 语义、情景、程序化（经验）三类长期记忆并行检索与二阶段关联补全

得到短语窗口的向量匹配结果后，系统通过向量相似度检索定位候选记录，读取同行结构化槽位列，再做二阶段关联表补全，从三类长期记忆中并行检索并读入短期工作记忆（见图 4.2）：

  • 长期记忆 ① — 语义记忆检索（Semantic Memory Retrieval）：正向窗口向量命中 expression（达到相似度阈值 \(\tau_{\text{sim}}\)）后，读取同行 target_col 将口语叫法转为标准应用与业务；若只提到业务而未指定应用，查询 service_to_app 补全默认应用；结合当前时间与地点匹配常驻周期习惯 periodic_preference 或场景常驻偏好 scene_preference（仅查询 active 记录，分开管理常驻主线与外出支线 —— 参考 MemPABench），再通过二阶段关联查询 preferred_value 补齐最新默认分辨率与时长（自动跳过标为 superseded 的旧记录 —— 参考 LongMemEval）。
  • 长期记忆 ② — 情景记忆检索（Episodic Memory Retrieval）：① 查询历史保障单据记录（episodic_order_record）：将口语时间词（如“上周六”）换算为具体日期范围，结合地点向量匹配查询历史单据。如果用户要求“照没卡那次办”，优先保留 app_quality = 'good' 的正常单据并降低同地点 bad 异常单据的排名；如果同一地点命中多笔不同规格单据，则将候选单据及各自运行结果一并读入短期工作记忆；② 查询阶段性事件与临时偏好（episodic_event_preference）：核查当前时间 reference_time 下处于有效期内（未超过 ttl）的差旅事件窗、短期临时降档偏好及最新显式纠正记录，已过期记录（expired）直接过滤。
  • 长期记忆 ③ — 程序化 / 经验记忆检索（Procedural / Experiential Memory Retrieval）：将当前地点归入通用场景类别（如“工体中心”归为“大型演艺与体育聚集场馆”），匹配 procedural_experience 记录的触发条件与多单消歧流程，并检查不适用列表 scope.exclude——如果当前请求属于下行视频点播或普通室内常驻场景，直接剔除该条经验记录。

4.3 综合排序评分与多记忆联合检索

对通过条件过滤的长期记忆候选记录，综合向量相似度、记忆保持率、近期访问热度与置信度加权计算排序得分：

$$S_i = \alpha_i \big(w_s s_i + w_r R_i + w_h h_i + w_c c_i\big)$$

符号解释如下：

  1. \(s_i, R_i, h_i, c_i\)：分别为正向窗口最高余弦相似度（命中否定表达已扣减 \(\delta_{\text{neg}}\)）、时间保持率、近期访问热度与记录置信度；\(w_s, w_r, w_h, w_c\) 为对应的权重参数（满足 \(w_s + w_r + w_h + w_c = 1\)）。
  2. \(\alpha_i\)：状态过滤系数；正常生效记录取 \(1\)，用户指代顺畅体验时的同地点卡顿异常情景单据取降权系数 \(\gamma_{\text{bad}}\)（\(0 < \gamma_{\text{bad}} < 1\)，排在正常单据之后），已替代的旧语义档位（superseded）、已过期的情景临时偏好（expired）或落入不适用列表 scope.exclude 的程序化/经验记录取 \(0\)（直接剔除）。

5.1 短期工作记忆的容量控制与长期检索结果结构化拼装

在 CoALA 架构中，短期工作记忆（Working Memory）是连接外部长期记忆库与大模型推理核心的唯一枢纽。如果把外部长期记忆库中的原始长对话或已失效的历史记录全部塞进短期工作记忆，一方面会超出上下文窗口容量上限，另一方面容易让下游模型混淆当前生效值与历史旧值。参考 CoALA 与 Letta / MemGPT (arXiv:2310.08560) 的工作记忆换页管理机制，系统按以下三项原则将检索出的三类长期记忆拼装进短期工作记忆（见图 5.1）：

  • 常驻摘要与按需明细分离（控制短期工作记忆容量）：短期工作记忆中仅常驻保留当前会话的活跃槽位状态、生效中（active）的长期语义映射/默认档位摘要以及未过期（未超 TTL）的情景临时偏好；长期情景记忆中的具体历史单据明细与长期程序化/经验记忆条目仅在当轮检索命中时按需换入短期工作记忆，且严禁混入标为 superseded 或 expired 的旧记录。
  • 程序化/经验偏移参数预计算与时间算术自洽：当检索命中长期程序化/经验记忆中的提前预热偏移规则（如 start_time_offset_min = -20）时，在读入短期工作记忆时直接基于基准起止时间算好调整后的推荐时间窗与总时长（保证 \(t_{\text{end}} - t_{\text{start}} = \text{duration}\)），避免下游大模型口算时间出错。
  • 同地多笔候选情景单据与状态差异显式呈递：当长期情景记忆在同一地点命中多笔不同规格或不同运行结果的单据（如奥体中心同时存在顺畅单 NE-09 [good] 与卡顿单 NE-05 [bad]）时，在短期工作记忆上下文中明确列出每笔候选单据的单号、规格差异与 AppQuality 运行结果状态，并附上程序化消歧流程供下游使用。

当会话终结且保障单据执行完毕后，系统触发从短期工作记忆向三类长期记忆的写回闭环（Learning）：① 将本次完整单据与网元实际运行结果（AppQuality = good / bad 及实测时延、丢包）作为新事件原样追加写入长期情景记忆（episodic_order_record）；② 将常规执行记录滑入中期候选池累加证据得分，跨越 \(W_{\text{span}}\) 且达 \(\theta_{\text{long}}\) 时晋升写入长期语义记忆（Semantic Memory）；③ 若本次会话在短期工作记忆中经历了慢路径多轮澄清纠偏，则结合情景单据对比提炼新规则写入长期程序化/经验记忆；若本次单据直接复用了已有程序化/经验规则，则根据实际运行结果（参考 arXiv:2505.16067）更新该规则的成功/失败验证计数与置信度，随后清空释放当前短期工作记忆。

5.3 本章小结

本章明确了短期工作记忆与三类长期记忆之间的上下文拼装与写回闭环：通过常驻摘要与按需明细分离控制短期工作记忆长度，屏蔽已替代与已过期长期记录，在读入工作记忆时预计算经验时间偏移以保证起止时间与总时长一致，并在事后根据网元实际运行结果从短期工作记忆写回更新三类长期记忆。

7 总结与工程检查项

围绕 6G NGC 网络体验保障场景，本报告基于 CoALA 架构给出了短期工作记忆（Working Memory）与三类长期记忆（语义记忆、情景记忆、程序化/经验记忆）分层管理的记忆系统方案。工程实现与参数配置时需核对以下四项要求：

工程实现检查项
  1. 长短期分层与分表字段边界：短期工作记忆（working_session_state）仅驻留当前会话内存，维护当轮活跃槽位与检索读入的上下文，会话终结后释放；长期语义记忆的固定时段记录（periodic_preference）不重复保存画质与时延，基础默认档位（preferred_value）的短语向量文本中不带入具体地点词；长期情景记忆（episodic_order_record）逐笔原样保存历史单据与运行结果而不跨单合并；最小有效时长 \(T_{\min}\)、断流合并间隔 \(\Delta t_{\text{gap}}\)、晋升长期语义记忆的时间跨度 \(W_{\text{span}}\) 与得分阈值 \(\theta_{\text{long}}\) 统一放入配置文件管理。
  2. 无效单据过滤与阶段性情景隔离：不足最小有效时长 \(T_{\min}\) 的后台流量记录或中途取消的无效单据在写入长期情景记忆前剔除，间隔在 \(\Delta t_{\text{gap}}\) 内的同业务断流记录合并计算；带有效期 TTL 的差旅或单次临时改动只写入长期情景记忆（episodic_event_preference），到期自动转为 expired，严禁污染长期语义记忆。
  3. 程序化/经验规则的正反单据证据链与排除范围：每条长期程序化/经验记忆记录（procedural_experience）均需关联对应的长期情景记忆前序异常单据（bad）、短期工作记忆多轮澄清对话与调整后正常单据（good）编号，同时将触发条件归纳为通用场景类别，并写明非空的不适用业务列表（scope.exclude）。
  4. Retrieval 读入工作记忆与 Learning 写回长期记忆闭环：检索读入短期工作记忆前自动过滤 superseded 与 expired 记录，叠加程序化经验提前预热偏移后在工作记忆拼装层核对 \(t_{\text{end}} - t_{\text{start}} = \text{duration}\)；单据执行完毕后根据网元实际运行结果从短期工作记忆异步追加长期情景单据并更新程序化/经验规则的验证计数与置信度。
