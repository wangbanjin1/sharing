1 四类记忆正交架构与双索引存储设计

1.1 单层向量库混存的局限性

在 6G NGC 移动网络体验保障场景中，联接 Agent 同时处理两类异构信息源：一类是占总量约 75% 的网元结构化保障单据与事后体验回执（包含基站小区 CGI、位置语义、起止时间、上下行吞吐、时延丢包以及体验评估标签 AppQuality=good/bad）；另一类是占约 25% 的用户自然语言多轮对话（包含口语简称、历史工单指代、中途改口与多轮澄清）。若采用常规 RAG 做法，将所有对话摘要与历史单据平铺写入单一向量库，在实际长周期运行中会出现四类典型问题：

  1. 自定义简称与常驻参数耦合污染：用户口头使用的“破站开播”、“打排位”等个性化简称，若与某次具体工单的地点（如“奥体中心”）和时长混存在同一段文本向量中，当用户回到常驻基地再说“破站开播”时，检索器会连带召回上次场馆的特殊参数，造成跨场景参数串味。
  2. 单次偶发单据与背景短单篡改常驻习惯：用户在工作日晚间因暴雨临时将户外推流降为 720p，或后台产生 1~8min 的短视频浏览碎片单；若不区分“单次已发生事实”与“多次重复验证的常驻习惯”，单次记录会直接覆盖用户长期稳定的 4K 直播默认档位。
  3. 同地正反双单缺乏回执极性区分：用户上周六在鸟巢先后产生两笔工单（一笔抖音上行推流体验顺畅 AppQuality=good，另一笔快手看直播卡顿劣化 AppQuality=bad）。当用户再次到达场馆并说“照上周六没卡那单办”时，纯语义向量检索对两笔同地工单的余弦相似度几乎相同，极易误选失败单参数。
  4. 慢路径澄清结论未能沉淀为可泛化规则：首次在大型聚集场馆开播时，因开场空口高并发拥塞及同晚预约重叠，Agent 经过 2~3 轮慢路径追问才对齐“需提前 20 分钟开启 6G NGC 上行专网切片”；若只保存最终工单而不单独提炼“触发条件 $\rightarrow$ 原因 $\rightarrow$ 参数调整规则 $\rightarrow$ 适用边界”，下次用户换到工人体育场或换种口语说法时，系统仍会退化回多轮追问，或者在用户仅看下行视频点播时错误套用上行预热规则。
设计约束：禁止单层文本块混存与跨子类型槽位耦合

将“用户静态属性”、“单次历史工单台账”、“常驻周期与场景习惯”以及“冲突与拥塞调参规则”混装在同一向量条目中，会导致更新机制冲突（原样追加、满阈值晋升与新代旧覆盖相互覆盖）并稀释短词向量的余弦相似度分布。

1.2 四类记忆的职责切分与演化规律

结合认知长时记忆分类与 memory_system 的工程实践，系统按决策职责与生命周期更新规律，将记忆体系划分为四类独立存储、协同检索的模块：

  • 事实记忆 — 语义记忆（Factual - Semantic Memory）：解决“用户是谁、口语简称指代什么、基础权益与默认档位是什么”。涵盖用户身份与 6G NGC 套餐加速包权益上限、个性化表述映射层（expression：如“破站开播” $\rightarrow$ bilibili:openlive）、无主业务到常驻 APP 绑定（service_to_app）以及全局基础默认 QoS 档位（preferred_value）。此类记忆通过显式声明直通或跨单据归纳生成，发生套餐升级或偏好迁移时执行新代旧覆盖（superseded）。
  • 事实记忆 — 情景记忆（Factual - Episodic Memory）：解决“过去具体哪一天、在什么地点办过哪笔单、网元实际回执好不好”。对应历史具体保障工单与网元回执台账（episodic_record）。此类记忆是客观发生过的历史事实，遵循“一单一记录按时间原样追加、不跨单合并、不随时间衰减”原则，支撑跨周特定单回溯（“照上周六没卡那单办”）与单次临时改期隔离。
  • 程序化记忆（Procedural Memory）：解决“在特定周期时间窗或特定空间场景下，默认按什么标准流程与规格执行保障”。涵盖周期时间窗路由指针（periodic_preference，如工作日午间 12:00~13:30 绑定抖音推流）与特定空间场景默认档位及降级底线（scene_preference，如常驻直播基地与高速大巴移动视频会议）。此类记忆要求连续一致重复达 ≥ 3 次（跨度 ≥ 7 天）方能从中期候选池（candidate）晋升为长期生效态（active），长期未触发时按时间保持率自然冷衰减。
  • 经验记忆（Experiential Memory）：解决“遇到特定无线风险或历史多单冲突时，系统如何主动调整参数或选择快慢交互路径”。将首次慢路径多轮澄清与同地正反单据回执对比（bad 与 good）提炼为结构化因果规则卡（experience_card：含触发条件 condition、问题原因 cause、参数调整规则 recommended_adjustments、回执结果 outcome 及适用与不适用边界 scope），使后续同类场景请求从 2~3 轮慢路径追问收敛为 1 轮快路径直办闭环。

1.4 四类记忆正交 Schema 与字段边界对照

为避免短词向量池被无关修饰词稀释，memory.db 执行“左结构化槽位列 + 右高纯度短词向量列”的正交分表规范：每类记忆子项只允许在结构化列中保存本层职责内的槽位，且右侧 phrase_text 限制为 4~10 字的核心触发短词。表 1.1 给出了四类记忆（共 7 个存储子项）的完整 Schema 与字段边界：

experience_card		 scene_type | biz_type | risk_tag condition（高层场景+业务+无线特征）, cause, recommended_adjustments（如 lead_time: -20m, slice: 6G-A/NGC）, scope（include / exclude）, evidence_ids, confidence 抽象触发短语（如 "大型聚集场馆 上行高清推流 演艺赛事"）；慢路径澄清+正反回执验证生成，按后续回执动态调权
设计要点：周期时间窗指针（periodic_preference）与默认档位（preferred_value）解耦

periodic_preference 仅存储“时段 $\rightarrow$ 应用与业务 + 空间场景”的路由关系，不存储具体画质或时延。当用户升级 6G NGC 套餐并将 preferred_value 更新为 4K 时，检索阶段通过二阶段关联表补全实时拉取 preferred_value 的最新档位，避免旧周期记录中残留过期画质。

1.5 本章小结

2 记忆萃取与短期到长期演进机制

2.1 双模态输入流特征与萃取难点

在长周期运行中，记忆萃取管线持续摄入 30~90 天内交织到达的网元结构化单据与多轮会话，面临三个工程问题：

  1. 网元单据流存在碎片噪声与切换断流切分：蜂窝网侧既有持续 60~180min 的真实保障主单，也夹杂 1~8min 的后台消息推送短单，以及用户在移动或基站负载均衡下产生的“断流重连子单”（一次 90 分钟直播被切为两笔间隔 1 分钟的子单）。直接按原始单据计数会导致伪习惯误晋升或真实频次漏计。
  2. 单次临时改期与长期习惯迁移混杂：当某天单据或对话出现新参数（如平时每晚 20:00 播 120min，某天改为 21:00 播 60min），系统需区分“单次临时变动（temporary）”与“新常驻习惯的起点”，防止偶发脉冲污染长期程序化记忆。
  3. 经验记忆的慢路径源头样本淹没在长周期混杂流中：给定一段单独挑出的多轮澄清对话提取“条件 $\rightarrow$ 动作”规则较为直接；但在实际系统中，并没有预先标注哪一轮对话、哪两笔单据构成了一次经验学习事件。系统必须从数十笔日常单据、背景短单和闲聊会话中，定位出“前序参数不足导致体验劣化或冲突 $\rightarrow$ 慢路径多轮追问纠偏 $\rightarrow$ 参数调整后回执恢复正常”的因果事件链。

2.3 记忆保持率衰减与状态流转规则

对于事实-语义记忆与程序化记忆，每条记录维护跨日期去重后的正向证据票数、检索复用次数以及生命周期状态（candidate 初筛候选 $\rightarrow$ active 生效 $\rightarrow$ reinforced 稳固 $\rightarrow$ superseded 被新档位替代）。为体现“重复与复用次数越多、遗忘越慢”的规律，每条记录的时间保持率 $R(t, n)$ 按带复习强化因子的指数衰减公式计算：

$$R(t, n) = \exp\left(-\frac{\lambda}{1 + \kappa \ln(1 + n)} \cdot \Delta t\right)$$

符号解释如下：

  1. $n$：有效复习与复用总次数，等于超出首票的复现票数与下游检索命中复用次数之和。
  2. $\kappa$：记忆强度增强系数（默认取 $0.8$）；$n$ 越大，分母越大，时间衰减越平缓。
  3. $\lambda$：基础时间衰减率；程序化记忆默认取 $\lambda = 0.03\text{ d}^{-1}$，而事实-情景记忆台账（episodic_record）与经验记忆规则卡（experience_card）固定取 $\lambda = 0$（历史工单不随时间衰减，经验卡仅按事后回执准确率动态调权）。
  4. $\Delta t$：当前会话基准时间距离该记忆最近一次被证实或被访问的天数。

2.4 经验记忆萃取：混杂流慢路径源头定位与正反单差分提炼

在长周期混杂流中，系统通过慢路径经验源头三元锚定准则自动识别需要提炼为经验记忆的事件链。当时间轴上出现同时满足以下三项条件的关联序列 (NE_bad, S_slow, NE_good) 时，触发经验记忆萃取器：

  1. 前序异常或冲突锚点（NE_bad 或多单冲突态）：在同类空间场景（如大型体育场馆、跨城高铁）与同业务下，存在前序网元单据回执劣化（AppQuality = bad，如上行丢包率偏高、多次卡顿），或存在同地多笔不同规格单据冲突、同晚预约单重叠。
  2. 慢路径澄清与纠偏会话锚点（S_slow）：会话交互轮数 ≥ 2，且包含系统消歧反问动作（A3 / A7）或用户显式纠偏/抱怨指代动作（U2 / U9 / U10，如“上次在五棵松开场卡死了”、“照没卡那次办，提前二十分钟把切片开上”）。
  3. 后验正向回执闭环锚点（NE_good）：会话 S_slow 达成共识下发的参数所生成的网元单据 NE_good，其事后网元回执验证为顺畅（AppQuality = good，零卡顿）。

锁定三元事件链后，萃取器对比 NE_good 与 NE_bad 的结构化参数差异，提取出真正生效的参数调整规则（recommended_adjustments，如起点平移 -20min、时长增加 +20min、开启 6G NGC 上行切片），同时完成两项关键泛化与边界处理：

经验卡的高层场景抽象（condition）与反向排除边界（scope.exclude）

1. 高层场景抽象支撑跨场馆泛化：将具体基站小区 CGI 与具体场馆名（如“北京奥体中心”）向上抽象为无线场景类别 scene_category = "大型演艺与体育聚集场馆"，具体单号仅存入 evidence_chain。当用户后续前往“工人体育场”或“五棵松体育馆”开播时，仍可通过场景类别匹配召回该经验卡。

2. 反向排除边界拦截字面相似异类请求：根据正反单的业务方向与无线特征，显式写入不适用列表 scope.exclude = ["下行视频点播 (live_watch / vod)", "普通室内常驻基地", "非赛事演出空闲时段"]。当用户在同场馆看台上刷短视频点播或在家中室内直播时，检索层据此直接拦截，防止误触发场馆上行专网切片预热。

3.1 自然语言长句检索难点

当用户在当前会话发起一条自然语言请求（例如：“今天不去滨江基地了，今晚七点半在工体中心用小破站开播，别用上次卡顿那套参数，照没卡那次办”）时，如果直接将整句 Query 编码为单个向量去检索记忆库，会面临三个检索瓶颈：

  1. 长句编码导致局部短词语义稀释：一句话内同时包含地点转折（“不去滨江基地”、“在工体中心”）、时间（“今晚七点半”）、个性化简称（“小破站开播”）与历史工单体验指代（“照没卡那次办”）。整句编码后，4~6 字的口语简称（如“小破站开播”）在全局向量中的权重被稀释，导致余弦相似度低于召回阈值。
  2. 否定子句引发反向误召回：子句“今天不去滨江基地了”与“别用上次卡顿那套”包含实体词“滨江基地”，纯向量检索会因字面高重合度优先召回“滨江基地”的常驻记忆，造成否定污染。
  3. 四类记忆的命中条件与跨表关联逻辑不同：语义简称需要查表解码，程序化周期习惯需要对齐时间窗，情景工单需要换算相对日期并按 AppQuality=good/bad 过滤，经验规则则需要跨越具体地名做高层场景泛化并剔除不适用业务。单一向量 Top-k 排序无法同时满足这四类异构约束。

3.3 四路差异化检索路由与综合排序评分

对于通过结构化过滤与生效状态校验（status IN ('active', 'reinforced')）的候选记忆记录 $r_i$，系统结合有效向量相似度、时间保持率、近期访问热度与证据置信度计算综合排序分 $\text{Score}(r_i)$：

$$\text{Score}(r_i) = \Big(0.50 \cdot \text{sim}_{\text{eff}} + 0.20 \cdot R(t, n_i) + 0.10 \cdot \text{heat}_{\text{eff}} + 0.20 \cdot \text{conf}_i\Big) \cdot \Phi_{\text{gate}}$$

符号解释如下：

  1. $\text{sim}_{\text{eff}}$：跨正向滑动短窗的最大余弦相似度（若命中否定子句实体则扣减 0.35）。
  2. $R(t, n_i)$ 与 $\text{heat}_{\text{eff}}$：分别为第 2.3 节计算的记忆时间保持率与 7 天半衰期访问热度。
  3. $\text{conf}_i$：该记忆记录当前的证据置信度（范围 0.60 ~ 0.95）。
  4. $\Phi_{\text{gate}} \in \{0,\, 0.2,\, 1.0\}$：四类记忆业务门控乘子——在情景记忆路由中，当用户指代正向体验（“照没卡那次办”）时，对 app_quality = 'bad' 的卡顿单取 $\Phi_{\text{gate}} = 0.2$ 进行降权压制；在经验记忆路由中，若当前请求落入反向排除边界 scope.exclude（如在场馆内看下行点播），则取 $\Phi_{\text{gate}} = 0$ 直接剔除。

4.1 原始检索记录直塞上下文的缺陷

在完成四路记忆检索后，若直接将 Top-k 原始 JSON 记录拼接到 System Prompt 中，由对话大模型自行判断何时直接出单、何时发起反问以及如何加减预热时间，在工程评测中会出现两类高频问题：

  1. 盲目抢跑：当情景记忆中同一地点存在两笔不同业务规格的历史单（如既有“抖音开直播 4K”，又有“快手看直播 1080p”），或用户口误将常驻的“开直播”说成“看直播”，且当晚已有预约单重叠时，大模型容易直接挑选排名第一的记录生成派单指令，触发一票否决红线。
  2. 过度澄清与时间算术不一致：当四类记忆已经完备补齐了全部 7 个核心槽位且命中了高置信度场馆预热经验卡（本应 1 轮快路径直办）时，大模型却因历史单与当前时间不同而向用户重复确认时长；或者在执行“提前 20 分钟开启并顺延时长”时出现起止时间与总时长算术不自洽（end - start != duration）。

大模型在处理跨小时边界的时间加减（如 19:30 提前 20min 变为 19:10，结束时间保持 21:30 不变，总时长应变为 140min）时容易出现起止时间与时长不一致。由 fastpath.py 在注入前用确定性代码计算合成后的起止时间与总时长并直接写入注入卡片，可确保终态参数 100% 满足自洽断言。

6.1 核心设计总结

整套认知记忆系统从底层表结构到上层上下文注入遵循三条设计原则：

  1. 分类正交化（四类记忆分库治理）：将事实-语义记忆（身份权益、expression 简称映射、service_to_app、preferred_value）、事实-情景记忆（episodic_record 历史单据与好坏回执，一单一记录追加零衰减）、程序化记忆（periodic_preference 与 scene_preference，满 3 次晋升）与经验记忆（experience_card 因果调参规则与适用边界）物理分离，配合“左结构化槽位列 + 右 4~10 字短词向量”双索引表，消除跨层参数污染。
  2. 经验可定位、可泛化、可约束：针对经验记忆的三项工程难点——在萃取侧通过“前序差单 + 慢路径澄清会话 + 修正后好单”三元锚定与正反槽位差分从长周期混杂流中定位源头；在检索侧通过场景特征高层抽象实现跨场馆与跨说法泛化召回；在门控侧通过校验 scope.exclude 拦截场馆内看点播或普通室内直播等字面相似异类请求。
  3. 检索结构化与注入确定化：用“6~10 字滑动窗口向量匹配 + 否定子句分离 + 同行结构化槽位提取 + 二阶段关联表补全”替代粗放的长文本相似度检索；用注入前的确定性三路门控与代码层时间偏移算术合成替代大模型自由推演，将首次慢路径多轮澄清稳定转化为后续同类请求的 1 轮快路径闭环。
工程落地四项核查清单（Engineering Checklist）
  1. Schema 正交核查：检查 extractor.py 与 index.py，确保 periodic_preference 中不含画质/时延字段，preferred_value 的 phrase_text 中不混入地点词，所有短词向量控制在 4~10 字。
  2. 短期防污染核查：确保时长 < 10min 的背景短单在预处理阶段被滤除，间隔 ≤ 3min 的同业务断流子单合并计票，且带 is_temporary_override=true 的单次改期记录仅写入情景记忆台账，不进入程序化候选池。
