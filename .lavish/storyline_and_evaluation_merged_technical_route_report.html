1 故事线的正交因子方法论（排布层与内容层解耦设计）

1.1 故事线两层解耦设计思路

面向移动网络体验保障（联接 Agent）的长期记忆与多轮意图评测，需要构造跨度数周至数月、包含自然语言对话与网元单据的长周期测试数据，覆盖记忆萃取（偏好抽取、合并更新、分场景组织、画像生成、噪声抑制）与记忆检索（直接、排序、条件、排除、组合、缺失拒答）的各项测试点。

然而，传统的固定剧本模板或单层平铺变量表在实际构造中面临三方面局限：其一，时间线排布与事件内容耦合，调整干扰密度或主支线穿插方式时会影响单点业务内容；其二，同层因子之间存在条件依赖或跨层重复，例如将受时间窗口约束的“事件规模”与“时间跨度”并列，将仅在存在支线时生效的“支线归宿”与“事件线结构”并列，或在排布层与内容层重复定义“偏好演进”与“闲聊干扰”；其三，边界与噪声场景覆盖不足，缺少对负向排斥偏好、短期临时偏好过期、未提及属性拒答边界以及闲聊、试探、情绪发泄、单次偶发等非偏好噪声的控制参数。

为此，参考 PersonaMem-v3、LoCoMo、DynamicMem、MemoryAgentBench 与 LongMemEval 的主流做法，我们将故事线生成解耦为排布层与内容层两层结构（图 1）：

  • 第一层定排布（时间线与多任务穿插结构）：控制整条时间线的跨度、事件规模与疏密分布、主支线任务的穿插关系、跨期演化趋势以及测试点编排。具体而言，当用户诉求包含主线与支线交织（或单轮复合意图）时，系统在入口处先通过意图拆解（Intent Decomposition）将其拆分为彼此独立的业务任务（task_id）；每个任务映射至对应的业务场景（scenario_id），时间轴上的主支线交织即体现为不同业务任务之间的交替执行、同一时间窗并发或中断恢复。
  • 第二层定内容（业务画像属性与分场景独立记忆）：按“用户级 → 业务场景/任务级 → 节点级”三级粒度，覆盖用户身份与资产、应用与业务行为、时空轨迹与流量、网络环境与 KQI 偏好、信息来源与噪声干扰、多轮交互与反馈纠正六个维度。在此基础上，每个用户按不同的业务场景（scenario_id）各自维护一份独立的场景记忆分片（Scenario-Scoped Memory）；与此同时，由于单个用户的日常活动范围有限，每个用户并不一定在所有业务场景下都存在记忆（Sparse Scenario Coverage）——系统仅在该用户实际发生并达到沉淀门限的业务场景下建立记忆分片，未涉及的业务场景则自然留空（null）。
工程落地边界补充：三层信息可见性隔离与四类时间维度区分

1. 三层信息可见性边界隔离（防止全知视角信息泄漏（Omniscient Data Leakage））：

  • 故事层（作者设定真值，Ground-Truth Story State）：包含人物真实职业、家庭借用关系、活动线真实业务目的及细粒度房间状态，仅供数据生成器与标准答案推导使用；
  • 观测层（Agent 物理可见记录，Observable Records）：严格遵循真实系统触发机制——网元单据均为单次网络保障任务结束后的事后统计上报（仅含起止时间、基站小区标识 cell_id、应用名、吞吐量、时延抖动与卡顿异常记录，不含室内房间名或主观借用原因），自然语言对话（Sessions）仅在用户主动发起咨询、报障、改期或预订时稀疏产生；
  • 评测层（测试截止点可答范围，Cutoff-Valid Scope）：给定评测截止时刻 \(t_{\text{cut}}\)，Ground Truth 答案仅允许依赖到达时间满足 \(t_{\text{arrive}} \le t_{\text{cut}}\) 的已观测记录推导；任何仅在作者设定中存在但截止前未露出到观测层的属性均归入“当前未知（需拒答或主动澄清）”。

2. 四类时间维度显式区分：每条记录显式区分事件实际发生时间 \(t_{\text{event}}\)、未来预约计划时间 \(t_{\text{plan}}\)、单据统计窗口 \([t_{\text{start}}, t_{\text{end}}]\) 与 单据到达/可见时间 \(t_{\text{arrive}}\)。当网元单据存在批处理延迟上报（\(t_{\text{arrive}} > t_{\text{end}}\)）或乱序补报时，处于 \([t_{\text{end}}, t_{\text{arrive}})\) 区间内的测试点严禁引用尚未到达的单据。

3. 入口意图拆解（Intent Decomposition）与分业务场景稀疏记忆管理：① 先拆解任务再路由场景：面对主支线交织或复合诉求，系统在入口处先通过意图拆解将其拆分为独立的业务任务（task_id，如基地固定直播任务、高速大巴移动会议任务、高密场馆赛事推流任务、播前视频对词任务），每个任务各自具备独立的终端、应用与 KQI 目标，避免不同任务的参数在同一槽位表内相互覆盖；② 每个业务场景各自存一份记忆且允许场景留空：每个用户（user_id）名下按业务场景（scenario_id）分别存储各自的长期记忆（语义记忆、情景单据记录与程序化/经验记忆）。然而，具体到单个用户，其业务场景覆盖是稀疏的（即每个用户不一定每个业务场景都存在）——未发生过或仅偶发 1 次未达标的业务场景在该用户名下保持为空（null）；反之，当测试请求落入该用户尚未建档的陌生业务场景时，系统不得跨场景借用其他任务的参数硬套，而应如实拒答或转入慢路径追问。

CoALA（arXiv:2309.02427）短期记忆与长期记忆分层管理说明
  • 短期记忆（Short-Term Memory）—— 仅含工作记忆（Working Memory）：仅在当前单次会话存活的瞬时上下文草稿板，维护本轮输入、多轮澄清/中途改口中间槽位状态，以及当轮通过 Retrieval 从三类长期记忆读入的活跃记忆上下文；会话结束后释放。
  • 长期记忆（Long-Term Memory，跨会话持久保存）—— 含以下三类长期记忆： ① 语义记忆（Semantic Memory，事实记忆—语义层）：跨周期常驻的主力业务、周期作息习惯、分场景常驻偏好、默认档位与口语映射； ② 情景记忆（Episodic Memory，事实记忆—情景层）：包含每次历史保障单据记录与网元实际运行结果（SerialNo、good/bad，按单原样追加、不合并、不衰减）以及绑定具体时间窗的差旅/赛事事件与带 TTL 短期临时偏好； ③ 程序化 / 经验记忆（Procedural / Experiential Memory）：从短期工作记忆慢路径澄清与长期情景单据正反对比中提炼的因果调参规则、同地多单消歧流程（Workflows）与交互策略。

1.5 两层组合规则、配置表结构与跨 3 个月完整组合示例

第一层排布因子与第二层内容因子组合为具体故事线时，遵循以下工程规则：

  1. 先定时间线结构，再按三级粒度填内容：先从第一层采样得到时间线结构；再按取值粒度填第二层——“用户”级因子整条故事线取一次，“线”级因子每条事件线取一次，“节点”级因子每个事件节点独立取一次。
  2. 主从层级条件采样（消除父子条件冲突）：先采样主因子，再在其范围内采样对应子因子。例如先定1. 时间跨度，再定与之匹配的1.1 事件规模与1.2 事件密度；仅当3. 事件线结构包含支线时才采样3.1 支线触发事件与3.2 支线归宿；仅当10. 网络异常 ≠ 无异常时才采样10.1 异常发生阶段。
  3. 声明式合法性约束（不写死在代码分支中）：只排除物理或逻辑冲突的组合，并统一声明在配置表的 constraints 列表中（例如排除“时间跨度 2 周与按月周期规律”、“平稳保持型节奏与套餐跨期升降级”、“仅网元单据体现与对话显式直接陈述”）。
  4. “先答案后会话”反向真值绑定与分阶段构建策略：前期与中期采用“先定义答案、再反向生成会话”路线（参照 LongMemEval、DynamicMem、PERMA）：① 先定义评测骨架（测试维度、测试目的与难度分布）→ ② 先写出结构化标准答案（萃取侧写明 gold_profile 的生效值、过期值、来源与置信度，检索侧写明 gold_answer 与 gold_memory_ids）→ ③ 按成对覆盖（Pairwise Coverage）采样两层因子，反向生成能唯一推导出该答案的自然语言对话与网元单据序列 → ④ 通过多 LLM 交叉验证检验对话自然度与答案唯一性；到后期上线阶段再结合“先有真实会话、后抽检标注答案”路线（参照 LoCoMo、MemoryAgentBench）补充长尾边界样本。
  5. 增量扩展：新增测试维度时，直接在对应因子类别下补充主因子或子因子定义，不影响已有因子与数据。

从两层因子到双模式记录的六步构造流程与多源逐字段融合顺序

从两层因子配置到生成单据与对话样本分为六个步骤，合成 Ground Truth 快照时对应表 1.5 的六步逐字段融合规则：

  1. 第 1 步（选定评测目标与人物基底）：锁定故事线要考核的核心记忆或交互能力，从人物库选定匹配的人物基底（固定职业、常驻空间、终端主备分工与口语词典）。
  2. 第 2 步（主支线意图拆解为独立业务任务并绑定业务场景）：在前期意图拆解阶段，将人物的主线与支线直接拆解为 2~4 个独立的业务任务（task_id），每个任务绑定全量场景池中的一个具体业务场景（scenario_id），明确各任务之间属于独立交替穿插、主次支持、同一时间窗并发争抢（Concurrent Window Contention）还是打断恢复关系；该用户未分配任务的其余业务场景标记为“未覆盖场景（uninitialized_scenarios）”。
  3. 第 3 步（按主从层级与跨维约束具体化因子）：先采样主因子再采样条件子因子，过滤逻辑冲突组合。
  4. 第 4 步（构建关键事件前后状态中间表）：在展开具体记录前，先填写关键事件前后状态表（Intermediate State Table），锁定每次状态跃迁的发生时间、触发原因、事件前状态、事件后新状态、以及网元单据可观测项（仅单据可见）与对话补充项（仅单据+对话可见）的边界。
  5. 第 5 步（展开日常排期与并发/延迟窗口）：围绕关键事件铺设周期日常事件与背景干扰，计算满足 end - start == duration 的时间戳，并按需注入单据延迟到达（\(t_{\text{arrive}} > t_{\text{end}}\)）、短时误触撤单或家庭成员临时借用等扰动。
  6. 第 6 步（投影为 “仅单据 / 单据+对话”双输入模式记录并绑定截止点真值）：将事件流投影为仅单据输入版与单据+对话混合输入版输入，并按测试截止时刻 \(t_{\text{cut}}\) 与下方表 1.5 的六步融合顺序生成 Ground Truth 记忆快照与测试问答对。

11. 模糊量词与相对比较级修饰 “把延迟弄得比昨天再稳一点”、“换个稍微划算些的套餐” 少量覆盖（FinInteract 2609.24002、IN3 2402.09205） 欠缺将模糊比较级（“更稳/稍微快点”）结合历史基线数值转化为可量化参数或触发阈值追问的测试。
12. 跨表同名实体歧义与域外相似混淆 名下有两张副卡或两条同地点的历史保障单据；或诉求酷似业务内实则属跨界 OOD 手机硬件维修 OOD 覆盖较充分（DROID 2510.14110、Beyond the Known 2402.17256） OOD 识别多为静态单轮分类，欠缺“用户账户下真实存在多个同名/同类实例，必须核对工作记忆状态才能判断该问还是该办”的设计。

（Illegal Input Rate）		 实际投喂给 Agent 的输入中，混入了 \(t_{\text{arrive}}(r) > t_{\text{cut}}\)（未来或尚在延迟途中的记录）或混入了非当前模式记录（如向“仅单据”输入测试投喂了对话）的比例。 防止测试输入发生未来时间穿越或输入模式混淆。
指标 3：不可见引用率
（Invisible Citation Rate）		 样本标注的标准答案或Ground Truth 证据集 \(E^*\) 中，引用了截止时刻 \(t_{\text{cut}}\) 不可见记录（\(r \notin V(t_{\text{cut}})\)）或作者隐藏设定字段的比例。 拦截在“仅单据”输入题目的标准答案中要求模型答出仅对话才提到的信息，或在周二晚引用周三才到达的延迟单据。
指标 4：答案无支持率
（Unsupported Answer Rate）		 即使给定全部可见证据 \(V(t_{\text{cut}})\)，标准答案中的某个槽位结论仍无法由 \(V(t_{\text{cut}})\) 逻辑推出的比例。 拦截标准答案自身无中生有。
指标 5：答案矛盾率
（Contradictory Answer Rate）		 同一测试点下的标准记忆快照、Ground Truth 证据集与期望决策槽位之间存在逻辑冲突的比例。 拦截记忆快照标为 v2 (90min) 但下游期望工单仍按 v1 (60min) 判分的标注不一致。

4.3 证据充分性（Sufficiency）、最小性（Minimality）与受控扰动一致性测试（Metamorphic Testing）

在第四层Ground Truth 校准中，为确保每道评测题所标注的Ground Truth 证据集合 \(E^* \subseteq V(t_{\text{cut}})\) 既不缺失关键依据、也不塞入无关背景单据，我们要求每个充分证据子集 \(E \in \mathcal{E}^*\)（允许存在多个等价充分证据集 \(\mathcal{E}^* = \{E_1^*, E_2^*, \dots\}\)）同时满足充分性（Sufficiency）与最小性（Minimality）两项形式化条件：

$$\text{Sufficient}(E, y^*) \iff f_{\text{verify}}(E) = y^*, \qquad \text{Minimal}(E, y^*) \iff \forall e \in E,\; f_{\text{verify}}(E \setminus \{e\}) \neq y^*$$

符号解释如下：

  • \(E \subseteq V(t_{\text{cut}})\)：在评测截止时刻 \(t_{\text{cut}}\) 下的一组可见候选证据子集（包含网元单据或对话片段）；
  • \(y^*\)：该测试题的目标标准结论（如当前生效的习惯参数或排障决策）；
  • \(f_{\text{verify}}(\cdot)\)：严格仅依赖输入证据集合进行受控推导的验证器（在不引入外部猜测时，判断能否唯一导出 \(y^*\)）；
  • 充分性（Sufficiency）要求仅凭子集 \(E\) 即可完整、无歧义地推导出标准答案 \(y^*\)；最小性（Minimality）要求 \(E\) 中不含任何冗余记录——只要从 \(E\) 中删去任意一条记录 \(e\)，剩余集合 \(E \setminus \{e\}\) 就不再足以唯一导出 \(y^*\)（退化为信息不足或退回旧版本结论）。
充分性与最小性校准计算示例：{D1, D2, R1} 组合证据核验

【测试问题】：在实例二（USER_002）第 3 周周三下午提问：“周四晚 20:00–21:30 远程培训期间，若有工程数据包待上传，系统应如何安排网络保障与上传任务？”

【目标结论 \(y^*\)】：保障周四 20:00–21:30 远程培训视频会议（保语音不断、画质目标 1080p / 最低可降 720p），并将后台工程包上传任务推迟至 21:30 培训结束后执行。

【候选证据集核验】：设 \(D_1\) 为周二/周四 20:00–21:30 常规培训基线单据，\(D_2\) 为 E05 培训与上传同一时间窗并发导致会议跌至 540p 且语音断续的冲突单据对，\(R_1\) 为 E06 用户明确“保语音、最低 720p、上传推迟到九点半后”的排障确认对话，\(D_{\text{noise}}\) 为周日误触撤单 D04：

  • 充分性检验：给定 \(E^* = \{D_1, D_2, R_1\}\)，\(f_{\text{verify}}(E^*)\) 可完整导出周四常驻时段、并发劣化根因与用户确认的错峰推迟及降级底线，故 \(\text{Sufficient}(E^*, y^*) = \text{True}\)。
  • 最小性（留一法消融）检验： 1）若删去 \(R_1\)，仅凭 \(\{D_1, D_2\}\) 虽知并发劣化，但无法得知用户允许画质最低降至 720p 及同意推迟上传的具体安排，\(f_{\text{verify}}(\{D_1, D_2\}) \neq y^*\)； 2）若删去 \(D_1\)，无法确认周四 20:00–21:30 为常驻周期培训窗口； 3）若有人将 \(D_{\text{noise}}\) 混入得到 \(E' = \{D_1, D_2, R_1, D_{\text{noise}}\}\)，由于删去 \(D_{\text{noise}}\) 后仍能完整导出 \(y^*\)，故 \(E'\) 违反最小性，审查脚本自动剔除 \(D_{\text{noise}}\)。

在第五层与第六层审查中，首先检查数据集层面的因子成对覆盖率（Pairwise Coverage）并计算故事状态转移序列的结构编辑距离以剔除表层改写但结构同构的重复样本（Isomorphic Duplicate Samples）；随后执行表 4.2 所示的 8 类受控扰动一致性测试（Metamorphic Testing）——对已有合格样本施加确定性扰动算子 \(\mathcal{T}\)，检验标准答案与待测系统输出是否发生符合因果逻辑的同步转移。

  • 1. 子集可测性分母条件：每项细粒度指标仅在具备对应触发条件的样本子集上核算分母（例如“偏好整合与状态更新率”仅在含跨期变更或双源冲突的样本上计算分母，“未知拒答率”仅在截止时刻 \(t_{\text{cut}}\) 证据缺失或含虚假前提的样本上统计，避免被普通全参样本稀释）。
  • 2. 多等价最小充分证据集合簇 \(\mathcal{E}^* = \{E_1^*, E_2^*, \dots, E_M^*\}\)：当历史流中存在多组同分布记录均可独立支撑同一常驻习惯时，阶段 2 的召回率按最优等价子集核算 \(\text{Recall}@k = \max_{E_m^* \in \mathcal{E}^*} \frac{|Q_k \cap E_m^*|}{|E_m^*|}\)，只要 Top-\(k\) 完整覆盖任意一组最小充分证据集 \(E_m^*\)，即判为跨层证据齐备（\(\text{Hit}_{\text{all}}@k = 1\)）。
  • 3. 旧记录作为必要因果对照时不机械判负：在“对比上次失败原因”或“核对套餐变更前后差异”类题目中，历史劣化单据（如 NE-10）或旧版记录属于必要对照项，召回时赋予正相关度（\(\text{rel}=1\)）；仅当系统在常规建单中把已作废旧值或劣化单当作当前执行模板排在首位或直接套用时，才触发排序折损与一票否决（\(V_{\text{veto}}=1\)）。
  • 4. 在“决策正确且未越权（\(V_{\text{veto}}=0\)）”前提下统计无效追问减少率与 \(\text{pass}^3\)：所有快路径轮次节省指标均以终态槽位正确且未违规调写接口为前置条件，并统计独立运行 3 次全部通过的一致性比例 \(\text{pass}^3\)。

5.2 核心指标的判分逻辑与精简算式表达

阶段 1 的抽取召回率与误抽率、阶段 2 的召回率及阶段 3 的克制率均为直观的比例统计（命中样本数除以总样本数）。全流程中保留两个核心算式：一是阶段 2 衡量“最新生效记录有没有排在旧记录/异常单前面”的时效分级排序分 NDCG@k；二是阶段 3 衡量“红线一票否决与三层记忆顺应”的受控决策得分 Score。

第一，在阶段 2 的排序评估中，当工作记忆存在同地多单冲突（如上周六在鸟巢既有下午顺畅单 SN_A、又有晚上卡顿单 SN_B）或事实记忆新旧交替时，即便两条记录都进入前 5 条，若卡顿单或过期旧记录排在第 1 位，下游模型仍易误用错误参数。因此按分级相关度 $\text{rel}_i$（当前生效事实/目标正常工单/对应经验规则 $\text{rel}=2$，辅助关联记录 $\text{rel}=1$，过期旧记录或体验异常卡顿单 $\text{rel}=0$）计算折损累计增益：

$$\text{DCG}@k = \sum_{i=1}^{k} \frac{2^{\text{rel}_i} - 1}{\log_2(i + 1)}, \qquad \text{NDCG}@k = \frac{\text{DCG}@k}{\text{IDCG}@k}$$
  • $\text{rel}_i$：检索列表第 $i$ 位结果的相关度等级（生效正例最高，过期或异常单据强制归零）；
  • $\text{IDCG}@k$：将所有生效正例排在最顶部时的理想最大 $\text{DCG}@k$；
  • 核对：当周六鸟巢的正常单 SN_A 与重叠消歧经验规则排在第 1、2 位，而卡顿单 SN_B 排在第 3 位时，正例占据最前位置，$\text{NDCG}@5 = 1.00$；反之若卡顿单排第 1 位，第 1 位的分子 $2^0 - 1 = 0$，总分立刻大幅折损。

第二，在阶段 3 的决策评估中，借鉴 PersonaMem-v3 的两步判分逻辑，引入一票否决指示项 $\mathbb{I}(V_{\text{veto}} = 0)$ 与槽位/动作满足度相乘：

$$\text{Score} = \mathbb{I}(V_{\text{veto}} = 0) \cdot \frac{|\hat{S} \cap S^*|}{|S^*|}$$
  • $V_{\text{veto}} \in \{0, 1\}$：一票否决红线标志。凡是套用已过期事实档位、照搬工作记忆中体验异常（卡顿/掉帧）单据的参数、未澄清直接执行（Premature Execution）下发冲突单、或违规刺探无关隐私，均令 $V_{\text{veto}} = 1 \implies \text{Score} = 0$；
  • $S^*$ 与 $\hat{S}$：分别为标准答案要求满足的“事实记忆补全槽位 + 工作记忆指代槽位 + 经验记忆调整动作”集合与系统实际输出集合。
