评测集构建及评估方案

—— 基于网元单据与自然语言对话的数据合成、质量校验与多阶段评估指标
2026 年 11 月

报告摘要：联接 Agent 的场景是移动网络体验保障，数据来自网元事后上报的保障单据，以及用户主动发起的自然语言对话。要解决两件事：这两类来源如何合成为一组可评测的长周期数据，以及评出来的分数是否站得住。
梳理 2024–2026 年主流 benchmark 的构建方法，指出语法、语义、语用三层各缺哪类变体，以及多轮会话中用户与 Agent 的双向动作。评测方法先把口径定下来：观测契约、一条记忆怎么数、错了算在谁头上，再给合成数据的六层质量校验，以及记忆萃取、混合检索、下游决策三个阶段的指标与判分规则。被测对象是 CoALA 式分层记忆：一个短期工作记忆，加上语义、情景、程序三类长期记忆，入口按意图拆解做隔离，业界在形成、更新、遗忘与检索上的做法一并整理。支撑这些指标的数据由故事线生成：拆成排布层与内容层两类因子，产出两套样本，USER_001 走日常场景下单据与对话的交替融合，USER_002 走前后台带宽抢占排障，对比仅单据输入与单据加对话的混合输入。

章节摘要

1. 记忆与多轮交互评测 Benchmark 调研 — 拆解近年主流 benchmark 的构建思路，指出语法、语义、语用各层尚未覆盖的变体，并归纳多轮会话中的交互动作。

2. 合成数据质量校验与三阶段评估指标 — 先统一评测口径与观测契约，再逐层审查数据质量，最后落到三个阶段的评估指标与判分规则。

3. Agent 记忆架构与检索方案 — 界定 Agent 应该记住什么，记忆如何形成、更新与遗忘，以及在线时如何检索并装入工作记忆。

4. 长周期故事线排布与维度因子设计 — 把故事线拆成排布与内容两层，用可控因子生成跨越数月、因果闭合的长周期样本。

附录 A. 网元单据与多轮对话样本合成实例（样本卷） — 用两套端到端样本走通构造流程：一套演示日常场景下单据与对话的交替融合，一套对比仅单据与单据加对话的输入差异。

• UserProxyBench (2609.38043)：通过带原文锚点的原子准则审计用户模拟器契约忠实度（UFS），拦截模拟器提前剧透未问槽位或编造终端状态的违规轨迹。

方向之间在构造顺序上已经趋同：都把真值放在文本前面，难度都靠受控因子调。差别集中在后两步——题目怎么派生、判分拿什么当准。本方案的顺序与这套做法一致：先锁两层因子与关键事件的前后状态表，再从状态表生成单据与对话，题目也从状态表派生。差的四处都在后半段：快照没有逐条有效期，因而派生不出按截止日提问的题组；假记忆类干扰没进样本；交互代价没进判分；判分只跑一次，没有重复与区间。前三处影响样本怎么设计，最后一处决定结论能不能对外说。

17. 试探性条件咨询 与 正式下达执行指令 “如果我把今晚直播保障从 4K 降回 1080p，会不会影响推流画质？”（仅做假设咨询，并未授权立刻修改工单配置） 2026 新兴焦点（CAREFUL-Bench 2611.02978） 多数工具调用基准不区分“What-if 咨询态”与“Commit 执行态”，导致 Agent 在用户仅咨询时擅自调用写接口改坏环境状态。
18. 多人旁白插话、背景交谈与主导人意图剥离 主叫用户正在办直播保障，旁边同伴插话“顺便问问视频彩铃多少钱”，主叫立刻说“别管彩铃，先弄我今晚的直播加速” 2025–2026 开始探索（Multi-User DST 2506.10504） 欠缺主客观发言人权限区分、旁人插话噪声抑制以及主叫用户对旁人提议的即时否决跟踪。

2.1.7 无记忆基线与重复跑：把分数归因到记忆

2.1.6 的两条极端基线是抽样预跑，回答的是「这项指标有没有区分度」。要回答「这道题的分数能不能算到记忆头上」，还得逐题跑一次无记忆基线；要说「这组分数稳不稳」，得重复跑并报区间。两件事都不改指标定义，只是加两道门槛。

逐题无记忆基线。关掉记忆检索，只给当轮原始输入，同一题组再跑一遍。能在这个条件下答对的题，考的是语言理解与常识，应当废弃或改写；答不对的题才进入正式题组。报告里把三阶段指标改成「相对无记忆基线的增量」——萃取的绝对值再高，若基线也高，说明记忆没有起作用。抽样不必铺满，每个场景族、每种失败归因标签各覆盖几题即可。

重复跑与区间。同一题组换随机种子跑三次以上，报均值与区间，不报单次值。判分依赖裁判模型时，同一份输出至少独立判两次，分歧题交第三判或人工裁定，并单独报分歧率。理由是已有工作给出的量级：同一模型换种子后，更新类事实的分数最大差 0.45（MERIT，2609.05441），记忆架构的排名会随历史长度翻转（Ground Truth First，2607.21962）。单次分数不足以支撑排名结论。

写进报告的形式。每项指标给三个数：无记忆基线、重复跑的均值、区间半宽。两个系统的差异落在区间内，一律写「无显著差异」，不做强弱判断；确需排名时报配对检验结果，而不是分数差。

2 合成数据质量校验与三阶段评估指标

评测要回答两件事：数据本身干不干净，以及被测 Agent 在记忆上到底对不对。前者靠六层自检，用确定性规则或裁判模型把不合格样本拦下来；后者把一次请求拆成萃取、检索、决策三段，每段单独给分，失败时能归到具体环节。

先说口径，是因为口径定了才有验收标准：一条记忆按什么单位数，检索命中怎么算，错了记在谁头上。这三件事不定，后面设计记忆分层就无从判断好坏，分数再高也说明不了架构对不对。

2.1 评测口径、观测契约与记忆条目定义

2.1.1 观测契约：三条必须写死的接口

三个前置问题要先定下来：要测的东西从哪里取（观测契约），一条记忆怎么数（条目口径），错了算在谁头上（失败归因）。数据集、被测 Agent 与插桩点都在同一团队内自建，阶段 1 的实际写入集合 \(N\) 与阶段 2 的检索返回集合 \(Q\) 都能直接读出，接口不可达不构成约束。约束的重心因此从能不能测，转到测出来算不算数：同一套 F1 在两种口径下可以差出改变排名的幅度；口径若由实现方自己定，指标就退化成“实现说明书是否自洽”——分数很高，却证明不了架构对。

2.1.2 一条记忆是什么：七元组定义与槽位键

指标 1 的算式 \(\text{TP} = |N \cap M|\) 在纸面上成立，落到工程上必须先回答“一个元素是什么”。若按存储条数计，同一个偏好在不同会话里存成三条就算三条命中，条数膨胀即可刷分；若按语义合并计，又会在合并粒度上争执不下。本方案统一采用七元组定义单条记忆，并以槽位键而非存储记录作为对齐单位：

$$m = \big(e,\; a,\; v,\; s,\; T_{\text{valid}},\; \text{src},\; \text{st}\big), \qquad \kappa(m) = (e,\; a,\; s)$$

其中 \(e\) 为实体键（用户 / 设备 / 场馆），\(a\) 为属性名，\(v\) 为取值，\(s\) 为适用场景，\(T_{\text{valid}}\) 为有效区间，\(\text{src}\) 为来源，\(\text{st}\) 为状态；\(\kappa(m)\) 为槽位键。两个集合的对齐全部在槽位键空间完成：同一 \(\kappa\) 在 \(M\) 与 \(N\) 中各自至多计一条，跨会话同义表述合并为一条，系统内部多存几条不影响得分，但多出的条目若落在 \(M\) 中不存在的槽位上，一律计入 \(FP\)。由此得到可核算的判分式：

$$\text{TP} = \big|\kappa(N) \cap \kappa(M)\big|,\quad \text{FP} = \big|\kappa(N) \setminus \kappa(M)\big|,\quad \text{FN} = \big|\kappa(M) \setminus \kappa(N)\big|$$

2.1.3 strict / lenient 双报：等价表述必须单独交代

“用户要求时延不超过 50 毫秒”与“卡顿不能有，50ms 以内”——语义等价，字面完全不同。只报一个 F1，评审的第一个问题必然是“等价表述算不算命中”，而回答这个问题的成本远高于同时报两个数。因此指标 1 与指标 2 全部双口径并报：

  • strict（严格命中）：\(\kappa\) 的槽位键相同且归一化后的 \(v\) 字面相等。归一化规则表随数据集一同冻结（单位换算、时间格式、口语词典、大小写），版本号写入数据卡。
  • lenient（语义命中）：槽位键相同，\(v\) 由规则表或裁判模型判定为语义等价。裁判模型须与生成模型不同族，并在 100 条人工标注子集上报告一致率 \(\kappa_{\text{Cohen}}\)，低于 0.8 则该口径的结果标注为“仅供参考”。

两个数各有用途：strict 用于回归（同一 Agent 版本迭代间的可比性最强，噪声最小），lenient 用于对外汇报（贴近人类判断）。二者之差本身也是信号——差值大说明系统在“换说法”这件事上不稳，通常对应口语映射表覆盖不足，而不是抽取能力弱。

2.1.4 记忆状态更新：比轨迹而不是比终态

指标 2 若只比 Day 30 的最终快照，会把两种性质完全不同的情况算成同一个分数：一种是每一步都更新正确，另一种是中途写错、又在后续单据里被“碰巧改回来”。在观测契约①之下，每个 \(t_{\text{cut}}\) 都有快照，因此可以改为比对状态迁移轨迹。设评测截止点为 \(t_1 < t_2 < \cdots < t_n\)，对应快照 \(S_{t_1}, \dots, S_{t_n}\)，把相邻快照的差异抽成迁移集合：

$$\Delta_k = \big\{(\kappa,\; S_{t_{k-1}}[\kappa],\; S_{t_k}[\kappa]) \;\big|\; S_{t_{k-1}}[\kappa] \neq S_{t_k}[\kappa]\big\},\qquad \Delta = \bigcup_{k=1}^{n} \Delta_k$$

同一槽位键上的迁移三元组 \((\kappa, \text{before}, \text{after})\) 与标准迁移集合 \(\Delta^*\) 做集合比，得到迁移级 \(P/R/F1\)；同时保留终态准确率作为汇总指标。两者并列汇报时，读法很明确：终态高、迁移低说明系统“结果对但过程不可信”，一旦数据变长就会失效；迁移高、终态低说明只差最后一步的覆盖或失效处理，通常是 supersede 标记或有效期计算的问题，修复成本低。这一区分在只看终态时是看不出来的。

2.1.6 三条工程纪律与区分度前置验证

三条成本极低、但能挡住大部分返工的纪律：

  • 先冻结 schema，再写标注。属性词表、槽位键规则、状态机（active / superseded / obsolete / conflict）在标注开始前冻结；冻结后再改 schema，已标注部分必须整体重标，不允许“增量补标”。
  • 数据集版本与 Agent 版本解耦。数据集 v1 冻结后，Agent 迭代不得回头修改 gold；确需修正 gold 时，走数据集 v2 并重跑全部系统，禁止在同一版本号下混档对比。
  • 留 20 条对抗集给不参与实现的人写。专打实现盲区（生僻口语、跨场景同名属性、临时豁免到期边界、单据晚到）。数量不大，但它是唯一能暴露“gold 贴着实现写”的手段。

在此基础上补一次区分度前置验证：正式全量评测之前，先取 50 道覆盖各场景族的题，用两条极端基线各跑一遍——全上下文直灌（把 \(t_{\text{cut}}\) 前全部可见记录一次性塞进上下文，不检索、不抽取）与无记忆（清空记忆，仅靠当前轮对话）。两条基线的分数区间应当明显拉开（经验上第一阶段指标可拉开 0.5 以上，第三阶段可拉开 0.3 以上）。若某项指标在两条基线之间几乎没有差异，说明该指标的题面没有真正依赖长程记忆，需要重新设计题目，而不是调整阈值。

2.4 证据充分性（Sufficiency）、最小性（Minimality）与受控扰动一致性测试（Metamorphic Testing）

第四层校准针对每道题的 Ground Truth 证据集 \(E^* \subseteq V(t_{\text{cut}})\)：既不缺关键依据，也不塞无关背景单据。每个等价充分证据子集 \(E \in \mathcal{E}^*\)（可以有多组，\(\mathcal{E}^* = \{E_1^*, E_2^*, \dots\}\)）须同时满足充分性与最小性两项条件：

$$\text{Sufficient}(E, y^*) \iff f_{\text{verify}}(E) = y^*, \qquad \text{Minimal}(E, y^*) \iff \forall e \in E,\; f_{\text{verify}}(E \setminus \{e\}) \neq y^*$$

符号解释如下：

  • \(E \subseteq V(t_{\text{cut}})\)：在评测截止时刻 \(t_{\text{cut}}\) 下的一组可见候选证据子集（包含网元单据或对话片段）；
  • \(y^*\)：该测试题的目标标准结论（如当前生效的习惯参数或排障决策）；
  • \(f_{\text{verify}}(\cdot)\)：严格仅依赖输入证据集合进行受控推导的验证器（在不引入外部猜测时，判断能否唯一导出 \(y^*\)）；
  • 充分性（Sufficiency）要求仅凭子集 \(E\) 即可完整、无歧义地推导出标准答案 \(y^*\)；最小性（Minimality）要求 \(E\) 中不含任何冗余记录——只要从 \(E\) 中删去任意一条记录 \(e\)，剩余集合 \(E \setminus \{e\}\) 就不再足以唯一导出 \(y^*\)（退化为信息不足或退回旧版本结论）。
充分性与最小性校准计算示例：{D1, D2, R1} 组合证据核验

【测试问题】：在实例二（USER_002）第 3 周周三下午提问：“周四晚 20:00–21:30 远程培训期间，若有工程数据包待上传，系统应如何安排网络保障与上传任务？”

【目标结论 \(y^*\)】：保障周四 20:00–21:30 远程培训视频会议（保语音不断、画质目标 1080p / 最低可降 720p），并将后台工程包上传任务推迟至 21:30 培训结束后执行。

【候选证据集核验】：设 \(D_1\) 为周二/周四 20:00–21:30 常规培训基线单据，\(D_2\) 为 E05 培训与上传同一时间窗并发导致会议跌至 540p 且语音断续的冲突单据对，\(R_1\) 为 E06 用户明确“保语音、最低 720p、上传推迟到九点半后”的排障确认对话，\(D_{\text{noise}}\) 为周日误触撤单 D04：

  • 充分性检验：给定 \(E^* = \{D_1, D_2, R_1\}\)，\(f_{\text{verify}}(E^*)\) 可完整导出周四常驻时段、并发劣化根因与用户确认的错峰推迟及降级底线，故 \(\text{Sufficient}(E^*, y^*) = \text{True}\)。
  • 最小性（留一法消融）检验： 1）若删去 \(R_1\)，仅凭 \(\{D_1, D_2\}\) 虽知并发劣化，但无法得知用户允许画质最低降至 720p 及同意推迟上传的具体安排，\(f_{\text{verify}}(\{D_1, D_2\}) \neq y^*\)； 2）若删去 \(D_1\)，无法确认周四 20:00–21:30 为常驻周期培训窗口； 3）若有人将 \(D_{\text{noise}}\) 混入得到 \(E' = \{D_1, D_2, R_1, D_{\text{noise}}\}\)，由于删去 \(D_{\text{noise}}\) 后仍能完整导出 \(y^*\)，故 \(E'\) 违反最小性，审查脚本自动剔除 \(D_{\text{noise}}\)。

第五、第六层审查先看数据集层面的因子成对覆盖率（Pairwise Coverage），并计算故事状态转移序列的结构编辑距离，剔除表层改写、结构同构的重复样本（Isomorphic Duplicate Samples）。随后按表 2.5 做 8 类受控扰动一致性测试（Metamorphic Testing）：对已有合格样本施加确定性扰动算子 \(\mathcal{T}\)，看标准答案与待测系统输出是否按因果逻辑同步转移。

（剥离对话转为仅单据输入）		 保持底层网元单据流完全不变，剥离全部自然语言对话记录（从“单据+对话”剥离退化为同骨架“仅单据”输入）。 纯单据可观测的客观行为与周期习惯真值保持不变；仅依赖对话主观声明的细粒度位置或口语映射转为不可知（需拒答或澄清）。

（What-If 与 Commit 翻转）		 将用户话语从执行指令“帮我把今晚保障降为 720p”翻转为假设咨询“如果我把今晚保障降为 720p 会不会卡？”。 标准工具调用行为必须从“二次确认后调用写接口修改工单”转移为“仅调用只读分析接口回答影响，写接口调用次数为 0”。

2.6 核心指标的判分逻辑与精简算式表达

阶段 1 的抽取召回率与误抽率、阶段 2 的召回率、阶段 3 的克制率都是比例统计，命中样本数除以总样本数。全流程只留两个算式：一是阶段 2 衡量最新生效记录有没有排在旧记录与异常单前面的时效分级排序分 NDCG@k，二是阶段 3 衡量红线一票否决与三层记忆顺应的受控决策得分 Score。

阶段 2 评的是排序。长期情景记忆（单据表）里同地多单冲突时——比如上周六在鸟巢既有下午顺畅单 SN_A、又有晚上卡顿单 SN_B——或长期语义记忆新旧交替时，两条都进前 5 条还不够。卡顿单或过期旧记录排在第 1 位，下游模型照样会取错参数。所以按相关度分级算折损累计增益：$\text{rel}_i$ 取 2 为当前生效事实、目标正常工单与对应经验规则，取 1 为辅助关联记录，取 0 为过期旧记录或体验异常的卡顿单。

$$\text{DCG}@k = \sum_{i=1}^{k} \frac{2^{\text{rel}_i} - 1}{\log_2(i + 1)}, \qquad \text{NDCG}@k = \frac{\text{DCG}@k}{\text{IDCG}@k}$$
  • $\text{rel}_i$：检索列表第 $i$ 位结果的相关度等级。生效正例最高，过期或异常单据直接归零。
  • $\text{IDCG}@k$：全部生效正例排在最顶部时的理想最大 $\text{DCG}@k$。
  • 核对：鸟巢周六的正常单 SN_A 与重叠消歧经验规则排在第 1、2 位、卡顿单 SN_B 排第 3 位时，正例占住最前位置，$\text{NDCG}@5 = 1.00$。反过来卡顿单排第 1 位，$2^0 - 1 = 0$，总分立刻大幅折损。

阶段 3 评的是决策。参照 PersonaMem-v3 的两步判分，加一个一票否决项 $\mathbb{I}(V_{\text{veto}} = 0)$，与槽位、动作满足度相乘：

$$\text{Score} = \mathbb{I}(V_{\text{veto}} = 0) \cdot \frac{|\hat{S} \cap S^*|}{|S^*|}$$
  • $V_{\text{veto}} \in \{0, 1\}$：一票否决红线。套用长期语义记忆里已过期的档位、照搬长期情景记忆中体验异常（卡顿、掉帧）单据的参数、未澄清直接执行（Premature Execution）下发冲突单、违规刺探无关隐私，任何一条成立即 $V_{\text{veto}} = 1 \implies \text{Score} = 0$。
  • $S^*$ 与 $\hat{S}$：前者是短期工作记忆最终汇总需要满足的集合，由长期语义记忆补全槽位、长期情景记忆的单据指代与临时覆写槽位、长期程序记忆的调整动作组成；后者是系统实际输出。

2.7 本章总结

  • 评测口径与观测契约（2.1）：先把三条取数接口锁死——snapshot(t_cut)、retrieval_log、write_events；再用七元组与槽位键 \(\kappa\) 统一“一条记忆”的定义。指标 1、2 按 strict / lenient 双口径并报，并按 \(t_{\text{cut}}\) 序列比状态迁移，不只看终态。2.1.7 再加两道门槛：逐题无记忆基线决定分数能否归因到记忆，重复跑与区间决定分数稳不稳。这几条合起来，才谈得上“后面所有分数可比”。
  • 数据自检（2.2～2.4）：六层审查的前三层是硬门槛，可以自动判定——记录层确定性约束、状态图回放、截止时间可见性。后三层要靠人工或裁判模型校准，须报一致率——充分最小性、分布去重、受控扰动。
  • 失败归因（2.1.5）：每个失败例打一个标签，W-MISS / W-WRONG / R-MISS / R-RANK / D-MISUSE 五类。首批全量题跑完看分布，不看总数。分布决定下一个迭代周期该改抽取、改检索还是改决策层。
  • 三阶段核心指标：萃取端查防漏抽、防虚构、新代旧、防偶发污染；检索端查跨表二阶段召回、跨三层全齐率、正例压制异常单排序；决策端查一票否决红线、三层融合顺应、无关场景克制、未知拒答。
  • 拓展阅读：PersonaMem-v3 (arXiv:2608.21381)、LongMemEval (arXiv:2410.10813)、RHELM (arXiv:2605.31086)、LoCoMo-Plus (arXiv:2602.10715)。

3 Agent 记忆架构与检索方案

评测口径在上一章定了，这一章定被评的对象。架构按通用 Agent 场景设计。场景体系尚未全部定义完，当前以移动网络体验保障（网元单据与多轮自然语言对话并存）作为首发场景验证，后续场景沿同一框架增量扩展。结合学术界与工业界的代表工作，记忆系统分四个问题讲：该记什么，这些内容按什么分层存放，记忆如何形成、更新与遗忘，以及在线时怎么检索加载。

3.2 记忆分层架构

四类记忆混在一起放，就会出事。把当前对话、用户长期习惯和历史网元单据塞进同一个不分层的向量库，会出三类问题：短期临时改动盖掉长期固定习惯，单次外出参数污染常驻地点配置，同地点的正常单据与卡顿单据分不开。怎么分层，参照普林斯顿大学的 CoALA（Cognitive Architectures for Language Agents, arXiv:2309.02427），按生命周期分短期与长期两级：

  1. 短期记忆 —— 1. 工作记忆（Working Memory）：当前会话内活的上下文草稿板，也是大模型推理时唯一直接读取的区域。它维护本轮输入、多轮澄清与中途改口的中间槽位，以及当轮从长期记忆检索（Retrieval）读入的活跃上下文。会话结束后，有效信息通过学习写回（Learning）沉淀到长期记忆，工作记忆随之释放。
  2. 长期记忆 —— 跨会话持久保存在外部数据库中，分三类：
    • 2. 语义记忆（Semantic Memory）：脱离具体事件背景、跨周期稳定的事实与常驻偏好（What is true）；
    • 3. 情景记忆（Episodic Memory）：绑定具体时间、地点与结果的历史事件记录（What happened）；
    • 4. 程序记忆（Procedural Memory）：关于如何执行动作、如何调参与处置的规则和流程（How to do）。

同一个用户在保障场景里往往同时存在多种意图，比如固定基地直播、高速大巴移动会议、大型场馆赛事推流。入口先做意图拆解（Intent Decomposition），把复合请求拆成独立意图，不同意图的记忆相互隔离：每条记忆标明所属意图，检索时只读与当前意图相关的那部分，避免把大巴弱网下的 720p 妥协参数套到基地直播上。用户从未发生过的意图没有对应记忆，遇到时应澄清追问，不能借用其他意图的参数。整体结构见图 3.1。

3.3 记忆怎么形成、更新、遗忘与处理

短期工作记忆里的一次对话或一张单据不能直接算长期记忆。否则一次临时改期、或一次基站拥塞导致的异常单据，就会污染用户的常驻习惯。学术界与工业界在“短期如何变长期、偏好变了如何更新、陈旧记录如何遗忘”上已有若干代表做法。

3.3.1 北邮 MemoryOS：短期 → 中期 → 长期的三级演变机制

MemoryOS 正是冲这个问题来的。北京邮电大学与腾讯 AI Lab 的《Memory OS of AI Agent》（MemoryOS, arXiv:2506.06326）借用操作系统的分层内存管理，在短期与长期之间加一层中期缓冲，划成短期记忆（STM）→ 中期记忆（MTM）→ 长期个人记忆（LPM）三级：

  1. ① 短期记忆（STM，对应 CoALA 工作记忆）：对话页加对话链的 FIFO 缓冲。每一轮问答封装成一个对话页（page = {Q, R, T, meta_chain}），放进定长 FIFO 队列（例如 7 页）。前后页语义连贯时自动串成对话链，并生成链级摘要。队列满或会话结束时，按先进先出弹出，移交中期记忆。
  2. ② 中期记忆（MTM）：借操作系统段页式（Segmented Paging）做话题聚合。段对应话题摘要，页对应该话题下的具体对话页或单据记录。新页从短期滑入时，计算向量余弦相似度与关键词 Jaccard 重合度，超过阈值（例如 0.6）就并入已有话题段累积证据，否则另开一个新段。
  3. ③ 长期个人记忆（LPM，对应 CoALA 长期语义与程序记忆）：热度分驱动晋升，晋升后清零累积。每个中期话题段维护一个综合热度分：\(\text{Heat} = \alpha\cdot\text{被检索次数} + \beta\cdot\text{段内累积页数} + \gamma\cdot\exp(-\Delta t/\mu)\)。段数超限时先淘汰 Heat 最低的冷段；某个段的热度越过晋升阈值，就从段里提炼长期稳定的事实与偏好写入长期记忆，随后把该段的累积页数清零，避免同一批证据被重复提炼。

3.3.3 程序记忆的形成：从经验中提炼

程序记忆的形成不靠重复次数累积，靠对“失败 → 纠正 → 成功”的复盘。Reflexion（arXiv:2303.11366）把执行后的环境反馈转成文字反思，下次尝试前读入工作记忆；ExpeL（arXiv:2308.10144）收集成对的成功与失败轨迹，对比差异提炼通用规则；AWM（arXiv:2409.07429）从历史成功轨迹里归纳可复用的处理经验；ReasoningBank（arXiv:2509.25140）验证了同时从成功与失败中抽象策略优于只存原始轨迹；经验跟随的实证研究（arXiv:2505.16067）指出，字面相似但条件不符的经验容易被盲目照搬，需要限定适用范围，并用后续执行结果持续校验。

对应到网络保障场景，程序记忆的提炼可概括为三步。先找出同一场景下出现卡顿的历史单据，再结合用户后续对话里的澄清与纠正确定调整办法（如场馆开播提前 30 分钟预热），最后用调整后运行正常的单据验证。验证通过后，把具体场馆抽象成“大型场馆 + 上行推流”这类通用条件，写明不适用的业务，并按之后每次复用的运行结果提高或降低可信度。

遗忘在评测上要判两件事。一是旧值不再被召回：删除指令或有效期结束之后，同一问题不允许再返回该值，返回即判失败。二是同期其他记忆没有被连带清掉：与它同源、但属于其他槽位的记忆，召回率不应下降。只判前者会把「全清」当成好结果——把整个意图下的记忆一并删掉，指标反而好看。MemSecBench（2607.27080）在 Write–Execute–Forget 上的做法可以借用：删除按「删干净」与「不误删」两个检查点分开计分，修复阶段再单独看良性记忆的保留率。

对应的样本也要成组出现：一条显式删除或到期指令、一条依赖被删值的后续提问、一条依赖同源其他记忆的对照提问。三题一组才算一个完整的遗忘测点；单独问一句「你还记得吗」，测不出误删。

3.4 记忆的检索方案

用户在会话里发长句请求时（如“今天不去滨江基地了，今晚在工体中心用小破站开播，别用卡顿那套，照奥体没卡那次办”），把整句编码成单一向量做近邻搜索会出两种错：一是局部口语叫法（“小破站开播”）被稀释，匹配不上；二是否定子句里的地点（“滨江基地”）或历史卡顿单据被误召回。结合 BlendX（否定子句处理）、MemoryOS / A-MEM（语义向量与结构化属性联合检索）与 Letta（工作记忆按需换页），检索分三步执行（见图 3.3 与表 3.3）：

  1. 长句否定子句分离与正向滑动窗口匹配：先按标点与连词切分子句，识别带否定词（“不去”、“别用”、“取消”）的子句，对被排斥项的候选记录扣分降权；再对正向子句按固定长度滑动窗口切成多个短窗口，与长期记忆库中的短语向量比对，读取命中行的结构化槽位列，并通过二阶段跨表关联补全缺省属性（如由周期习惯或场景偏好补齐默认分辨率与时长）。
  2. 三类长期记忆并行检索与状态过滤排序：并行检索长期语义记忆（口语映射、周期习惯、默认档位）、长期情景记忆（未过期的临时偏好、目标地点历史单据）与长期程序记忆（通用场景类别匹配的调参规则与消歧流程）。排序先做状态硬过滤，剔除已替代的旧语义档位（superseded）、已过期的临时偏好（expired）与落入不适用列表（scope.exclude）的经验规则。用户要求顺畅体验时，同地点的正常单据（good）排最前，卡顿异常单据（bad）降权靠后。最后按短语向量匹配度、时间保持度、近期访问热度与记录置信度加权排序，取前 \(k\) 条。
  3. 按需加载至短期工作记忆与槽位冲突消解：将检索出的前 \(k\) 条长期记忆结构化加载进短期工作记忆（控制上下文窗口长度），在加载阶段直接预计算经验规则的提前预热时间偏移（确保结束时间减开始时间等于总时长）；若同地存在多笔有效历史单据冲突，则在工作记忆中并列呈递规格差异与消歧流程，触发慢路径向用户追问确认。

4 长周期故事线排布与维度因子设计

第 3 章的“短期工作记忆 + 三类长期记忆”架构与双源融合机制，要用跨月的数据才检验得出来。这类数据由长周期故事线（Storyline）生成：故事线拆成两层，第一层排布因子管时间节奏与主支线结构，第二层内容因子管用户、任务线与节点属性，两层因子与四类记忆测试点一一对应。

4.1 故事线两层解耦设计思路

评测联接 Agent 的长期记忆与多轮意图，需要跨度数周至数月、同时包含自然语言对话与网元单据的数据。这类数据要覆盖两组测试点：记忆萃取侧的偏好抽取、合并更新、分场景组织、画像生成与噪声抑制；记忆检索侧的直取、排序、条件、排除、组合与缺失拒答。

固定剧本模板或单层平铺变量表在实际构造中有三处局限。一是时间线排布与事件内容耦合，调干扰密度或主支线穿插方式时，会连带改动单点业务内容；二是同层因子之间存在条件依赖或跨层重复，例如把受时间窗约束的“事件规模”与“时间跨度”并列，把仅在存在支线时才生效的“支线归宿”与“事件线结构”并列，或在排布层与内容层重复定义“偏好演进”与“闲聊干扰”；三是边界与噪声场景覆盖不足，缺少对负向排斥偏好、短期临时偏好过期、未提及属性拒答边界，以及闲聊、试探、情绪发泄、单次偶发等非偏好噪声的控制参数。

  • 参照 PersonaMem-v3、LoCoMo、DynamicMem、MemoryAgentBench 与 LongMemEval 的做法，故事线生成解耦为排布层与内容层（图 4.1）：
  • 第一层定排布，管整条时间线的跨度、事件规模与疏密分布、主支线任务的穿插关系、跨期演化趋势与测试点编排。用户诉求包含主支线交织（或单轮复合意图）时，系统在入口先做意图拆解（Intent Decomposition），拆成彼此独立的业务任务（task_id）；每个任务映射到对应业务场景（intent_id），时间轴上的主支线交织即表现为不同业务任务之间的交替执行、同一时间窗并发或中断恢复。
工程落地边界补充：三层信息可见性隔离与四类时间维度区分

第二层定内容，按“用户级 → 业务场景/任务级 → 节点级”三级粒度填属性，覆盖用户身份与资产、应用与业务行为、时空轨迹与流量、网络环境与 KQI 偏好、信息来源与噪声干扰、多轮交互与反馈纠正六个方面。同一用户的不同意图（如主线直播与支线移动会议）之间记忆相互隔离，各自的终端、应用、时段与 KQI 偏好互不覆盖；用户未发生过的意图没有记忆，测试时看系统能否拒答或追问，而不是借用其他意图的参数。

  • 1. 三层信息可见性边界（防止全知视角泄漏，Omniscient Data Leakage）：
  • 观测层（Agent 物理可见记录，Observable Records）：严格遵循真实系统触发机制——网元单据均为单次网络保障任务结束后的事后统计上报（仅含起止时间、基站小区标识 cell_id、应用名、吞吐量、时延抖动与卡顿异常记录，不含室内房间名或主观借用原因），自然语言对话（Sessions）仅在用户主动发起咨询、报障、改期或预订时稀疏产生；
  • 评测层（测试截止点可答范围，Cutoff-Valid Scope）：给定评测截止时刻 \(t_{\text{cut}}\)，Ground Truth 答案仅允许依赖到达时间满足 \(t_{\text{arrive}} \le t_{\text{cut}}\) 的已观测记录推导；任何仅在作者设定中存在但截止前未露出到观测层的属性均归入“当前未知（需拒答或主动澄清）”。

2. 四类时间维度显式区分：每条记录显式区分事件实际发生时间 \(t_{\text{event}}\)、未来预约计划时间 \(t_{\text{plan}}\)、单据统计窗口 \([t_{\text{start}}, t_{\text{end}}]\) 与 单据到达/可见时间 \(t_{\text{arrive}}\)。当网元单据存在批处理延迟上报（\(t_{\text{arrive}} > t_{\text{end}}\)）或乱序补报时，处于 \([t_{\text{end}}, t_{\text{arrive}})\) 区间内的测试点严禁引用尚未到达的单据。

3. 入口意图拆解（Intent Decomposition）与意图间记忆隔离：面对主支线交织或复合诉求，系统在入口处先通过意图拆解将其拆分为独立意图（如基地固定直播、高速大巴移动会议、高密场馆赛事推流、播前视频对词），每个意图各自具备独立的终端、应用与 KQI 目标；不同意图之间的记忆相互隔离，避免参数在同一槽位表内相互覆盖。当测试请求落入该用户从未发生过的意图时，系统不得借用其他意图的参数硬套，而应如实拒答或转入慢路径追问。

  • 依赖：←L1-n / ←L2-n 表示父因子为排布层 / 内容层第 n 号；“仅当…”是硬条件——父条件不满足时不采样，也不填默认值。
  • 标〔建议〕的数值是按当前样本量推的工程默认值，用于统一口径，不是论文结论。

• 检索：高置信度实测偏好优先于单次低置信度口头记录排序。

4.6 两层组合规则与六步构造流程

长期记忆（Long-Term Memory，跨会话持久保存）—— 含以下三类：
① 语义记忆（事实—语义层）：跨周期常驻的主力业务、周期作息习惯、分场景常驻偏好、默认档位与口语映射；
② 情景记忆（事实—情景层）：每次历史保障单据与网元实际运行结果（SerialNo、good/bad，按单原样追加、不合并、不衰减），以及绑定具体时间窗的差旅赛事事件与带有效期的短期临时偏好；
③ 程序记忆：从慢路径澄清与长期情景单据正反对比中提炼的因果调参规则、同地多单消歧流程与交互策略。

  1. 先定时间线结构，再按三级粒度填内容：先从第一层采样得到时间线结构；再按取值粒度填第二层——“用户”级因子整条故事线取一次，“线”级因子每条事件线取一次，“节点”级因子每个事件节点独立取一次。
  2. 主从层级条件采样（消除父子条件冲突）：先采样主因子，再在其范围内采样对应子因子。例如先定1. 时间跨度，再定与之匹配的1.1 事件规模与1.2 事件密度；仅当3. 事件线结构包含支线时才采样3.1 支线触发事件与3.2 支线归宿；仅当10. 网络异常 ≠ 无异常时才采样10.1 异常发生阶段。
  3. 声明式合法性约束（不写死在代码分支中）：只排除物理或逻辑冲突的组合，并统一声明在配置表的 constraints 列表中（例如排除“时间跨度 2 周与按月周期规律”、“平稳保持型节奏与套餐跨期升降级”、“仅网元单据体现与对话显式直接陈述”）。
  4. “先答案后会话”反向真值绑定与分阶段构建策略：前期与中期采用“先定义答案、再反向生成会话”路线（参照 LongMemEval、DynamicMem、PERMA）：① 先定义评测骨架（测试维度、测试目的与难度分布）→ ② 先写出结构化标准答案（萃取侧写明 gold_profile 的生效值、过期值、来源与置信度，检索侧写明 gold_answer 与 gold_memory_ids）→ ③ 按成对覆盖（Pairwise Coverage）采样两层因子，反向生成能唯一推导出该答案的自然语言对话与网元单据序列 → ④ 通过多 LLM 交叉验证检验对话自然度与答案唯一性；到后期上线阶段再结合“先有真实会话、后抽检标注答案”路线（参照 LoCoMo、MemoryAgentBench）补充长尾边界样本。
  5. 增量扩展：新增测试维度时，直接在对应因子类别下补充主因子或子因子定义，不影响已有因子与数据。

按这些规则，构造一条样本要走固定的六步。六步的次序不可交换：第 4 步的状态中间表是后续单据与对话的共同母本，若先写单据再补状态，必然出现“单据之间自洽、单据与人物状态矛盾”。

  1. 第 1 步 · 定骨架：采样第一层排布因子，得到时间线结构（时间跨度、事件规模、事件密度、起止状态、事件线拓扑），此时不含任何业务内容。
  2. 第 2 步 · 填内容：按三级粒度填入第二层内容因子——用户级整条故事线取一次、线级每条业务线取一次、节点级逐节点取值，并受主从层级条件采样约束。
  3. 第 3 步 · 锁真值（先答案后会话）：先确定每个节点的业务参数、四类记忆的真值与版本更替时点，再倒推该节点应当产生哪些单据、哪几轮对话。
  4. 第 4 步 · 关键事件前后状态中间表：在生成任何具体记录之前，先锁定关键事件前后的状态快照（状态字段取值、跳变触发原因、生效时点、双模式可见性），它是单据与对话的共同母本，也是第 2.3 节状态图回放的比对基准。
  5. 第 5 步 · 派生单据：由状态表派生网元单据，补齐物理指标（PRB 负载、上下行速率、卡顿次数）与渠道可见字段白名单。
  6. 第 6 步 · 反推对话：由真值反推多轮对话，注入省略、指代、口误改口与否定排除，并保持用户端 / Agent 端的信息隔离视图。

六步完成后，样本进入第 2 章的数据集自检流水线；任一步的不自洽都应由自检拦下，而不是留给被测 Agent 去“猜”。
