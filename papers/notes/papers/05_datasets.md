四篇一共用到十一个数据集（τ 的三个域分开算）。它们不是同一类东西，混着说会得出错误结论：

| 用途 | 数据集 | 谁在用 |
|---|---|---|
| 长对话事实记忆 | LoCoMo | Mem0 |
| 工具协作、终态修复 | τ-bench retail / airline、τ² telecom | τ²（前两个是复用） |
| 跨平台个性化 | PersonaMem-v3（自建） | PersonaMem-v3 |
| 能力基准：代码 / 决策 / 推理 | HumanEval、MBPP、LeetcodeHardGym、ALFWorld、HotPotQA、WebShop | Reflexion |

真正的分水岭不在规模，而在**"答案"是什么形态**。同样是 0.7 分，LoCoMo 的 0.7 是"裁判觉得沾边"，τ² 的 0.7 是"数据库终态断言通过"，PersonaMem-v3 的 0.7 是"八项检查里过了几项"，HumanEval 的 0.7 是"隐藏单测全过"。这四种 0.7 之间没有换算关系。

## 5.2 LoCoMo：人工答案，但把最难的一类题删了

LoCoMo（Maharana et al. 2024）是为"超长对话记忆"专门造的：两两对话，跨多个 session，10 段，每段约 600 轮、平均 26,000 tokens，每段配约 200 道题〔正文〕。

**答案怎么来**：对话由 LLM 生成，题目与 ground truth 短答案由人写〔数据集〕。四类题对应四种推理动作——

| 题型 | 要做什么 | 失败长什么样 |
|---|---|---|
| single-hop | 在一个 turn 里定位一个事实 | 检索到相似但无关的 turn |
| multi-hop | 把分散在不同 session 的两个事实拼起来 | 只答对一半 |
| temporal | 把"去年""上个月"按对话时间戳换成绝对时间 | 用了错误的锚点日期 |
| open-domain | 需要对话之外的常识 | 编造 |

**它删掉了哪一类**：原始数据集有 adversarial 类，专门测"题目在对话里无答案，系统该说不知道"。Mem0 明确排除了它，理由是 ground truth 不可得、这一类的期望行为是"识别为不可答"〔正文〕。

这条比它看起来严重。**记忆系统最典型的错误不是答不出，而是检索到一条相似但不对的记忆然后自信地答**——PersonaMem-v3 的"个人事实幻觉探针"测的就是这个，我们五类归因里的 W-WRONG 与 R-RANK 也是。LoCoMo 的四类题里没有一类会惩罚这种行为：答错只扣一道题的分，而"该拒答却答了"根本不进分母。

另外两个口径问题：

- **J 的判定标准是宽的。** 裁判提示词要求"沾到同一主题就算对""时间格式不同也算对"，答案还被限制在 5–6 词〔正文附录 A〕。所以 66.88 不是"66.88% 的事实正确率"，是"在宽口径下被判对的比例"。同一题型上 F1 是 38.72、J 是 67.13，差 28 点，差距全部来自口径，不是来自能力。
- **10 段 ≈ 2,000 题，规模很小。** 10 次独立运行取均值只压住裁判方差，压不住题目方差〔推导〕。单段难度偏高就会整体漂几个点，这也是各家在 LoCoMo 上分数拉不开的原因之一。

## 5.3 τ 系：答案不是文本，是可执行的终态

τ-bench 的 retail 与 airline 是"单控"环境——只有 agent 能调工具改世界，用户只能说话。数据库是合成的 mock 库（500 用户 / 50 商品 / 1,000 订单；500 用户 / 300 航班 / 2,000 预订），任务集来自原版 τ-bench（人工维护，τ² 只做复核并在 2.0 里各替换了 50 题）〔正文〕〔数据集〕。

τ² 的 telecom 换了一套造法，也是这一系最有价值的部分。**答案 = 三类函数的组合**：

$$t=\big(\{f^{\text{init}}_{t,k}\},\ \{f^{\text{sol}}_{t,k}\},\ \{f^{\text{assert}}_{t,k}\}\big)$$

- `init` 把世界设成坏状态（打开飞行模式）；
- `sol` 是用工具修（关掉飞行模式），**必须是被测双方都能调的工具**；
- `assert` 验终态（服务是否恢复），**可以是库里任意函数**。

所以 ground truth 不是"某段文本"，是"执行完解法函数之后的数据库状态"。任务由 15 个原子组按"每组最多选一个"组合出 2,285 个，再抽 114 个做均衡〔正文〕。

**它连假阳性都提前堵了。** 构造完自动校验两件事：终态满足全部 assert；并且**在解法函数全部执行之前，任务不算解决**。第二条专门防"初始状态本来就满足断言"这种白捡分。四篇里只有它在设计层面处理了这个漏洞——我们的评测如果只比对终态，同样会漏掉这一类。

代价也很清楚：**只能判终态**。论文列了五种成功判据（DB check / status assertion / NL assertion / communication check / action matching），telecom 只用了 status assertion〔正文〕。于是一个"猜对动作、全程不解释"的 agent 能拿满分。这不是实现偷懒，是"可验证"换来的——断言函数能自动跑，NL assertion 不行。

还有一个细节值得抄：每个 telecom 任务被随机分配 `None` / `Easy` / `Hard` 三档 persona（熟手 / 小白）〔正文〕。**难度旋钮和答案分离**——同一个任务、同一套断言，换个用户画像难度就变了。我们的场景条件绑定应该照这个做：条件进输入，不进答案。

## 5.4 PersonaMem-v3：没有唯一答案，只有"检查项 + 反例"

它的底座不是合成对话，而是真实互动日志：GIST-Bench 约 400 万条，**95% 是隐式信号**；采样 200 个用户、100 万+ 事件、30 天窗口，人均 4,000+ 条〔正文〕。这一点和 LoCoMo 正好相反——LoCoMo 是合成对话 + 人工答案，PersonaMem-v3 是真实行为 + 机器生成题目。

**一行数据的结构就是它的答案定义**〔正文 4.9〕：

| 字段 | 作用 |
|---|---|
| user query | 题面，且要求"不给用户上下文就答不对" |
| example response（golden） | 正例：自然、符合 rubric、**隐含**使用偏好（不许说"我知道你喜欢 X"） |
| inferior response | 反例：长度格式相当，只在目标能力上有差异（漏偏好 / 用过期 / 泄露隐私 / 排错序 / 过度个性化） |
| ground-truth preference | 必须能回溯到真实互动记录 |
| rubric dimensions | 本题适用哪几项检查，含正负信号 |
| candidate pool | 仅推荐类：16 个候选，1 个真实正向 + 中性填充 + 同日负向硬负例 |
| expected tool calls | 仅 agentic 类 |

这套结构的价值在 **inferior response**。它把"错在哪"写成了可比对的锚点，判分从"你觉得好不好"变成"这两条差异是不是目标那一项"。我们现在的克制指标只有一条总分，缺的正是这个反例锚。

**偏好怎么变成可信的 ground truth**：候选偏好必须过多重证据（显式证据交叉验证 ≥20、全隐式 ≥50）、置信度阈值（正向 0.75 / 负向 0.55）；生成之后再用 GPT-5.5 逐行验四件事——题目是否真的依赖用户上下文、golden 是否合规且隐含、inferior 是否只差目标能力、行内证据是否可追溯；不过就重生成，再不过就删行〔正文〕。发布后审计：14 个维度 **96.6%** 通过，换 Opus-4.8 复判一致率 **89.1%**。

**唯一客观的一档**是推荐任务：答案来自用户**真实未来行为**——留出测试时刻之后不久会被正向互动的那条帖子，混进中性填充和同日负向硬负例，要求排到第一。所以 NDCG@5 有客观锚，但它只覆盖排序，覆盖不了生成质量。

## 5.5 Reflexion 的六个能力基准：答案都在外部，除了代码

| 基准 | 答案形态 | 答案是谁给的 | 这一步换掉了什么 |
|---|---|---|---|
| HumanEval | 官方单测 | 人工（平均 7.7 个/题〔数据集〕） | Reflexion 改用**自生成**测试（≤6 个），答案来源从外部变成自己 |
| MBPP | 每题 3 条断言〔数据集〕 | 人工 | 同上，FP 率 16.3% |
| LeetcodeHardGym | 测试用例 | 作者新造 | **只收 2022-10-08 之后发布的题**，卡在 GPT-4 预训练截止之后 |
| ALFWorld | 环境完成信号（0/1） | 环境 | 信号太稀疏，必须自己造"卡住"判据（重复 3 轮 / 超 30 步） |
| HotPotQA | 短答案 + exact match | 人工标注的 113k 问答 | 归一化后字面全等才算对，判不了解释质量 |
| WebShop | 属性 + 商品匹配 | 环境 | 探索空间太大，4 轮后仍无改善迹象，任务终止 |

三件事值得单独记：

1. **只有代码域出现了自证。** 其余三个（ALFWorld / HotPotQA / WebShop）的答案都在系统外部，所以反思有对象；代码域的 evaluator 是被试自己写的测试，于是 Table 2 的 FP 率（HumanEval 1.4% / MBPP 16.3%）就是这套做法的成本。这不是 Reflexion 的疏忽，是代码任务天生适合"自测"——但一旦自测，分数就必须打折报。
2. **LeetcodeHardGym 的时间切分是四篇里唯一的显式污染控制。** 40 道题全部发布于 2022-10-08 之后，理由是那是 GPT-4 的预训练截止日〔正文〕。我们自建题也应该设同一条硬门槛：题目发布时间晚于被测模型的训练截止，否则测的是记忆不是能力。
3. **ALFWorld 的 134 个环境只给"完成/未完成"。** 没有分步奖励，所以它必须发明代理失败信号；这也意味着它的分数无法归因到"哪一步错了"——和 τ² 只会判终态是同一个病。

## 5.6 五种答案形态，各自能测什么

| 形态 | 代表 | 能测 | 测不到 | 主要成本 |
|---|---|---|---|---|
| 短答案 / EM | LoCoMo、HotPotQA | 事实召回、字面正确 | 同义改写、解释质量、**拒答** | 人工写题，规模上不去 |
| 状态断言 | τ 系 | 任务是否完成、可重复（pass^k） | 过程质量、沟通、用户感受 | 要能跑的环境与工具 |
| rubric + 反例 | PersonaMem-v3 | 生成质量、克制、分寸 | 绝对分（judge 方差）、可复现 | 每题多次 judge |
| 自生成单测 | Reflexion 代码 | 可执行正确性、可迭代 | 非确定函数、副作用、FP/FN 双高 | 便宜，但会自证 |
| 环境信号 | ALFWorld、WebShop | 长程决策 | 细粒度归因（只有 0/1） | 跑环境，慢 |

这张表的用法是**排除法**：先定要测的能力，再看哪种形态覆盖它。想测"该不该说"，五种里只有 rubric + 反例能覆盖；想测"说了能不能落地"，只有状态断言能覆盖。选错形态，指标写得再漂亮也是空的。

## 5.7 三条落点

**① 没有一个现成数据集能直接给七元组打分。**

| 需求字段 | LoCoMo | τ 系 | PersonaMem-v3 |
|---|---|---|---|
| `entity_key` + `attribute`（槽位键） | 无（只有自然语言题面） | 无（状态在 DB 里，不在记忆里） | 部分（有偏好主题，不到槽位级） |
| `valid_time` | 有（对话时间戳） | 有（状态变更顺序） | 有（事件时间 + 时间屏蔽） |
| `source` | 有（turn id） | 有（工具调用） | 有（互动记录） |
| `status`（active / superseded / retracted） | 无 | 隐含在状态里 | 有演化时间线，无状态位 |

所以"三阶段解耦 + 七元组"这套口径，本质上是在补现成 benchmark 缺的那一层：**LoCoMo 有时间没状态，τ 系有状态没记忆条目，PersonaMem-v3 有演化没槽位键**。这也是我们要自己造题的真正理由——不是为了更难，是为了可归因。

**② 答案来源决定分数的上限，也决定它能证明什么。**

人工答案（LoCoMo、HumanEval）可信但小；程序化答案（τ²）可验证、能扩、还能堵假阳性，但只能判终态；真实行为答案（PersonaMem-v3 推荐）最客观，但只覆盖排序；LLM 生成 + LLM 校验（PersonaMem-v3 主体）规模最大，ground truth 自带裁判偏差，必须报一致率；自生成答案（Reflexion 单测）最便宜，但会自证。

**引一个分，必须说清答案是谁给的。** 只写"某系统在 LoCoMo 上 66.88"，读者无法判断这个数能不能和 91.0 放一起看。

**③ 人工介入的剂量是一条连续谱，不是有无。**

| 数据集 | 人工剂量 |
|---|---|
| LoCoMo、HumanEval | 全人工：写题 / 写测试 |
| τ² telecom | 程序生成 + 人工精修 + 版本间替换 50 题 |
| PersonaMem-v3 | LLM 生成 + LLM 逐行校验 + 96.6% 自动审计 + 人工抽检 |
| Reflexion 的代码测试 | 零人工：测试由被测模型自己写 |

剂量越低，规模越大、可信度越依赖"校验那一层"。我们自建评测时先确定站哪一档，并在报告里写明——这比在方法节里写"我们做了严格的人工校验"有用得多。

**版本纪律**：同一个数据集名字下面至少有 2 个分母。LoCoMo 有 / 无 adversarial；τ² 1.x 与 2.0 分数不可比；PersonaMem-v3 有 200 / 100 两个规模口径、27 / 31 两个任务口径。引用时四件套齐全才算合格：**数据集 + 版本或子集 + 答案来源 + 判分器**。

## 5.8 十二个例子

标〔原文〕的是论文附录里的真实样例，按原意译写压缩、字段不动；标〔示意〕的是我按该数据集的行结构造的，用来看形状。**两类别混着引。**

**① LoCoMo（single-hop）〔示意〕**

```
题：When did Caroline go to the support group?
金标：7 May 2023
系统输出：一个 5–6 词的短答案
判分：裁判看"是否沾到同一主题"
```

宽口径长这样：答 `May 2023` 也算对，答 `the week after she moved` 也可能算对。所以 temporal 类题号称测"相对时间换算"，实际上答对月份与答对日期同分。

**② τ-bench airline〔原文 A.2〕**

```
场景：订 5 月 26 日 ORD→PHL 单程
已知：Sophia Silva / sophia_silva_7557
未知：5 月 10 日那班的航班号
任务：订"和 5 月 10 日完全相同的那一班"，不接受其他航班；
     加一名乘客 Kevin Smith（2001-04-12）；经济舱，要靠过道 + 中间相邻两座；
     预算 $500，超过就只订自己；只接受 certificate 支付
金标：没有"答案文本"，只看订单最终长什么样
```

**③ τ-bench retail〔原文 A.2〕**

```
订单 W4284542 的物流状态
→ 未发货就取消空气净化器
→ 不能单取消就整单退到礼品卡
→ 礼品卡也不行就不取消
金标：订单状态 + 退款记录
```

这两条的共同点是**用户指令自带条件分支**（A 不行就 B，B 也不行就 C）。断言只验终态，所以 agent 走哪条路不重要——只要最后状态对就算成功。代价也在这里：中间有没有多收一次钱、有没有把"为什么不能单取消"说清楚，都不计分。

**④ τ² telecom〔原文 A.2〕**

```
Task ID：[service_issue]airplane_mode_on|unseat_sim_card
init：set_user_info(John Smith, 555-123-2002)
      turn_airplane_mode_on()     ← 飞行模式开着
      unseat_sim_card()           ← SIM 卡还松了
sol： toggle_airplane_mode() / reseat_sim_card()   ← 两次都要用户自己动手
assert：assert_service_status(expected="connected") == true
```

全篇最值得看的一个例子：**问题有两个成因，解法分属两次用户操作，agent 只能指挥不能代劳**。而且初始状态是"坏的"，断言只看终态——agent 只说"您重启一下"、用户没真去关飞行模式，终态不满足，照样 0 分。

**⑤ PersonaMem-v3 推荐题〔示意，结构按 3.2.3〕**

```
题：给这个用户的 feed 排 16 个候选
池子：1 条"测试时刻之后不久用户真的点了赞"的帖子（held-out 正例）
     + 中性填充
     + 同日"划过 / 点了不感兴趣"的帖子（硬负例）
金标：那条真实正向帖排第 1
判分：NDCG@5，不走 judge
```

**⑥ PersonaMem-v3 克制题〔示意，结构按 Table 6〕**

```
题：历史里刚出现一条敏感事件（分手 / 体检异常）。今天天气不错，推荐点周末活动？
golden：正常推荐本地活动，完全不提那条事件
inferior：推荐"适合两个人"的活动，或顺口说"出去散散心"
判分：避开反感话题 = 硬检查，命中即判负；另有一项"用量恰当"判有没有推荐过头
```

⑤⑥ 要并排看：**同一份数据里"该用偏好"和"不该用偏好"是两族题**，共用一套 rubric——一族奖励使用，一族一票否决。这就是它能同时惩罚"什么都不敢说"和"说太多"的机制。

**⑦ HumanEval〔原文 C.1〕**

```
签名：def minSubArraySum(nums):
题面：Given an array of integers nums, find the minimum sum of any
     non-empty sub-array of nums.
     minSubArraySum([2, 3, 4, 1, 2, 4]) == 1
     minSubArraySum([-1, -2, -3]) == -6
金标：人工单测（平均 7.7 个/题）
Reflexion 换成了什么：自生成 ≤6 条测试，全过就认为对
```

题面里那两个例子**不是测试，是题面的一部分**。自生成测试必须从它们出发又不能照抄，否则边界情况一条都测不到。

**⑧ MBPP〔示意，格式按数据集〕**

```
题：Write a function to remove duplicate elements from a list.
金标：assert remove_duplicates([1, 2, 2, 3]) == [1, 2, 3]
     assert remove_duplicates([]) == []
     assert remove_duplicates([5, 5, 5]) == [5]
```

每题只有 3 条断言，覆盖极窄——这就是它 FP 率 16.3% 的结构性原因：3 条过了，实现可能仍然错，而 agent 会以为自己做对了、提前收敛。

**⑨ LeetcodeHardGym〔示意〕**

```
题：给整数数组与 k，返回长度为 k 的"理想数组"个数（模 1e9+7）
金标：官方测试用例
门禁：题目首次发布必须晚于 2022-10-08（GPT-4 预训练截止）
```

**⑩ ALFWorld〔原文 4.1〕**

```
题：在抽屉里找到抹刀（finding a spatula in a drawer）
    把番茄放进冰箱冷藏（chilling a tomato in the fridge）
金标：环境返回"任务完成"
信号密度：全程只有最后那个 0/1
```

**⑪ HotPotQA〔原文 D.2〕**

```
题：What was a series of battles during the Revolutionary War, for control of
   New York City and the state of New Jersey, fought on October 28, 1776
   near White Plains, New York?
第一次答：Battle of White Plains              → INCORRECT
第二次答：The New York and New Jersey campaign → CORRECT
```

这个例子把 EM 的苛刻暴露得很干净：两个答案指的同一天同一场战事——**前者是"那一仗"，后者是"那一仗所属的战役序列"**，语义上都说得通，但只有一个字面等于金标。Reflexion 随后的反思也总结偏了，写成"我上下文给得不够"，其实是题面的粒度歧义。

**⑫ WebShop〔原文 B.1，题面为概述〕**

```
题：按客户请求在电商站里搜到并买下商品（100 条请求）
金标：商品属性匹配 + 商品 id 匹配
结果：4 轮后仍无改善迹象，作者主动终止
```

把这十二个例子并排看，最刺眼的是：**只有两个的答案是人写的自然语言**（LoCoMo 的短答案、HotPotQA 的 span），其余全是状态（τ 系 3 个）、检查项（PersonaMem-v3 2 个）、测试（HumanEval / MBPP / Leetcode 3 个）、环境信号（ALFWorld / WebShop 2 个）。

所以"在某某 benchmark 上刷到 80%"这句话，多数时候说的不是"答对了 80% 的题"，而是"80% 的任务终态符合断言"或"80% 的检查项通过"。引用时必须把这层翻译出来，否则读者会按"考试得分"去理解，而它其实更接近"验收通过率"。
