## 1. 两篇论文的核心设计对比

| 维度 | BEMULA (`2610.18052`) | MemSecBench (`2607.27080`) |
| :--- | :--- | :--- |
| **评测切入点** | **用户显式遗忘请求（Explicit Unlearning）**：在多轮对话中插入删除敏感或过时事实的请求，检验记忆系统能否按用户意图精准擦除 | **记忆投毒全生命周期安全（Write → Execute → Forget）**：追踪同一条恶意规则从写入持久化、后续召回采纳引发外部后果，到被要求选择性修复的全链路 |
| **防“未存先忘”控制** | 每条对话均配对一份**无遗忘请求的对照组 $D'$**，只有先确认系统确实记住了目标事实（`Retention Accuracy`），才计入遗忘得分 | 从同一份经过**确定性写入校验**（`W1/W2`）的污染后记忆快照独立分支出 `Execute` 与 `Forget` 两阶段 |
| **规模与测试维度** | **50** 个多会话对话实例、**135** 条（6 类 `F1–F6`）遗忘请求、**1,742** 道测试题；涵盖保留、遗忘效力（`FE`）、同源保留（`PR`）、再学习（`RLA`）、抗套取攻击（`AR`）五大套件 | **310** 个案例包（来自代码/科学、日常生活、办公 48 个场景），覆盖 `2 × 4 × 3 = 24` 配置矩阵（`OpenClaw/Hermes` × `Native/Mem0/Mem0-Graph/A-MEM` × `DeepSeek-V4-Pro/MiniMax-M3/GPT-5.5`） |
| **双约束联合指标** | $\text{Score} = \sqrt{\text{FE}\cdot\text{AR}} \times \sqrt{\text{PR}\cdot\text{RLA}}$（几何平均乘积，任一项归零总分归零）与严格请求通过率 `RPR` | 选择性修复成功率 $\text{SRSR} = \frac{\sum_i w_i f_i}{\sum_i w_i}$，其中 $f_i = d_{F_1,i} d_{F_2,i}$（同时满足“恶意语义清除/无效化 $F_1$”与“全部良性记忆完好保留 $F_2$”） |

## 2. BEMULA：显式遗忘请求的全军覆没实证（`2610.18052.md` §4 & Table 1）

### 2.1 五大测试套件与双乘积评分逻辑

```text
  [对照对话 D' (无删除请求)] ──► 检验是否确实存入目标 (RA: Retention Accuracy)
  [遗忘对话 D  (含 F1~F6 请求)]
         │
         ├──► 遗忘能力 FA = sqrt(FE * AR)
         │       ├─ FE (Forgetting Efficacy): 常规提问不再答出已删目标
         │       └─ AR (Attack Robustness):   诱导/越狱/重述套取仍无法恢复目标
         │
         └──► 可用性守卫 UG = sqrt(PR * RLA)
                 ├─ PR (Preservation): 同实例内无关/同源良性记忆不误删
                 └─ RLA (Relearning):  删除后仍能正常学习类似新事实
```

**三大核心失效模式**（`2610.18052.md` §4.3）：
1. **端到端几乎零通过**：所有被测系统与底座模型组合中，没有任何系统的端到端遗忘通过率（`RPR`）超过 **`1.5%`**，绝大多数直接为 **`0.0%`**。
2. **遗忘请求根本未触达底层存储**：`Naive RAG` 无删除路径，只把“请忘记 X”当普通新轮次嵌入入库；`LightMem` 依赖离线合并，对话中无法即时响应；`SimpleMem` 对窗口只压缩一次且永不回改；`Mem0` 虽支持更新，但往往原文吐出敏感信息（`AR = 4.7`）。
3. **过删或全局拒答**：`LangMem` 在 `GPT-5.6-Luna` 上把用户街道地址等无关事实一并删除（`PR` 暴跌至 `20.0`）；`Full Context` 在 `DeepSeek-V4.1-Flash` 上 81 次保留失败中有 **66 次**直接机械回答“我不知道该信息”（全局拒答而非精确擦除）。

## 3. MemSecBench：投毒全生命周期与选择性修复的连带损伤（`MemSecBench-arXiv-v1.tex` §4 & Table 1）

### 3.1 24 配置宏平均规律与代表性数字

- **全配置宏平均结果（`24` 配置 × `310` 案例）**：
  - **Write 写入阶段**：`W1` 通过率 `91.1%`，恶意记忆持久化率 **`MPSR = 84.2%`**（存储阶段几乎无防御）。
  - **Execute 执行阶段**：召回暴露 `E1 = 76.1%`，采纳 `E2 = 53.7%`（最大收口瓶颈在采纳阶段），完整端到端攻击成功率 **`E2E-ASR = 50.3%`**（以成功投毒为条件时 `MESR = 59.6%`）。
  - **Forget 选择性修复阶段**：成功投毒案例中，**`86.3%`** 通过目标移除（`F1`），但只有 **`62.5%`** 通过良性保留（`F2`）；同时满足两项的 **`SRSR` 降至 `56.1%`**。
- **典型后端反差（`tab:main-lifecycle-results`）**：
  - 在 `OpenClaw / DeepSeek-V4-Pro` 下，将 `Native` 换为 `A-MEM` 时，`E2E-ASR` 仅微降（`59.03% → 56.45%`），但 `SRSR` 从 **`46.31%`** 跃升至 **`87.63%`**（`OpenClaw / GPT-5.5` 下 `A-MEM` 的 `SRSR` 更达 **`93.26%`**）；然而同一 `A-MEM` 放到 `Hermes / DeepSeek-V4-Pro` 下 `SRSR` 却暴跌至 **`21.23%`**。
  - **最大绝对差异**：相比匹配的 `Native` 配置，不同记忆后端导致 `E2E-ASR` 最大差 `16.1` 个百分点、`SRSR` 最大差 **`41.3`** 个百分点——记忆安全与修复能力强依赖于“Agent 框架 + 记忆后端 + 底座模型”整套栈，不能只看单一组件。

### 3.2 关键结论：连带损伤（`30.2 pp` 缺口）大于删不干净（`6.4 pp` 缺口）

`F1`（`86.3%`）与 `SRSR`（`56.1%`）之间 **`30.2` 个百分点** 的落差，远大于 `F2`（`62.5%`）与 `SRSR` 之间 **`6.4` 个百分点** 的落差——证明选择性修复的主要失败原因不是“删不掉恶意/过期规则”，而是**“把恶意规则删掉的同时误伤了同源良性偏好”**。

## 4. 对我们当前方案的直接启发

1. **记忆修改/删除必须采用“主从精准索引 + 非破坏性版本失效”，禁止整段重写误伤良性偏好**：我们的规则条目与历史记录修改不能依赖大模型重新摘要整份记忆文件（极易出现 `LangMem` 式误删或 `MemSecBench` 中 `30.2 pp` 的连带损伤），而应按单条记录 ID 精准置为 `invalidated / deleted`。
2. **评测遗忘能力必须同时跑通四项校验**：借鉴 `BEMULA` 的对照组思想与双乘积约束，测试“用户要求取消某项长期习惯/偏好”时，必须同时检验：**① 此前确实写入（`RA`）、② 后续不再触发且多角度追问不泄露（`FE + AR`）、③ 同一用户同源的其他习惯完好无损（`PR / F2`）**。
3. **警惕“全局拒答”伪装成精准遗忘**：如果模型在被要求遗忘 A 后，连带对 B/C 也一律回答“我不清楚”，必须在保留率 `PR` 维度直接判负。
