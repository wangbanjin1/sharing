## 18.1 背景与核心贡献

1. **现有长期记忆基准的两大短板**〔正文 `Sec 1–2`〕：
   - 多聚焦**人人闲聊**（如 `MSC`、[`LoCoMo`](16_benchmark_locomo.md)、`DialSim`），缺少真实助手场景中大量包含长输入/长回复的**任务型人机对话（Task-Oriented User–AI Chat）**，且历史长度不可自由伸缩；
   - 能力覆盖不全：普遍遗漏对**助手侧回复信息（Assistant-Side Information）**的回忆、**动态知识更新（Knowledge Updates）**、**带时间戳元数据的时序推理**，以及对**未提及事实的未知拒答（Abstention）**。
2. **核心贡献**〔正文 `Sec 1, 3–5`〕：
   - 构建包含 **500 道人工精选与核验问题**的 `LongMemEval`，提供标准化 **`LongMemEval_S`（约 40 个会话 / `~115k tokens`）**与 **`LongMemEval_M`（约 500 个会话 / `~1.5M tokens`）**，并开源任意长度对话拼接流水线；
   - 提出“**索引—检索—读出（Indexing / Retrieval / Reading）**”三阶段记忆统一框架，沿 **Value / Key / Query / Reading Strategy** 四个控制点做系统控制变量实验，给出可直接落地的最优组合设计。

## 18.2 形式化定义、五维能力与基准构造管线

### 18.2.1 任务形式化与五维七类题型

每条测试样本是一个四元组 $(\mathbf{S}, q, t_q, a)$〔正文 `Sec 3.1–3.2`〕：
- $\mathbf{S} = [(t_1, S_1), (t_2, S_2), \dots, (t_N, S_N)]$：按时间从早到晚排列的 $N$ 个历史人机对话会话，每个会话由多个轮次（`round`：1 条用户消息 + 1 条助手回复）组成；
- 测试时会话流式逐一输入系统，最后在时刻 $t_q > t_N$ 提出问题 $q$，比对答案或评分标准 $a$。

| 五大核心记忆能力 | 对应 7 类评测问题 (`question_type`) | 核心考核点 |
| :--- | :--- | :--- |
| **1. 信息提取 (`IE`)** | `single-session-user`、`single-session-assistant`、`single-session-preference` | 回忆单个会话中**用户**或**助手**提到的具体事实，以及利用隐含偏好做个性化回答 |
| **2. 多会话推理 (`MR`)** | `multi-session` | 跨多个会话（最多 6 个证据会话）聚合、计数与对比分散信息 |
| **3. 知识更新 (`KU`)** | `knowledge-update` | 识别用户状态/住所/工作等随时间的动态变更，以最新有效信息覆盖旧事实 |
| **4. 时序推理 (`TR`)** | `temporal-reasoning` | 结合对话内相对时间表达（“上个月”）与会话元数据时间戳 $t_i$ 计算绝对时间与顺序 |
| **5. 未知拒答 (`ABS`)** | `*_abs`（从前几类中抽取 **30 题**改写为“错误前提”问题） | 识别历史中从未提及的信息并正确拒答，而非编造幻觉 |

### 18.2.2 三步“大海捞针”式构造管线

〔正文 `Sec 3.2, Fig. 2`〕：
1. **属性本体与问题生成**：定义覆盖 5 大类（生活方式、个人物品、生活事件、情境背景、人口属性）共 **164 个用户属性**的本体；用 `Llama 3 70B Instruct` 生成背景段落并提出种子问答，再由 **3 位资深 NLP 研究员（累计约 400 人工小时）**筛选、改写为高难度问题并拆解为带时间戳的**证据陈述（Evidence Statements）**。
2. **间接化证据会话构造**：用自对话（Self-Chat）把每条证据嵌入任务型对话中，**强制要求用户模型间接流露证据**（如不直说“我上个月买了新车”，而是咨询汽车保险时顺带提起）；人工复核并调整证据在会话中的位置（偏前/偏中/偏后）与口语化时间表达，同时标注轮次级标签 `has_answer: true`。
3. **自由伸缩干草堆拼接**：从无冲突属性自对话与公开语料（`ShareGPT` + `UltraChat`）抽取无关填充会话，将证据会话随机嵌入其中并分配连贯时间戳。

## 18.3 先导实证：商业系统与长上下文大模型同样失守

〔正文 `Sec 3.4` + 附录 `Sec 8, Fig. 4, Table 7`〕：
- **商业记忆产品人工实测（97 题简化版，仅 3–6 个会话，比 `S` 短约 10 倍，累计约 150 人工小时）**：
  - 离线把全部 3–6 个会话直接喂给 `GPT-4o` 可达 **`91.84%`**；
  - 逐轮网页交互测试 **`ChatGPT`（GPT-4o / 4o-mini）** 仅为 **`57.73% / 71.13%`**（相对离线掉点 `37%`），主要死因是后续压缩改写历史时**覆盖丢弃早期关键细节**；
  - **`Coze`（GPT-4o / 3.5-turbo）** 仅为 **`32.99% / 24.74%`**（掉点 `64%`），主要死因是**漏记未直白强调的间接信息**（`MR` 仅 `14.7%`、`KU` 仅 `20.8%`）。
- **长上下文模型实测（`LongMemEval_S`, `~115k tokens`）**（`Fig. 4b`）：
  - 与只看证据会话的 `Oracle` 对比，直接读全量 `S` 时所有模型均出现 **`30%–66%` 相对掉点**：`GPT-4o` 从 `87.0% → 60.6%`（加 `CoN` 后 `92.4% → 64.0%`）；`Llama 3.1 70B` 从 `74.4% → 33.4%`（加 `CoN` 后 `84.8% → 28.6%`）；`Phi-3.5 Mini` 从 `66.0% → 34.2%`。

## 18.4 三阶段四控制点统一架构与全量实验

```
┌──────────────────────────────────────────────────────────────────────────────┐
│            LongMemEval 三阶段四控制点统一记忆框架 (Sec 4, Fig. 6 & App 9)    │
└──────────────────────────────────────────────────────────────────────────────┘
  (1) Indexing 离线/在线索引 I(S, D)
      ├── CP1 Value 粒度: Session (整会话) vs. Round (轮次对) vs. Summary / Fact
      └── CP2 Key 扩展:   K = V + User Fact (文档扩展拼接，胜过独立多路 Rank Merging)
                          + Event Timestamps (事件发生日期索引)
              │
              ▼
  (2) Retrieval 检索 Q(q) & S(q', D)
      ├── 稠密检索: Stella V5 1.5B (优于 BM25 / Contriever)
      └── CP3 Query 扩展: 强 LLM M_T 推断查询时间窗 [start±2d, end±2d] 剪枝搜索空间
              │
              ▼
  (3) Reading 读出 R(M, D')
      └── CP4 读出策略:   按时间戳排序 + 结构化 JSON 格式 + Chain-of-Note (先逐条摘录再推理)
```

### 18.4.1 控制点 1 & 2：Value 粒度与 Key 扩展对比（`LongMemEval_M` 500 会话, `Table 2`）

**核心机制结论**〔正文 `Sec 5.2–5.3` + 附录 `Sec 11.3`〕：
1. **粒度选择**：在同等检索 Token 预算下，将长会话拆分为**轮次（`Round`）**显著提升强阅读器（GPT-4o）的端到端 QA 表现；而若完全丢弃原文仅存压缩摘要/事实，会因细节丢失导致整体指标下滑（仅 `multi-session` 题目受益于结构化统一抽取）。此外小模型 `Llama 3.1 8B` 检索上下文超过 `3k tokens` 后明显退化，而 `GPT-4o` 在 `20k+ tokens` 仍持续收益。
2. **键扩展胜过替换与多路融合**：单纯用事实或关键词替换原文键反而降分；把抽取的用户事实拼接回原文键（`K = V + fact`）平均提升 `Recall@k` **`+9.4%`**、最终 QA 准确率 **`+5.4%`**；且在索引阶段拼接（`Key Merging`）明显优于检索阶段建多索引再融合排序（`Rank Merging`，后者索引膨胀 $m+1$ 倍且召回更差）。

### 18.4.2 控制点 3 & 4：时间感知查询扩展与结构化读出（`Table 3, Fig. 8, Table 5, Table 8`）

- **时间感知剪枝（`Temporal Reasoning` 子集，`Table 3`）**：
  - `Value = Round` + `K = V + fact` 下，用 `GPT-4o` 从问题中推断时间区间 `[start - 2d, end + 2d]` 进行过滤，`Recall@10` 从 `0.550 → 0.722`（`NDCG@10` `0.598 → 0.669`），平均提升 **`+11.3%`**；`Value = Session` 时从 `0.721 → 0.797`（平均 **`+6.8%`**）。
  - 但若用弱模型（`Llama 3.1 8B`）推断时间窗，会在**无时间指代的问题上幻觉出时间范围**并误杀正确证据，反而掉分（`App 11.4`）。
- **读出策略（`Oracle` 检索下，`Fig. 8`）**：即使检索召回 100% 完美，直接用自然语言读出仍比最优方案低高达 **10 个百分点**；采用 **`JSON` 结构化格式 + `Chain-of-Note`（逐条提取笔记再汇总推理）** 在各能力档次模型上稳定取得最高分。
- **更多中小模型跨 `S / M` 对比（`Table 8`）**：在 `LongMemEval_S` 上，`Mistral-Nemo` 直接长上下文仅 `16.2%`，采用 `Round + (K = V + fact)` 升至 **`66.6%`**；`Llama-3.2-3B` 从 `0.8%` 升至 **`50.8%`**（`M` 上仍保持 `47.0%`）。
- **自动 Judge 元评估与错误归因（`Table 5, Fig. 19`）**：每类抽 30 题人工对齐检验，`GPT-4o` Judge 对 `GPT-4o` 和 `Llama-3.1-8B` 回答的判分一致率分别达 **`98%`** 与 **`97%`**。全系统误差分布表明：**40%–50% 的错误源于“检索已召回 Top-10 但读出推理出错”**（占全样本 `15%–19%`）。

## 18.6 批判性评价与对主报告的落点启发

1. **对主报告 `1.1 / 2.5 / 4.2` 节的直接支撑**：
   - 确立了面向人机长交互记忆评测的五大能力标准分类（`IE / MR / KU / TR / ABS`），特别是补齐了 [`LoCoMo`](16_benchmark_locomo.md) 缺失的**知识更新（`KU`）**与**助手侧发言记忆**评测维度。
   - 实证验证了“**保留原文轮次 `Round` + 抽取结构化事实拼接为增强索引键（`K = V + fact`）+ 按时间窗过滤 + `JSON + CoN` 分步读出**”这条高性价比工程基线，直接支撑我们混合记忆索引层的设计选型。
2. **自身局限与差异校准**：
   - `LongMemEval` 仍采用离线静态拼装单题干草堆的方式（500 道题各自拥有独立拼接的历史上下文），**每道题之间互不共享、也不存在持续在线写入后的多轮累积污染与记忆遗忘压力**（这是后续 [`MemoryAgentBench`](19_benchmark_memory_agent_bench.md) 与 [`Epistemics`](11_memory_epistemics_agent_memory.md) 重点弥补的方向）。
   - `knowledge-update` 的官方 Judge 允许回复同时带出旧信息而不扣分，而在实际企业/联接业务中，若旧约束残留在生成结果中会引发参数冲突，因此我们在报告中应像 [`IntentDelta`](23_benchmark_intent_delta.md) 那样额外考核**作废旧约束残留率**。
