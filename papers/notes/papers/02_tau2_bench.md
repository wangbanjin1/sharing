## 2.1 形式化：七元组

论文把双控交互建模成 Dec-POMDP，元组 $(S,\{A_i\},\{O_i\},T,R,U,M)$〔正文〕：

| 分量 | 定义 | 电信域实例 |
|---|---|---|
| $M$ 消息空间 | agent 与 user 之间交换的自然语言消息 | 用户："我流量用不了" |
| $S$ 状态空间 | $S=S_{\text{world}}\otimes S_{\text{history}}$，$S_{\text{world}}=S_{\text{db,agent}}\otimes S_{\text{db,user}}$ | CRM 客户档案 ⊗ 模拟手机的开关状态 |
| $A_i$ 动作空间 | 工具调用 $a_{i,\text{tool}}$ 或消息 $m_i$；**每轮只有一个玩家动作** | agent：`get_customer_by_id`；user：`toggle_airplane_mode` |
| $O_i$ 观测空间 | 工具返回或对方消息；**每轮只有一个玩家收到观测** | 用户看到"移动数据已开启" |
| $T$ 转移 | $T:S\times A\to S\times O$ | `enable_roaming` 改变世界状态 |
| $R$ 奖励 | $R:S\to[0,1]$，只看整体状态 | 用户数据库里服务已恢复 |
| $U$ 指令空间 | 场景指引 + agent 必须遵守的域策略 | 附录 D 的三份 policy |

把用户也放进状态空间、也给它工具，是整个 benchmark 的核心动作。它换来的是**用户行为的可预测性**——原文明确说，可靠性来自"定义用户工具及其对用户状态的影响"，而不是靠长段自然语言规范去约束模拟器〔正文〕。

## 2.2 五阶段构建与任务组合

〔正文〕流程是：PRD → agent 侧 schema/工具 → **user 侧 schema/工具** → 程序化任务 → 域策略 → 人工精修。第 2 阶段是 τ² 相对 τ 的新增项，也是最容易被忽略的一步：没有它，用户就没法执行"你帮我把飞行模式关一下"。

任务不是人写的，是组合出来的。每个原子子任务

$$t=\big(\{f^{\text{init}}_{t,k}\},\ \{f^{\text{sol}}_{t,k}\},\ \{f^{\text{assert}}_{t,k}\}\big)$$

- 初始化函数设初始状态（如 `set_airplane_mode(True)`）；
- 解法函数用工具修（如 `toggle_airplane_mode()`），**必须是被测双方可用的工具**；
- 断言函数验终态（如 `assert_service_status("connected")`），**可以是库里任意函数**。

原子子任务按"互斥或可替代"分组，一个复合任务从每组里**最多选一个**子任务，把函数调用串起来。构造完还要自动校验两件事：终态满足全部断言，且**解法函数全部执行前任务不算解决**（防止"碰巧已经是好状态"被判过）。

电信域：**15 个原子子任务组**，覆盖 3 类意图（`service_issue` / `mobile_data_issue` / `mms_issue`），按"每组最多选一个"组合出 **2,285 个任务**，再抽样 **114 个**做均衡。子任务个数被当作难度代理〔正文〕。

各域规模〔图表 Table 1〕：

| 域 | agent 数据库 | agent 工具 | user 工具 | 任务数 |
|---|---|---|---|---|
| retail | 500 用户 / 50 商品 / 1,000 订单 | 7 写 6 读 | — | 115 |
| airline | 500 用户 / 300 航班 / 2,000 预订 | 6 写 6 读 | — | 50 |
| **telecom** | 5 套餐 / 9 条线 / 4 客户 | 6 写 7 读 | **15 写 15 读** | **114（全量 2,285）** |

## 2.3 五种评估准则，它只用了一种

论文列了五种任务成功判据〔正文〕，这是个很实用的清单：

| 准则 | 判什么 | 电信域用了？ |
|---|---|---|
| DB check | 数据库终态 | 否 |
| **status assertion** | 用预定义断言函数查 $S_{\text{world}}$ | **是（唯一）** |
| natural language assertion | 用自然语言描述查 $S_{\text{history}}$，如"agent 诊断出了原因" | 否 |
| communication info check | agent 是否传达了某条信息 | 否 |
| action matching | 每个解法函数是否真的出现在轨迹里 | 否 |

**只看 assertion 的后果**：一个靠"猜对动作"通过、但全程没跟用户解释的系统，在电信域能拿满分。所以它的分数是"问题解决了没有"，不是"服务好不好"。我们如果要判"过程质量"，不能在 τ² 的口径下做，得另加 NL assertion 或 communication check。

## 2.4 结果：Pass^k 与三分法消融

`Pass^k` 的定义是**同一任务连跑 k 次全部成功**的比率；每任务跑 4 次、temperature 0〔正文〕。四个模型的完整数值〔图表 Figure 3〕：

| 模型 | retail $k{=}1..4$ | airline $k{=}1..4$ | telecom $k{=}1..4$ |
|---|---|---|---|
| gpt-4.1 | 0.74 / 0.64 / 0.58 / 0.53 | 0.56 / 0.46 / 0.42 / 0.40 | **0.34 / 0.26 / 0.22 / 0.19** |
| gpt-4.1-mini | 0.66 / 0.53 / 0.44 / 0.39 | 0.51 / 0.39 / 0.32 / 0.26 | 0.44 / 0.30 / 0.22 / 0.18 |
| o4-mini | 0.71 / 0.59 / 0.52 / 0.46 | 0.59 / 0.48 / 0.42 / 0.38 | 0.42 / 0.33 / 0.29 / 0.26 |
| claude-3.7-sonnet | 0.79 / 0.69 / 0.63 / 0.60 | 0.50 / 0.41 / 0.38 / 0.36 | 0.49 / 0.37 / 0.31 / 0.25 |

telecom 上 gpt-4.1 从 0.34 掉到 0.19（−44%）、claude-3.7-sonnet 从 0.49 掉到 0.25（−49%）。**单次通过率把能力高估约 1.8 倍**（$0.34/0.19$）。而且 telecom 的斜率明显比 airline 陡——同一模型在"要跟人协作"的域里重复性更差，这个差别不是难度差，是双控引入的方差。

更有价值的是三分法消融〔图表 Figure 4〕：

| 模式 | 设定 | gpt-4.1 | o4-mini |
|---|---|---|---|
| Oracle Plan | 直接给出正确工具调用序列（含用户侧动作），只考"能不能协作执行" | **0.73** | **0.96** |
| No-User | 给一张工单说明问题与成功标准，agent 独占全部工具，不需要沟通 | **0.52** | 0.67 |
| Default | 双控 + 用户共享工具 | **0.34** | 0.42 |

这三个数可以当一把尺子用〔推导〕：

- Default → No-User 差 **18 / 25 点**，这部分是**双控协调成本**（把用户当执行器使唤的损耗）；
- No-User → Oracle 差 **21 / 29 点**，这部分是**诊断与规划成本**（不知道正确动作序列时的推理损耗）；
- Oracle 0.73 意味着即使计划全给对，仍有 27% 失败——**执行与沟通本身的损耗**。

我们报告里的五类失败归因（W-MISS / W-WRONG / R-MISS / R-RANK / D-MISUSE）目前全落在"信息"上，缺一个"协调"维度。τ² 这个三分法正好补上：**同一套任务，换三种控制模式跑三遍，就能把失败拆成规划错、执行错、协调错**。这比事后人工归因便宜得多。

另外两个结论：

- **策略文档的写法会反向影响高分区间**。给更具体的工作流 policy，在 Default / No-User 上小涨，但在 Oracle Plan 上**反而跌**（gpt-4.1 0.73→0.57，o4-mini 0.96→0.88）〔图表〕。原文的猜测是"已经有标准答案了，再给流程会干扰"。对我们的启示：**提示词增益要在能力区间内测，不能只在弱配置上验证**。
- **动作数一多就崩**。按所需动作数分箱，Default 模式下超过 7 个动作接近 0 分；No-User 好一些，但两者差距从 0.3–0.4 收窄到 0.2 以内〔图表 Figure 5〕。说明长程可靠性是独立瓶颈，不是沟通问题。

## 2.5 用户模拟器：它被评了，但评的是行为合规

人工双标注结果〔图表 Table 2〕：

| 域 | 对话数 | 致命错误 | 非致命错误 | 总错误率 |
|---|---|---|---|---|
| airline | 100 | 13（13%） | 34（34%） | 47% |
| retail | 50 | 6（12%） | 14（28%） | 40% |
| **telecom** | 50 | **3（6%）** | **5（10%）** | **16%** |

标注准则是四条〔正文〕：遵守模拟器指南、遵守用户指令、正确使用用户工具、对话自然连贯。每段对话两人复核，错误分"阻止任务完成"与"不影响完成"两类。

**电信域错误率只有零售的 40%，原因不是任务更简单，而是接口更硬**——用户有 30 个结构化工具，动作空间把模拟器约束住了。

信息节奏（会不会把用户没问到的槽位提前说出来）这件事要分三层看：

1. **有明文规范**：模拟器指南的 Core Principles 里写着 `Disclose information progressively. Wait for the agent to ask for specific information before providing it.`，任务指令还把信息拆成 `Known info` / `Unknown info` 两栏，明确告诉模拟器"这个你不知道"。
2. **有人工标注**：四条准则第一条就是"遵守模拟器指南"，理论上覆盖了这条。
3. **没有独立指标**：错误率只分致命/非致命，没有单列"提前泄露槽位"的比率，也没报每条准则的通过率。

所以缺口的确切表述是：**规范有、标注有、指标没有**——不是"没管"，是"管了但不可度量"。这个区别对我们自己搭评测很关键：写进 prompt 不等于能被测出来，得有独立计数。

顺带记一处论文内部不一致：Table 2 的 caption 写 "no critical errors were reported"（电信域没有致命错误），但表里 telecom 那一行是 `3 (6%)`。以表为准，caption 是笔误。

## 2.6 提示词与接口设计

〔正文附录 C〕两段系统提示词都值得抄：

**Agent**：`In each turn you can either: send a message to the user, or make a tool call. You cannot do both at the same time.` —— **一轮一个动作，说话和调工具互斥**。这是个 half-duplex 设计，逼模型自己决定"这一轮是问还是做"。

**User simulator** 的 Core Principles 里有几条是硬约束：
- 一次只发一条消息，保持自然节奏；
- 不许编造场景里没给的信息，没给的就算"不知道"；
- 不许编造工具返回，必须基于真实调用结果；
- 不复述指令原文，要改写；
- **逐步披露**，等 agent 问到再说；
- 只在 agent 要求时调工具；agent 一次让做多个动作，要明确说"我一次只能做一个"；
- 结束用 `###STOP###`，转人工用 `###TRANSFER###`，场景信息不足用 `###OUT-OF-SCOPE###`。

`###STOP###` / `###TRANSFER###` / `###OUT-OF-SCOPE###` 这三个 token 是个很省事的设计：把"对话为什么结束"变成可统计的枚举，而不是靠事后判断。我们的对话接口应该直接抄这一条——**终止原因是评测数据，不是日志**。

## 2.7 实现对账

仓库 `sierra-research/tau2-bench` 现在是 **2.0.0**，README 明确写 **2.0 与 1.x 的分数不可比**（输入不完全一致、提示词变更、裁判模型变更），要对比 1.x 榜单得用 `v1.0.1` 那个 tag。2.0 还对英语 retail 与 telecom **各替换了 50 道复核过的任务**〔实现〕。

判分实现上，`evaluation_criteria.actions` 决定动作正确性怎么查，`reward_basis` 门控奖励计算；`tau2 judges suite` 是自然度/语音保真/工具使用这类裁判，**不改变任务奖励**〔实现〕。这条边界很重要：裁判只做诊断，不参与打分。

CLI：`tau2 run --domain telecom --num-trials 4` / `tau2 view --file data/simulations/<run>` / `tau2 judges suite <run>`。

成本〔正文〕：gpt-4.1 作 agent 与模拟器时，单任务 $0.086 / $0.059；全部域跑 1 trial 约 **$40**。这个量级决定了"能不能 nightly 重跑"——40 美元一轮，可以，但不能每改一版提示词就跑。
