## 1. 核心问题与 `UFS` 评测架构

现有交互式评测（如 `tau-bench`、`tau^2-bench`）和多轮 RL 训练（如 `MUA-RL`）只对**被测 Agent** 的最终任务奖励 $R_\tau$ 打分，默认“充当环境一部分的用户模拟器”忠实执行了指令。然而实证表明：当固定被测 Agent 为 `GPT-5.5`，仅切换 7 个不同的用户模拟器（`375` 个企业任务：`Telecom 114`、`Airline 50`、`Retail 114`、`Banking Knowledge 97`）时，Agent 的平均任务奖励 $R_\tau$ 竟出现 **`.152`（`.644` → `.796`）** 的剧烈波动，且 **24.4%** 的“Agent 成功轨迹”里其实包含用户模拟器的违规操作（`Telecom` 高达 **39.7%**）。

```text
  [私有用户蓝图 + 模拟器契约规范 + 用户工具面]
         │
         ▼  Claude Opus 4.8 生成原子准则 (4~8 条/任务, 共 2,141 条)
            └─► GPT-5.6-Sol 独立校验 9 项合规性 (可证伪/归因用户/无冗余)
         │
         ▼  对候选交互轨迹逐条盲评 (盲去模拟器身份)
    f_i = Π_j 1{c_ij 通过}   ──►   UFS = (1/N) Σ_i f_i  (全票通过率)
         │
         └─► 与成本结合做约束选型: U*(q) = argmin_U Cost(U)  s.t. UFS(U) >= q
```

**四大失效家族（共 19 个细分模式，实际触发 18 个）**（`2609.38043.md` Sec. 2 & Appendix Failure Taxonomy）：
1. **提前剧透（`premature disclosure`，最高发：480 次）**：包含 `volunteers_unasked_info`、`preempts_diagnosis`、`dumps_blueprint`（例如 `Qwen3.6-35B` 在首轮未询问时直接说出姓名和电话号码），导致原本考察多轮追问的环节被跳过。
2. **事实接地失效（`groundedness`）**：包含 `unexecuted-action claims`（例如 `Gemma-26B` 口头声称“已关闭飞行模式”，但实际未调用 `toggle_airplane_mode`）、编造设备/个人状态（例如检查返回失败却声称“图片发送成功”）。
3. **目标偏离（`goal deviation`，134 次）**：过早终止对话、接受禁止或不充分的结果、放弃任务目标。
4. **遗漏信息（`missed information`）**：Agent 已明确追问却拒不提供已知槽位，或跳过被要求执行的用户动作。

### 2.2 为什么任务奖励 $R_\tau$ 对模拟器违规“视而不见”

1. **最大破坏与最隐蔽违规错位**：目标偏离（`goal deviation`）虽只出现 134 次，但会让 Agent 通过率暴跌 **`.515`**；而最泛滥的**提前剧透（480 次）**对 $R_\tau$ 的平均影响仅 **`-.043`**，中位数甚至是正数 **`+.033`**。在 `Telecom` 上，`Sonnet-4-6` 与 `GPT-4.1-mini` 给出的 Agent $R_\tau$ 同为 `.947`，但两者的 `UFS` 却相差悬殊（`.474` 对比 `.737`）。
2. **严重扭曲多轮交互与 RL 训练轨迹**：在所有 $R_\tau = 1$ 的成功轨迹中，提前剧透会让冻结的 `GPT-5.5` 平均少发起 **`1.06` 次工具调用**、少提 **`0.26` 个问题**，从而强化出“懒于追问”的错误策略。跨 7 个模拟器的平均交互轮数与 `UFS` 的相关性高达 **$r = .955$**（而与 $R_\tau$ 仅 $r = .594$）。
3. **机械动作探针补充盲区**：在 `Telecom` 的 658 条轨迹中，无裁判工具比对发现了 54 次漏掉金标准用户写操作的情况，其中 **23 条**竟通过了全部语义准则检查——证明语义审计之外仍需对工具写入状态做硬核校验。

## 3. 对我们当前方案的直接启发

1. **把用户模拟器自身纳入评测审计（契约忠实度门禁）**：在跑通我们的“隐去细则 + 追问释放”多轮评测前，必须先用类似 `UFS` 的规则清单抽检用户模拟器：重点排查“首轮/未问先答（`volunteers_unasked_info`）”与“口头答应操作但未改状态（`unexecuted-action`）”。
2. **用工具状态断言补足 LLM 语义裁判盲区**：涉及开关配置、参数修改或单据提交的用户动作，不能只靠裁判模型读对话文本打分，必须比对底层状态/工具调用日志。
3. **性价比选型而非盲目堆超大模型**：高价闭源模型（如 `Sonnet-4-6`）在“不提前剧透”上未必优于轻量级开源或 Flash 模型（如 `Gemma-31B` / `Gemini-3.5-Flash`），应基于我们的业务域实测 `UFS` 与单轮成本选定固定版本的模拟器。
