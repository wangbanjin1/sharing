## 一、Part I — WASP-Mem：自组织互链 Wiki 与程序记忆的“苦涩教训” (`2611.04003`)

### 1. 核心思路与三大反直觉实证贡献

#### (1) 核心思路：填补“残差程序知识”缺口，把组织权还给 Agent

企业环境充满了系统提示词和 API 文档没写的潜规则（特殊分页参数、权限前置条件、服务异常恢复分支），作者称之为**残差程序知识（Residual Procedural Knowledge）**。不同于情景记忆（多次事件独立保存）和语义记忆（错误事实直接丢弃），一条合格的**程序记忆必须凑齐四要素：「目标 + 触发条件 + 可执行命令细节 + 失败恢复路径」**。

WASP-Mem 受 Obsidian 双链笔记启发，让巩固子 Agent 按序维护一个由 `index.md` 总路由和 `[[wikilinks]]` 互连的本地 Markdown Wiki，并通过受控消融得出了程序记忆领域的“苦涩教训（Bitter Lesson）”：

- **别替模型定死 Schema，也别写脚本强行合并**：人工预设强类型字段会削足适履截断关键代码细节；用脚本按工具名归一化强合并更会把“用 Python 改卷子”和“用 Python 抽视频帧”硬揉成一页；**让 Agent 写入前先读旧 Wiki、自主决定改旧页还是建新页（`Free Form` 隐式去重），体积最小、分最高**。
- **失败轨迹本身是噪声，“带诊断的失败”才是金矿**：纯靠模型自评（`Self-Judge`）收失败轨迹不仅不涨分反而倒退；但只要给失败轨迹配上检查点报错定位与人工根因诊断，1 轮迭代就能吊打 4 轮模型自嗨。

#### (2) 三大核心贡献

1. **证实无约束双链 Wiki（`Free Form`）全面击败预设 Schema 与分层树**：在 TheAgentCompany（127 职场任务 / 542 检查点）与隐藏 SOP 的 τ²-Bench Retail 上，横跨三款旗舰模型，`Free Form` 存储体积比强类型 `Schema Form` 缩小 **57%–71%**，检查点通过率反而高出 **+4.6 ~ +6.8 pp**。
2. **厘清“信息过滤器假说（Filter Hypothesis）”四类退化机理**：审计揭示独立提取基线（`SkillX`）对同一 GitLab 认证重复建了 **15 个碎片页**（过滤不足），而预设 `Schema Form` 丢弃具体脚本格式（过度过滤）、脚本去重 `Schema Form-ED` 触发跨业务误合并。
3. **定量锁定人类介入的最高 ROI 位置**：人工诊断用在成功轨迹上几乎零增益（`+0.9~2.0 pp`），用在失败轨迹上则引爆 **+9.6 ~ +10.5 pp** 检查点跃升（完整任务通关率 **+13.4 ~ +14.2 pp**）；经过 4 轮诊断迭代（`R0 -> R4`），GPT-5.4 通关率从 `40.2%`（51/127）翻倍推至 **`78.0%`（99/127）**，单轮执行 API 成本反降 17%–20%。

### 2. WASP-Mem 双阶段闭环与七种受控对比设计 (`Sec 3, App B`)

```text
【阶段 1: 冻结执行期 Execution】 (只读挂载当前轮 Wiki 库 M_r)
   新任务 q_i ──► 只读检索子 Agent: 查 index.md 总目录 + Cohere Embed v4 (1024d) 搜 Top-5 页面
                                  ──► 顺着 [[wikilinks]] 跨页拉取关联前置条件/异常教训
                                  ──► 若顶层未命中或中途步骤报错，触发子目标级补搜 (Top-3)
              ──► Bash 执行器跑完任务产出轨迹 τ_i (.jsonl) + 采集反馈信号 (自评 / 检查点二值 / +人工诊断)

【阶段 2: 离线巩固期 Consolidation】 (在可变副本上按字典序逐条消化达标轨迹，生成 M_{r+1})
   1. 先读后写隐式归并 (Ingestion): 唤醒巩固子 Agent 审阅 [轨迹 + 反馈]，【强制先查阅现有 Wiki 页面】
                                    ──► 自主决定原地增补旧页面(如追加异常分支) 或 新建页面挂 [[wikilinks]]
   2. 巡检整形 (Lint): 全局扫描泛化性、歧义、超长页与断链冲突，执行拆页、合页或重连双链
   3. 重建索引 (Re-index): 对更新后的 Markdown 文件集重算 1024 维稠密向量索引，冻结供下一轮使用
```

**三款内部变体 vs. 四类外部基线的核心差异边界**：

- **外部基线**：`No Memory`（裸跑）、`No Consolidation`（直接搜最像的 1 条 `.jsonl` 原始轨迹）、`Insights`（每条轨迹独立抽扁平原则，跨会话零去重）、`SkillX`（固定 `Planning/Functional/Atomic` 三层技能树，跨树零去重）。
- **内部受控三变体**：
  1. **`Free Form`（主力推荐）**：无固定字段约束的 Markdown 页 + **写前读库隐式去重** + 自由双链；
  2. **`Schema Form`**：人工强行拆死 `Procedures / Actions / Lessons` 三种页面模板与枚举槽位 + 写前读库隐式去重（禁止 Action 间互链）；
  3. **`Schema Form-ED`（显式脚本去重）**：不读旧库盲抽强类型页，再用确定性脚本把页面 ID 归一化（如凡调 Python 统一映射为 `action-bash-run-python`）强制 LLM 合并同 ID 页。

## 二、Part II — SPEM：反向切片 DAG 提纯与状态感知 Skill-GNN (`2610.26995`)

### 1. 核心思路与三大算法贡献

当可用技能扩展到数百至 2,000 个时，全量塞进 Prompt（`Vanilla Skills`）直接撑爆上下文，而纯向量 Top-$K$ 检索（`Vector Skills`）只看字面相似，完全不懂**“必须先调技能 A 拿到句柄、才能调技能 B”**的前置状态依赖（2,000 技能下纯向量 `Hit@1` 跌至 **0.0**）。

**SPEM 的破局思路是“熟路直接走提纯 DAG 骨架，生路/报错用 2ms 轻量 GNN 看状态选下一步”**：

1. **双层记忆分工**：上层存跨任务验证过的**多步技能依赖图模板（`Skill-DAG`）**，命中高置信模板（余弦 $\ge 0.80$）直接一步挂载紧凑主干；下层存**原子技能卡片（`Atomic Skill`）**，检索向量只编码 `名称 + 一句话功能` 防长文档稀释，跑完用指数移动平均（EMA）动态刷新每个技能的成功率与开销账本；
2. **终点反向切片提纯（Backward Slicing）**：Agent 成功跑完的原始轨迹（平均 13.4 步）充斥试错空转；入库前以最终成功节点为锚点**倒推因果可达路径**，配合步骤效用打分剪掉 54.9% 废分支（压至 6.0 步）；失败局绝不建烂模板，只扣减所调技能的 EMA 可靠分；
3. **2ms 级状态感知 `Skill-GNN` + 零轨迹冷启动**：未命中模板或中途报错重规划时，把「当前任务 + 实时环境状态 + 已执行历史 + Top-$K$ 候选技能」临时连成一张小子图，跑 2 层异构 GNN（耗时仅 **1.5–2.4 ms**）选出最匹配当前状态的下一步技能；初期无轨迹时直接用技能 I/O 接口兼容性合成伪查询预热 GNN。

### 2. SPEM 读写与提纯全链路 (`Sec 3, App A`)

```text
【在线两级检索与执行回路】
   新任务 q ──► 匹配上层 Skill-DAG 模板库 (阈值 sim >= 0.80)
     ├── 命中高置信模板 (ALFWorld 命中率 ~56%–61%):
     │     直接注入紧凑 Skill-DAG 骨架引导执行 (省掉近 50% 步数与 Token！)
     └── 未命中模板 或 执行中途报错触发重规划:
           1. 从下层原子技能库按 [name + 1-line summary] 向量初筛 Top-K 候选
           2. 动态拼装任务子图 (节点: 任务 / 实时状态 / 已走历史 / 候选技能[拼入 EMA 成功率统计])
           3. 2 层 Hetero-GNN (耗时 ~2ms) 消息传递打分重排 ──► 注入最优技能完整文档驱动下一步动作

【回合结束后的记忆更新分流】
   ├── 任务失败 (Negative Protection): 严禁生成新 DAG 模板！仅对本局调用过的技能/模板衰减 EMA 可靠性分
   └── 任务成功 (Trajectory-DAG 四步提纯流水线, Fig. 2):
         1. 建初始执行图: 解析每步动作与参数实体，连时序边与参数数据流边 (原始均值 13.4 步)
         2. 终点反向切片 (Backward Slicing): 从成功终态节点逆向回溯，砍掉对终局无因果贡献的死胡同分支
         3. 效用打分剪枝: 正向奖任务推进/新颖度，负向罚报错/no-op/原地打转，剪除低分冗余探测步
         4. 同意图折叠写回: 连续同阶段动作折叠合并，修复跨步依赖边生成紧凑骨架 (均值 6.0 步, 砍掉 54.9%！)
```

*(注：零轨迹冷启动机制——在 `SkillsBench` 等无历史轨迹的新环境，系统扫描技能库元数据，从每个技能的一句话描述与 I/O Schema 自动生成伪查询，并按共享工具/接口输入输出类型兼容度连接弱关系边，离线预训练 GNN 的下一步预测、整图价值与边存在性三个轻量头。)*

#### (2) 核心组件消融与 2,000 技能大规模压测 (`Tables 2–3, Fig. 3`)

- **三组件缺一不可（`Table 3`, ALFWorld + MiniMax-M2.7，完整版 `70.7% / 18.3 步 / 45.8K tok`）**：
  - 砍掉上层 `Skill-DAG` 模板库 $\rightarrow$ 暴跌 **-13.9%**（至 `56.8%`），步数涨至 `23.0` 步、Token 涨至 `67.5K`；
  - 砍掉 `Skill-GNN` 退回纯向量检索 $\rightarrow$ 暴跌 **-12.4%**（至 `58.3%`），前置动作失败或状态跳变时无法动态换技能；
  - 砍掉反向切片提纯、直接存整条成功原轨 $\rightarrow$ 下跌 **-7.7%**（至 `63.0%`），冗余试错步污染提示词并推高开销至 `56.2K`。
- **2,000 技能规模扩容测试（`Fig. 3c–d`）**：当技能池扩充至 **2,000 个**时，纯向量检索因同义词拥挤彻底瘫痪（`Hit@1 = 0.0`, `MRR = 0.112`）；叠加 ~2ms `Skill-GNN` 状态图重排后，依然稳在 **`Hit@1 = 0.51`, `MRR = 0.573`（超 5 倍提升）**。

## 三、双篇合璧：向联接 Agent 主报告（3.3.3 / 3.3.4 / 3.4 节）的四大落地准则

把 `WASP-Mem` 与 `SPEM` 拼在一起，正好闭环了主报告 [`storyline_and_evaluation_merged_technical_route_report.html`](../../../../.lavish/storyline_and_evaluation_merged_technical_route_report.html) 中排障规程从**“去噪提纯 $\rightarrow$ 归并防串味 $\rightarrow$ 专家诊断纠偏 $\rightarrow$ 双轨选技”**的完整工程流水线：

1. **慢路径长轨迹入库前先跑“成功终态反向切片（Backward Slicing）”砍废步（对标 `SPEM`）**
   多轮慢路径澄清与网元调参往往夹杂着试探性查询、用户中途改口作废分支与 `no-op` 空操作（原样入库掉点 7.7%）。以最终网元顺畅回执节点为锚点做**因果反向切片**，剪掉无因果贡献的旁支，仅把「告警症状 $\rightarrow$ 关键消歧槽位 $\rightarrow$ 最终生效参数组合」折叠成 ~5 步以内的紧凑 `Skill-DAG` 骨架。
2. **弃用按工具名脚本强合并，改用“先读后写隐式归并 + 弹性注解页”（对标 `WASP-Mem Free Form`）**
   严防 `Schema Form-ED` 的覆辙——在电信网元系统中，不能因为两条排障轨迹都调了同一个底层 `modify_qos_profile` 接口就用脚本把它们强行合并成一条规则（业务场景可能分别是高铁漫游保障与居家直播上行提速）。采用 `index.md` 业务目录路由 + **入库前先读取相似旧规程页，由巩固 Agent 判断是原地增补异常恢复分支，还是新建独立规程并挂接 `[[wikilinks]]`**，同时保留自由文本区承载特殊基站/时段的边角料参数细节。
3. **建立“纯自评拒收失败、网元报错码/人工诊断定向转规则”铁律（双篇共识）**
   - 没有任何报错码定位或用户确认的模糊失败会话，**绝不提取新规程模板**，仅按 `SPEM` 机制扣减本局所调规程的 EMA 可靠性分；
   - 把宝贵的运维专家复盘精力 100% 聚焦在失败工单的根因标注上（对标 `WASP-Mem CP-binary + Human`），结合网元检查点报错回执将失败单精准转化为现有规程页下的“前置条件与异常恢复分支”。
4. **线上“高频 DAG 模板直通 + 异常状态子图重排”双轨调度（对标 `SPEM` 两级检索）**
   原子工具/技能检索向量仅编码 `接口名 + 一句话能力摘要`（完整参数文档命中后再加载）；常规高频诉求命中高置信度 `Skill-DAG`（相似度 $\ge 0.80$）直接一步走快路径省掉一半 Token；一旦模板未命中或下发后收到网元异常码，立即拼入「当前目标 + 刚失败动作 + 实时网元状态」重排候选恢复技能。
