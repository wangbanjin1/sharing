## 一、核心思路与两代演进贡献

### 1. 一句话核心思路 (Core Insight)

生产级记忆系统面临三个经典死结：① **合并失真**——像 Mem0/MemOS 那样让 LLM 重写合并旧记忆，极易把人名、金额、日期改丢；② **二元边拆碎多方事件**——像 Zep/Graphiti 把“某人某日乘某航司从 A 飞 B”拆成多条独立二元边后，查多趟航班时会张冠李戴，且容易把不同天发生的两次无日期同类事件（如两次网络卡顿）误去重成一次；③ **经验自嗨污染**——像 ReasoningBank 纯靠 LLM 盲猜任务成败抽经验，极易把礼貌客套话当成任务成功写进技能库。

**MIRIX（1.0 $\rightarrow$ 2.0）的四招破局思路**：

1. **分库专治（1.0 底座）**：按认知职能拆成 **6 张独立 PostgreSQL 表**，由总管 Agent（`Meta Memory Manager`）按需唤醒对应子 Agent 并行写入，读侧强制先提炼话题主动检索（`Active Retrieval`）；
2. **底表只读保真 + $n$ 元超图建索引（2.0 架构）**：PostgreSQL 原始记录作为唯一事实源**永不覆写篡改**；Neo4j 只做外挂索引（挂了也不回滚落库），且用 **$n$ 元事实帧（N-ary Frame）**把一次完整事件的所有角色绑在一起，数值/日期只存属性不建节点；
3. **双轨哈希防事件坍缩 + 显式预算检索（2.0 读写）**：语义常识跨会话合并引文，而情景事件哈希强制拼入“显式发生时间或原始行 ID”，杜绝不同天的同类无日期事件被误合并；检索按 5 类问题算子硬卡返回行数上限；
4. **AutoDream 离线双路巩固（2.0 演进）**：后台空闲时，对**用户事实**只合并同指实体指针、绝不改原始文本；对**程序技能（Skill）**强制用“原文 Quote 子串硬匹配 + 外部工具结果核验”压住模型自夸幻觉，再编修 `Skill`。

### 2. 四大核心贡献 (Key Contributions)

1. **六类分库底座与高压缩多模态记忆（v1.0）**：在 2K–4K 长程电脑屏幕流基准 `ScreenshotVQA` 上，相比图像 RAG 存储体积砍掉 **99.9%**（15.07 GB $\rightarrow$ 15.89 MB），准确率反超 **+35%**（0.441 $\rightarrow$ 0.595）。
2. **保血缘 $n$ 元超图与双轨身份哈希（v2.0）**：解决二元图谱丢失多跳角色绑定与无日期重复事件坍缩难题，配合区分 `planned`（计划中）与 `completed`（已发生）的状态打分，使 LongMemEval-S 准确率从扁平版 `58.8%` 暴涨至 **`72.6%`**（甩开最强超图基线 HyperMem **+14.3%**），长文档多跳 QA 领先 **+22%~+31%**。
3. **有界预算检索与倍速建图响应（v2.0）**：按 5 类查询算子分配严格行数配额，建图摄取比 HyperMem **快 2.4–3.2 倍**，单题作答耗时全面领先（LoCoMo `5.46s` vs `9.70s`）。
4. **带原文 Quote 硬核验的 `ProceduralDream` 技能自演进（v2.0）**：在 ALFWorld 与 WebShop 上，当 `ReasoningBank` 出现负迁移掉分时，MIRIX-2.0 稳定提分并拿下最高成功率（WebShop 成本最低且成功率 `37.4%` 第一；MetaClaw-Bench 跨 30 天任务准确率从 `41.1%` 提至 **`49.2%`**）。

### 2.2 MIRIX-2.0 三路径核心流水线

```text
【1. 在线写路径 Write】 (Fail-Soft 原则：先落 PostgreSQL 底表，图索引失败绝不回滚底表)
   新输入 (对话 / 满20张去重截图) ──► Meta Memory Manager 路由判定需更新的子库 (1~6) ──► 并行写 PostgreSQL
     └─► 若写入 Episodic 或 Semantic 表，异步触发 Neo4j 超图挂载 (graph_memory_manager_v7.py):
           ① 抽 n 元事实帧 + 缺失细节补漏 (源文本数字/引号词覆盖率 <45% 时触发 1 次补充提取)
           ② 锚点清洗与注册表对齐 (剔除 52 个泛化词，保留数字；搜同用户 cos>=0.72 的 Top-4 老锚点调 1 次 LLM 判同指)
           ③ 双轨哈希落图: 语义帧按 [用户+谓词+角色锚点] 合并引文；情景帧额外拼入 [显式事件时间 或 原始行ID] 防坍缩

【2. 在线读路径 Read & Answer】 (显式算子预算硬限流，结果伪装成 Tool Output 注入)
   用户提问 q ──► 确定性规划器识别 5 类算子 (Single / Temporal / Intersection / List-union / Count) 分配行数配额
     ├─► 锚点入口选 Top-15 (向量召回 + 精确词命中 - 高频中心节点度数惩罚，防主角节点霸榜)
     ├─► 双通道有界扩展:
     │     • 基础召回通道 (Base Lane): 拉取关联底表行 + 同分块/相邻时间片上下文 (严卡预算 6~8 行)
     │     • 关系引用通道 (Relation Lane): 谓词过滤截断 ≤240 候选帧 ──► 9 维加性打分选 Top 4~12 帧
     │       *核心状态分: 自动识别 planned(仅计划) vs completed(已发生)，统计/时序题自动对“未成行计划”降权！
     └─► 融合返回【超图事实 + PostgreSQL 原文行】──► 初稿规则自检 (数字/月份无出处或不确定时最多重搜 1 次)

【3. 后台离线巩固 AutoDream】 (彻底脱离前台写路径)
   ├─► SemanticDream (每满 5 个分块触发): 仅对人/机构/地点等安全实体，在 cos>=0.86 的 Top-4 近邻中合并同指锚点边
   │     *铁律: 被否决对写入负例缓存永不再问；合并只改 Neo4j 指针，【绝不触碰改写 PostgreSQL 原始证据行】！
   └─► ProceduralDream (每满 5 个已完成任务会话触发):
         ① 原话引文蒸馏 (session_experience_distiller.py): 抽成败结局与正/反经验，强制做【原文 Quote 子串存在性匹配】
            (搜不到原话或仅靠 Agent 自吹成功无工具/用户佐证，强制降级为 unclear / MEDIUM)
         ② 技能闭环编修 (skill_experience_curator.py): 评估旧 Skill 执行效果 (helped/hurt)，凭原文引文增删改 Skill 步骤
```

### 2.3 四个最值得细品的算法设计细节

1. **为什么非要搞“$n$ 元事实帧（N-ary Frame）”取代传统三元组？（`frame_extractor.py`）**
   - 二元图谱把*“Caroline 于 5 月 6 日乘达美从波士顿飞迈阿密”*拆成多条两两相连的边，一旦她飞了三次，图遍历根本分不清哪次航班配哪个航司。$n$ 元帧直接用一个超边节点把 `agent: Caroline`、`carrier: Delta`、`origin: Boston`、`destination: Miami` 锁死在同一帧里。
   - **数值剥离与角色折叠**：价格、日期、速率（如 `$420`、`500 Mbps`）严禁建实体节点，一律存为帧内属性字典；同时用 `_ROLE_CANON` 词表把大模型自由发散出的 71 种同义角色名（导致 7.2% 重复帧）折叠映射到核心标准角色。
2. **怎么做到“跨会话同事件合并，不同天无日期事件不坍缩”？（双轨身份哈希）**
   - **语义常识帧**：哈希键只算 `Hash(用户, 谓词, 角色锚点集)`——多次聊到同一客观关系会自动落入同一帧，不断累加底表原文行引用列表。
   - **情景事件帧**：哈希键多拼一项发生标识 `Hash(用户, 谓词, 角色锚点集, 发生键)`——若抽出了明确事件日期就用日期；**若原话没提具体日期（如“昨晚打游戏又卡了”），直接拿不可变的数据库原始行 ID 当发生键**，从数学上保证两次不同会话的无日期卡顿绝不会被误合并成一次。
3. **五类查询算子的硬预算配额表（防上下文随历史膨胀）**：
   规划器先判断问题属于哪一类，直接锁死两路召回的最大数据库行数（`Base Rows / Relation Facts`）：
   - `Single`（单事实）：`6 / 4` ｜ `Temporal`（时序）：`6 / 6` ｜ `Intersection`（多实体交集）：`7 / 7`
   - `List-union`（列表枚举）：`7 / 9` ｜ `Count`（计数统计，需防漏算）：放宽至 **`8 / 12`**。
4. **`ProceduralDream` 怎么根治“大模型自我感觉良好”的毒经验？（`session_experience_distiller.py:20-59`）**
   - 只准读真实外部对话表（物理屏蔽内部调度 Agent 消息）；
   - LLM 判成败或给旧 Skill 打分（`helped / hurt`）时，**必须附上原话引文 `outcome_evidence`**；Python 代码当场去掉标点空格做**确定性子串查找**——原对话里找不到这句话直接打回标为 `unclear`；如果“任务成功”只出现在 Agent 自己的回复里、没有任何工具回执或用户认可（`agent_only`），可信度强制封顶 `MEDIUM`；若失败仅靠自述无报错回执，同样打回 `unclear`。

## 四、源码独有实战教训对账（论文正文未展开的 3 个工程真相）

翻阅 `repos/MIRIX/mirix/services/` 源码注释，作者留下了三段极其宝贵的踩坑实录：

1. **为什么检索结果塞 System Prompt 完全没用？（`graph_retriever_v7.py:122-129` 血泪教训）**
   源码注释直言：起初把超图搜出来的事实拼成静态文本塞进 System Prompt，在 60 道探针题上实测 **“60/60 次被回答模型彻底无视（moved nothing）”**！后来改成把超图事实包装成标准数据库行（`V7MemoryRow`），直接混入 Agent 自己发起的搜索工具返回值（**Tool Output**）里，模型才真正采信并大幅提分。
2. **早期“伪超图”重构教训与星型退化防爆（`frame_extractor.py:1-98, 169-180`）**
   注释披露 `v7.10` 虽号称超图，但抽取器写成了三元组，实测 534 条事实里 **100% 都是二元边（arity=2）**，还把 `"42 campsites"` 这类数字建成实体节点污染了合并空间。`v7.12` 才强制剥离数值字面量，并规定当单个事实帧绑定实体超过 4 个（`_CLIQUE_MAX_ARITY = 4`）时，二元投影从两两全连接（Clique）自动退化为中心星型连接（Star），防止边数平方级爆炸。
3. **严禁 LLM“和稀泥”编折中摘要 + `prior_values` 留档（`meta_agent.py:160-186`）**
   遇到用户改套餐、搬家等前后矛盾事实时，大模型默认爱写成 `"居住在北京，但部分记录显示在上海"` 这种模棱两可的废话。源码 `_CONFLICT_RESOLUTION_POLICY_PROMPT` 严令禁止折中表述，强制以最新事实覆写 `summary`，同时自动把被替代的旧值标为 `superseded` 压入 `prior_values` 历史数组留底。

## 五、向联接 Agent（主报告）的四大落地映射

MIRIX-2.0 几乎是把你前面看的“用户事实记忆”与“ReasoningBank 程序经验记忆”在工业级标准下做了一次完美缝合，可直接映射到主报告对应模块：

1. **底表证据与上层索引物理分离（对齐主报告 `3.2 / 3.4 节` 存储架构）**
   严格采用 **“PostgreSQL 原始单据/对话不可变证据平面 + 上层画像与图索引只存行号引用”** 架构：后台任何实体对齐或周期性画像合并（类似 `SemanticDream`）只允许修改上层索引指针，**绝不允许覆写或摘要涂改底层原始网元单据与用户原话**，确保每一条推理决策都能无损回溯原始单号。
2. **情景双轨哈希 + `planned / completed` 状态区分（根治保障频次误统计）**
   在通信保障场景中，用户常多次反馈“晚上打王者荣耀卡”（无具体日期），或先问“周末办个加速包多少钱”（`planned` 咨询未办）后真正下单（`completed`）。引入“无显式日期时拼入原始单据/会话 ID”的身份哈希与完成态标签，既能防止多次真实卡顿被向量去重坍缩成 1 次（保证频次统计 $N_{\text{min}}$ 准确），又能避免把“口头咨询过但未办理”的业务误当成已生效配置。
3. **检索结果走 `Tool Output` 通道注入而非全堆 `System Prompt`**
   直接采纳 `graph_retriever_v7.py` 60/60 探针实测结论：除极精简的 `Core Memory`（基础人设与常驻套餐等级）放 System Prompt 外，其余按需召回的历史故障单与关联画像，统一封装为结构化工具返回结果注入对话流，大幅提升模型对检索证据的注意力采信率。
4. **慢路径经验入库前加装“原文 Quote 子串硬匹配 + 网元回执强校验”门禁（升级主报告 `3.3.3 节`）**
   你在对比表里已经看到：原版 `ReasoningBank` 因缺乏硬核验，在 ALFWorld 和 WebShop 上均发生了**负迁移掉分**；而 MIRIX-2.0 靠 `check_reply_outcome` 稳步提分。我们在沉淀慢路径澄清规则与排障 `Skill` 时，直接照搬这道确定性代码门禁——**凡是拿不出用户确认原话子串、或没有底层网元成功回执佐证（仅靠 Agent 自述完成）的轨迹，一律拦截禁止升格为全局 `Skill`**。
