## 4.1 核心思路与主要贡献

### 1. 一句话核心思路 (Core Insight)

既有经验记忆要么直接塞原始交互轨迹（`Synapse`，充斥页面 DOM 噪声），要么只从成功样本里硬抽固定动作序列（`AWM`，丢弃失败教训且换网站即崩）。**ReasoningBank 的破局思路是将“经验”的抽象层级从“具体动作（Action）”拉升到“高层推理策略（Reasoning Strategy）”**：

- **入口严控防带偏**：以题搜题仅取 Top-1 历史经验（$\le 3$ 张卡），并在每步 `<think>` 强制逐条表态“用或不用”（软门控排毒）；
- **出口双向抓因果**：无需人工真值标签，靠同源 `LLM-as-a-Judge` 自判成败——**成功轨迹提炼“为什么成”的正向套路，失败轨迹提炼“死在哪一步”的预防性护栏**；
- **算力与记忆共生**：将测试时多采样（TTS）与经验库耦合成飞轮——旧记忆帮多路采样收敛方向，同一题下的成败多轨迹对比（Self-Contrast）又反过来提纯出高信噪比策略卡片。

### 2. 四大核心贡献 (Key Contributions)

1. **高迁移性的三段式“推理记忆”表征**：提出剥离具体域名与 DOM 字面量的 `{Title, Description, Content}` 结构化策略卡（源码强化 `Description` 明确界定 `when or when NOT to use`），在跨网站（WebArena-Multi）与开放式纯 Bash 代码环境（SWE-Bench）中均保持正向迁移。
2. **无真值标签下的“成败双通道蒸馏”闭环**：打破“只抄满分作文”的幸存者偏差（`Sec 5` 证明将失败轨迹塞入 `AWM` 会使成功率从 44.4% 倒退至 42.2%，而 `ReasoningBank` 纳入失败轨迹后从 46.5% 跃升至 **49.7%**），实现纯测试时流式冷启动建库。
3. **首创记忆感知的测试时扩展（`MaTTS`）**：打通了隔离单题盲目撒网的 Vanilla TTS 与记忆系统，提供**并行多轨迹自对比（Parallel Self-Contrast）**与**串行多步自检修正（Sequential Self-Refinement）**两种高信噪比经验提纯机制。
4. **“提准确率 + 砍步数省开销”的工程双赢验证**：在 WebArena、Mind2Web、SWE-Bench 三大基准及 12B 开源小模型上全面提分（WebArena 总成功率提升 **+8.3% ~ +11.3%**）；且因高维策略减少了盲目试探，成功样本交互步数最多削减 **30.9%**，前台省下的网页重读 Token 几乎抵消了后台复盘成本，单题全链路总 Token 仅微增 **4.3%**。

## 4.2 核心架构与真实执行管线（融合源码实现）

```text
[新任务查询 q_i]
   │  1. 非对称以题搜题 (memory_management.py:172-215)
   │     拼接 Instruct 前缀 ──► gemini-embedding-001 (3072d) ──► 检索前 i-1 题中 Top-1 相似任务 (≤3 张卡)
   ▼
[显式门控注入] (agent.py:134-138, appendix.tex:66-68)
   │     卡片拼入 sys_msg，强制每步 <think> 先逐条讨论是否采用，屏蔽错配经验对 <action> 的干扰
   ▼
[环境交互 / MaTTS 扩展] (Sec 3.2-3.3)
   ├── 基础单轨 (k=1): ReAct 循环产出轻量轨迹 τ = (<think>_t, <action>_t)，剥离原始 DOM 树
   ├── MaTTS 并行 (k=5): 同一记忆引导下并发采样 5 条轨迹 ──► 直送 PARALLEL_SI 横向对比找茬 (提取 ≤5 条)
   └── MaTTS 串行 (k=5): 首轮结束后追加 First-time Check 与 k-2 轮 Follow-up Check 自检纠错
   ▼
[无真值自评与双路蒸馏] (induce_memory.py:70-163)  *仅单轨模式走此分支*
   │     同骨干 Judge (Temp=0.0) 读入 (q_i, τ, 终态页面 cap, 回复) ──► 输出 autoeval_thoughts + Status
   │     轨迹末尾拼接 "\n\nThe task {succeeded|failed} because: {autoeval_thoughts}" 后分流：
   ├── Status == Success ──► SUCCESSFUL_SI (Temp=1.0): 分析成功主因，提炼 ≤3 条可迁移正向策略
   └── Status == Failure ──► FAILED_SI     (Temp=1.0): 定位失败根因，提炼 ≤3 条预防性避坑护栏
   ▼
[极简入库] (appendix.tex:72-85)
         绑定原始 q_i 向量与新卡片，Append-Only 追加写入 JSONL 记忆池，立即供第 i+1 题检索
```

### 1. 三段式记忆卡片 Schema（`prompts/memory_instruction.py:15-87`）

- **`Title`**：核心推理模式或策略标识（如 `User-Specific Information Navigation`、`Category Filter Prioritization`）。
- **`Description`**：一句话界定**触发条件与禁用边界**（源码指令写死为 `<one sentence summary describing when or when NOT to use the memory item>`）。
- **`Content`**：1–3 句（`PARALLEL_SI` 为 1–5 句）抽象核查步骤、决策依据或防错准则，严禁含域名、商品名或硬编码元素 ID。

### 2. 支撑闭环不崩的四个关键机制

1. **以题搜题 + $k=1$ 窄召回**：检索向量建在历史原始 Query 上而非抽象卡片上，且默认只取最相似的 **1 道**历史任务经验（`Sec 5 / Appendix C.1` 消融显示 $k=1$ 达峰值 `49.7%`，增大至 $k=2,3,4$ 反而因多策略冲突回落至 `46.0% / 45.5% / 44.4%`）。
2. **每步 `<think>` 显式推理门控**：注入提示词强制要求 *"In each step, please first explicitly discuss if you want to use each memory item or not, and then take action."* ——既利用自回归近因效应在单步粒度隔离错配检索，又保证当前跑出的轨迹干净纯粹，避免脏轨迹在任务结束后污染新卡片提取。
3. **去 DOM 轨迹压缩 + 裁判归因透传**：丢弃数万 Token 的网页无障碍树 `axtree_txt`，仅保留 `<think> + <action>` 序列（`induce_memory.py:70-76`），并将 `LLM-as-a-Judge` 的归因推理 `autoeval_thoughts` 直接附在轨迹末尾喂给蒸馏器，使单题抽取仅耗 `1,562` Token。
4. **`MaTTS` 并行找茬与串行打磨**：并行模式（`PARALLEL_SI`）绕开单轨二元误判，直接横向比对同一题下“为何部分轨迹成、部分轨迹败”提炼共性因果；串行模式则把 `First-time / Follow-up Check` 的自我纠错转折点沉淀为防错经验。

## 4.3 流式评测协议与实验数据对账

### 1. 怎么测的？—— 无独立训练集的“单遍流式评测（Single-Pass Online Streaming）”

- **子集内白手起家串行跑**：在单域子集（如 Shopping 187 题、SWE-Bench 500 题）上**不切分训练集**，初始经验库置空 $\mathcal{M}_0 = \emptyset$，按队列顺序逐题串行测试。考第 $i$ 题时仅允许检索前 $i-1$ 题沉淀的 $\mathcal{M}_{i-1}$（源码先写缓存再切片历史向量防自命中）；评测脚本在后台静默记录真实得分 $s_i$ 但绝不泄露给 Agent，Agent 仅凭自身 `LLM-as-a-Judge` 盲猜成败并抽卡入库供第 $i+1$ 题使用。最终汇报全队列首次交卷的平均成功率。
- **跨站直接挂载迁移**：评测 WebArena `Multi`（29 道跨站综合题）时，直接继承挂载前述单站子集积累的记忆池，检验跨站泛化能力；`+MaTTS (k=5, Pass@1)` 汇报的仍是单轨期望成功率（而非挑最优的 Best-of-5），其涨分来自前序题目通过 5 轨对比产出了更高纯度的卡片。

## 4.5 架构局限与联接 Agent 落地对齐方案

### 1. 原生设计的四处工程局限

- **只追加不治理（Append-Only 膨胀）**：无去重、冲突覆盖或过期淘汰机制（`appendix.tex:72-78`），长稳运行数千单后同义/矛盾卡片会挤占 Top-1。
- **粗粒度单键索引**：卡片绑死在顶层 `cur_query` 向量下，自身无独立索引；若长任务中途遇到特定局部子故障但顶层意图不相似，则无法跨任务召回排障经验。
- **纯串行耦合与顺序敏感**：评测采用“做完一单立刻同步抽卡再接下一单”，不仅对初期冷启动题目顺序敏感，也无法直接承接线上高并发请求。
- **自然语言堆叠上限低**：$k>1$（超过 3 张卡）即引发注意力分散与性能倒退。

### 2. 向联接 Agent（[主报告](file:///d:/coding/sharing/.lavish/storyline_and_evaluation_merged_technical_route_report.html)）的改造迁移

对齐主报告**“第三层：程序性经验与反思规则层”**，保留双路蒸馏与显式门控，针对性补齐工业级短板：
