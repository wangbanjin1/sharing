## Soar 认知架构的直接继承

CoALA 的模块划分直接继承自经典认知架构 **Soar**（Laird, 2022）〔正文 Sec 2.3, 图表 Fig. 2〕：

1. **记忆四分法**：基于 Atkinson & Shiffrin (1968) 与 Baddeley (1974) 的心理学模型，Soar 将记忆分为跟踪当前状态的**短期工作记忆（Working Memory）**，以及三类**长期记忆**——存放产生式规则本身的**程序记忆（Procedural Memory）**、存放世界事实的**语义记忆（Semantic Memory）**与存放过往行为序列的**情景记忆（Episodic Memory）**〔正文 Sec 2.3〕。
2. **两阶段决策环与僵局（Impasse）拆解**：Soar 在每个决策周期将程序记忆中的规则前提与工作记忆匹配，经 **Proposal & Evaluation（提议与评估）** 选出最优算子（Operator），再进入执行阶段修改内部记忆或下发外部动作〔正文 Sec 2.3, 图表 Fig. 2B, 脚注 1〕；当无合法动作或多个动作平局时触发**僵局（Impasse）**，系统自动创建子目标进行层级任务拆解〔脚注 2〕。
3. **块化学习（Chunking）**：除向语义/情景记忆写入事实与经历、用强化学习调整产生式权重外，Soar 可将解决僵局的过程编译为新产生式写入程序记忆（即修改自身源码）〔正文 Sec 2.3〕。

### 四类记忆模块定义与边界

LLM 本身是无状态（Stateless）函数，跨调用不保留任何信息；CoALA 在 LLM 外围显式维护四个模块化记忆区域，以文本作为默认内部表征〔正文 Sec 4, Sec 4.1〕：

| 记忆模块                                  | 生命周期                         | 存储内容与数据结构（Sec 4.1）                                                                                                                                                                                                                               | 启动与读写约束                                                                                                                                                                                                                                                                                            |
|:----------------------------------------- |:-------------------------------- |:----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |:--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **1. 工作记忆**<br/>（Working Memory）    | 短期<br/>（单决策环/跨调用持久） | 维护当前决策周期活跃的**符号变量（Symbolic Variables）**：最新感知输入、当前活跃目标、由推理生成或从长期记忆检索出的活跃知识、以及上一周期结转的中间状态〔正文 Sec 4.1〕                                                                                    | **全架构中心枢纽（Central Hub）**：每次调用 LLM 时，从工作记忆抽取变量填入提示词模板；LLM 输出经解析器（Parser）拆回变量写回工作记忆〔正文 Sec 4.1, 图表 Fig. 3A〕；LLM、三类长期记忆与外部环境均只与工作记忆直接交互，彼此不直连〔图表 Fig. 4A〕                                                         |
| **2. 情景记忆**<br/>（Episodic Memory）   | 长期                             | 存储早先决策周期的具体经历：历史事件流（Event Flows）、过往完整交互轨迹（Trajectories）或输入—输出示例对〔正文 Sec 4.1〕                                                                                                                                    | 初始可为空；在规划阶段可被检索（Retrieval）读入工作记忆作为上下文示例，也可通过学习（Learning）将新经历从工作记忆写入〔正文 Sec 4.1, Sec 4.5〕                                                                                                                                                            |
| **3. 语义记忆**<br/>（Semantic Memory）   | 长期                             | 存储关于世界与智能体自身的事实知识（Facts about the world and itself）〔正文 Sec 4.1〕                                                                                                                                                                      | 初始可为空，或由外部非结构化文本库/游戏手册只读初始化（如标准 RAG）；高阶智能体可通过 LLM 对原始经历做推理反思，将归纳出的事实写回语义记忆〔正文 Sec 4.1, Sec 4.5〕                                                                                                                                       |
| **4. 程序记忆**<br/>（Procedural Memory） | 长期                             | 分为两类：<br/>• **隐式（Implicit）**：存储在 LLM 权重中的先验与推理分布；<br/>• **显式（Explicit）**：写在智能体源码中的过程（实现 Reasoning / Retrieval / Grounding / Learning 四类动作的过程代码 + 实现顶层 Decision-Making 循环的代码）〔正文 Sec 4.1〕 | **唯一不可为空的长期记忆**：必须由设计者预置合法代码与初始权重才能引导启动（Bootstrap）智能体；向程序记忆写入新代码/修改权重虽可行，但风险远高于写情景或语义记忆，极易引入程序 Bug 或让智能体偏离设计者意图〔正文 Sec 4.1, Sec 4.5〕<br/>→ [四类记忆分工与写入图](resources/coala_procedural_memory.html) |

> **关键边界区分〔正文 Sec 4.1〕**：思维链（CoT）或 Scratchpad 把 LLM 自身的单次上下文窗口当作临时工作记忆；CoALA 的工作记忆是**独立于单次 LLM 调用、跨多次 LLM 调用持久化的外部符号变量数据结构**，单次 LLM 调用只从中按需合成子集作为输入。

### 面向垂直领域的三步架构设计法（Sec 6 `Agent design`）

Sec 6 不只是一套坐标系，还给了把它落到具体业务的顺序：**先定模块，再收紧读写权限，最后设计决策循环**。三步的顺序不能换——权限要在模块定下来之后才谈得上，决策循环又受权限约束。

#### 原文例子

以“个性化零售助手（根据用户查询与历史购买记录推荐商品）”为例，给出将 CoALA 落地到具体业务系统的三步流程〔正文 Sec 6〕：

1. **第一步：确定必需的记忆模块（Determine memory modules）**
   - 语义记忆（Semantic）：存放商品目录知识；
   - 情景记忆（Episodic）：存放每个用户的历史购买与历史对话记录；
   - 程序记忆（Procedural）：定义查询上述数据库的函数；
   - 工作记忆（Working）：跟踪当前会话状态〔正文 Sec 6〕。
2. **第二步：收紧内部动作空间的读写权限（Define read/write access）**
   - 赋予情景记忆**可读写权限（Read & Write）**，以便记录用户新交互；
   - 将语义记忆与程序记忆设为**只读权限（Read-Only）**，防止智能体擅自篡改商品库存或修改自身核心代码〔正文 Sec 6〕。
3. **第三步：权衡定制化与泛化性，设计决策循环（Define decision-making procedure）**
   - 规划阶段：先检索该用户的情景记忆作为当前搜索意图的先验，再显式加入 `Evaluation` 步评估搜索结果是否满足用户意图；
   - **推迟写入（Deferring Learning）**：为简化在线决策循环，将 `Learning` 推迟到整轮交互结束时执行——会话结束后统一摘要本次对话并写入情景记忆〔正文 Sec 6〕。

| 语义记忆 | 左栏世界事实（商品目录，只读）；右栏关于用户的事实（偏好、规避项） | 关于世界与自身的事实；可外部只读初始化，也可经反思写入 |
| 情景记忆 | 三条带时间戳的事件：10-21 成交、10-14 问价未下单、10-02 首单       | 早先决策周期的经历流，规划阶段被检索进工作记忆当范例   |
| 程序记忆 | 隐式权重 + SKILL.md 三条规程 + catalog_api.py                      | 隐式在权重里；显式是四类动作的过程代码与顶层决策循环   |

#### 场景 A：四类记忆怎么协作（5 步）

| 步  | 动作             | 动到谁                     | 关键点                                                                                                                     |
|:--- |:---------------- |:-------------------------- |:-------------------------------------------------------------------------------------------------------------------------- |
| 1   | 任务输入（感知） | 外部环境 → 工作记忆        | 用户那句「复购 + 预算 300 + 送公司」先变成活跃目标。此刻三类长期记忆一条都没读，「上周清单」还是未知项                     |
| 2   | Retrieval        | 情景 → 语义 → 程序         | 目标落定后才读，三路各取一个子集：情景给范例（整条轨迹），语义给事实（这才解析出「上周清单 = 250g×2 + 滤纸」），程序给规程 |
| 3   | Reasoning        | 工作记忆 + 隐式权重        | 折算成检索条件，策略照抄范例，约束来自语义记忆里的用户事实（避开深烘）                                                     |
| 4   | Grounding        | 工作记忆 ↔ 代码 ↔ 外部环境 | 价格求和、库存校验、变体归一全交给 `catalog_api.py`，模型不算数                                                            |
| 5   | Evaluation       | 工作记忆                   | 预算 / 偏好 / 配送三项自检，任一不过就退回第 3 步，不硬推                                                                  |

第 1 步不属于四类动作，但它是整个循环的起点：Sec 4.1 说工作记忆装的是「最新感知输入 + 当前活跃目标 + 检索出的活跃知识 + 上一周期结转的中间状态」，前两样就是这一步装进去的。没有这一步，第 2 步的检索就变成没有目标的遍历——图上一眼看得出「先有目标，才有检索哪三条记忆」。

Evaluation 同样不在四类动作里：Sec 6 第三步明确要求「显式加入 `Evaluation` 步评估检索结果是否满足用户意图」，所以图上把它标成「Sec 6 补充」，与 Retrieval / Reasoning / Grounding / Learning 区分开。它发生在工作记忆内部，不碰外部世界。

#### 场景 B：三类长期记忆各自被写入（4 步）

同一次经历，三类记忆写的东西完全不同——这是这张图比表格更值的地方。

| 步  | 写谁     | 写进什么                                                               | 为什么是它                                                                         |
|:--- |:-------- |:---------------------------------------------------------------------- |:---------------------------------------------------------------------------------- |
| 1   | 都不写   | 工作记忆里一条新输入：「还是太苦」                                     | 「本月第三次」这个判断不在这条输入里，工作记忆不会凭空生出来                       |
| 2   | 都不写   | 读情景记忆，看到 11-04、11-07、11-11 三条同类事件                      | 情景只回答「发生过什么」；读到才形成「同一原因」的判断，此刻语义记忆的规避项仍为空 |
| 3   | 语义记忆 | 归纳出的事实：「用户对深烘苦味敏感」，附 3 条证据与置信度              | Sec 4.5 的反思写入——对原始经历做推理，把归纳出的事实写回。写事实，不写做法         |
| 4   | 程序记忆 | 三档固化：SKILL.md 加第 4 条 / guard.py 加 `filter_avoid` / 蒸馏进权重 | 「以后怎么做事」归程序记忆，三档分别落在文本态、代码态、隐式                       |

前两步都是「什么都没写」，这恰好是三者的边界：输入只是输入，事件只是事件，归纳才是事实，规则才是程序。图里第 1 步三类记忆全是「本轮尚未读取」的占位，读到第 2 步才出现事件流，第 3 步右栏才多出一行规避项——三块内容是一步步长出来的。

**第 3 步带了一个门槛**：单次拒绝不写（可能只是当天心情），同类事件 ≥3 次才升格为常驻事实。原文没给这个阈值，图里显式化成一行断言，落到的正是「核心思路」第 2 条那个缺口：不给量化门限，系统就会把偶发当偏好。

**第 4 步的三档就是软硬两种固化**：`SKILL.md` 是软固化（可读可审，每次推理占 token），`guard.py` 是硬固化（100% 确定、零 token，要过单测），蒸馏权重落在隐式那一侧（零开销，最慢）。三者都读语义记忆里的同一个 `avoid` 字段，不各自另存一份——否则偏好一变就要改三处。

**整个 Learning 被推到会话结束**（第 2 步读完再统一归纳，不在推荐当轮就写），对应原文第三步的 Deferring Learning：把在线决策循环压轻，代价是同一会话内用不上这条教训。

#### 一处与原文的偏离

原文 Sec 6 建议「程序记忆只读」，目的是防智能体改坏自身核心代码。但业务级调参规则与排障流程必须能写，所以图上只放开 `SKILL.md` 与 `guard.py`，框架层（决策循环、工具注册）仍然只读。原文把这两层混在同一个 Procedural Memory 里，也就是「核心思路」第 4 条说的那个坑。

### 核心思路和局限

- **核心贡献**：把散乱的 Agent 工程实践统一收束到 `Working + Episodic / Semantic / Procedural` 四类记忆与 `Grounding / Retrieval / Reasoning / Learning` 四类动作的正交坐标系中，且在 Sec 6 给出的“读写权限收紧”与“会话结束异步 Learning”直接切中工业界落地痛点。
- **原文留下的四处机制空白（需由 2025–2026 后续论文补齐）**：
  1. **缺“同一用户多意图/多场景隔离”**：CoALA 的 Semantic 与 Episodic Memory 是按智能体全局平铺定义的，未讨论同一用户在不同任务场景（如“基地固定直播”对比“高铁移动会议”）下同名属性的隔离存储，直接平铺会导致跨场景参数互相污染。
  2. **缺“短期向长期晋升的量化门槛”**：原文只定性描述 `Working → Episodic → Semantic` 的反思写入（Sec 4.5），没有给出“出现几次、累积多少热度分才允许从单次情景升格为常驻语义习惯”的定量门限（这部分由 P0-3 `MemoryOS` 与 P0-6 `PersonaMem-v3` 补齐）。
  3. **缺“修改与删除的状态机”**：原文在 Sec 4.5 坦承当时工作只做 `Adding`、未解决 `Modifying` 与 `Deleting`；偏好变更时如何做版本接替与防旧值复活，需由 P0-2 `Mem0`（四操作）与 P0-4 `Zep`（双时间戳有效期接替）补齐。
  4. **把“业务调参经验规则”与“系统底层源码”混在同一个 Procedural Memory 里**：
     * 原文将 Agent 主循环源码和业务规则统称为显式程序记忆（Sec 4.1），因此在 Sec 6 建议把 Procedural Memory 设为只读以防改坏代码。但在真实排障业务中，**底层框架代码必须只读，而高密场馆预热、多单冲突消歧这类“业务级程序记忆（调参规则与标准排障流程）”必须支持从正反交互例子对比中动态学习写入**（这部分由 P0-5 `ReasoningBank` 与 P1-6 `AWM` 补齐）。

     * 经验沉淀出来分为硬规则和软规则两种

       * **软固化为经验规则**（文本态程序记忆）：对于失败与重试日志或者多次出现的反复澄清轮，提炼出共性教训，写入对应的 `SKILL.md`（比如追加一条边界条件检查规则）。

       * **硬固化为代码规则（代码态程序记忆）**：如果某条 `SKILL.md` 里的经验规则每次都要消耗几百 Token 让大模型去现推，而且逻辑完全固定，干脆把它写成一段 20 行的 Python 校验函数塞进 `scripts/` 里实现从提示词的叮嘱到代码的拦截。
