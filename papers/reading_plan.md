# 阅读地图：四篇的定位、读法与配套

> **状态更新（2026-11-13）**：这四篇已由我下载并读完，论文机制与开源实现的对账结果见 [`notes/reading_notes.md`](notes/reading_notes.md)。逐项的完成度与待补清单见 [`notes/PROGRESS.md`](notes/PROGRESS.md)。本文件的「读完之后我们的落点」一节已在该文中落实为具体四条修改项；下面的读法与配套工作仍可作为你自己复读时的索引。

**用途**：这四篇不是并列的四份材料，它们正好卡在我们报告的三个阶段上。按这条线读，四篇能拼成一条完整的因果链；打散读，就只是四个互不相干的 benchmark。

| 论文 | 卡在哪一环 | 解决的问题 |
|---|---|---|
| Mem0 | 阶段 1 · 写入 | 从对话里抽出哪些原子事实、旧事实怎么被新事实覆盖 |
| PersonaMem-v3 | 阶段 2 · 题面 | 偏好藏在行为日志里时，题怎么出才能测出"补全"而非"检索" |
| τ²-bench | 阶段 3 · 决策 | 记忆读对了以后，动作是否落到正确的终态 |
| Reflexion | 贯穿 · 程序记忆 | 一次失败怎么变成下次可复用的规则（而非又一条事实） |

顺序建议：**Mem0 → PersonaMem-v3 → τ²-bench → Reflexion**。前三篇是同一件事的三个断面，Reflexion 是横切面，放最后读不会打断主线。

## 1. Mem0（arXiv:2504.19413）

**为什么读它**：它是"抽取—更新"两段式的事实型记忆基线，几乎所有后续系统的对照对象。我们的指标 1（抽取 F1）和指标 2（状态更新准确率）在概念上就是从它这套流水线长出来的。

**读之前先想三个问题**
1. 它抽取的单位是"事实"还是"对话片段"？粒度由谁决定——模型、提示词，还是阈值？
2. 新旧冲突时它做 ADD / UPDATE / DELETE / NOOP 四选一，这个判断靠什么？判断错了会留下什么痕迹？
3. 它报的分数是相对谁的？基线是什么？

**读法**：第 3 章（方法）和第 4 章（实验）精读，前面的 related work 略读。重点看它的**抽取提示词**和**更新判定的输入构造**——这两处是它能被复现的全部秘密，也是我们复现时最容易走样的地方。表格看主结果表，别只看最好那一行。

**配套**：MemGPT（arXiv:2310.08560，分页式上下文管理的另一条路）、MemoryOS（2506.06326，热度置换）、Zep（2501.13956，时序知识图谱）、LoCoMo（2402.17753，它常用的评测载体）。
> 本地已有：`notes/memory_summary.md` 第 3 章是我之前的拆解，读原文时可以拿它当对照，但**以原文为准**，有出入告诉我。

**读完请给我**：① 抽取提示词原文（截图或复制）；② 更新判定的输入输出示例；③ 主结果表整张（含各基线行，不要只给 Mem0 那行）。

## 2. PersonaMem-v3（arXiv:2608.21381）

**为什么读它**：它把"偏好"从显式陈述挪到了隐式行为日志里，题目按轨迹类型派生。这正是我们要造的那类题面的现成范本，也是"合成数据 → 评测题"整条管线的可对标实现。

**读之前先想三个问题**
1. 真值是先定的还是后标的？先定真值再反向生成事件，和先生成日志再标注，会带来完全不同的偏差。
2. 四类轨迹（强化稳定 / 逐渐消退 / 近期新增 / 单次偶发）的判定阈值是多少？阈值一变，题目分布就变。
3. 快照里有没有"逐条有效期"？没有的话，"按截止日提问"这一整类题就派生不出来。

**读法**：重点在**构造管线**和**阈值表**，实验结果反倒次要。看它是怎么从真值反推出事件表的、清洗规则是什么、每类轨迹各占多少。表格盯四类轨迹的配比与赋分规则（显式 +1.0 / 隐式 +0.5 这类）。

**配套**：PersonaMem v1/v2（2504.14225，看三代之间改了什么，尤其是"为什么 v1 的题被刷穿了"）、LoCoMo / LoCoMo-Plus（2402.17753 / 2602.10715）、LongMemEval（2410.10813）。

**读完请给我**：① 构造管线那张图或那段流程描述；② 四类轨迹的判定阈值与配比；③ 六类题各自的判分规则；④ 它的 limitations 一节。

## 3. τ²-bench（arXiv:2506.07982）

**为什么读它**：它只比终态，不评过程。这正好是我们阶段 3 指标 5（决策与约束满足）的判分范式来源，也是"违规请求要拒绝"这类题的出处。

**读之前先想三个问题**
1. 它凭什么敢只比终态？——因为环境是确定性的（数据库 + API + 规程），动作可复现。我们的场景具备这个前提吗？
2. 双端协同（用户要亲手开关飞行模式、插拔 SIM、重置 APN）时，Agent 的输出是"指导语"，这怎么判分？
3. `Pass^k` 为什么要 k=1,2,4,8 全成功才算过？它想惩罚的是能力不足还是稳定性不足？

**读法**：先看**任务定义**和**判分实现**，再看结果。特别看它的"不可解任务人工剔除"这一步——这一步决定了它的分数上限是多少，也是合成数据最容易糊弄过去的地方。

**配套**：τ-bench 原始版（单端；编号待你确认）、CAREFUL-Bench（2611.02978，区分只读与破坏性写接口的二次确认）、UserBench（2507.22034）与 Disclosure-Gated Sim（2609.00982，分步释放偏好）。

**读完请给我**：① 任务的三元组定义（用户目标 / 环境 / 判分）；② `Pass^k` 的算式与 k 的取值理由；③ 它对模拟器的处理方式（模拟器本身评不评）；④ limitations。

## 4. Reflexion（arXiv:2303.11366）

**为什么读它**：它是"程序记忆"这条线的源头范式——不是把经历存成事实，而是把失败复盘成规则。我们报告里 S-03 那条题（用户口述规则 vs 系统自己归纳规则）的分野，就取决于这篇怎么定义"反思"。

**读之前先想三个问题**
1. 反思的产物存在哪？是自然语言的一段话，还是结构化的可执行条目？两者在下游检索时的行为完全不同。
2. 它需要"试错多次"才有效，那单次任务、不可重试的场景还适用吗？
3. 反思会不会把偶然因素固化成规则？它有没有做去偏或剪枝？

**读法**：方法一节精读，重点看**反思提示词**和**记忆缓冲区的读写时机**（什么时候写、什么时候读、读几条）。实验部分只需看清它在什么任务类型上有效——这类方法对"有明确成败信号"的任务有效，对开放式对话通常不成立。

**配套**：ExpeL（2308.10144，正反例归纳，比 Reflexion 更接近"规则"而非"教训"）、ReAct 与 Self-Refine（编号待你确认）。若时间紧，先读 ExpeL，它和我们的场景更贴。

**读完请给我**：① 反思提示词原文；② 记忆缓冲区的读写规则；③ 实验任务类型清单（哪些任务上有效、哪些上无效）；④ 它对"反思被固化成错误规则"的讨论。
